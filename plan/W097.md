  - *Mental model*: a margin engine is a pure integer function `(positions, marks, params) → MarginVerdict` evaluated millions of times per second across all accounts and (at W103) replicated bit-identically. The types are the contract that makes that function `Copy`, alloc-free, and cross-arch-deterministic. Money is integers (base-units); prices are integer ticks; ratios are basis points. There is no `f64` in this crate except a presentation/test helper, and clippy enforces it.
  - *Contract* (signatures only, never bodies):
    ```rust
    #[derive(Clone, Copy, PartialEq, Eq)] pub struct InstrumentId(pub NonZeroU16); // BTC-PERP, ETH-PERP, ... ids are 1-based ON PURPOSE:
                                                                                 // the NonZero niche keeps Option<Position> at 24B (no tag byte)
    pub type Symbol = [u8; 8];                                                   // Copy, no String
    #[derive(Clone, Copy)] pub struct Px(pub i64);          // integer ticks; tick_size in InstrumentSpec
    #[derive(Clone, Copy)] pub struct Qty(pub i64);         // signed lots: +long / -short
    #[derive(Clone, Copy)] pub struct BaseUnits(pub i128);  // notional/margin in integer base-units (i128: 100k acct headroom)
    #[derive(Clone, Copy)] pub struct Bps(pub u32);         // margin rates in basis points (e.g. IM=500bps, MM=300bps)
    pub const MAX_INSTRUMENTS: usize = 8;                   // v1.0 lock: BTC+ETH live, headroom to 8
    #[derive(Clone, Copy)] pub struct Position { pub instrument: InstrumentId, pub qty: Qty, pub entry_px: Px }
    #[derive(Clone, Copy)] pub struct Account {
        pub id: AccountId,
        pub positions: [Option<Position>; MAX_INSTRUMENTS],   // static-cap, no Vec
        pub collateral: BaseUnits,                            // single-collateral in v1.0
    }
    #[derive(Clone, Copy)] pub enum MarginVerdict {
        Healthy { equity: BaseUnits, maintenance_margin: BaseUnits },
        BelowMaintenance { equity: BaseUnits, maintenance_margin: BaseUnits, shortfall: BaseUnits },
    }
    ```
  - *Back-of-envelope* (bar (c) — the budget is the acceptance): `Position` is 24B (NonZeroU16 + pad + two i64), and the NonZeroU16 niche makes `Option<Position>` **24B too** (`None` lives in the forbidden zero of `InstrumentId`), so `Account` ≈ 8 × 24B + id 8B + collateral 16B ≈ **~216B** (≤224 after i128-alignment padding — comfortably inside the 256B const_assert), fully `Copy` (a memcpy ≈ tens of ns), **0 allocs**. With a plain `u16` id there is NO niche: `Option<Position>` grows to 32B (8B of tag+padding per slot), the array alone is 256B, and `Account` lands ≥288B — the const_assert fails on a design that "looks" static-cap. With `Vec<Position>`: a heap pointer + ~1 alloc/account-construction × 100k accounts = 100k mallocs just to load state, plus a pointer-chase per recompute → cache misses on the hot path. Integer `px * qty`: `i64 * i64 → i128`, exact, bit-identical on x86 and ARM. Float money math is the divergence vector — but NOT via auto-FMA (rustc never auto-contracts; a plain IEEE-754 `f64` mul/add is also bit-identical cross-arch): the real vectors are libm transcendentals (platform-specific), an explicit `mul_add` introduced by a perf refactor, `-C target-cpu`/future fast-math flags, and NaN-payload propagation — and float accumulation drifts incremental-vs-full IDENTICALLY on both arches, which is why the incremental==full equivalence oracle (W98), not cross-arch hashing alone, is the real guard. The integer-only-money conclusion stands.
  - **Requirements** (write in `crates/risk-engine/notes/97mon_types_design.md`): (R1) every public type is `Copy` (`static_assertions::assert_impl_all!`); (R2) **no `f64`/`f32` anywhere** (clippy `disallowed-types` + CI grep); (R3) `Account` holds `[Option<Position>; MAX_INSTRUMENTS]`, never `Vec` (static-cap); (R4) money is `i128` base-units, prices are `i64` ticks, rates are `u32` bps — all integer; (R5) `MarginVerdict` is an enum that carries the equity + maintenance-margin it was computed against (no bare `bool`); (R6) `size_of::<Account>()` ≤ 256B (one-to-few cache lines); (R7) `notional(px, qty)` returns `i128` and saturates/errors on overflow rather than wrapping (a wrapped notional is a silent margin hole).

  #### Phase 3 — Make the tests pass, one failure at a time (~35 min)
  - **(NEWBIE) When `types_are_copy_and_small` fails because `Account` is 24 bytes "and small":**
    - Symptom: `assert_impl_all!(Account: Copy)` fails, or `size_of` reports 24 (a `Vec` is 3 words and looks small).
    - Why: `Account` holds `Vec<Position>` — `Copy` doesn't derive, and the "24 bytes" is a heap pointer hiding the real cost.
    - Fix: `positions: [Option<Position>; MAX_INSTRUMENTS]`, inline, `Copy`. The size grows to ~200B but it is *flat* — no pointer chase, no alloc.
    - Cost avoided: 100k allocs to load state + a cache miss per account on the 1M-recompute/s path — the difference between hitting and blowing the §4A sub-tick budget at W99.
    - Muscle: on a per-tick-fan-out path, every account type is flat `Copy`; a `Vec` field is a hidden heap edge. Reapplies at: W98 incremental-margin deltas, W100 liquidation account read, W103 VSR snapshot serialization.
  - **(SENIOR) When `types_are_copy_and_small` fails at 288 bytes even with the static-cap array:**
    - Symptom: `positions` is already `[Option<Position>; 8]`, no `Vec` anywhere — yet `const_assert!(size_of::<Account>() <= 256)` fails with `Account` at 288B.
    - Why: `Option<Position>` has no niche when `InstrumentId` wraps a plain `u16` — every bit pattern is a valid id, so the compiler must add a discriminant + padding: `Option<Position>` is 32B not 24B, i.e. 8B of pure tag overhead × 8 slots = 64B; 256B array + 8B id + 16B i128 collateral ⇒ ≥288B.
    - Fix: `InstrumentId(NonZeroU16)` — instrument ids are 1-based, zero is forbidden, and the compiler packs `None` into it: `Option<Position>` collapses back to 24B and `Account` lands at ~216B (8×24 + 8 + 16) ≤ 256 ✓.
    - Cost avoided: 72B/account × 100k accounts = 7.2MB of dead tag bytes ≈ **2.3× fewer accounts per L2 slice** on the 1M-recompute/s path — paid on every memcpy, every cache fill, every snapshot serialize.
    - Muscle: an `Option` in a hot struct is free only if the inner type has a niche — check with `size_of`, not faith. Reapplies at: W98 dense margin vec (`Vec<AccountMargin>` slot layout), W103 `VenueOp` envelope.
  - **(SENIOR) When `notional_saturates_not_wraps_on_overflow` shows a wrapped small notional:**
    - Symptom: a huge `px * qty` wraps `i128` (or overflows `i64` first) to a tiny or negative value; the account looks under-leveraged when it is enormously over-leveraged.
    - Why: plain `*` on integer money math wraps in release builds; `i64` intermediate overflowed before widening.
    - Fix: widen to `i128` *before* multiply (`px as i128 * qty as i128`), then `checked_*` / `saturating_*` with an explicit `RiskError::NotionalOverflow`. Never let money math wrap silently.
    - Cost avoided: a silent margin hole — the single worst class of bug in a margin engine (an account that should be liquidated reads healthy until it blows the insurance fund).
    - Muscle: money math is checked integer math at the widest type; overflow is an explicit error, never a wrap. Reapplies at: W98 equity recompute, W100 shortfall sizing, W92 ledger balance math.
  - **(EXPERT) When `account_load_zero_alloc` reports ~100k allocs:**
    - Symptom: dhat shows one alloc per account constructed; the "small" account was hiding a `Vec`.
    - Why: same `Vec<Position>` root cause as the layout test — it surfaces again as allocs under volume.
    - Fix: static-cap array (already done if the layout test is fixed); add this dhat test to CI so a future "convenience `Vec`" refactor fails loudly.
    - Cost avoided: 100k mallocs per state load × every recompute pass that rebuilds accounts — allocator pressure that destroys p99 tail at the §4A scale.
    - Muscle: static-mem is a CI invariant, not a one-time choice; guard it with dhat at the boundary. Reapplies at: W99 zero-alloc audit, W103 capstone static-mem gate.
