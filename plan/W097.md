        pub(crate) wal: wal::Wal,
        pub(crate) txn_manager: txn::TxnManager,

- [ ] **Build**: `crates/mini-db/src/kv.rs` — `get(key) -> Option<Value>` checks memtable → SSTables in order.
  Bloom-filter rejection per `bloom::ClassicBloomFilter`. (~75 min)
  - **Why**: get() is the hottest read path. Bloom-filter false-positive cost dominates if bloom isn't consulted FIRST
    before SSTable disk read. This is the textbook LSM read path; getting it wrong tanks throughput by 10×.
  - **Read first**: RocksDB `table/block_based/full_filter_block.cc` (FilterBlockReader::KeyMayMatch); skyzh mini-lsm
    Week 1 Day 5 (Get path); `crates/lsm-core/src/read.rs` (your existing `LsmTree::get_with_bloom`); `crates/bloom/`
    (`ClassicBloomFilter::contains`).
  - **Design**: ```rust
    impl Db {
        pub fn get(&self, key: &[u8]) -> Result<Option<Value>> {
            metrics::GET_TOTAL.inc();
            // 1. Memtable (always check, no bloom)
            if let Some(v) = self.inner.lsm.memtable_get(key)? { return Ok(v.into_value()); }
            // 2. Immutable memtables (linear scan, newest first)
            for imm in self.inner.lsm.immutable_memtables() {
                if let Some(v) = imm.get(key) { return Ok(v.into_value()); }
            }
            // 3. SSTables level-by-level, bloom-first
            for level in self.inner.lsm.levels() {
                for sst in level.candidate_ssts(key) {
                    if !sst.bloom().contains(key) {
                        metrics::BLOOM_REJECT.inc();
                        continue;
                    }
                    if let Some(v) = sst.get(key, &self.inner.bufpool)? { return Ok(v.into_value()); }
                    metrics::BLOOM_FP.inc();
                }
            }
            Ok(None)
        }
    }
    pub enum Value { Live(Bytes), Tombstone }
    ```
    **Invariants**: bloom check is ALWAYS before SST disk read; tombstone returns Ok(None) to caller but is
    distinguishable internally for compaction; never skip memtable (no bloom on memtable — would hide writes).
  - **Build steps**: 1. (~10 min) Define `Value` enum with `into_value` returning `Option<Bytes>`; 2. (~20 min)
    Implement memtable check delegating to lsm-core; 3. (~25 min) Implement SST loop with bloom + bufpool-mediated
    read; 4. (~10 min) Wire metrics counters (`GET_TOTAL`, `BLOOM_REJECT`, `BLOOM_FP`); 5. (~10 min) Quick smoke test:
    insert 1k keys → get all → expect 100% hit; query 1k non-existent → expect ~99% bloom rejection at 10 bits/key.
  - **Pitfalls** (named):
    - *Bloom-after-disk*: **Symptom**: bloom check after the SST read in code reorder — disk IO happens anyway,
      defeats the filter. **Fix**: structure as guard clause `if !bloom.contains { continue; }` BEFORE any
      `sst.get`. Add an integration test that mocks the disk read and asserts it's not called for known-absent keys.
    - *Memtable bloom*: **Symptom**: someone adds a bloom check on the memtable for "consistency" — now writes to a
      key not yet flushed get filtered out and reads return None. **Fix**: explicitly comment "no bloom on memtable
      — write-visibility invariant"; assert in test.
    - *Tombstone leak*: **Symptom**: tombstone bytes returned to caller as a "real" Value. **Fix**: `into_value()`
      collapses `Tombstone` → `None`; make `Value` non-`pub` constructors so only kv.rs creates them.
    - *Level-skip*: **Symptom**: candidate_ssts misses overlapping ranges, key in L2 never consulted. **Fix**: lsm-core

**Wednesday — mini-db write path**

- [ ] **Build**: `crates/mini-db/src/kv.rs` — `put(key, value) -> Result<()>` writes WAL via `wal::Wal::append()`, then
  memtable. Group commit honored. (~105 min)
  - **Why**: Write path is durability boundary. The WAL-before-memtable ordering is a HARD invariant: if memtable is
    updated first and crash happens before fsync, recovery omits the write but in-process readers already saw it.
    Inverting the order silently breaks linearizability under crash.
  - **Read first**: RocksDB `db/db_impl/db_impl_write.cc` (WriteImpl → group commit); skyzh mini-lsm Week 1 Day 1
    (Put path); `crates/wal/src/lib.rs` (`Wal::append_group`, `Wal::sync`); `crates/backpressure/`.
  - **Design**: ```rust
    impl Db {
        pub fn put(&self, key: &[u8], value: &[u8]) -> Result<()> {
            let _guard = self.inner.backpressure.acquire()?;  // bail on overload
            let ts = self.inner.clock.now();
            let rec = wal::WalRecord::Put { key: key.into(), value: value.into(), ts };
            // 1. WAL append + group commit fsync
            let lsn = self.inner.wal.append(&rec)?;
            self.inner.wal.sync_up_to(lsn)?;  // group-commit-aware
            // 2. Memtable update (only after durable)
            self.inner.lsm.memtable_put(key, value, ts)?;
            metrics::PUT_TOTAL.inc();
            Ok(())
        }
    }
    ```
    **Invariants**: WAL fsync MUST complete before memtable insert; backpressure guard acquired BEFORE WAL append
    (don't waste IO on a request we'll reject); timestamp from HLC, never from `Instant::now()` (HLC needed for
    cross-node ordering in W99).
  - **Build steps**: 1. (~10 min) Confirm `wal::WalRecord` variants exist (Put, Delete) or add; 2. (~20 min)
    Implement put() with the exact 3-step order above; 3. (~20 min) Wire group-commit via `Wal::sync_up_to` (must
    coalesce concurrent puts into one fsync); 4. (~20 min) Backpressure integration — limiter has admission token;
    test that 10× over-rate floods get `Err(Backpressure::Full)`; 5. (~25 min) Concurrent put proptest with 32
    threads, assert all keys readable post-commit; 6. (~10 min) Bench: 100k put loop, assert ≥100k ops/sec single
    thread with `wal::SyncMode::Periodic` (group commit), ≥50k with `SyncMode::Always`.
  - **Pitfalls** (named):
    - *Inverted order*: **Symptom**: memtable_put before wal.append — readers see value, crash → recovery loses it,
      tests pass single-threaded. **Fix**: code review checklist + integration test that kill -9's between memtable
      insert and (would-be) WAL append; only valid order survives.
    - *Sync amplification*: **Symptom**: each put calls `Wal::sync()` independently — fsync per op tanks throughput
      to 100 ops/sec on consumer SSD. **Fix**: `sync_up_to(lsn)` consults a shared "last-synced-lsn" condvar;
      simultaneous waiters get one fsync.
    - *HLC clock backward jump*: **Symptom**: HLC adjusts based on remote ts (in W99 raft path) and goes backward
      locally, breaking the "monotone per-key version" assumption. **Fix**: HLC is **monotone-nondecreasing by
      construction**; assert in lsm-core memtable_put that incoming ts ≥ last ts for that key (or take max).
    - *Backpressure deadlock*: **Symptom**: limiter is a tokio Mutex but engine is sync — block on async context
      panics. **Fix**: use a sync-safe `parking_lot::Mutex` or atomic-counter token bucket; no async in put path.
  - **Test scenarios**: 32-thread put barrage of 1M keys, all readable after; kill -9 mid-batch, recovery yields
    state matching fsynced LSN; flood at 10× rate, observe ~10% admit + 90% Backpressure errors.
  - **Acceptance**: ≥500k puts/sec single-thread with group-commit; ≥100k with Always sync; backpressure rejects at
    configured ceiling.
  - **Downstream**: W98 MVCC wraps this with txn write-set staging; W99 raft path appends via apply() instead of
    direct call.

- [ ] **Build**: `delete(key)` writes tombstone. (~75 min)
  - **Why**: Tombstones are the LSM way to express delete. Reads must see them as "absent"; compaction must preserve
    them until all snapshots that could see the pre-tombstone version have advanced. Skipping the snapshot rule
    causes phantom resurrections (a deleted key reappears).
  - **Read first**: RocksDB `db/dbformat.h` (kTypeDeletion); skyzh mini-lsm Week 2 Day 2 (compaction + tombstones);
    `crates/lsm-core/src/compaction.rs` (tombstone GC predicate).
  - **Design**: ```rust
    impl Db {
        pub fn delete(&self, key: &[u8]) -> Result<()> {
            let _guard = self.inner.backpressure.acquire()?;
            let ts = self.inner.clock.now();
            self.inner.wal.append(&wal::WalRecord::Delete { key: key.into(), ts })?;
            self.inner.wal.sync_current()?;
            self.inner.lsm.memtable_tombstone(key, ts)?;
            metrics::DELETE_TOTAL.inc();
            Ok(())
        }
    }
    ```
    **Invariants**: tombstone has its own timestamp; tombstone is preserved across compactions until
    `min_active_snapshot_ts > tombstone.ts` (W98 GC rule); tombstone above live version of same key hides it; lower
    tombstone below newer live version does NOT (the live version wins).
  - **Build steps**: 1. (~15 min) WalRecord::Delete variant + serde; 2. (~15 min) `LsmTree::memtable_tombstone`
    delegates; 3. (~15 min) Get-after-delete returns None test; 4. (~15 min) Get-after-delete-after-put returns

    - *Tombstone GC too eager*: **Symptom**: compaction drops tombstone, older SST has live version, key resurrects.
      **Fix**: compaction filter consults `txn_manager.min_active_snapshot_ts()`; only drop tombstone when older

  - **Test scenarios**: put K=1 → delete K → get None; put K=1 → delete K → put K=2 → get 2; put K=1 → delete K →

- [ ] **Build**: `crates/mini-db/src/scan.rs` — `Scan { iter: lsm_core::MergeIterator }`. Inclusive range scans. (~150 min)
  - **Why**: Range scan is the second-hottest read path and the hardest to get right under MVCC + tombstones +
    compaction. A correct merging iterator over memtable + per-level SSTables that filters tombstones AND respects
    snapshot is the keystone of mini-db reads.
  - **Read first**: RocksDB `db/db_iter.cc` (DBIter::Next loop, tombstone handling); skyzh mini-lsm Week 1 Day 6 + 7
    (merging iterator, two-merge-iterator); `crates/lsm-core/src/merge_iterator.rs` (your existing
    `MergeIterator<K, V>`); Postgres `src/backend/access/heap/heapam.c` for visibility logic (conceptually similar).
  - **Design**: ```rust
    pub struct Scan<'a> {
        inner: lsm_core::MergeIterator<'a>,
        snapshot_ts: Option<TxnId>,    // None => latest
        upper_bound: Bound<Bytes>,
        _guard: Option<bufpool::PinGuard<'a>>, // keep SST pages pinned for scan lifetime
    }
    impl Db {
        pub fn scan(&self, lower: Bound<&[u8]>, upper: Bound<&[u8]>) -> Result<Scan<'_>> { ... }
        pub fn scan_at(&self, snapshot: &Snapshot, lower: Bound<&[u8]>, upper: Bound<&[u8]>) -> Result<Scan<'_>> { ... }
    }
    impl<'a> Iterator for Scan<'a> {
        type Item = Result<(Bytes, Bytes)>;
        fn next(&mut self) -> Option<Self::Item> {
            loop {
                let (k, v, ts) = self.inner.next()?.ok()?;
                if self.upper_bound_exceeded(&k) { return None; }
                if let Some(snap) = self.snapshot_ts { if ts > snap { continue; } }
                match v {
                    Versioned::Tombstone => continue,
                    Versioned::Live(bytes) => return Some(Ok((k, bytes))),
                }
            }
        }
    }
    ```
    **Invariants**: scan yields keys in ascending order with NO duplicates (merge iterator de-dups by picking newest
    visible version per key); tombstones are skipped, not yielded as None; bounds are inclusive lower / exclusive
    upper (RocksDB convention — document); scan holds a pin so compaction can't free SSTable pages mid-scan.
  - **Build steps**: 1. (~20 min) `Scan` struct + `Iterator` impl skeleton; 2. (~40 min) Bound handling
    (Unbounded/Included/Excluded for both ends); 3. (~30 min) Tombstone skip + duplicate-key dedup (assert merge

**Friday — mini-db crash recovery via `recovery`**

- [ ] **Build**: `MiniDb::open()` calls `recovery::Recovery::recover(&wal, &mut page_provider)`. ARIES analysis → redo →
  undo from the txn log. (~150 min)
  - **Why**: Recovery is the durability proof. Mini-db's inheritance pitch fails if recovery has bugs — every other
    module above stands on the assumption that on-disk state + WAL replay reconstructs the last fsynced consistent
    state. ARIES three-pass (analysis/redo/undo) is the canonical algorithm.
  - **Read first**: Mohan et al. 1992 "ARIES" paper (Sections 4-6); `crates/recovery/src/lib.rs` (`Recovery::recover`
    entry); PostgreSQL `src/backend/access/transam/xlog.c` (StartupXLOG); skyzh mini-lsm Week 2 Day 1 (Manifest +
    recovery). RocksDB `db/wal_manager.cc` (WalManager::PurgeObsoleteWALFiles).
  - **Design**: ```rust
    impl Db {
        pub fn open(cfg: EngineConfig) -> Result<Self> {
            let bufpool = bufpool::BufferPool::open(&cfg.data_dir.join("pages"))?;
            let mut wal = wal::Wal::open(&cfg.data_dir.join("wal"))?;
            let mut lsm = lsm_core::LsmTree::open_locked(&cfg.data_dir.join("lsm"), bufpool.clone())?;
            if wal.has_uncommitted_records()? {
                let mut page_provider = LsmPageProvider::new(&mut lsm);
                let report = recovery::Recovery::recover(&mut wal, &mut page_provider)?;
                tracing::info!(target: "mini-db", redo_count = report.redo, undo_count = report.undo,
                               last_lsn = ?report.last_durable_lsn, "recovery complete");
            }
            // ... txn_manager, gc, etc.
            Ok(Self { inner: Arc::new(EngineInner { lsm, wal, ... }) })
        }
    }
    struct LsmPageProvider<'a> { lsm: &'a mut lsm_core::LsmTree }
    impl<'a> recovery::PageProvider for LsmPageProvider<'a> {
        fn apply_redo(&mut self, rec: &wal::WalRecord) -> Result<()> { ... }
        fn apply_undo(&mut self, rec: &wal::WalRecord) -> Result<()> { ... }
        fn last_applied_lsn(&self) -> recovery::Lsn { self.lsm.manifest().last_lsn() }
    }
    ```
    **Invariants**: recovery runs BEFORE any new write is accepted; redo is idempotent (re-applying a redo records
    same state); undo only applied to uncommitted txns from WAL analysis pass; last_applied_lsn from lsm manifest
    so we don't redo already-flushed records.
  - **Build steps**: 1. (~20 min) `LsmPageProvider` impl bridging recovery trait to lsm-core memtable_put/tombstone;
    2. (~20 min) `wal.has_uncommitted_records` check (compare WAL tail LSN vs manifest LSN); 3. (~25 min) Wire
    recover() call in open() with proper error propagation (recovery failure → Db::open returns Err); 4. (~30 min)
    Test: write 10k records, panic between memtable update and WAL fsync (use mock that drops the fsync),
    re-open, assert state matches the fsynced subset; 5. (~25 min) Test: write 10k records, normal close, re-open,
    assert recovery skipped (LSN matches); 6. (~20 min) Test: partial WAL (truncate tail), recovery reads up to
    last valid record, ignores corruption tail (recovery::Recovery must surface this).
  - **Pitfalls** (named):
    - *Double-replay*: **Symptom**: recovery replays records already in flushed SSTables → tombstones or duplicate
      writes confuse get(). **Fix**: PageProvider::last_applied_lsn() is consulted; recovery starts from
      max(checkpoint_lsn, last_applied_lsn) + 1.
    - *Torn-page on WAL tail*: **Symptom**: power-loss mid-write leaves a half-record at WAL end → crc fails →
      recovery panics. **Fix**: recovery must classify CRC failure on tail as "tail truncation" (stop reading,
      truncate WAL); CRC failure in middle is real corruption (fail open with explicit error).
    - *Undo of unbegun txn*: **Symptom**: WAL has "abort T1" but no "begin T1" — analysis pass mis-identifies as
      active. **Fix**: analysis must build txn_table from begin-records forward; abort-without-begin → log warning,
      skip.
    - *Open accepts writes during recovery*: **Symptom**: Db::open returns the handle, GC thread starts spawning
      writes before recovery done → corrupted state. **Fix**: recovery runs inside open() synchronously BEFORE
      gc/backpressure/txn_manager are spawned. Make open() blocking.
    - *No checkpoint*: **Symptom**: every open() replays the entire WAL from beginning → cold-start time grows
      linearly. **Fix**: periodic checkpoint writes a manifest entry; recovery starts from checkpoint LSN.
  - **Test scenarios**: 1k write batches with 10% probability of kill -9 between any two ops; over 100 trials,
    every re-open yields state = "all writes whose WAL fsync completed pre-crash"; partial-WAL truncation
    handled gracefully; corrupted mid-WAL fails open with clear error.
  - **Acceptance**: recovery of 100k WAL records ≤2 sec on NVMe; idempotent (running recover() twice does same
    thing); 100% durability match in 100-trial kill -9 stress.

    state-machine resync; W100 chaos tests exercise this under aggressive kills.
