**Tuesday — MDBX first look + `Database` trait sketch**

- [ ] Read libmdbx high-level README (lookup-when-stuck, not cover-to-cover). Output: `notes/23_mdbx_layering.md` with the env → txn → cursor lifetime chain and the single-writer rule. (~30 min)
  - *Mental model*: MDBX is a memory-mapped B+tree with MVCC: readers never block writers, but there is exactly one writer at a time. Every trait method you sketch next has to respect that — a `TxMut` is exclusive, a `Tx` is shared.
  - 🎯 **Hardened acceptance**: the note states the cursor-outlives-txn rule (a cursor borrows its txn; the borrow must end before the txn commits) — the lifetime constraint your trait sketch must encode in Rust.
- [ ] **Sketch**: `crates/storage-trie/src/lib.rs` — define the `Database` trait shape (signatures only, no bodies). (~45 min)
  - *Mental model*: this is the contract the W27-W28 MDBX implementation will satisfy. Get the lifetimes and the read/write split right NOW (in cheap, untestable trait form) so the expensive real impl can't paint itself into a corner. Mirrors `reth-db-api::Database`.
  - *Contract*: a `Database` trait with two associated types — `type Tx<'a>: DbTx where Self: 'a;` (read-only view) and `type TxMut<'a>: DbTxMut where Self: 'a;` (read-write view) — plus `fn tx(&self) -> Result<Self::Tx<'_>, DbError>` and `fn tx_mut(&self) -> Result<Self::TxMut<'_>, DbError>`. The GAT (generic associated type) ties each transaction's lifetime to the borrow of the env, encoding "the cursor can't outlive the txn, the txn can't outlive the env" in the type system. NEVER write the bodies — there is no MDBX env to open yet.
  - **Output**: `cargo check -p storage-trie` is green with the trait + two associated-type stubs + a placeholder `DbError` enum and empty `DbTx`/`DbTxMut` marker traits; `lib.rs` carries `//!` module-level docs naming W27 as the implementor.
  - **Expect to hit #1 — modeling the txn as an owned handle instead of a borrow**: sketching `fn tx(&self) -> Self::Tx;` with `type Tx: DbTx;` (no lifetime), because that's the obvious Java/Kotlin shape (a `Transaction` object you hold and close).
    - Symptom: when W27 implements this over libmdbx, `Self::Tx` must store a raw txn pointer with no lifetime tying it to the env — the borrow checker can't stop a txn from outliving the env, so you fall back to `unsafe` or `'static` + runtime panics, exactly the bug libmdbx's API exists to prevent.
    - Why: an MDBX txn *borrows* the mmap'd env; modeling it as an owned, lifetime-free handle erases that borrow and pushes a compile-time invariant to runtime.
    - Fix: make the txn a GAT borrowing `self` — `type Tx<'a>: DbTx where Self: 'a;` and `fn tx(&self) -> Result<Self::Tx<'_>, DbError>` — so the lifetime is non-negotiable from day one.
    - Muscle: when an upstream resource's safety rule is "X must not outlive Y," encode it as a borrow/GAT, not an owned handle — push the invariant to the type system before any code depends on it. Reapplies at: W27 MDBX `Tx` impl, W29 recovery txn handles, W41-W42 txn `LockManager` guard lifetimes, W100 mini-db transaction API.
  - **Expect to hit #2 — collapsing read and write into one trait**: defining a single `Tx` with `get` AND `put`, mirroring a naive "Transaction does everything" interface.
    - Symptom: every read-only provider must accept a read-write txn; MDBX's many-readers-one-writer concurrency is unrepresentable, and W29's MVCC snapshots can't be typed as read-only.
    - Why: MDBX's core invariant is the asymmetry between readers (concurrent, snapshot-isolated) and the single writer; one trait erases it.
    - Fix: split `DbTx` (read methods) from `DbTxMut: DbTx` (adds write methods), exactly as `reth-db-api` does.
    - Muscle: model an asymmetric concurrency invariant as two traits, not one trait with conditionally-valid methods. Reapplies at: W27 cursor vs dup-cursor split, W29-W30 read-snapshot vs write-txn, W42 shared vs exclusive lock modes.
