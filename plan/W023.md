  #### Phase 1 — Problem, prediction, design (~45 min, no code yet)
  - 🎯 **Pre-prediction prompt** — write sealed answers in `crates/latency-lab/notes/23mon_perf_prediction.md`:
    - P1: the syscall (and exact libc/crate import line) you'd reach for to read a hardware PMU counter from userspace on Linux — name it from memory.
    - P2: predicted overhead (ns) of reading one PMU counter via the syscall vs via an mmap'd counter page (`PERF_EVENT_IOC_*` + `rdpmc`). Two numbers, give the ratio.
    - P3: predicted `LLC-load-misses` count for a tight loop summing a 1MB array sequentially vs the same array accessed in a cache-line-stride random order. Two ballpark numbers.
    - P4: will your *first* design accidentally allocate (Vec growth, String formatting) on the measured path between counter-start and counter-stop? Yes/No + where.
    - P5: **list every Phase-2 test you predict your first attempt will fail.**
  - *Mental model*: a PMU counter is a hardware register the CPU increments on a micro-architectural event; you arm it before the region of interest and read the delta after. The expensive part is the *syscall to read it* — on the bar-(c) hot path you want the counter read to be cheaper than the thing it measures, which means `rdpmc`/mmap, not a `read(2)` per sample.
  - *Contract*:
    ```rust
    pub struct Counters { /* fd(s) on Linux; () on others */ }
    pub struct CounterSnapshot { pub cache_misses: u64, pub llc_load_misses: u64,
                                 pub llc_store_misses: u64, pub instructions: u64 }
    impl Counters {
        pub fn new(events: &[Event]) -> Result<Self, PerfError>;   // PERF_COUNT_HW_CACHE_* etc.
        pub fn snapshot(&self) -> CounterSnapshot;                  // reads deltas; zero-alloc
        pub fn reset(&self);
    }
    // Non-Linux: every method compiles to a no-op returning zeroed snapshots, gated #[cfg].
    ```
  - *Back-of-envelope* (bar (c) — the budget IS the acceptance): a `read(2)` of a perf fd ≈ **~1-2 µs** (syscall + copy); an mmap'd counter page read via `rdpmc` ≈ **~30-50 ns**. An LLC miss costs ≈ **~70-100 ns** (DRAM latency) vs an L1 hit ≈ **~1 ns** — a ~70-100× cliff, which is exactly why a false-shared counter pair (W4) is a 30-70% throughput regression under contention. For a per-mark-tick risk recompute touching ~16 cache lines/account at 100k accounts × 10 ticks/s, even a 10% extra LLC-miss rate adds ~100k×16×0.1×80ns ≈ **128 ms/s** of stall — over an eighth of a core, gone. Target: `snapshot()` must be **zero-alloc** and **< 100 ns** so the harness doesn't perturb what it measures.
  - **Requirements** R1..R8 — write in `crates/latency-lab/notes/23mon_perf_design.md`:
    - R1. `Counters::new` opens the requested events via `perf_event_open` (group-leader + followers, `read_format = GROUP`) so a single read returns all counters atomically.
    - R2. `snapshot()` is **zero-alloc** — no `Vec`, no `format!`, no heap; reads into a stack `CounterSnapshot`.
    - R3. **`#[cfg(not(target_os = "linux"))]` no-op fallback**: every method compiles and returns zeroed counters on macOS (the dev box) so the harness builds everywhere; the no-op path is itself tested.
    - R4. counter reads use the mmap'd page + `rdpmc` where available; fall back to `read(2)` with a documented overhead note (the syscall path is *measurement-only*, never on a bar-(c) hot path).
    - R5. counters are **per-thread, pinned** — opened with `pid = 0` (calling thread) so a shard's counters don't bleed across cores; document the requirement to pin the thread first (`runtime-thread-per-core` will do this in W85).
    - R6. a `with_counters(|| hot_region())` scoped helper arms/reads around a closure with the read overhead *outside* the measured delta.
    - R7. no `unwrap()` on the syscall path — `PerfError` carries the `errno` (paranoid kernels return `EACCES`/`EPERM` on `perf_event_paranoid`); the error message tells the user the sysctl to set.
    - R8. snapshots are subtractable (`Sub`) so `after - before` yields the region delta; overflow is saturating (counters can wrap on multiplexing).
  - **Design walk-through** D1..D6 (answer in the design doc; no peeking at the `perf-event`/`perfcnt` crate source until Phase 3):
    - D1. Group-leader vs independent fds: why open the events as a group with `read_format = PERF_FORMAT_GROUP`? (Atomic multi-counter read; counters are scheduled together so ratios like misses/instruction are coherent.) What goes wrong with independent reads under PMU multiplexing?
    - D2. `rdpmc` (mmap page) vs `read(2)`: write the latency of each and state which path the bar-(c) `snapshot()` must use and why the `read(2)` fallback is acceptable *only* for the once-per-region path.
    - D3. Thread pinning: why must the measured thread be pinned to a core before `Counters::new`? (PMU counters are per-CPU; a migrated thread reads another core's counter or resets on migration.) Where does pinning come from in this codebase? (`runtime-thread-per-core`, W85 — for now, document the precondition and pin in tests via `core_affinity`.)
    - D4. The no-op fallback: why make non-Linux a *typed no-op* rather than `#[cfg]`-deleting the API? (So every downstream bench compiles on the macOS dev box; the alternative — call sites `#[cfg]`-gated — rots.) How do you *test* a no-op so it doesn't silently rot into returning garbage?
    - D5. `perf_event_paranoid`: enumerate the values (2 = default-restricted … -1 = unrestricted) and which one is needed for userspace HW counters; the error path must name the sysctl.
    - D6. **Pre-mortem (load-bearing)** — write the EXACT 5-line trace where the harness's own counter read *pollutes the measurement* it's taking:
      ```
      1. snapshot_before = counters.snapshot()       // does a read(2) syscall: ~1.5µs + its own cache misses
      2. hot_region()                                // the thing we want to measure: ~300ns, 2 LLC misses
      3. snapshot_after  = counters.snapshot()       // another read(2): ~1.5µs + cache misses from the syscall path
      4. delta = after - before                      // now includes the syscall's OWN cache misses + the 2 real ones
      5. report says "hot_region caused 9 LLC misses" // 7 of them were the harness — the measurement is a lie
      ```
      What design choice removes the harness from its own measurement? (mmap page + `rdpmc` for the in-region reads — no syscall, ~30ns, negligible cache footprint; and a *negative-control* test that measures an empty region and asserts ≈0 misses.)
  - **Output**: `notes/23mon_perf_design.md` with R1-R8, D1-D6, the self-pollution trace + the chosen `rdpmc`-vs-`read(2)` decision.

  #### Phase 3 — Make the tests pass, one failure at a time (~75 min)
  Ordered newbie → expert.

  - **(NEWBIE) When `test_perf_noop_fallback_returns_zero_on_non_linux` errors on macOS instead of no-op'ing:**
    - Symptom: `Counters::new` returns `Err` (or fails to compile) on the dev box; every downstream bench is now Linux-only and won't even build locally.
    - Why: the impl called `perf_event_open` unconditionally; macOS has no such syscall.
    - Fix: `#[cfg(target_os = "linux")]` for the real impl, `#[cfg(not(...))]` for a zero-returning twin with the *same* public signature; a single re-export picks the right one.
    - Cost avoided: a harness only buildable on the CI runner — kills local iteration on the mac the whole plan runs on.
    - Muscle: a measurement crate that doesn't build on the dev OS won't get used; gate the *implementation*, never the *interface*. Reapplies at: W24 tick-to-trade report, W58/W85/W99 benches (all developed on mac, measured on Linux).

  - **(SENIOR) When `test_perf_snapshot_zero_alloc` reports allocations:**
    - Symptom: `snapshot()` allocates 1-2× per call.
    - Why: the read collected counters into a `Vec<u64>` (one per group member) or formatted a debug string en route.
    - Fix: read the group buffer into a fixed-size stack array sized at construction; map into the `CounterSnapshot` struct by index; no `Vec`, no `format!`.
    - Cost avoided: the allocator's own cache misses contaminate the very LLC-miss number being measured — the measurement reports itself.
    - Muscle: the measured path must be quieter than the thing measured; zero-alloc is not optional for a latency harness. Reapplies at: W21 HdrHistogram record path, W58 ring bench, W99 risk recompute bench.

  - **(SENIOR) When `test_perf_paranoid_error_names_sysctl` shows a bare `errno` message:**
    - Symptom: error reads `EACCES (os error 13)` with no remedy; a teammate on a fresh box is stuck.
    - Why: the syscall error was `?`-propagated raw.
    - Fix: map `EACCES`/`EPERM` to a `PerfError::Paranoid` whose `Display` says `set kernel.perf_event_paranoid <= 1 (sysctl -w kernel.perf_event_paranoid=1) or run as root`.
    - Cost avoided: hours of stack-overflow archaeology for every new machine the harness touches.
    - Muscle: an operability error names the fix, not just the failure. Reapplies at: W85 thread-pin failures, W92 io_uring setup errors, W105 ops-monitoring.

  - **(SENIOR) When `test_perf_random_stride_exceeds_sequential` shows random ≈ sequential:**
    - Symptom: both access patterns report near-equal LLC misses; the counter can't tell cache-friendly from cache-hostile.
    - Why: the wrong PMU event was requested (e.g. a frontend event, not `PERF_COUNT_HW_CACHE_LL | READ | MISS`), or the buffer fit in cache so neither pattern missed.
    - Fix: request the exact `PERF_COUNT_HW_CACHE_*` encoding; size the buffer well past the LLC slice; re-measure.
    - Cost avoided: shipping a "cache-miss counter" that measures nothing — every downstream cache verdict would be noise.
    - Muscle: prove the counter discriminates a known-good vs known-bad pattern before trusting it on real code. Reapplies at: W4 `CachePadded` validation (Tuesday), W85 shard-locality audit, W99 convergence cell.

  - **(EXPERT) When `test_perf_empty_region_near_zero_misses` reports double-digit misses on an empty region:**
    - Symptom: the "hot region" does nothing, yet the delta shows ~10 LLC misses.
    - Why: `snapshot()` does a `read(2)` syscall between before/after; the syscall path itself touches cache lines and is attributed to the region (the D6 pre-mortem made real).
    - Fix: use the mmap'd counter page + `rdpmc` for the in-region reads (~30ns, no syscall); keep `read(2)` only for the coarse once-per-bench path; the negative-control test now passes.
    - Cost avoided: every micro-region measurement inflated by the harness's own footprint — small budgets (sub-µs) become unmeasurable.
    - Muscle: a measurement instrument must be removed from its own reading; `rdpmc` is to `perf` what coordinated-omission correction (W21) is to HdrHistogram. Reapplies at: W24 tick-to-trade, W58 sub-µs ring bench.

  - **(EXPERT) When `test_perf_group_read_is_atomic` shows misses > instructions:**
    - Symptom: incoherent ratio (more cache-miss events than instructions retired) in the same window.
    - Why: events were opened as independent fds and PMU-multiplexed (time-sliced + scaled), so the two counters cover different sub-windows.
    - Fix: open one event as group leader and the rest with `group_fd = leader`, `read_format = PERF_FORMAT_GROUP`; read all in one buffer so they share a scheduling window.
    - Cost avoided: derived metrics (misses/instruction, IPC) silently wrong — the most dangerous kind, because they look reasonable.
    - Muscle: counters compared as a ratio must be read as a group, never independently. Reapplies at: W24 report (IPC + miss-rate columns), W99 convergence-cell efficiency table.

- [ ] Read libmdbx high-level README (lookup-when-stuck, not cover-to-cover). Output: `notes/23_mdbx_layering.md` with the env → txn → cursor lifetime chain and the single-writer rule. (~30 min)
  - *Mental model*: MDBX is a memory-mapped B+tree with MVCC: readers never block writers, but there is exactly one writer at a time. Every trait method you sketch next has to respect that — a `TxMut` is exclusive, a `Tx` is shared.
  - 🎯 **Hardened acceptance**: the note states the cursor-outlives-txn rule (a cursor borrows its txn; the borrow must end before the txn commits) — the lifetime constraint your trait sketch must encode in Rust.
- [ ] **Sketch** `[bar b]`: `crates/storage-trie/src/lib.rs` — define the `Database` trait shape (signatures only, no bodies). (~45 min)
  - *Mental model*: this is the contract the W27-W28 MDBX implementation will satisfy. Get the lifetimes and the read/write split right NOW (in cheap, untestable trait form) so the expensive real impl can't paint itself into a corner. Mirrors `reth-db-api::Database`.
  - *Contract*: a `Database` trait with two associated types — `type Tx<'a>: DbTx where Self: 'a;` (read-only view) and `type TxMut<'a>: DbTxMut where Self: 'a;` (read-write view) — plus `fn tx(&self) -> Result<Self::Tx<'_>, DbError>` and `fn tx_mut(&self) -> Result<Self::TxMut<'_>, DbError>`. The GAT (generic associated type) ties each transaction's lifetime to the borrow of the env, encoding "the cursor can't outlive the txn, the txn can't outlive the env" in the type system.
