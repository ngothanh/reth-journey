  - **Design**: ```rust
    // mvcc.rs
    use crate::engine::EngineInner;
    use crate::kv::Value;
    use bytes::Bytes;
    use std::sync::Arc;

    pub type TxnId = u64;   // HLC ts; monotone within process
    pub type VersionId = u64;

    #[derive(Clone)]
    pub struct Snapshot {
        pub(crate) ts: TxnId,
        // Active txns at snapshot creation. Versions written by these are INVISIBLE.
        // Postgres calls this "running xids".
        pub(crate) running: Arc<roaring::RoaringTreemap>,
        pub(crate) engine: Arc<EngineInner>,
    }

    pub struct Txn {
        pub(crate) id: TxnId,                            // commit ts assigned at begin (provisional)
        pub(crate) snapshot: Snapshot,
        pub(crate) write_set: parking_lot::Mutex<BTreeMap<Bytes, Option<Bytes>>>, // None = tombstone
        pub(crate) read_set: parking_lot::Mutex<BTreeSet<Bytes>>,  // for OCC validation
        pub(crate) state: AtomicU8,                     // 0=Active 1=Prepared 2=Committed 3=Aborted
        pub(crate) engine: Arc<EngineInner>,
        pub(crate) isolation: Isolation,
    }

    pub enum Isolation { ReadCommitted, SnapshotIsolation, Serializable }

    impl Txn {
        pub fn get(&self, key: &[u8]) -> Result<Option<Bytes>> {
            // Local write-set first
            if let Some(local) = self.write_set.lock().get(key) {
                return Ok(local.clone());
            }
            if matches!(self.isolation, Isolation::Serializable) {
                self.read_set.lock().insert(Bytes::copy_from_slice(key));
            }
            // Snapshot read: walk versions newest→oldest, find one with ts ≤ snapshot.ts AND NOT IN running.
            self.snapshot.read(key)
        }

        pub fn put(&self, key: &[u8], value: &[u8]) -> Result<()> {
            self.write_set.lock().insert(Bytes::copy_from_slice(key), Some(Bytes::copy_from_slice(value)));
            Ok(())
        }

        pub fn delete(&self, key: &[u8]) -> Result<()> {
            self.write_set.lock().insert(Bytes::copy_from_slice(key), None);
            Ok(())
        }

        pub fn commit(self) -> Result<TxnId> {
            // OCC validation pass (for SI: write-write conflict detection; for SER: also read-set re-check).
            self.engine.txn_manager.validate(&self)?;
            let commit_ts = self.engine.clock.tick(self.id); // HLC tick
            // Stage to WAL as one batch (atomic durability)
            let mut wal_batch = wal::Batch::new();
            wal_batch.push(wal::WalRecord::TxnBegin { id: self.id, ts: commit_ts });
            for (k, v) in self.write_set.lock().iter() {
                match v {
                    Some(val) => wal_batch.push(wal::WalRecord::Put {
                        key: k.clone(), value: val.clone(), ts: commit_ts,
                    }),
                    None => wal_batch.push(wal::WalRecord::Delete { key: k.clone(), ts: commit_ts }),
                }
            }
            wal_batch.push(wal::WalRecord::TxnCommit { id: self.id });
            self.engine.wal.append_batch(&wal_batch)?;
            self.engine.wal.sync_current()?;
            // Apply to memtable AFTER durable
            for (k, v) in self.write_set.lock().iter() {
                match v {
                    Some(val) => self.engine.lsm.memtable_put_versioned(k, val, commit_ts)?,
                    None => self.engine.lsm.memtable_tombstone_versioned(k, commit_ts)?,
                }
            }
            self.engine.txn_manager.commit(self.id, commit_ts)?;
            self.state.store(2, Ordering::Release);
            Ok(commit_ts)
        }

        pub fn abort(self) {
            self.engine.txn_manager.abort(self.id);
            self.state.store(3, Ordering::Release);
            // write_set dropped, no on-disk side effects (never reached memtable)
        }
    }

    impl Snapshot {
        pub fn read(&self, key: &[u8]) -> Result<Option<Bytes>> {
            // Iterate versions newest→oldest from memtable + SSTs.
            // Visible iff: version.ts ≤ self.ts AND version.ts NOT IN self.running.
            for ver in self.engine.lsm.versions_for(key)? {
                if ver.ts > self.ts { continue; }
                if self.running.contains(ver.ts) { continue; }
                return match ver.value {
                    Versioned::Tombstone => Ok(None),
                    Versioned::Live(b) => Ok(Some(b)),
                };
            }
            Ok(None)
        }
    }

    impl EngineInner {
        pub fn begin(self: &Arc<Self>, iso: Isolation) -> Txn {
            let snapshot = self.txn_manager.snapshot_with_clock(&self.clock);
            let id = self.clock.tick_logical();
            Txn { id, snapshot, write_set: Default::default(), read_set: Default::default(),
                  state: AtomicU8::new(0), engine: self.clone(), isolation: iso }
        }
    }
    ```
    **Invariants**:
    - Every key has a **version chain** sorted by ts DESC; reads walk newest→oldest until finding a visible one.
    - Snapshot ts is the **read timestamp**; running xid set captures txns that BEGAN before snapshot but had not
      yet committed at snapshot creation (their writes are invisible — this matches Postgres xmin/xmax exactly).
    - Commit ts is assigned at commit time, MUST be > the snapshot ts of any active reader (HLC enforces). This is
      the "monotonicity of commits" property; violation = lost-update.
    - Write-set is **process-local** until commit; reads-your-own-writes via write_set check first.
    - WAL records commit as one batch (TxnBegin + N Put/Delete + TxnCommit). Recovery treats anything without
      TxnCommit as aborted (W97 Friday's recovery integration handles this).
    - OCC validation under SI checks write-write conflicts only; under Serializable, also re-reads the read-set at
      commit time and aborts on any change (the SSI variant in Cahill 2008 is a future stretch).

  - **Build steps**:
    1. (~15 min) Types: `TxnId`, `VersionId`, `Snapshot`, `Txn`, `Isolation`. `Txn::id` is the HLC-assigned begin ts;
       commit may rewrite via HLC tick.
    2. (~25 min) `EngineInner::begin(iso)` — capture snapshot via `txn_manager.snapshot_with_clock`; running-set
       collected by txn_manager (it tracks active txns).
    3. (~30 min) `Txn::get` — write_set check + snapshot.read(); for Serializable, add key to read_set.
    4. (~20 min) `Txn::put/delete` — write_set staging only (no engine call).
    5. (~30 min) `Txn::commit` — OCC validation, HLC commit_ts, WAL batch (begin + writes + commit), fsync,
       memtable apply, txn_manager.commit.
    6. (~15 min) `Txn::abort` — txn_manager.abort, write_set discarded.
    7. (~15 min) `Snapshot::read` — version iteration newest→oldest, ts + running-set visibility filter.

  - **Pitfalls** (named, deep):
    - *Timestamp skew under HLC*: **Symptom**: clock on shard A drifts ahead of shard B; a read at ts=100 on B
      misses writes committed at ts=99 on A that "should" be visible (B's wall clock thinks 99 is past). **Fix**:
      HLC's logical-clock component bumps on every observed remote ts; reads use `HlcClock::now()` which
      already returns max(physical, last_observed_remote + 1). For single-node mini-db v0.5 this is fine; for W99
      raft path, reads must `tick_with_observed(remote_ts)` before snapshot capture. Document the "snapshot is
      always at-or-behind global state" property — eventual-consistency reads. **Test**: simulate HLC skew with
      mock clock, assert reads see writes.
    - *Snapshot too old (GC eviction)*: **Symptom**: long-running scan holds snapshot at ts=100; GC at ts=200
      drops versions older than min_active=50 — fine. But if scan was stale-released and snapshot was at ts=50
      but GC ran at min_active=60, the scan's referenced versions are gone → reads return None spuriously.
      **Fix**: `txn_manager` maintains `min_active_snapshot_ts` as a registered low-water mark; GC ALWAYS reads
      this atomic before pruning. Snapshot creation publishes its ts into the active-set; Drop removes it.
      RAII guard pattern: `let snap = db.snapshot(); /* ... */ drop(snap);` releases.
      **Test**: 1000 concurrent snapshot create+hold+drop, assert min_active never exceeds youngest live snap;
      hold a snap for 10× gc_interval and assert reads still succeed.
    - *Commit/abort retry storm*: **Symptom**: high-contention workload, OCC validation aborts 50% of commits,
      clients retry, abort again, livelock. **Fix**:
      (a) jittered exponential backoff in client wrapper (mini-db lib exposes a `transact(closure, retry_policy)`
      helper that owns backoff);
      (b) optionally fall back to 2PL for hot keys (txn::TxnManager already supports 2PL — pick at begin time);
      (c) metric `TXN_ABORT_RATE` — alert if > 10%.
      **Test**: 16 threads, 100 keys, 50% conflict rate, assert overall commit rate ≥ 80% with backoff.
    - *Read-your-own-writes violation*: **Symptom**: txn writes K=1, reads K, expects 1 but sees old version
      because read went straight to engine, missing write_set. **Fix**: Txn::get ALWAYS checks write_set first;
      assert via test that `txn.put("k", "1"); txn.get("k") == Some("1")` in same txn before commit.
    - *Write-after-commit*: **Symptom**: caller calls txn.put after txn.commit (typed-state model can prevent, but
      via Arc<> aliasing they might). **Fix**: commit consumes self (`pub fn commit(self) -> ...`) — caller can't
      reuse. abort same. Make Txn `!Clone`.
    - *Phantom reads under SI*: **Symptom**: T1 does `count(*)` (scan), T2 inserts new row, T1 re-counts and sees
      more rows — phantom. SI doesn't prevent this. **Fix**: document — mini-db default is Snapshot Isolation,
      NOT Serializable. Phantom prevention requires Serializable + predicate-locking or SSI; both out of scope
      v1.0 but documented as future.
    - *Long-running write txn blocks GC*: **Symptom**: a txn open for 1 hour holds min_active at its snapshot ts;
      GC stalls, on-disk versions grow unbounded. **Fix**: configurable `max_txn_age`; txn_manager aborts txns
      older than threshold (returns Err on next op). Metric `OLDEST_ACTIVE_TXN_AGE`.

  - **Test scenarios** (adversarial):
    - Postgres-style "lost update" test: T1 reads K=10, T2 reads K=10, T1 writes K=11 + commit, T2 writes K=11 +
      commit. Under SI: T2 commit MUST abort (W-W conflict on K from T2's snapshot's perspective).
    - "Write skew" test (SI-permissible anomaly): T1 reads A,B then writes A; T2 reads A,B then writes B; both
      commit. Under SI: BOTH commit (this is the canonical SI write-skew example, document as known limitation).
      Under Serializable + read-set validation: at least one aborts.
    - "Read-your-own-writes": single txn does 100 put/get pairs interleaved, all gets return latest put for that
      key, no engine access.
    - Tombstone visibility: T1 deletes K, T2 with snapshot before T1's commit reads K, must see old value.
    - GC ordering: 100 concurrent snapshots, drop them in random order, gc never prunes a version still visible
      to any active snapshot.
    - Crash mid-commit: kill -9 between WAL fsync and memtable apply; recovery must re-apply (TxnCommit was in
      WAL); state matches.
    - Crash before WAL fsync: state must NOT include partial writes (TxnCommit absent → recovery treats as aborted).

  - **Acceptance**:
    - 100k mixed read/write txns at 16 threads under SI: commit rate ≥ 95% on 1k-key workload (low conflict),
      ≥ 70% on 100-key workload (medium conflict).
    - Linearizability checker (e.g., elle or jepsen-clojure style — even a simple knossos run) passes for
      Serializable; SI run shows expected anomalies.
    - GC reclaims at least 80% of obsolete versions within 2× gc_interval.
    - `TXN_ABORT_RATE` exposed as Prometheus gauge.
    - Inheritance contribution: mvcc.rs ≤ 400 LOC native, calling into txn::TxnManager + lsm::versions_for +
      wal::append_batch + time::HlcClock.

**Wednesday — mini-db GC**

- [ ] **Build**: `crates/mini-db/src/gc.rs` — `GcWorker` runs every N seconds, drops versions older than the oldest
  active snapshot. Coordinates with txn_manager's active-set. (~105 min)
  - **Why**: Without GC the version chain grows unbounded; reads slow down (more chain to walk) and disk fills.
    Naive GC drops versions still referenced by long-running snapshots → spurious None returns. The
    `min_active_snapshot_ts` low-watermark protocol is the standard fix.
  - **Read first**: Postgres `src/backend/access/heap/vacuumlazy.c` (vacuum loop + visibility horizon); CockroachDB
    `pkg/kv/kvserver/gc/gc_iterator.go`; RocksDB `db/db_impl/db_impl_compaction_flush.cc` (CompactionFilter for
    SnapshotChecker); `crates/txn/src/lib.rs` (`min_active_snapshot_ts` API you exposed in W42).
  - **Design**: ```rust
    pub struct GcWorker {
        engine: Arc<EngineInner>,
        interval: Duration,
        shutdown: Arc<AtomicBool>,
        handle: Option<JoinHandle<()>>,
    }
    impl GcWorker {
        pub fn spawn(engine: Arc<EngineInner>, interval: Duration) -> Self { ... }
        pub fn shutdown(&mut self) { /* signal + join */ }
        fn run_loop(engine: Arc<EngineInner>, interval: Duration, shutdown: Arc<AtomicBool>) {
            while !shutdown.load(Ordering::Relaxed) {
                std::thread::sleep(interval);
                let watermark = engine.txn_manager.min_active_snapshot_ts(); // u64::MAX if no active
                let stats = engine.lsm.gc_versions_below(watermark)?;
                metrics::GC_VERSIONS_DROPPED.inc_by(stats.dropped as u64);
                metrics::GC_BYTES_RECLAIMED.inc_by(stats.bytes as u64);
            }
        }
    }
    ```
    **Invariants**: GC drops versions with ts STRICTLY LESS than watermark (boundary inclusive of the watermark is
    safe to keep); watermark is read atomically; GC may run concurrently with compaction (lsm-core serializes via
    its own lock); GC never runs on memtable (memtable versions auto-pruned on flush via compaction filter); GC
    never crosses into uncommitted versions (compaction filter checks TxnCommit presence).
  - **Build steps**: 1. (~15 min) GcWorker spawn + shutdown lifecycle (runtime-thread-per-core: pin to a dedicated
    GC core if v2 substrate supports); 2. (~20 min) `lsm::gc_versions_below(watermark)` — invokes compaction with a
    snapshot-aware filter that drops obsolete versions; 3. (~15 min) Metrics: dropped/reclaimed counters + GC
    duration histogram; 4. (~25 min) Test: 1000 txns, half abort, half commit; close all txns; GC; assert dropped
    versions count matches expectation; 5. (~20 min) Test: hold a snapshot at ts=50; insert versions up to ts=200;
    GC; assert no versions <= 50 dropped (they're protected); drop snapshot; GC; assert pruning down to current
    min_active; 6. (~10 min) Shutdown test — GcWorker::shutdown joins thread cleanly within 2× interval.
  - **Pitfalls** (named):
    - *Watermark race*: **Symptom**: GC samples watermark = 100; just-then a new snapshot begins at ts=90 (HLC
      regression??); GC drops version at ts=92 but new snapshot needs it. **Fix**: HLC is monotone → can't happen.
      But defensively: txn_manager.begin() acquires a ticket BEFORE consulting clock; GC reads
      min_active_snapshot_ts AFTER acquiring an exclusive "gc-in-flight" flag; new snapshots wait briefly if flag
      held. Or simpler: `min_active_snapshot_ts` is `AtomicU64` with proper ordering; new snapshot CAS-updates the
      atomic before observing it; GC uses Acquire load.
    - *Tombstone reincarnation under GC*: **Symptom**: GC drops a tombstone at ts=100 because watermark = 150; an
      older live version at ts=50 (also below watermark) was previously preserved by an existing snapshot now
      gone; GC drops both → for a fresh snapshot starting at ts=160, the key appears to reappear. **Fix**:
      compaction filter must drop tombstone + ALL versions older than it together, atomically; if any version
      between tombstone and live is preserved, tombstone is preserved. Simpler: drop entire version chain prefix
      below watermark atomically.
    - *GC starving foreground*: **Symptom**: GC runs continuously on a hot table, foreground reads/writes get
      bufpool eviction pressure. **Fix**: GcWorker rate-limits via `backpressure::Limiter`; on high foreground
      load, sleep extra. Budget GC to ≤ 10% of CPU.
    - *Orphaned snapshot ref*: **Symptom**: caller leaks a Snapshot (forgets to drop), min_active stuck forever.
      **Fix**: Snapshot has Drop impl that decrements txn_manager active count; if leaked, `max_snapshot_age`
      configurable timeout forcibly evicts (Snapshot::read returns Err after timeout).
  - **Test scenarios**: tombstone-+-live pair across GC; long-held snapshot blocks GC; GC during compaction;
    GC during recovery (must wait for recovery to complete); 1M-version pruning bench.
  - **Acceptance**: GC reclaims ≥ 80% of obsolete versions within 2 cycles; never drops a version visible to an
    active snapshot (proptest 1000 trials); CPU usage of GC thread < 15% under sustained load.
  - **Downstream**: W100 chaos tests run GC concurrent with kill -9; vector-db W101 inherits same pattern (in W103
    "wal for writes" — the vector-db wal+gc parallel).
