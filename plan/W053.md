**Monday — RETURN, REVERT, INVALID (terminal opcodes)**

- [ ] **Build**: `crates/exec-vm/src/instructions/control.rs` — `ret`, `revert`, `invalid` terminal halts + their interaction with the call-frame exit path in `crates/exec-vm/src/frame.rs`. (~total 200 min across 3 phases)
  - 🔧 **Why this matters**: mirrors `revm::interpreter::instructions::control::{ret, revert, invalid}`. These three are the call-frame EXIT paths and they differ in exactly the places a first attempt conflates: RETURN commits the journal + returns data; REVERT commits NOTHING + returns data + REFUNDS remaining gas; INVALID is an abnormal halt that BURNS ALL gas, returns no data, no refund. Four traps: (1) REVERT vs INVALID gas accounting (refund vs burn), (2) REVERT pre-Byzantium must be `InvalidOpcode` (EIP-140 gating), (3) RETURN/REVERT both emit data but INVALID must NOT, (4) `return_data_buffer` lifetime across frames. A first attempt that treats REVERT and INVALID as "both abort" mis-bills gas and forks the chain. The debug session walking those failures IS the lesson. Downstream: W55 journaling reads these `InstructionResult` signals to decide commit-vs-rollback; W91 STF replay across forks.

  - *Mental model*: a terminal opcode does not itself finalize state — it sets an `InstructionResult` that the call-frame unwinder in the caller interprets. RETURN/REVERT differ only in that signal + gas treatment; INVALID additionally zeroes `gas.remaining`. The opcode is a *flag-setter*, not a state-committer.
  - *Contract* (signatures only — never the body):
    ```rust
    fn ret<H>(interp: &mut Interpreter, _host: &mut H);     // -> InstructionResult::Return
    fn revert<H>(interp: &mut Interpreter, _host: &mut H);  // -> InstructionResult::Revert (refund remaining)
    fn invalid<H>(interp: &mut Interpreter, _host: &mut H); // -> InstructionResult::InvalidFEOpcode (burn all gas)
    // shared memory-window read used by ret + revert:
    fn read_output_window(interp: &mut Interpreter, offset: U256, len: U256) -> Bytes;
    ```
  - *Back-of-envelope* (bar (b) — correctness-sizing, not a latency budget): the only "cost" worth budgeting is the `to_vec()` copy of the output window — RETURN/REVERT copy `len` bytes from shared memory into `return_data_buffer`. A 1 MB return copies 1 MB once (~bounded by `MemoryLimit`); this is consensus-irrelevant but informs W55 (the journal must NOT clone the buffer again). INVALID copies nothing. No latency budget; the bar here is byte-exact + gas-exact, enforced by the differential test against revm.
  - *Anti-shortcut audit* — name the tempting-but-wrong move (each is exactly what a Phase-2 test below must fail on):
    - **Treat REVERT and INVALID with one shared `abort()` that zeroes gas.** Wrong: REVERT must REFUND `gas.remaining` to the caller; INVALID burns it. → trapped by `revert_refunds_remaining_gas` + `invalid_burns_all_gas`.
    - **Always dispatch `0xFD` to `revert()`.** Wrong: pre-Byzantium `0xFD` is an unknown/invalid opcode (EIP-140 introduced REVERT). → trapped by `revert_pre_byzantium_is_invalid_opcode`.
    - **Emit `return_data_buffer` on INVALID "for symmetry".** Wrong: INVALID is an abnormal halt with no data. → trapped by `invalid_emits_no_return_data`.
    - **Commit/roll the journal inside the opcode handler.** Wrong: the handler only sets the signal; the caller unwinds. → trapped by `terminal_handlers_do_not_touch_journal`.

  - **Requirements** — write in `crates/exec-vm/notes/53_terminal_design.md`:
    - R1. `ret`: pop `(offset, len)`; resize memory if `len > 0`; copy `memory[offset..offset+len]` into `return_data_buffer`; set `instruction_result = Return`; gas unchanged except memory-expansion gas.
    - R2. `revert`: identical output-window handling to `ret`, but set `instruction_result = Revert`. The remaining gas is NOT zeroed — the caller refunds it.
    - R3. `invalid`: set `gas.remaining = 0`; set `instruction_result = InvalidFEOpcode`; do NOT touch `return_data_buffer`.
    - R4. EIP-140 gating: `0xFD` dispatches to `revert` ONLY when `spec >= BYZANTIUM`; otherwise it is an unknown opcode → `InstructionResult::OpcodeNotFound` (consuming all gas, like any invalid opcode).
    - R5. None of the three handlers mutates journal/state directly — they only set `instruction_result`. The caller-frame unwinder commits (Return) or rolls back (Revert/InvalidFEOpcode).
    - R6. Differential round-trip against revm for all three across Frontier, Byzantium, London, Cancun specs.

  #### Phase 3 — Make the tests pass, one failure at a time (~90 min)

  - **(NEWBIE) When `invalid_burns_all_gas` reports `gas.remaining == 100_000` instead of `0`:**
    - Symptom: INVALID returns `InvalidFEOpcode` but leaves the gas untouched.
    - Why: you set only the `instruction_result` and forgot the explicit `gas.remaining = 0`.
    - Fix: `interp.gas.remaining = 0;` before setting the result — INVALID is an abnormal halt that consumes everything.
    - Muscle: an abnormal-halt opcode must explicitly zero remaining gas; the result variant alone does not bill it. Reapplies at: W54 precompile out-of-gas, W55 journaling halt accounting, W91 STF gas-used reconciliation.

  - **(SENIOR) When `revert_refunds_remaining_gas` reports `gas.remaining == 0` instead of `100_000`:**
    - Symptom: REVERT zeroes the gas like INVALID; the tx over-charges 100k gas and the block's `gasUsed` diverges from mainnet.
    - Why: you funneled REVERT and INVALID through one shared `abort()` that zeroes gas — the classic "they both abort" conflation.
    - Fix: two distinct paths — `revert()` sets `Revert` and leaves `gas.remaining` intact (caller refunds); only `invalid()` zeroes it.
    - Cost avoided: a 100k-gas-per-revert consensus split — every reverting tx on chain would diverge; this is a hard fork, the bar (b) "differential green" gate exists precisely to catch it.
    - Muscle: REVERT refunds, INVALID burns — never share a halt path between a refunding and a burning terminal. Reapplies at: W54 precompile failure (refund vs burn), W55 journaling commit-vs-rollback signal, W62 nested-call revert propagation.

  - **(EXPERT) When `revert_pre_byzantium_is_invalid_opcode` runs `revert()` under Frontier:**
    - Symptom: `0xFD` produces `Revert` on a Frontier block during historical replay; the block's result diverges from the canonical chain.
    - Why: your dispatch table is spec-blind — it maps `0xFD → revert` unconditionally.
    - Fix: spec-gate the opcode table; for `spec < BYZANTIUM` slot `0xFD` resolves to the unknown-opcode handler (`OpcodeNotFound`, all gas consumed).
    - Muscle: an opcode introduced by an EIP is absent (= invalid) before its fork; the dispatch table is fork-dependent, not static. Reapplies at: W54 precompile activation forks, W61 EOF opcode gating, W91 historical-block replay.

  - **5-year failure mode** (write in `crates/exec-vm/notes/53_terminal_followup.md` after green): a future EIP could add a *fourth* terminal that refunds gas but also clears return data (a "silent revert"). Trigger: a new `InstructionResult` variant appears in an upstream revm bump. Migration: keep the gas treatment and the data treatment as two ORTHOGONAL fields on the result, not a single enum-variant assumption, so a new combination is one row in D1's table, not a rewrite.

- [ ] **Build**: `crates/exec-vm/src/instructions/host.rs::selfdestruct` + the journal entries in `crates/exec-vm/src/journal.rs` (`AccountDestroyed`, `created_in_same_tx` tracking). (~total 240 min across 3 phases)
  - 🔧 **Why this matters**: mirrors `revm::interpreter::instructions::host::selfdestruct` + `revm::context::journaled_state::selfdestruct`. SELFDESTRUCT has survived THREE consensus pivots — EIP-150 (Tangerine, gas rise), EIP-3529 (London, refund removed), EIP-6780 (Cancun, restricted to same-tx-create) — so replaying old blocks needs a fork-aware impl, and it is the #1 historical source of "I thought this contract was gone but it isn't." A first attempt that ignores any fork boundary forks the chain on replay. Downstream: W55 journaling needs the `AccountDestroyed` variant; W62 storage-trie account-deletion path consumes the end-of-tx sweep.

    ```rust

    struct SelfDestructResult { had_value: bool, target_exists: bool, is_cold: bool, previously_destroyed: bool }

    }
    // Journal:
    enum JournalEntry {
        AccountDestroyed { address: Address, target: Address, was_destroyed: bool, had_balance: U256 },
        AccountCreated   { address: Address }, // its rollback clears created_in_same_tx
        // ...
    }
    ```

Cost is consensus-irrelevant; the bar is fork-exact gas + correct rollback, enforced by the cross-fork differential. The only quantity to budget is *journal entry count* — exactly one per SELFDESTRUCT, so REVERT is a bounded pop-and-undo, never a state rescan.
