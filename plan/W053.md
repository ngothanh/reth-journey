**Monday — RETURN, REVERT, INVALID**

- [ ] Terminal opcodes. (~30 min)
  - **Why**: RETURN/REVERT/INVALID are the call-frame exit paths. Each has subtle semantic differences: RETURN commits journal + returns data; REVERT commits NOTHING + returns data + refunds remaining gas; INVALID is "abnormal halt" — burns ALL gas, returns no data, similar effect to REVERT but no refund.
  - **Read first**: `revm/crates/interpreter/src/instructions/control.rs::ret, revert, invalid`; Yellow Paper §H.2 (terminal halts).
  - **Design**:
    ```rust
    fn ret<H>(interp: &mut Interpreter, _: &mut H) {
        pop!(interp, offset, len);
        let offset = as_usize_or_fail!(interp, offset);
        let len = as_usize_or_fail!(interp, len);
        if len > 0 { resize_memory!(interp, offset + len); }
        interp.return_data_buffer = interp.shared_memory.slice(offset, len).to_vec().into();
        interp.instruction_result = InstructionResult::Return;
    }

    fn revert<H>(interp: &mut Interpreter, _: &mut H) {
        // identical setup to ret(), but:
        interp.instruction_result = InstructionResult::Revert;
        // caller will see Revert and propagate journal rollback
    }

    fn invalid<H>(interp: &mut Interpreter, _: &mut H) {
        // burn all remaining gas, set InvalidFEOpcode result, NO return data.
        interp.gas.remaining = 0;
        interp.instruction_result = InstructionResult::InvalidFEOpcode;
    }
    ```
    **Invariants**:
    - RETURN: gas unchanged (just memory-expansion gas), data emitted, journal committed by caller.
    - REVERT: gas refunded (remaining gas returns to caller), data emitted, journal REVERTED by caller.
    - INVALID: ALL gas burned, no data, journal reverted.
    - REVERT was added in EIP-140 (Byzantium) — pre-Byzantium REVERT must be InvalidOpcode.
  - **Build steps**: implement all three; ensure spec-gating; differential-test against revm.
  - **Pitfalls**:
    - *RETURN data persists across frames*: caller's RETURNDATACOPY reads `return_data_buffer`; if cleared too early, returns zeros. **Fix**: clear on next call, not on this frame exit.
    - *REVERT pre-Byzantium*: opcode 0xFD is InvalidOpcode pre-Byzantium. **Fix**: spec-gate.
    - *INVALID and remaining gas*: implementations sometimes forget to zero `remaining`. **Symptom**: refund leak. **Fix**: explicit `gas.remaining = 0`.
  - **Test scenarios**: RETURN with len=0 (zero memory growth, empty return). REVERT with reason-string. INVALID burns 100k gas (none refunded).
  - **Acceptance**: differential green; spec-gating correct.
  - **Downstream**: W55 (journaling consumes Revert/Return signals); W61 (EOF reuses RETF/JUMPF).

**Tuesday — SELFDESTRUCT**

- [ ] Implement. (~120 min)
  - **Why**: SELFDESTRUCT has gone through THREE consensus changes: EIP-150 (Tangerine — gas cost rise), EIP-3529 (London — refund removed), EIP-6780 (Cancun — restricted to same-tx-create). Each pivot left mainnet history with different semantics; replaying old blocks requires fork-aware impl. SELFDESTRUCT is the #1 historical source of "I thought this contract was gone but it isn't" attacks.
  - **Read first**: EIP-6780 spec; `revm/crates/interpreter/src/instructions/host.rs::selfdestruct`; `revm/crates/context/src/journaled_state.rs::selfdestruct`.
  - **Design**:
    ```rust
    fn selfdestruct<H: Host>(interp: &mut Interpreter, host: &mut H) {
        require_non_staticcall!(interp);
        pop_address!(interp, target);
        let Some(StateLoad { data, is_cold }) =
            host.selfdestruct(interp.contract.target_address, target)
        else { return interp.fatal_error(); };

        // Gas computation:
        let mut gas_cost = 5000; // EIP-150 baseline
        if is_cold { gas_cost += 2600; }  // EIP-2929
        if data.had_value && !data.target_exists && !spec.is_enabled_in(LONDON) {
            // pre-London: account-creation surcharge (no longer applies post-London)
            gas_cost += 25000;
        }
        gas!(interp, gas_cost);

        // EIP-3529 (London): refund REMOVED (was 24000 pre-London).
        // EIP-6780 (Cancun): SELFDESTRUCT only deletes if account was created in SAME tx.
        if spec.is_enabled_in(CANCUN) && !data.created_in_same_tx {
            // Behavior: transfer balance only; do NOT delete account.
        }
        interp.instruction_result = InstructionResult::SelfDestruct;
    }
    ```
    **Invariants**:
    - SELFDESTRUCT in STATICCALL context returns WriteProtection (revert, no gas refund).
    - Target address always becomes warm (EIP-2929).
    - Pre-Cancun: account marked for destruction at TX END (not immediately); allows re-creation via CREATE2 if collision.
    - Cancun: deletion only if created_in_same_tx; otherwise just balance-transfer.
  - **Build steps** (granular):
    1. (~15 min) Implement opcode 0xFF with `require_non_staticcall` guard.
    2. (~15 min) Pop target address, mark target warm via Host.
    3. (~20 min) Compute fork-aware gas: pre-Tangerine = 0; Tangerine = 5000; Spurious onwards = 5000 + (25000 if creates new account); Berlin = 5000 + 2600 (cold) + (25000 if creates new); London onwards same (refund removed).
    4. (~20 min) Wire SELFDESTRUCT to Host. Host pushes `JournalEntry::AccountDestroyed { was_destroyed, had_balance }` so REVERT undoes.
    5. (~25 min) Implement Cancun semantics: track `created_in_same_tx` flag on account (set on CREATE/CREATE2 inside this tx). SELFDESTRUCT checks before scheduling deletion.
    6. (~20 min) End-of-tx sweep: drain `accounts_pending_destruction` (pre-Cancun) or `accounts_pending_destruction_if_created_this_tx` (Cancun).
    7. (~15 min) Differential test: SELFDESTRUCT then CREATE2 at same address (pre-Cancun: deletion + recreation OK; Cancun: deletion only if created_in_same_tx).
  - **Pitfalls** (named, consensus-critical):
    - *EIP-6780 created_in_same_tx flag drops on revert*: if sub-call creates A then SELFDESTRUCTs A, then outer REVERTs, flag must roll back (so future re-creation of A in next tx isn't "same-tx"). **Symptom**: ghost destruction. **Fix**: `JournalEntry::AccountCreated` rollback clears the flag.
    - *Balance double-credit*: SELFDESTRUCT to self (target == address) transfers balance to self. Naive impl loses balance (delete account then transfer to deleted account). **Symptom**: ETH burn. **Fix**: special-case self-target — balance untouched OR explicit add-then-zero.
    - *Static-call enforcement missing*: SELFDESTRUCT inside STATICCALL must revert with WriteProtection. **Symptom**: write side-effects from "read-only" call. **Fix**: `require_non_staticcall` at opcode entry.
    - *Refund-tracker confusion across forks*: pre-London, SELFDESTRUCT added 24000 to refund-counter. London removed. Post-London exec-vm must NOT add to refund. **Symptom**: refunds 24k extra → consensus diff. **Fix**: spec.is_enabled_in(LONDON) gate on refund add.
  - **Test scenarios**:
    - Pre-London: SELFDESTRUCT, verify 24000 refund.
    - London: same → 0 refund.
    - Cancun: created_in_same_tx = false → balance transferred, account survives.
    - Cancun: created_in_same_tx = true → balance transferred, account deleted.
    - REVERT after SELFDESTRUCT: account restored.
    - Static-call: SELFDESTRUCT inside STATICCALL → WriteProtection.
  - **Acceptance**: differential green across Tangerine, Spurious, Berlin, London, Cancun specs.
  - **Downstream**: W55 (journaling has all required entry variants); W62 (storage-trie account-deletion path).

**Saturday — Reth evm PR**

- [ ] Find reth evm crate issue. Implement. (~120 min)
  - **Why (call-family deep dive — pair with reth PR)**: CALL/DELEGATECALL/STATICCALL/CALLCODE comprise the EVM's interprocedural call mechanism. Their gas-forwarding rules (EIP-150 63/64), value-transfer semantics, return-data buffer lifecycle, and authority context (`caller`/`address`) differences are the highest-density opcode area in the EVM and the most-asked area in EVM-internals interviews. While doing the reth PR, internalize this family — likely your PR touches one of them.
  - **Read first**:
    - `revm/crates/interpreter/src/instructions/contract.rs::{call, callcode, delegatecall, staticcall}`
    - `revm/crates/interpreter/src/gas/calc.rs::call_cost`
    - EIP-150 (63/64 rule), EIP-214 (STATICCALL), EIP-2929 (cold/warm), EIP-7702 (delegation designators)
  - **Design**:
    ```rust
    pub struct CallInputs {
        pub input: Bytes,
        pub return_memory_offset: Range<usize>,
        pub gas_limit: u64,           // post-63/64 cap
        pub bytecode_address: Address, // for DELEGATECALL: caller's bytecode loc
        pub target_address: Address,   // for DELEGATECALL: SAME as caller
        pub caller: Address,           // for DELEGATECALL: caller's caller!
        pub value: CallValue,          // Transfer(U256) | Apparent(U256) | None
        pub scheme: CallScheme,        // Call | CallCode | DelegateCall | StaticCall
        pub is_static: bool,
        pub is_eof: bool,
    }

    // Gas forwarding (EIP-150):
    fn call_gas_forwarded(remaining: u64, requested: u64) -> u64 {
        let max = remaining - remaining / 64;  // keep at least 1/64
        requested.min(max)
    }
    ```
    **Invariants**:
    - DELEGATECALL: `target_address = caller.contract.target_address` (executes in CALLER's storage), `caller = caller.contract.caller`, `value = Apparent(caller's value)`. Storage, balance, msg.sender all delegate.
    - CALLCODE: like DELEGATECALL but `caller = caller.contract.target_address` (storage shared with caller, but msg.sender is caller). Deprecated, retained for old contracts.
    - STATICCALL: `is_static = true`. Sub-frame forbidden from any state mutation (no SSTORE, no LOG, no CREATE, no SELFDESTRUCT, no CALL with value).
    - 63/64 rule: forwarded gas is capped at `floor(63/64 × remaining)`. Even if caller requests more, max is enforced. Pre-Tangerine: ALL remaining gas forwarded (no cap).
    - Value-transfer surcharge: +9000 gas if value > 0; if target is new account: +25000 (pre-EIP-161 cleanups).
  - **Build steps** (granular):
    1. (~20 min) Implement CALL opcode: 7 stack args (gas, to, value, in_off, in_len, out_off, out_len). Resize memory for in/out ranges. Compute gas: base + warm/cold + value-surcharge + new-account-surcharge. Apply 63/64 cap.
    2. (~20 min) Implement DELEGATECALL: 6 stack args (no value). Sub-frame's caller = parent's caller. STORAGE is parent's. Apparent value = parent's value.
    3. (~15 min) Implement STATICCALL: 6 stack args (no value). Sub-frame's `is_static = true`. All state-mutating opcodes return WriteProtection inside.
    4. (~15 min) Implement CALLCODE: 7 stack args. Like DELEGATECALL but caller = parent's address. Mostly legacy support.
    5. (~15 min) `require_non_staticcall!` macro guards: SSTORE, LOG0..4, CREATE/CREATE2, SELFDESTRUCT, CALL-with-value, TSTORE.
    6. (~20 min) Differential against revm: 100 random call patterns; assert gas exact + return data exact + state-diff exact.
    7. (~15 min) Test 63/64 rule explicitly: caller has 100 gas, requests 99 — receives 98 (63/64 of 99 capped further).
  - **Pitfalls** (named, consensus-critical):
    - *Off-by-one on 63/64*: revm computes `gas / 64` then subtracts → integer floor. Easy to get wrong with sub-then-divide vs divide-then-mul. **Symptom**: ±1 gas diff → consensus fork. **Fix**: `remaining - remaining / 64` exactly.
    - *DELEGATECALL storage isolation broken*: if sub-frame writes to its own storage (instead of caller's), libraries break. Most common bug. **Symptom**: token contracts behave wrong. **Fix**: `target_address` in sub-frame's contract MUST be parent's target_address.
    - *STATICCALL with non-zero value*: spec says revert immediately at opcode level. Some impls forget. **Symptom**: state-mutation possible through static-call-with-value. **Fix**: `if scheme == StaticCall && value > 0 { return Halt::WriteProtection; }`.
    - *Return-data buffer pollution*: sub-call REVERTs; RETURNDATACOPY in parent must read REVERT's data, not the previous CALL's. **Symptom**: stale data. **Fix**: caller updates `return_data_buffer` regardless of sub-call result (success or revert).
    - *Pre-Tangerine 1/64 rule*: pre-EIP-150, ALL gas was forwarded. Replaying Frontier blocks requires no-cap path. **Symptom**: replay fork. **Fix**: spec-gated cap.
  - **Test scenarios**:
    - DELEGATECALL: callee SSTOREs slot 1 → caller's slot 1 changed.
    - STATICCALL with value=0: callee tries SSTORE → WriteProtection.
    - CALL with value > balance: revert before any state change, no gas burn beyond base.
    - 63/64: caller remaining=64, request=64 → forwarded=63.
    - Return-data: caller does CALL, sub-frame RETURNs 8 bytes "abc"; RETURNDATACOPY in caller reads "abc". Then caller does CALL with sub-frame REVERTing "def"; RETURNDATACOPY reads "def".
  - **Acceptance**: differential green for all 4 call types across all forks; static-context enforcement complete (no state mutation possible from STATICCALL subtree).
  - **Downstream**: W55 (journal handles per-call-frame); W62 (storage-trie sees DELEGATECALL as same-account writes); W66 (perpetuals contracts use STATICCALL for read-only price oracles).
