  #### Phase 3 — Make the tests pass, one failure at a time (~90 min)

  - **When `transport_trait_uses_recv_batch_not_recv` fails with single-frame API:**
    - Symptom: trait has `recv(&mut self) -> Frame` (single); profile shows `__GI___libc_recv` consuming 95% CPU; throughput plateaus at ~3M pps.
    - Why: 100M pps × ~300 ns syscall = 30 sec/sec syscall — physically impossible.
    - Fix: trait around `recv_batch<'a>(&'a mut self, out: &mut ArrayVec<Frame<'a>, N>) -> usize` with N≥256. All three transports (epoll via recvmmsg, io_uring via multi-shot, AF_XDP via RX-ring drain) naturally batch. Single-frame recv is NOT part of public API.
    - Cost avoided: ~300 ns syscall × 256 amortized to ~0.3 µs/packet; 100× syscall amortization at trait level.
    - Muscle: in any kernel-bypass / batched-I/O API, batch belongs in the TRAIT, not in an "optimization pass later". Adding batching after the fact requires changing every callsite. Reapplies at: W86 io_uring multi-shot recv, W89 AF_XDP RX-ring drain, W90 io_uring journal group-commit, W77 messaging-aeron term-buffer scan.

  - **When `transport_frame_lifetime_bound_to_self` fails with `Vec<u8>`:**
    - Symptom: `type Frame = Vec<u8>`; profile shows `jemalloc::malloc` dominating at 50M pps.
    - Why: heap allocation per received packet; at 50M pps = 50M × ~50 ns = 2.5 sec/sec malloc + allocator lock contention.
    - Fix: `type Frame<'a>: AsRef<[u8]> where Self: 'a` GAT. Frame borrows from transport's pre-registered buffer (UMEM for AF_XDP, registered buffer ring for io_uring, recv_buf field for epoll); zero allocation per packet. Caller must consume Frames before next recv_batch — encoded in lifetime.
    - Cost avoided: ~50 ns malloc + 1 cache line allocator metadata per packet. At 50M pps = 2.5 sec/sec reclaimed.
    - Muscle: in any zero-copy data-plane API, buffer owned by PRODUCER (transport), borrowed by CONSUMER. Vec<u8> in hot-path API surface is ALWAYS a bar-(c) violation. Reapplies at: W86 io_uring ProvidedBuf<'a>, W89 UmemFrame<'a>, W87 FeedParser::Event<'a> GAT, W77 messaging-aeron Fragment<'a>, W92 ledger Archive event borrows.

  - **5-year failure mode** (write in `notes/85_scaffold_followup.md`): when DPDK becomes dominant kernel-bypass mechanism, the AF_XDP impl gets a sibling. Migration: `DpdkTransport` as 4th impl behind same trait.

  #### Phase 3 — Make the tests pass, one failure at a time (~110 min)

  - **When `epoll_edge_triggered_drain_loop` reports ~10k epoll_wait/sec at 10M pps:**
    - Symptom: throughput collapses to ~500k pps; flamegraph shows epoll_wait at 80% CPU.
    - Why: forgot EPOLLET (edge-triggered); every readable byte triggers another epoll_wait round-trip (~1 µs); 10M × 1 µs = 10 sec/sec.
    - Fix: `epoll_ctl(EPOLL_CTL_ADD, fd, EPOLLIN | EPOLLET)`; on each notification, drain socket fully via `while recvmmsg(...) == BATCH` until EAGAIN. One epoll_wait amortizes over thousands of packets.
    - Cost avoided: 40 ms/sec vs 10 sec/sec = 250× win.
    - Muscle: edge-triggered + drain-fully is the ONLY correct pattern at ingress scale. Reapplies at: W86 io_uring multi-shot recv (drain-on-CQE_F_MORE), W89 AF_XDP RX-ring drain, W77 messaging-aeron poll-fragment-handler loop.

  - **When `epoll_recv_buf_pre_allocated_field` reports per-call allocation:**
    - Symptom: heaptrack flags 64 KB allocations per recv_batch; `memset` in top 3 perf samples.
    - Why: `let mut buf = vec![0u8; MAX_FRAME * BATCH]` per recv_batch = 50 ns malloc + 64 KB zero-fill (~10 µs) per call; at 100k batches/sec ≈ ~1 sec/sec just zeroing.
    - Fix: `recv_buf: AlignedBox<[u8; MAX_FRAME * BATCH]>` as struct field, allocated once in `new()`. Each recv_batch reuses; old contents overwritten by kernel via recvmmsg's msgvec[i].msg_iov pointing into same buffer. Document Frame<'a> lifetime: valid only until next recv_batch.
    - Cost avoided: 64 KB zero-fill + 50 ns malloc per batch; at 100k batches/sec ≈ ~1 sec/sec reclaimed; cache-warmth win.
    - Muscle: any pre-sizable buffer on hot path lives as struct field, allocated at new(). `&mut self` receiver lets kernel overwrite in place. Reapplies at: W86 io_uring registered buffer ring, W89 AF_XDP UMEM, W77 messaging-aeron scratch_buf, W89 ledger static-mem pools, W92 versioned-memory slot reuse.
