  - *Mental model*: a `Transport` is a **batched, zero-copy packet source**. It owns its receive buffers and
    hands the consumer a *borrowed* view of each frame valid only until the next batch. It is the producer; the
    feed handler is the consumer. This is the same producer-owns/consumer-borrows shape as a ring buffer.
  - *Contract* (signature-level only — NEVER the body):
    ```rust
    pub trait Transport {
        type Frame<'a>: AsRef<[u8]> where Self: 'a;          // GAT: borrows from self
        /// Drain up to `out.capacity()` frames; returns count. Frames valid until next call.
        fn recv_batch<'a>(&'a mut self, out: &mut ArrayVec<Self::Frame<'a>, 256>) -> usize;
        fn drops(&self) -> u64;                              // kernel-side drop counter
    }
    ```
  - *Back-of-envelope* (bar (c), Jeff-Dean numbers): target 100M pps peak (multicast burst), 50M pps sustained.
    - Single-frame `recv`: 1 syscall/packet × ~300 ns = **30 sec of syscall per wall-second at 100M pps —
      physically impossible**. Batch of 256 amortizes the syscall to ~1.2 ns/packet → 256× win. Cliff:
      3M pps (syscall-bound) vs 100M+ pps (batched) ≈ **30× ceiling lift just from the trait shape**.
    - `Vec<u8>` frame: ~50 ns malloc + 1 cache-line allocator metadata per packet. At 50M pps =
      **2.5 sec malloc per wall-second** + allocator-lock contention. GAT borrow = 0 ns, 0 allocs.
  - **Requirements** R1..R7 — write in `crates/marketdata-kernelbypass/notes/85_scaffold_design.md`:
    - R1. All three transports satisfy the SAME `Transport` trait → apples-to-apples benchmarks.
    - R2. Feature flags (`epoll` default, `io-uring`, `af-xdp`) gate kernel-version-dependent code.
    - R3. No transport allocs on the hot path; UMEM/io_uring buffers pre-registered at startup.
    - R4. `Frame` borrows from the transport (GAT) — zero-copy; valid only until next `recv_batch`.
    - R5. `recv_batch` (NOT `recv`) — batched is the only viable API at 100M pps.
    - R6. macOS dev loop + Linux production both compile.
    - R7. v0.5 SHIP target W90 Tue: P99 ≤ 2 µs end-to-end.
  - **Design walk-through** D1..D6 — answer in the design doc; no peeking at OpenOnload/DPDK source until Phase 3:
    - D1. Sketch `Transport` trait + `EpollTransport`/`IoUringTransport`/`AfXdpTransport` stubs.
    - D2. **Primitive property table** — fill it in: for each candidate frame type (`Vec<u8>`, `Box<[u8]>`,
      `&'a [u8]` field-borrow, GAT `Frame<'a>`): allocs/packet? Sync/Send? can caller retain across batches?
      zero-copy? Pick the row that gives 0 allocs AND encodes the retain-ban in the type.
    - D3. **Dx Pre-mortem (recv-per-packet trait shape, load-bearing):** write the EXACT bad trace —
      `recv() -> recvmmsg(1)` → `syscall` → `return 1 frame` → repeat 100M× → CPU pinned in
      `__GI___libc_recvmmsg`. If you can't write this 4-line trace, you can't prove `recv_batch` fixes it.
    - D4. **Dy Pre-mortem (Vec<u8> Frame allocates):** trace — `recv_batch` → `let f = packet.to_vec()` →
      `jemalloc::malloc(1500)` per packet → return owned Vec → caller drops → `free`. 50M malloc+free/sec.
    - D5. **Pre-mortem (feature combinatorial explosion):** `--all-features` pulls AF_XDP syscalls that don't

  #### Phase 2 — Write the failing tests (~30 min)
  Each test is engineered so a naive first trait will FAIL it. Tier-annotated. Real assertions.

  - **(SENIOR) `transport_trait_uses_recv_batch_not_recv`** — *anti-shortcut trap*: the obvious single-frame
    `recv` compiles and is correct, but fails the BAR (syscall-per-packet). Asserts the public trait has NO
    single-frame `recv` and DOES have `recv_batch`. A naive `fn recv(&mut self) -> Frame` fails this.
    ```rust
    #[test]
    fn transport_trait_uses_recv_batch_not_recv() {
        // Reflection-free: assert via a generic fn that only compiles against the batch API.
        fn assert_batch_api<T: Transport>(t: &mut T) {
            let mut out: ArrayVec<T::Frame<'_>, 256> = ArrayVec::new();
            let n = t.recv_batch(&mut out);     // must exist, must take an out-buffer
            assert!(n <= out.capacity());
        }
        // grep guard: no single-frame recv leaked into the public surface.
        let src = include_str!("../src/lib.rs");
        assert!(!src.contains("fn recv(&mut self)"),
            "single-frame recv() leaked into public API — that is 1 syscall/packet, a bar-(c) violation");
        let _ = assert_batch_api::<EpollTransport>;
    }
    ```
  - **(EXPERT) `transport_frame_lifetime_bound_to_self`** — *anti-shortcut trap*: GAT compile-check. A naive
    `type Frame = Vec<u8>` (owned) compiles; a `type Frame<'a> = &'a [u8]` that the caller tries to retain
    across a second `recv_batch` must NOT compile. This is a `trybuild` negative — the EXACT borrow error is
    asserted.
    ```rust
    // tests/ui/frame_retain_across_batch.rs — must FAIL to compile with E0502.
    fn retain(t: &mut EpollTransport) {
        let mut a: ArrayVec<_, 256> = ArrayVec::new();
        t.recv_batch(&mut a);
        let held = a[0].as_ref();          // borrow of t's buffer
        let mut b: ArrayVec<_, 256> = ArrayVec::new();
        t.recv_batch(&mut b);              // second &mut t while `held` is live
        let _ = held[0];                   // EXPECT: E0502 cannot borrow `*t` as mutable...
    }
    ```

  #### Phase 3 — Make the tests pass, one failure at a time (~90 min)
  Ordered newbie→expert.

  - **(NEWBIE) When `stub_impls_satisfy_trait` reports `the trait bound EpollTransport: Transport is not satisfied`:**
    - Symptom: generic bound check fails to compile; the three stubs declare methods but don't `impl Transport`.
    - Why: stub structs exist but the `impl Transport for X` blocks (even empty/`todo!()`) aren't written.
    - Fix: add `impl Transport for EpollTransport { type Frame<'a> = &'a [u8]; fn recv_batch(...) -> usize { 0 } fn drops(&self) -> u64 { 0 } }` for each (returning 0 until W86).
    - Cost avoided: none yet (scaffold) — but locks the trait so W86-W89 don't each re-shape it.
    - Muscle: scaffold the trait + empty impls together so the contract is frozen before any impl optimizes.
      Reapplies at: W86 io_uring impl, W89 AF_XDP impl, W76 messaging-aeron transport scaffold.

  - **(SENIOR) When `transport_trait_uses_recv_batch_not_recv` reports `single-frame recv() leaked`:**
    - Symptom: grep guard fires; the natural design was `fn recv(&mut self) -> Frame`. Once W86 fills it,
      profile shows `__GI___libc_recvmmsg` at 95% CPU and throughput plateaus at ~3M pps.
    - Why: 100M pps × ~300 ns syscall = 30 sec/sec — physically impossible. The shape, not the impl, is wrong.
    - Fix: `recv_batch<'a>(&'a mut self, out: &mut ArrayVec<Frame<'a>, 256>) -> usize`. All three transports
      batch naturally (epoll→`recvmmsg`, io_uring→multi-shot, AF_XDP→RX-ring drain). Single-frame recv is NOT
      public.
    - Cost avoided: ~300 ns syscall × 256 amortized to ~1.2 ns/packet — **256× syscall amortization at the
      trait level** (bar (c) violation if missed: caps the whole crate at ~3M pps).
    - Muscle: in any kernel-bypass/batched-I/O API, batch belongs in the TRAIT, not a "later optimization" —
      adding it after the fact rewrites every callsite. Reapplies at: W86 io_uring multi-shot recv, W89 AF_XDP
      RX-ring drain, W90 io_uring journal group-commit, W77 messaging-aeron term-buffer scan.

  - **(EXPERT) When `transport_frame_lifetime_bound_to_self` reports the trybuild case COMPILES (or `Vec<u8>`):**
    - Symptom: either `type Frame = Vec<u8>` (owned — `jemalloc::malloc` dominates once filled), OR the
      retain-across-batch trybuild case unexpectedly compiles (no lifetime tie → use-after-overwrite).
    - Why: owned `Vec<u8>` allocates per packet; a non-GAT or wrongly-bounded Frame lets the caller hold a
      frame while the next `recv_batch` overwrites the underlying buffer (silent data corruption).
    - Fix: `type Frame<'a>: AsRef<[u8]> where Self: 'a`; the `&'a mut self` on `recv_batch` makes the returned
      frames borrow `self`, so a second `recv_batch` while a frame is live is `E0502`. Encodes "consume before
      next batch" in the type.
    - Cost avoided: ~50 ns malloc + 1 cache-line metadata per packet (2.5 sec/sec at 50M pps) AND a class of
      silent use-after-overwrite corruption — **bar-(c) violation** (Vec<u8> on a hot-path API surface always is).
    - Muscle: in any zero-copy data-plane API, buffer owned by PRODUCER, borrowed by CONSUMER, retain-ban
      encoded in the lifetime. Reapplies at: W86 io_uring `ProvidedBuf<'a>`, W89 `UmemFrame<'a>`, W87
      `FeedParser::Event<'a>` GAT, W77 messaging-aeron `Fragment<'a>`, W92 ledger Archive event borrows.

  - **(SENIOR) When `compile_all_features_linux` reports macOS `--all-features` fails on AF_XDP syscalls:**
    - Symptom: `cargo check --all-features` red on macOS; `error: cannot find function xsk_socket__create`.
    - Why: feature flag `af-xdp` alone isn't enough — the code is still compiled on macOS where the syscall
      doesn't exist.
    - Fix: gate the AF_XDP module body with `#[cfg(all(target_os = "linux", target_arch = "x86_64"))]` in
      ADDITION to the `af-xdp` feature; provide a `#[cfg(not(...))]` stub that `compile_error!`s only if
      `recv_batch` is actually called, not at compile time.
    - Cost avoided: dev-loop friction (macOS iteration dies) — keeps R6 (both platforms compile) true.
    - Muscle: feature flags gate *intent*, `cfg(target_os)` gates *availability* — you need both for
      kernel-version-dependent code. Reapplies at: W86 io_uring (Linux 5.6+), W89 AF_XDP, W92 io_uring fdatasync.
