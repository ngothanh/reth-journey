  #### Phase 3 — Make the checks pass, one failure at a time (~80 min)

  Ordered newbie→expert — the ladder you actually walk.

  - **(NEWBIE) When `check_six_criteria_all_present` reports `defined 5`:**
    - Symptom: the script lists only 5 §6 checks — `core-criticality` and `cycle-timing` were never added to `ecosystem_criteria.toml`.
    - Why: the §6 checklist has 7 items; an incomplete criteria file silently under-checks every venue, so a venue "passes" on the 5 you remembered.

    - Muscle: an audit that doesn't enumerate the full bar under-checks silently. Reapplies at: W131 Bet #1 re-run, W144 M36 audit, any future §6 application.

  - **(SENIOR · ANTI-SHORTCUT) When `check_six_of_seven_is_FAIL_not_pass` reports `verdict=PASS` on the 6/7 venue:**
    - Symptom: a venue failing exactly one §6 check (tier-1 backing) scores "86%" / "strong" and reads as a GO.
    - Why: the verdict was a weighted sum or a ≥6/7 band; §6 is explicit that a single fail converts a bet into a bridge job — a sum hides the disqualifying fail. This is the Airwallex anti-pattern made mechanical.
    - Fix: overall verdict = all-7 AND (`PASS` iff every check is `PASS`, else `FAIL`); emit the named failing check(s) in the row so the WHY is visible. Never a numeric band.
    - Cost avoided: placing Bet #1 against a venue with no tier-1 backer → late-employee equity, the shot burned, §7's "each bet upgrades the next" broken at #1.
    - Muscle: a disqualifying-criterion checklist is an AND, never a sum. Reapplies at: W131 Bet #1 decision (this exact re-run), every future bet/bridge sort.

  - **(SENIOR · ANTI-SHORTCUT) When `check_no_transitive_leakage` reports any count ≠ direct on `perp-dex-core` (40+ full walk, or 7-9 partial de-dupe):**
    - Symptom: the script walks `cargo tree` without `--depth 1`; `perp-dex-core` reports 40+ when its `Cargo.toml` declares 6. A subtler variant reports 7-9 (partial de-dupe / dev-deps folded in) which the old `-lt 10` band wrongly passed.
    - Why: `cargo tree` defaults to the full transitive graph — that measures "what your build resolves to," not "what you chose." Correct as a build inventory, wrong metric for this bar.
    - Fix: `cargo metadata --no-deps`, read each package's `dependencies` filtered to `kind==null`, or `cargo tree --depth 1`. Assert exact equality, never a `< N` ceiling.
    - Cost avoided: a "30+ deps" capstone row in the W121 blog reads as bloat to a tier-1 reviewer; the true 6 reads as discipline.
    - Muscle: a dependency audit measures **direct intent**, not transitive resolution. Reapplies at: W121 blog dep claim, W144 M36 audit, every supply-chain review at a tier-1 venue.

  - **(SENIOR · CROSS-PRIMITIVE) When `check_workspace_inherited_deps_counted_once` reports a dropped dep:**
    - Symptom: a crate using `serde = { workspace = true }` reports one fewer dep than declared; the naive line-count saw `workspace = true` and skipped it.
    - Why: workspace-inherited deps still ARE direct deps — the version just lives in the workspace manifest. The audit composed with workspace-inheritance and the composition leaked.
    - Fix: count any key in `[dependencies]` regardless of value shape; `cargo metadata --no-deps` already resolves the inherited version — use its `dependencies` array.
    - Muscle: a feature that *resolves* a value elsewhere doesn't change *that the dep is yours*. Reapplies at: W144 M36 audit, any `cargo deny`/SBOM tooling over a workspace.

  - **(EXPERT) When `check_unknown_criterion_fails_closed` / `check_uncategorized_dep_fails_closed` report `exit 0` on unknown input:**
    - Symptom: an unrecognized §6 criterion (or a dep added between M29 and M30) produced a row with `unknown`/`other` and `exit 0` — no human noticed.
    - Why: the script defaulted to a pass/`other` instead of failing on unknown input. Fail-open defeats both halves of the audit.
    - Fix: hard-code the §6 criterion list + the dep-category map; on any unknown criterion or dep, `exit 1` with a named error (`error: §6 criterion '$X' undefined` / `error: dep '$NAME' has no rationale`). Fail closed.
    - Cost avoided: a smuggled-in §6 check or dep silently passing the gate — the worst false-confidence at the pivot point.
    - Muscle: an audit that can pass silently on unknown input is not an audit. Reapplies at: W131 Bet #1 re-run, W144 M36 close, every future SBOM/cargo-deny gate.

  - **(SENIOR) When `check_bar_c_crate_threshold_enforced` reports the violation but no follow-up issue:**
    - Symptom: a bar-(c) crate shows 11 deps; no column flags it; the audit "passes" because no script logic enforced the bar.
    - Why: the threshold was a documented target, not a script check — humans were supposed to notice. They don't.
    - Fix: after computing each row, `if is_bar_c_crate(name) && non_mirror_direct_count > 10` require a `followup_issue: <URL>` field, else `exit 1` naming the crate.
    - Muscle: a target that isn't a script check is a wish. Reapplies at: W144 M36 threshold (tightened to 7), future bar-(c) crate additions.

  - **(EXPERT · NEGATIVE-CONTROL) When `check_output_is_diffable` reports byte-different output between two runs:**

    - Why: HashMap iteration order is non-deterministic.
    - Fix: sort venues alphabetically, crates alphabetically, deps within each crate alphabetically (BTreeMap or sort the Vec before emit). Pin date format (ISO 8601, UTC). The grep-for-headers half guards the degenerate "emit nothing, two empty files diff clean" pass.

    - Muscle: artifacts that may be quoted out of context must carry their bar in every row. Reapplies at: W121 blog evidence rows, W122 outbound portfolio extracts, W131 Bet #1 decision row.
