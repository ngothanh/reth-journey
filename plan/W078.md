  - 🔧 **Why this matters**: mark is the single most consequential number in a perp venue — it drives liquidation (W101), margin (W85-90), and funding (Wed). The traps: (1) a **mean** index lets one manipulated/stale source drag mark → manipulated liquidations (trimmed-median is the production answer); (2) **any `f64`** in the EMA breaks cross-replica determinism — the same trap that bites every deterministic state machine, here on the most safety-critical path; (3) a **stale source** silently poisons the index unless freshness is checked (`is_market_open` seam + per-source staleness); (4) integer EMA done naively loses all precision or overflows. First-attempt impls fail ≥1 Phase-2 test; the debug session is the lesson. Downstream: W80 funding-loop reads mark; W82 mark-keyed triggers; W85-90 risk-engine; W101 liquidation.

  - *Mental model*: the index is a manipulation-resistant consensus of external spot prices; the mark layers a smoothed funding-basis on top so it tracks the perp's own fair value, not a single noisy trade. It exists because liquidation must key off a price no single actor can jam.

  - *Contract*:
    ```rust
    pub struct SourceTick { pub px: Price, pub ts: Ts }              // integer newtypes
    pub struct MarkEngine { ema_basis: i64, alpha_shift: u32, max_staleness: Duration }
    impl MarkEngine {
        pub fn index(&self, sources: &[SourceTick], now: Ts) -> Option<Price>; // trimmed-median, freshness-gated, no alloc

    ```

Trimmed-median of 8 = one `select_nth_unstable` over a stack array (no alloc). Integer EMA: `ema += (sample - ema) >> alpha_shift` — exact, deterministic, ~1 ns.

  #### Phase 3 — Make the tests pass, one failure at a time (~95 min)

  - **(SENIOR) When `index_trimmed_median_ignores_one_manipulated_source` reports a dragged index:**
    - Symptom: index sits near 106k instead of 50k with one 500k source present.
    - Why: used the mean (`sum/n`) — one outlier moves it proportionally.
    - Fix: `select_nth_unstable` over a stack array, drop top/bottom k, take the median of the middle; robust to <50% bad sources.
    - Cost avoided: a manipulable index = manipulable liquidations — the single highest-severity failure in a perp venue; not "slow", a correctness/security disqualifier.
    - Muscle: external price aggregation is trimmed-median, never mean — robustness beats arithmetic convenience. Reapplies at: W101 liquidation mark-ratio trigger, W104 perp-dex-core oracle wiring.

  - **(EXPERT) When `mark_ema_cross_replica_determinism` reports a 1-unit divergence:**
    - Symptom: golden vector recorded on x86_64 differs from the M2 run by 1 unit in <0.1% of ticks.
    - Why: `ema = ema * (1.0 - alpha) + sample * alpha` — IEEE-754 intermediate rounding differs across arches/FPUs.
    - Fix: integer EMA `ema += (sample - ema) >> alpha_shift` (or a fixed-point Q-format multiply with a defined rounding rule); add the CI `disallowed-types` lint banning `f32`/`f64` in `mark.rs`.
    - Cost avoided: one replica's mark diverging = a VSR split in the replicated venue (state machines must agree bit-for-bit) — the §4A acceptance #2/#7 disqualifier, on the most safety-critical number.
    - Muscle: the deterministic VSR core forbids floats end-to-end, including the "harmless" smoothing in mark. Reapplies at: W80 funding accrual, W85-90 risk-engine margin, W92 ledger v1.0 audit, W108 cluster-VOPR.

  - **(SENIOR) When `index_excludes_stale_source` includes the stale source:**
    - Symptom: a frozen source pins the index; mark stops tracking.
    - Why: no per-source freshness gate; all sources blindly aggregated.
    - Fix: filter `now - tick.ts <= max_staleness` before the trimmed-median; if fewer than the min-fresh count remain, return `None` (R2).
    - Cost avoided: a dead feed silently freezing mark → missed liquidations → insurance-fund drain (the W101 backstop is the moat — feeding it a stale mark defeats it).
    - Muscle: every external input on a safety-critical path carries a freshness gate; absence of data is a state, not silence. Reapplies at: W85-90 risk-engine input validation, W101 liquidation, W107 projection staleness contracts.

    - R3. Retransmit state IS the term buffer; frames accessible for `3 × TERM_LEN` of data.
    - R4. NAK storm suppression: publisher dedupes by gap range; coalesces within `coalesce_window`; retransmits ONCE.
    - R5. Exponential backoff per gap (1 ms, 2 ms, …, cap 1 s); after N attempts, drop the subscriber.
    - R6. Out-of-window NAK → publisher replies `ResetSession` → subscriber re-establishes.
    - R7. Hot recv path bypasses the `BTreeMap` for in-order frames; only the gap branch enters the map.
    - R8. Under 5% loss, zero app-level loss; retransmit overhead < 10% extra bandwidth.

  - **Design walk-through** D1-D6:

  #### Phase 3 — Make the tests pass, one failure at a time (~80 min)

  - **(SENIOR) When `nak_in_order_frames_bypass_btreemap` reports the BTreeMap dominating the profile:**
    - Symptom: NAK-disabled bench 2M pps; NAK-enabled 600k pps; flame graph dominated by `BTreeMap::range`/`entry`.
    - Why: `on_frame` calls `self.gaps.entry(...)` on EVERY frame — O(log N) (~50 ns) even with no gap.
    - Fix: fast-path first — `if position == self.highest_seen + 1 { self.highest_seen = position; return NakAction::None; }` BEFORE any map op; enter the map only on a gap.
    - Cost avoided: **~50 ns/frame × 1M pps = ~50 ms/sec**; restores L1 (bar (c) violation).
    - Muscle: the hot-path data structure must be ABSENT from the common path. Reapplies at: Tue mark stack-array (no map), W82 Image reorder buffer, W84 deterministic event-history append.

  - **(SENIOR) When `nak_storm_publisher_dedupes` reports 100 retransmits per loss event:**
    - Symptom: publisher CPU saturates; 100 retransmits of the same gap to 100 subs.
    - Why: no dedupe; every NAK triggers an independent retransmit.
    - Fix: publisher dedupes by `(stream_id, term_id, gap_range)`; coalesce within `coalesce_window`; one retransmit serves all.
    - Cost avoided: 100× retransmit work; a melted publisher is a correctness failure under load (bar (c) violation).
    - Muscle: any fan-in on a common request needs dedup at the receiver. Reapplies at: W79 multi-sub NAK suppression, W82 Image fan-in.

  - **(SENIOR) When `nak_exponential_backoff_on_repeated_loss` reports cadence 1, 1, 1 ms:**
    - Symptom: same retransmit rate regardless of attempts; infinite retransmit storm under sustained loss.
    - Why: backoff missing; cadence always `nak_retransmit_delay`.
    - Fix: per-gap attempt counter; `delay = base × 2^attempts` capped at 1 s; drop the subscriber after N attempts.
    - Cost avoided: unbounded retransmit bandwidth + publisher CPU under a black-holed subscriber.
    - Muscle: every retry mechanism needs exponential backoff + a max-attempts cap. Reapplies at: W75 view-change retry, W84 archive replay reconnect.
