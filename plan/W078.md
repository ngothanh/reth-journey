  - *Mental model*: at a price-discovery moment, freeze the book, and over all candidate prices pick the one that trades the most volume; resolve ties with a documented total order. It exists because continuous matching can't bootstrap a fair opening price from thin air — you batch and clear once.

  - *Contract*:
    ```rust
    pub struct AuctionBook { /* sorted bids desc, asks asc, market orders both sides */ }
    pub struct UncrossingResult { pub clearing_px: Price, pub matched_qty: Qty, pub imbalance: i64 }
    impl AuctionBook {
        pub fn uncross(&self, reference_px: Price) -> UncrossingResult; // pure, no floats, no alloc
    }
    ```
    `Price`/`Qty` are integer newtypes (i64/u64). `uncross` is deterministic and allocation-free.

  - *Back-of-envelope*: target 10k-order uncross < 1 ms = ≤ 100 ns/order. Naive O(N²): for each of N candidate prices recompute cumulative buy/sell = N × N = 100M ops × ~5 ns/op = **500 ms** (500× over). Pre-computed cumulative arrays: two O(N) sweeps + N × O(1) evaluations = ~20k ops × ~5 ns = **~100 µs** (10× headroom). The cliff: **500 ms vs 100 µs = 5000×** — entirely from not recomputing the aggregate inside the candidate loop.

  - **Requirements** — write in `crates/matching-engine/notes/78_auction_design.md`:
    - R1. Clearing price in `[best_bid, best_ask]` of the auction book.
    - R2. Matched qty = traded volume; every matched lot fills against the opposite side at `clearing_px`.
    - R3. Tie-breaks deterministic + totally ordered: `(max_volume, min_imbalance, closer_to_reference, lower_price)`.
    - R4. Market orders fill BEFORE priced orders at `clearing_px`.
    - R5. NO floats — all i64/u64 price math; cross-replica determinism preserved.
    - R6. 10k-order uncross < 1 ms (≤ 100 ns/order budget).
    - R7. Allocation-free + float-free apply path.
    - R8. Imbalance sign convention: `imbalance = buy_qty - sell_qty`; positive = buy excess.

  - **Design walk-through** D1–D6 — answer in the design doc; no peeking at NYSE/Nasdaq pseudocode until Phase 3:
    - D1. Enumerate the candidate-pricing strategies in a property table: per-candidate recompute (O(N²), 0 alloc), pre-computed cumulative arrays (O(N), 2×N alloc OR reuse scratch), segment tree (O(N log N), overkill). Pick + justify.
    - D2. **Pre-mortem (O(N²) naive, load-bearing):** write the exact 4-line trace — outer loop over candidate `px`, inner loop summing `cum_buy_at_or_above + cum_sell_at_or_below` per candidate. Show the op-count blow-up for N=10k. If you can't write the bad trace you can't prove the cumulative-array fix removes it.
    - D3. **Pre-mortem (f64 in tie-break):** write the exact line `(px - ref_px).abs() as f64` and the 2-replica trace where M2 rounds one way, x86_64 the other, and clearing_px differs by 1 tick in <0.1% of books. Fix sketch: `px.0.abs_diff(ref_px.0) as u128`.
    - D4. **Pre-mortem (reference-price omission):** two prices tie on volume AND imbalance; with no third rule the picker takes first-seen → non-deterministic across iteration order. Cite NYSE Rule 7.35.
    - D5. **Pre-mortem (opening auction, no prior trade):** `reference_px = 0` → must fall through to the lowest-price rule deterministically, not panic or divide.

  #### Phase 1 — Problem, prediction, design (~45 min, no code yet)

  - *Mental model*: a thin batched-I/O endpoint — gather up to 64 outgoing frames into one `sendmmsg`, scatter up to 64 incoming frames from one `recvmmsg` into pre-owned buffers, and fragment above MTU at the Aeron layer so the IP layer never does. It exists because syscalls and per-packet allocation are the two ceilings on UDP throughput.

  - *Contract*:
    ```rust
    pub struct UdpTransport { fd: RawFd, send_hdrs: [mmsghdr; 64], recv_pool: RecvBufferPool }
    impl UdpTransport {
        pub fn open(local: SocketAddr, peer: SocketAddr) -> io::Result<Self>; // sets DF, SO_RCVBUF, SO_REUSEPORT
        pub fn send_batch(&mut self, frames: &[Frame]) -> io::Result<usize>;  // one sendmmsg
        pub fn recv_batch(&mut self) -> io::Result<RecvBatch<'_>>;            // one recvmmsg, MSG_DONTWAIT
    }
    ```

  - *Back-of-envelope*: target ≥ 1M pps single-thread, P99 < 5 µs. Per-packet `sendto` ≈ 1 µs syscall → ~1M pps ceiling, ~920 µs/sec of pure syscall at 1M pps. `sendmmsg(64)` ≈ 5 µs for 64 = **~80 ns/pkt amortized = ~12.5M pps** theoretical (12× headroom). Per-recv `vec![0u8;1500]` ≈ 200 ns malloc + 50 ns memset = **~250 ns/pkt** = ~250 ms/sec wasted at 1M pps — eliminated by a pre-allocated pool.

  - **Requirements** — write in `notes/78_transport_udp_design.md`:
    - R1. Outgoing frames ≤ MTU; larger fragmented at Aeron level (BEGIN/MIDDLE/END flags).
    - R2. `set_dont_fragment(true)` — IP layer NEVER fragments; `frame > pmtu` returns `EMSGSIZE`.
    - R3. Batched send/recv — every syscall amortized over 64 packets typical.
    - R4. `SO_REUSEPORT` for multi-receiver load-balancing.
    - R5. `SO_RCVBUF = 8 MB` (`net.core.rmem_max` configured); monitor `UdpDrops` counter.
    - R6. Throughput ≥ 1M pps single-thread; P99 < 5 µs.
    - R7. Zero allocations on the hot path (pre-allocated recv buffer pool).
    - R8. Conservative path-MTU: 1300 across WAN to absorb VLAN/VPN overhead.

  - **Design walk-through** D1–D6:
    - D1. Sketch `UdpTransport` + `open`/`send_batch`/`recv_batch`. Property table of send strategies (`send_to`, `sendmmsg`, io_uring): syscalls/64pkt, ns/pkt, alloc.
    - D2. **Pre-mortem (per-packet sendto, load-bearing):** write the 4-line loop `for f in frames { socket.send_to(f, peer)?; }` and the syscall-count trace for 1000 frames = 1000 syscalls = ~1 ms.

    - D4. **Pre-mortem (MTU mismatch across hops):** assumed 1500, intermediate VPN 1400 → DF + oversize = drop; or DF-unset = silent IP fragmentation + reorder. PMTUD or conservative 1300 WAN.
    - D5. **Pre-mortem (recvmmsg blocking):** forgot `MSG_DONTWAIT` → the call blocks until N packets arrive → latency tail in low-traffic mode. Always `MSG_DONTWAIT` + spin/poll.
    - D6. **Anti-shortcut audit:** `tokio::net::UdpSocket` (per-call await + no batched syscall), `BytesMut::with_capacity` per recv (still allocs), `socket2` default (DF off) — one line each on why wrong HERE.

    ```rust
    pub struct MultiWriter { main: Arc<MmapQueue>, lock: Mutex<()> }
    thread_local! { static SHADOW: RefCell<ShadowBuf> = ...; }
    impl MultiWriter { pub fn append(&self, bytes: &[u8]); } // fills shadow, flushes under lock
    ```

  - *Back-of-envelope*: a shared `CAS` on the write position costs ~7 ns uncontended (L2) but under 8-way contention each `CAS` waits on MESI line transfer — effective ~100–200 ns/op, throughput sub-linear/collapsing. Double-buffer: per-thread fill ~0 contention; flush amortized over the shadow's batch. Crossover expected at **N=2**: at 1W the shadow indirection adds ~5%, at 4W+ it wins decisively.

  - **Requirements** — write in `notes/78_multi_writer_design.md`:
    - R1. N appender threads, each with a per-thread shadow buffer (thread-local).
    - R2. Flush serialized by a single lock; flush copies shadow → main and advances the main position once.
    - R3. Total order across writers is the flush order (documented; deterministic per flush).
    - R4. At 1W, ≤ ~5% overhead vs the v0.1 single-writer fast-path.
    - R5. At 4W+, double-buffer throughput > single-writer-CAS throughput.
    - R6. No lost or torn appends under concurrent flush (each flush is atomic w.r.t. readers).

  - **Design walk-through** D1–D6:
    - D1. Property table: shared-CAS-position (no buffer, contends line), `Mutex<MmapQueue>` (lock per append, serializes fill too), double-buffer (per-thread fill + brief flush lock). Pick + justify.
    - D2. **Pre-mortem (shared CAS, load-bearing):** write the 4-line interleaving of 8 threads each `position.fetch_add(len)` and annotate the MESI Invalid→Modified ping-pong on the position line.
    - D3. **Pre-mortem (flush holds lock during the whole fill):** if the lock covers fill+flush, you've serialized everything — no better than `Mutex<MmapQueue>`. Lock must cover ONLY the flush.
    - D4. **Pre-mortem (torn read during flush):** reader sees a half-flushed shadow. Flush must publish the new main position only AFTER the copy completes (release store).
    - D5. **Pre-mortem (shadow too large):** a huge shadow batches well but adds latency (append not visible until flush). Bound shadow size / flush on a time or size trigger.
    - D6. **Anti-shortcut audit:** `Mutex<MmapQueue>` (serializes fill), `crossbeam SegQueue` then drain (extra copy + alloc), sharded queues (changes the total-order contract) — one line each.

  - **Output**: `notes/78_multi_writer_design.md` with R1–R6, D1–D6, the shared-CAS MESI trace.

  #### Phase 3 — Make the tests pass, one failure at a time (~50 min)

  - **(SENIOR) When `multi_writer_4w_beats_shared_cas` reports double-buffer SLOWER:**
    - Symptom: at 4W the double-buffer loses; profile shows the flush lock held during the shadow FILL, not just the flush.
    - Why: the critical section covers fill+flush, serializing the contention-free part.
    - Fix: fill the shadow OUTSIDE the lock; acquire the lock only to `memcpy` shadow→main + advance position.
    - Cost avoided: collapses to `Mutex<MmapQueue>` throughput — negates the whole design (bar (c) violation under multi-producer load).
    - Muscle: a lock must cover only the genuinely shared step; everything thread-private stays outside it. Reapplies at: W83 archive multi-stream, W84 full-stack ingest, W89 io_uring SQ fill.

  - **(EXPERT) When `multi_writer_no_torn_appends_under_8w` reports invalid CRC on readback:**
    - Symptom: reader occasionally sees an entry with a garbage length / failed CRC under 8 writers.
    - Why: the main position was published (release) BEFORE the shadow copy finished, so the reader walked into half-written bytes.
    - Fix: copy shadow→main fully, THEN publish the new position with a `Release` store; readers `Acquire` the position — the copy happens-before the publish.
    - Cost avoided: torn reads = silent corruption on the durable queue (bar (c) violation).
    - Muscle: publish the index pointer only after the data it points to is fully written, with Release/Acquire pairing. Reapplies at: W82 Image publication, W83 archive position publish, W89 io_uring CQ.

  Write in `notes/78_multi_writer_followup.md`: if writer count routinely exceeds core count, lock-based flush contention returns. TRIGGER: flush-lock wait time exceeds shadow-fill time in profiling. Migration: shard the main queue per NUMA node, relaxing the single-total-order contract to per-shard order (document the contract change).
