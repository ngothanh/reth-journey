  - *Mental model*: ADL is the deterministic resolution of an *insolvency event the v1.0 fund could not absorb*. It is a pure function on the VSR apply path: `(bankrupt_position, ranked_counterparties, residual_shortfall) → deleverage_decisions`, applied byte-identically on every replica. The v1.0 design left exactly one seam — the tripwire predicate — and ADL is what plugs into it. It is *not* a continuous market mechanism; it is a discrete, rare, deterministic backstop that must replay bit-identically because it permanently alters real counterparties' positions.
  - *Contract* (signature-level interface, NEVER the body):
    ```rust
    pub struct AdlEngine {
        /* fixed-cap ranking ring + the W101 InsuranceFund handle + SequenceClock; no f64, no HashMap */
    }
    #[derive(Clone, Copy, PartialEq, Eq)]                     // R2: fully ordered, deterministic
    pub struct RankKey { pnl_bps: i64, leverage_bps: u64, account_id: AccountId } // integer-only
    impl AdlEngine {
        // Pure, deterministic, runs on the VSR apply path. Engages iff at the tripwire.
        pub fn on_shortfall(&mut self, b: BankruptPosition, fund: &mut InsuranceFund)

        fn incremental_rerank(&mut self, acct: AccountId, new: RankKey); // delta on position/mark change
        pub fn conservation_hash(&self) -> [u8; 32];          // Σ balances + fund, canonical
    }
    // NOTE (v3): ADL fires ONLY at the v1.0 tripwire (fund cannot cover residual). The fund + waterfall
    //            stay exactly as W101 shipped — this consumes the tripwire, it does not redefine the fund.
    ```
  - *Back-of-envelope* (bar (c) — name the cost): 100k accounts, 10 mark ticks/s, ADL is rare but rank maintenance is continuous.
    - Full-re-rank cliff: sort 100k keys ≈ 100k·log₂(100k) ≈ 1.7M comparisons; at ~5ns/cmp ≈ **8.5ms per re-rank × 10/s = 85ms/s** single-threaded — and that is *per shard before sharding*. With per-mark-tick re-rank this competes with the W98 incremental-margin budget and loses. **Incremental rank update** (one `BTreeMap` remove+insert ≈ 2·log₂(100k) ≈ 34 cmps ≈ 170ns/changed-account) is ~50,000× cheaper per update.
    - ADL-event alloc cliff: a `Vec<DeleverageDecision>` allocated per ADL event = a malloc on the apply path → cross-replica jitter + a determinism risk if capacity differs. Fixed-cap ring (pooled) = 0 allocs.
    - `f64` conservation cliff: `loss * profit_i / total_profit` in `f64` loses pennies to rounding; summed over 10k counterparties the residual is non-zero and *differs across arch* → money created/destroyed + cross-arch divergence. Integer largest-remainder apportionment = exact conservation, identical on x86/ARM.

  - **The problem this primitive solves**: the v1.0 fund + waterfall absorb shortfalls *until the tripwire*. Beyond it, an uncovered shortfall means the venue is insolvent — unless a deterministic mechanism redistributes the loss. ADL does this by closing the bankrupt position against the most-profitable, most-leveraged counterparties at the bankruptcy price; socialized loss is the final pro-rata backstop if ADL alone cannot clear it. The three new failure categories: (a) **trigger-boundary error** (engaging before the tripwire steals from solvent traders; after, the venue is briefly insolvent); (b) **ranking non-determinism** (any `f64` or `HashMap` iteration makes two replicas deleverage *different* counterparties — catastrophic, irreversible divergence); (c) **conservation violation** (`f64` apportionment creates/destroys money and diverges cross-arch). The fix: the tripwire predicate as the *only* trigger, integer-keyed deterministic ranking, and integer largest-remainder apportionment.
