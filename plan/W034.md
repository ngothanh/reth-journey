  - *Mental model*: a block-bloom is an array of 64-byte blocks; one key maps to exactly one block (so `contains` touches exactly one cache line), and within that block k bit-positions are set. Probabilistic set membership with a tiny footprint, used to skip the ~99% of SSTable reads that would otherwise be wasted I/O.

  - *Contract* (signature-level — never the body):
    ```rust
    impl BloomFilter {
        pub fn with_fpr_at_capacity(fpr: f64, n: usize) -> Result<Self, SizingError>;
        pub fn insert(&mut self, key: &[u8]);
        pub fn contains(&self, key: &[u8]) -> bool;  // hot path: zero alloc, ≤1 cache line
        pub fn cardinality(&self) -> usize;           // hardware popcount, not per-bit
        pub fn union_in_place(&mut self, other: &Self);
        pub fn serialize(&self) -> Vec<u8>;           // header MUST carry (m, k, seeds)
        pub fn deserialize(bytes: &[u8]) -> Result<Self, DeError>;
    }
    ```

  - *Back-of-envelope* (bar (c)): at W39's 5 M get/sec SSTable read rate, the bloom probe budget is ≤5% of CPU. A warm-L1 positive `contains` = 1 cache line + k bit-tests ≈ **25 ns** (k × ~1 ns test + one ~7 ns L2 line touch). The cliff: a **flat** layout scatters k=7 probes across 7 random lines on a 1.2 MiB filter (DRAM-resident) → 7 × ~100 ns = **~700 ns cold per contains vs ~25 ns warm-block = ~28× cliff**. `cardinality()` per-bit loop over 9.6 Mbits = ~10 ms (9.6 M iters × ~1 ns); POPCNT over 150 K u64 words at ~1 cycle/word ≈ **150 µs = ~60× cliff**. The block-layout FPR penalty is the trade: ~10–15% worse FPR than flat for the same memory (Putze et al. bound this).

  - **Requirements** R1..R7 — write in `crates/bloom/notes/34_classic_design.md`:
    - R1. `with_fpr_at_capacity(fpr, n)` sizes via closed form: `m = ceil(-n·ln(p)/ln(2)²)`, `k = max(1, round(m/n·ln(2)))`. The `max(1, k)` is load-bearing — `round()` can yield 0 for sparse cases.
    - R2. No false negatives: every inserted key returns `true` on `contains`.
    - R3. Measured FPR ≤ 1.2 × design FPR at design capacity (1 M inserts, 10 M disjoint lookups).
    - R4. Determinism: identical key + seeds → identical k bit positions across runs (no per-call randomness).
    - R5. **Block-bloom layout**: all k probes for one key land in the same 64-byte block (one cache line per `contains`, regardless of k).
    - R6. **Hardware popcount** for cardinality / union / intersection — `u64::count_ones()` per word, not a per-bit loop.
    - R7. Seeds serialize with the filter — a deserialized filter MUST probe identical positions to the original.

  - [ ] **(NEWBIE)** `classic_no_false_negatives` — insert N, query all N; all `true`. Exercises R2.

    ```rust
    #[test]
    fn classic_no_false_negatives() {
        let mut bf = BloomFilter::with_fpr_at_capacity(0.01, 100_000).unwrap();
        let keys: Vec<[u8;8]> = (0u64..100_000).map(u64::to_le_bytes).collect();
        for k in &keys { bf.insert(k); }
        for k in &keys { assert!(bf.contains(k), "false negative for {k:?}"); }
    }
    ```
  - [ ] **(SENIOR)** `classic_k_zero_clamp` — construct with `(fpr, n)` whose `round(m/n·ln2)` genuinely = 0; assert `bf.k >= 1` AND a fresh (empty) filter reports a finite measured FPR (not 100%). Exercises R1.
    ```rust
    #[test]
    fn classic_k_zero_clamp() {
        // p=0.9, n=10_000: m = ceil(n·ln(1/0.9)/ln(2)²) ≈ n·0.1054/0.4805 ≈ 2_193 bits;
        // k = round(m/n·ln2) = round((2193/10_000)·0.6931) = round(0.152) = 0.
        // A naive un-clamped round() ships k=0 → no bits set per insert → contains is the
        // empty AND = always true → FPR collapses to 100%. max(1, k) is what saves it.
        let bf = BloomFilter::with_fpr_at_capacity(0.9, 10_000).unwrap();
        assert!(bf.k >= 1, "k clamped to {} — must be >=1", bf.k);
        // Second trap: even a k=1-but-degenerately-sized filter must not be a 100%-FPR sieve.
        // Insert NOTHING, run 10k disjoint lookups against the empty filter: a k=0 (or all-ones)
        // filter answers `true` for every miss → measured FPR == 1.0 and this fires.
        let mut hits = 0usize;
        for i in 0u64..10_000 {
            if bf.contains(&i.to_le_bytes()) { hits += 1; }
        }
        let measured_fpr = hits as f64 / 10_000.0;
        assert!(measured_fpr < 1.0,
            "empty filter answers true for {hits}/10000 misses — FPR {measured_fpr} (k=0 degenerate sieve)");
    }
    ```

  #### Phase 3 — Make the tests pass, one failure at a time (~50 min)

  Ordered newbie → expert — the ladder you actually walk.

  - **(SENIOR) When `classic_k_zero_clamp` reports `bf.k == 0` and `measured_fpr == 1.0`:**
    - Symptom: at `(0.9, 10_000)` the empty filter answers `true` for all 10_000 disjoint misses (`hits == 10000`, `measured_fpr == 1.0`); `bf.k == 0`.
    - Why: `m/n·ln2 = (2193/10_000)·0.6931 = 0.152` and `round(0.152) = 0`; a too-loose FPR for the alloc budget rounds k below 0.5 and you didn't clamp. `k=0` sets no bits per insert; `contains` is the empty `and` = always `true`.
    - Fix: `k = max(1, round(m/n·ln2))`; return `Err(SizingError)` from the constructor when `m/n` is degenerate.
    - Cost avoided: the filter would silently skip its job — every SSTable read proceeds (no I/O saved), but no test catches it without the clamp assertion. Functional-equivalent of disabling the filter.
    - Muscle: closed-form sizing MUST clamp at degenerate boundaries. Reapplies at: W34 counting-bloom sizing, W34 scalable per-slice sizing, W101 vector-db PQ codebook sizing.

  - **(EXPERT) When `classic_serialization_round_trip` reports a false negative after deserialize:**
    - Symptom: serialize → deserialize → query an inserted key returns `false`; `bf.seeds != bf2.seeds`.
    - Why: seeds were regenerated (or defaulted) on deserialize — different seeds → different probe positions → bits checked in the wrong places. Silent data loss.
    - Fix: seeds are part of the serialized header. Persist `(m, k, seed0, seed1)` alongside the bit array; require them on deserialize.
    - Cost avoided: silent corruption — a persisted SSTable filter that returns false negatives causes the read path to skip a key that IS present → data-loss-class bug, not a perf bug. (bar (c) violation: a substrate that loses keys disqualifies the crate.)
    - Muscle: any hash-based primitive's seeds are part of its identity — serialize them with the data. Reapplies at: W34 counting/scalable bloom serialization, W101 vector-db PQ centroids, W95 mini-db SSTable filter header.

  - **(EXPERT, perf, bar (c)) When `bench_block_bloom_one_cacheline_per_contains` reports ~7 L1 misses per `contains` (expected ~1):**
    - Symptom: `perf stat` shows ~7 LLC-loads per negative `contains` on the 1.2 MiB filter; cliff vs target ~7×.
    - Why: flat layout — each of the k probe positions is computed independently across the whole `m`-bit array, so they scatter across k random cache lines.
    - Fix: **block-bloom** (RocksDB `FastLocalBloom`) — `block_idx = reduce(h1, num_blocks)`; all k probes land in the SAME 64-byte block via `bit_i = (h1 + i·h2) % 512`. One cache line per `contains`, regardless of k. FPR penalty ~10–15% (Putze bound).
    - Cost avoided: ~7 → 1 cache miss per contains; at 5 M get/sec, **~3 sec/sec CPU reclaimed cold**; warm positive stays ≤ 25 ns; bloom cost stays inside the 5% budget for W39 SSTable read. (bar (c) violation if shipped flat.)
    - Muscle: a probabilistic filter whose probe count exceeds 1–2 MUST use a block layout that keeps all probes in one cache line; flat bloom is only acceptable for k ≤ 2. Reapplies at: W39 SSTable bloom filter block, W95 mini-db CAPSTONE filter block, W101 vector-db filtered-search bitmap tile.

  - **(EXPERT, perf, bar (c)) When `bench_cardinality_hardware_popcount` reports ~10 ms (expected ~150 µs):**
    - Symptom: `cardinality()` over 9.6 Mbits takes ~10 ms; flamegraph shows ~9.6 M iterations through `bits.iter().filter(...).count()`.
    - Why: scalar bit-by-bit loop, ~1 ns/iter.
    - Fix: cast the backing store to `&[u64]` and call `u64::count_ones()` per word — POPCNT (x86, ~1 cyc/word) / `CNT` (aarch64, ~3 cyc/word) processes 64 bits/op. 150 K words ≈ 150 µs.
    - Cost avoided: ~10 ms → ~150 µs per cardinality; **~60× speedup**; eliminates the LSM compaction CPU spike at filter-merge time (W39 Tuesday union). (bar (c) violation: per-bit loop disqualifies the crate.)
    - Muscle: bitwise ops over arrays MUST go through `u64`-wise intrinsics (`count_ones`, `leading_zeros`, AVX2 `_mm256_and_si256`); the per-bit loop is correctness-only. Reapplies at: W39 SSTable bloom union for L0→L1, W101 vector-db roaring-bitmap intersection, W95 mini-db CAPSTONE filter merge.

  - **(EXPERT, negative-control) When `bench_sanity_band` reports <1 ns/contains:**
    - Symptom: the microbench median lands at ~0.3 ns — faster than a single cache hit, physically impossible for a real probe.
    - Why: the optimizer hoisted `contains` out of the loop / constant-folded a literal key, so the bench measured an empty loop. The other perf benches would then "pass" while measuring nothing.
    - Fix: wrap the filter and a per-iteration-varied key in `std::hint::black_box`; assert an instrumented `probes_observed` counter ≥ iters.
    - Cost avoided: a green-but-meaningless perf suite — the worst failure, because it hides regressions. Negative-control benches are the only thing that catch it.
    - Muscle: every perf bench needs a sanity band + a "did it actually run" counter; a bench that can't fail when the code is broken proves nothing. Reapplies at: W37 skiplist bench harness, W39 SSTable read bench, every bar (c) criterion suite.

  - *Mental model*: replace each bit with a small counter; `insert` increments k counters, `remove` decrements, `contains` checks all k > 0. u4 packing puts two counters per byte to keep the filter L3-resident. The hot-path cost is the nibble extract + saturation, both of which MUST be branchless.

  - *Contract*:
    ```rust
    impl CountingBloom {
        pub fn with_fpr_at_capacity(fpr: f64, n: usize) -> Result<Self, SizingError>;
        pub fn insert(&mut self, key: &[u8]);   // saturating increment at 15
        pub fn remove(&mut self, key: &[u8]);    // saturating decrement at 0; debug-panic if never inserted
        pub fn contains(&self, key: &[u8]) -> bool;  // all k counters > 0
        pub fn cardinality(&self) -> usize;       // count nonzero counters
    }
    ```

  - *Back-of-envelope* (bar (c)): a u4 counting filter for the pruner's 1 M entries at p=0.01 ≈ 4.8 MiB (L3-resident) vs u8 = 9.6 MiB (DRAM-spilling) — the 2× memory win keeps it warm. Hot-path costs: a non-constant `i / 2` is `idiv` ≈ **10 cyc ≈ 3 ns/probe**; an unpredictable parity branch ≈ **5 ns mispredict/probe**; at k=7 × 5 M contains/sec the div alone burns **~100 ms/sec** of a core. A saturation branch `if c < 15` mispredicts ~10–20% under skewed-hot workloads ≈ ~5 ns/insert. Branchless (shift+mask, CMOV/CSEL) drives both to ~1 cyc → counting `contains` ≈ **~50 ns = 2× classic** instead of ~4×.

  - **Requirements** R1..R7 — write in `crates/bloom/notes/34_counting_design.md`:
    - R1. `insert`/`remove`/`contains` semantics per the contract above.
    - R2. Counter saturation at MAX (15 for u4): further inserts at a saturated bucket are silent no-ops; removes of a saturated bucket stay saturated (no underflow drift documented as inherent to u4).
    - R3. **Underflow protection**: removing a never-inserted key is a debug-panic; release-mode it's `saturating_sub(1)` at 0.
    - R4. **u4 nibble extract is branchless** — `>>`, `&` only; no `div`, no `mod`, no parity branch on the hot path.
    - R5. **Saturation is branchless** — CMOV/CSEL via `.min()`/`.max()`/`as` casts; no `if c < 15` conditional.
    - R6. Block-bloom layout inherited from `classic.rs` — one cache line per op.
    - R7. Round-trip: insert N, remove N → cardinality 0 (modulo documented saturation drift).

  - **Design walk-through** D1..D7 (no peeking at Fan et al. impl until Phase 3):
