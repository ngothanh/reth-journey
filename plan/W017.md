- [ ] **Build**: `crates/exec-vm/src/instructions/system.rs` — RETURN, REVERT, INVALID, SELFDESTRUCT (skeleton — full
  impl Phase 4 needs journal). (~45 min)
  - **Why**: System opcodes are the only ones that exit the interpreter loop with a non-`Continue` status. Their unique role is to encode the *terminal action* for a frame (success/revert/exceptional halt/self-destruct). revm models this as `InstructionResult` — a flat enum, not an exception — so the interpreter dispatcher is branch-predictable.
  - **Read first**: revm `crates/interpreter/src/instructions/system.rs` (RETURN/REVERT) and `crates/interpreter/src/instructions/control.rs` (STOP/INVALID/SELFDESTRUCT shell). Also `crates/interpreter/src/interpreter_action.rs` for `InstructionResult`.
  - **Design**:
    ```rust
    pub enum InstructionResult {
        Continue,
        Stop, Return, Revert, SelfDestruct,
        OutOfGas, InvalidOpcode, StackOverflow, StackUnderflow, ...,
    }
    fn ret(interpreter: &mut Interpreter, _host: &mut dyn Host) {
        pop!(interpreter, offset, length);
        let (offset, length) = (offset.as_usize(), length.as_usize());
        resize_memory!(interpreter, offset, length);
        interpreter.return_data_buffer = interpreter.memory.slice(offset, length).into();
        interpreter.instruction_result = InstructionResult::Return;
    }
    ```
    **Invariants**:
    - RETURN/REVERT both copy from memory to `return_data_buffer` — same code path except for the result tag.
    - INVALID consumes ALL remaining gas (per yellow paper). STOP consumes none beyond the 0 stipend.
    - SELFDESTRUCT (post-Cancun, EIP-6780) only burns code if `address == created_in_same_tx`; this is a Phase-4 journal concern, today just stub the recipient transfer.
  - **Build steps**:
    1. (~10 min) `pop!` and `resize_memory!` macros — these are revm's, copy them verbatim with attribution. They expand to early-return on underflow/OOG.
    2. (~10 min) RETURN — 4 lines after macros.
    3. (~10 min) REVERT — identical to RETURN, different tag.
    4. (~5 min) STOP and INVALID — 2 lines each.
    5. (~10 min) SELFDESTRUCT skeleton: pop recipient, mark beneficiary in a TODO-list (Phase 4 journals it).
  - **Pitfalls**:
    - *Forgetting gas charge for memory expansion*: `resize_memory` must charge memory-quadratic-cost or you mis-meter all returns. **Symptom**: replay diverges from mainnet on any tx that returns >32 bytes. **Fix**: macro encapsulates the charge; never call `memory.resize` directly from a handler.
    - *INVALID partial consume*: charging only base gas means later opcodes get free fuel. **Symptom**: hard-fork specific test failures. **Fix**: `interpreter.gas.spend_all()` inside the INVALID handler.
    - *return_data_buffer aliasing*: in a CALL chain, child's return data overwrites parent's view. **Symptom**: RETURNDATACOPY reads stale bytes. **Fix**: own the buffer in `Frame`, not `Interpreter`; clone on call boundary (Phase 4 wires this).
  - **Test scenarios**:
    - PUSH-RETURN trivial: `0x60 0x42 0x60 0x00 0x52 0x60 0x20 0x60 0x00 0xF3` returns 32-byte word equal to 0x42.
    - REVERT with payload: assert `instruction_result == Revert` and bytes match.
    - Gas exhaustion: RETURN at memory offset 2^16 — expect OOG before tag set.

- [ ] **Concurrency drill #26 of 28 — the helping pattern (consumer completes producer's half-step)** (solo, ~5 hrs).
  Drill #25 exposed the half-step. The fix is non-obvious: when consumer sees tail with `next != null`,
  the consumer ALSO does a CAS to move tail forward — taking over a step that "belongs to" the producer.
  This is the *helping pattern*, the lock-free generalization of mutual aid.
  Take drill #25's `MsQueue` and explicitly implement helping in both enqueue (when you see another producer's
  half-step, complete it before retrying) and dequeue (same). Re-verify under loom.
  Constraints: no peek at MS 1996 paper's "fast path / slow path" section or `crossbeam_queue::SegQueue`'s
  helper logic until COMPARE.
  - **Spec**: write out the exact ops a consumer must perform when it sees `tail.next != null`. Predict the
    correctness invariant ("any thread that observes the half-step is responsible for completing it") and
    the liveness invariant ("no thread can be blocked indefinitely waiting for another's step"). Note:
    helping converts non-blocking algorithms from obstruction-free to lock-free.
  - **Build**: extend drill #25 with helping. Re-run drill #25's loom harness; helping should not regress
    correctness AND should reduce loom's exploration time (fewer "blocked on half-step" branches).
  - **Loom**: same harness as drill #25, but now also assert: in any schedule where a consumer arrives
    after a producer's first CAS, the consumer's dequeue eventually succeeds (no waits-for chain). This
    is loom's `loom::sync::Notify`-like progress assertion.
  - **Compare**: open `crossbeam_queue::SegQueue::push` and `pop` source. They have segment-boundary
    helping (push helping advance segment, pop helping deallocate emptied segments). Note the parallel to
    your node-level helping. Then re-read MS's paper §3 — the "make tail point to last node" step.
  - **Symptom card**: bug shape ("producer stuck — consumer can't proceed because tail is stale"); rule
    ("helping is what makes a lock-free algorithm progress-guaranteed; without helping it's only
    obstruction-free"); reapplies at: W74 raft (followers help leader by completing leader's incomplete
    AppendEntries via state-transfer), W42 OCC abort cascades, W26 group commit ACKs.
  - **Numbers**: predict per-op helping CAS cost (one extra CAS per ~1% of ops at low contention; up to
    50% under burst). Predict loom exploration reduction with helping (~30-50%).
  - **5-year failure mode**: helping conflates "I'm helping" with "I'm doing my own work" — debuggers
    can't tell. Trigger: an obscure production bug in helping path. Fix: tracing-instrument helping
    distinctly.
  - **Production handoff**: helping lands at W74 raft (followers complete leader's incomplete
    AppendEntries via state-transfer — the canonical "helper completes a remote half-step"), W42 OCC
    abort cascades, W26 group commit's drain. W74's hardened acceptance includes a kill-leader-mid-burst

- [ ] **Build**: `crates/exec-vm/src/instructions/stack.rs` — PUSH0..PUSH32, DUP1..DUP16, SWAP1..SWAP16, POP. All 96. (~75 min)
  - **Why**: 96 of the 140 EVM opcodes are pure stack manipulation. Their hot-path determines macro throughput. revm uses a fixed-size `[U256; 1024]` stack with a `len: usize` cursor — no heap allocation, no bounds check on hot path (debug-only). Mirroring this layout matters: a `Vec<U256>` stack costs you 2× on the dispatcher.
  - **Read first**: revm `crates/interpreter/src/instructions/stack.rs` and `crates/interpreter/src/interpreter/stack.rs` (the `Stack` itself — note `data: [U256; 1024]`, `top` pointer arithmetic).
  - **Design**:
    ```rust
    pub struct Stack {
        data: Box<[U256; 1024]>,  // heap-allocated to avoid 32 KiB stack-frame
        len: usize,
    }
    #[inline(always)]
    pub fn push(&mut self, v: U256) -> Result<(), Halt> { ... }
    fn push_n<const N: usize>(interp: &mut Interpreter, _: &mut dyn Host) {
        // Read N bytes from bytecode, zero-extend to U256, push.
        let bytes = &interp.bytecode[interp.pc + 1 .. interp.pc + 1 + N];
        interp.stack.push(U256::from_be_slice(bytes))?;
        interp.pc += N; // dispatch loop adds +1 for opcode itself
    }
    ```
    **Invariants**:
    - Stack depth ≤ 1024 strictly (push at 1024 → `StackOverflow`).
    - Underflow on POP/DUP_N if `len < N` → `StackUnderflow`.
    - DUP_N reads `data[len - N]`, pushes — never moves bytes, just copies.
    - SWAP_N swaps `data[len-1]` with `data[len-1-N]`.
  - **Build steps**:
    1. (~10 min) `Stack` struct with `Box<[U256; 1024]>` and `len`. Implement `push`, `pop`, `peek_n` with bounds checks behind `debug_assertions`; release path uses `get_unchecked`. Justify with SAFETY comment.
    2. (~25 min) `push_n::<N>` generic over N: 1..=32. `PUSH0` is a separate handler (push 0, no bytecode read).
    3. (~15 min) `dup_n::<N>` for N in 1..=16.
    4. (~15 min) `swap_n::<N>` for N in 1..=16.
    5. (~10 min) `pop()` handler — call `stack.pop` and discard.
  - **Pitfalls**:
    - *Underflow on DUP1 of empty stack*: classic. **Symptom**: panic in debug, UB in release with `get_unchecked`. **Fix**: every handler must check `len >= N` BEFORE the unsafe access. Codify with a `require_stack!(interp, N)` macro that early-returns `StackUnderflow`.
    - *Bytecode out-of-bounds on PUSH at end*: `PUSH32` at offset `code.len() - 5` reads off the end. Per yellow paper, missing bytes are zero. **Symptom**: panic. **Fix**: pre-pad bytecode with 32 zero bytes at load time (revm does this) or `slice` with bounds-clamped copy.
    - *Box vs inline stack*: `[U256; 1024]` is 32 KiB. Putting `Interpreter` on the stack with inline data triggers stack overflow in recursive contract calls. **Symptom**: SIGBUS at depth ~10. **Fix**: `Box<[U256; 1024]>` — heap allocates once per frame.
    - *PUSH0 SpecId gate*: introduced in Shanghai (EIP-3855). **Symptom**: bytecodes with 0x5f succeed pre-Shanghai when they should be INVALID. **Fix**: jump table swaps PUSH0 handler with `invalid` handler based on `cfg.spec_id`.
  - **Test scenarios**:
    - Fuzz: random sequences of PUSH/DUP/SWAP/POP for 10k steps, assert no UB under miri + ASan.
    - Boundary: 1024 PUSH1s then DUP1 → StackOverflow; 1023 + DUP1 succeeds.
    - PUSH32 at code-end with 5 bytes available: zero-extends correctly.
  - **Acceptance**:
    - Inheritance ratio 1.0 vs revm `stack.rs`.
    - Stack-op throughput ≥ 250 M ops/s single-threaded (revm baseline ~300 M).
  - **Downstream**: every other opcode handler uses these primitives; W19 precompile dispatchers reuse the stack abstraction.

- [ ] **Build**: `crates/exec-vm/src/instructions/contract.rs` — CALL, CALLCODE, DELEGATECALL, STATICCALL. EIP-150
  63/64ths gas. (~75 min)
  - **Why**: CALL is the *only* opcode that allocates a new interpreter frame. Its gas math (EIP-150 "all but one 64th") prevents stack exhaustion attacks. Mirroring revm's frame allocation pattern matters because Phase 4 W53+ extends it for snapshotting (journal) and W92 block-stm uses the frame boundary as the parallelism unit.
  - **Read first**: revm `crates/interpreter/src/instructions/contract.rs` (functions `call`, `call_inner`, `callcode`, `delegate_call`, `static_call`) — focus on `calc_call_gas` for EIP-150 arithmetic. Also EIP-150 spec for the 63/64ths derivation.
  - **Design**:
    ```rust
    pub fn call(interp: &mut Interpreter, host: &mut dyn Host) {
        pop!(interp, local_gas_limit, to, value, in_offset, in_len, out_offset, out_len);
        // 1. Resize memory for both calldata and return slot.
        // 2. Read calldata bytes from memory.
        // 3. Charge cold-account, value-transfer, new-account fees.
        // 4. Apply 63/64ths cap.
        // 5. Emit a CallOutcome action to the host; do NOT recurse.
        interp.next_action = InterpreterAction::Call { inputs: CallInputs { ... } };
        interp.instruction_result = InstructionResult::CallOrCreate;
    }
    ```
    **Invariants**:
    - `gas_given_to_callee = min(local_gas_limit, gas_left - gas_left/64)` post-Tangerine Whistle.
    - STATICCALL sets `is_static = true` for the child frame; child must reject any state-modifying opcode (SSTORE, LOG, CREATE, SELFDESTRUCT).
    - DELEGATECALL preserves `caller` and `value` from parent; storage targets parent's address.
    - CALLCODE is deprecated post-Homestead, but you implement it (used by old contracts).
  - **Build steps**:
    1. (~15 min) Shared `calc_call_gas(local_limit, gas_left, value_transfer, cold_account, new_account) -> (gas_for_callee, cost)` helper.
    2. (~20 min) `call` handler — full 7-arg pop, memory expansion, cost computation, action emission.
    3. (~10 min) `callcode` — same except target storage is parent.
    4. (~15 min) `delegate_call` — 6 args (no value), parent context preserved.
    5. (~10 min) `static_call` — 6 args (no value), set `is_static`.
    6. (~5 min) Tests: cold/warm account, OOG before child runs, 63/64ths exactness.
  - **Pitfalls**:
    - *Forgetting cold-access surcharge (EIP-2929)*: warm = 100 gas, cold = 2600. **Symptom**: post-Berlin replay diverges. **Fix**: host trait has `is_address_warm(addr) -> bool` consulted before charging.

    - *Static violation propagation*: child's static violation must abort cleanly without corrupting parent's state. **Symptom**: parent sees partial state mutations. **Fix**: revert child's journal frame on `InstructionResult::CallOrCreate` followed by static-violation.
  - **Test scenarios**:
    - Replay txs from mainnet block 12,244,000 (Berlin warm/cold transition).

    ```rust
    pub fn log<const N: usize>(interp: &mut Interpreter, host: &mut dyn Host) {
        check_staticcall!(interp);          // LOG forbidden in STATICCALL
        pop!(interp, offset, len);
        let mut topics = [B256::ZERO; N];
        for i in 0..N { pop_top!(interp, topics[i]); }
        gas!(interp, LOG_GAS + N * LOG_TOPIC_GAS + len * LOG_DATA_GAS_PER_BYTE);
        resize_memory!(interp, offset, len);
        let data = interp.memory.slice(offset, len).to_vec();
        host.log(Log { address: interp.contract.address, topics: topics.into(), data: data.into() });
    }
    ```
