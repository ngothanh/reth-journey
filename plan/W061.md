**Monday — EOF EIP deep re-read**

- [ ] Re-read EIP-3540, 3670. EOF container format. (~45 min)
  - **Why**: EOF (EVM Object Format) is the largest EVM change since The Merge — replacing the "everything-is-bytecode" mess with a structured container (magic + version + section table + code + data). Pre-deployment validation eliminates entire classes of bugs (invalid jumps, mid-PUSH JUMPDESTs). Critical for understanding upcoming mainnet (Prague?) hard forks. Citing Ipsilon repo + Reth EOF PRs ensures spec-current understanding.
  - **Read first**:
    - EIP-3540 (EOF container format), EIP-3670 (code validation), EIP-4200 (static relative jumps), EIP-4750 (functions: CALLF, RETF), EIP-5450 (stack validation)
    - github.com/ipsilon/eof (reference spec impl)
    - reth + revm open PRs touching `eof_*.rs`
  - **Design** (EIP-3540 format):
    ```text
    EOF1 container layout:
      magic:        2 bytes  0xEF 0x00
      version:      1 byte   0x01
      sections:     N entries of { kind: 1 byte, size: 2 bytes } each
      terminator:   1 byte   0x00
      section_data: concatenated bytes

    Section kinds:
      0x01 = type section (function signatures: input/output/max_stack)
      0x02 = code section (one entry per function)
      0x03 = data section (immutable data)
      0x04 = container section (subcontainers for CREATE3-style)

    Constraints:
      - exactly one type section
      - at least one code section (function 0 = entry point)
      - type section size = 4 × num_code_sections
      - data section optional
    ```
    ```rust
    pub struct EofContainer {
        pub magic: [u8; 2],
        pub version: u8,
        pub types: Vec<FunctionType>,    // one per code section
        pub code: Vec<Vec<u8>>,          // per function
        pub data: Vec<u8>,
    }
    pub struct FunctionType {
        pub inputs: u8,
        pub outputs: u8,
        pub max_stack: u16,
    }
    ```
    **Invariants**:
    - magic = `[0xEF, 0x00]` distinguishes EOF from legacy bytecode (legacy can't start with 0xEF — INVALID opcode).
    - version = 0x01 currently; future versions extend.
    - function 0's inputs = 0, outputs = 0x80 (sentinel for "main"); validated.
    - Pre-deployment validation REJECTS malformed containers — no runtime cost.
  - **Build steps (research today)**:
    1. (~15 min) Read EIP-3540 in full; sketch the byte layout.
    2. (~10 min) Read EIP-3670; note the per-opcode validation rules (no invalid opcodes, no truncated PUSH, JUMPDEST analysis embedded in container).
    3. (~10 min) Read EIP-5450; stack-overflow check moves from runtime to validation time.
    4. (~5 min) Note that EOF code can NOT use legacy JUMP/JUMPI — only static relative jumps (RJUMP, RJUMPI, RJUMPV, EIP-4200).
    5. (~5 min) Cross-reference to revm/reth open PRs to find production impl reference.
  - **Acceptance**: notes covering layout + validation + runtime semantics differences.
  - **Downstream**: Tue (validation impl), Wed (RJUMPV impl), Thu (CALLF/RETF/JUMPF impl), Fri (test vectors).

- [ ] [HFT] **Build**: `crates/matching-engine/src/match.rs` —
  `match_order(book: &mut OrderBook, incoming: Order) -> MatchResult`. Returns fills + remainder. Price-time priority. (~150 min)
  - **Why (MAX DETAIL — matching internals)**: This is THE function — the matching logic. Price-time priority means: incoming buy matches at lowest ask first; within same level, oldest order fills first. Every fill emits a `Fill` event into the log. Determinism is non-negotiable.
  - **Read first**: Nasdaq's OUCH protocol; LSE's order-matching rulebook; "Order Matching Algorithms" survey papers.
  - **Design**:
    ```rust
    pub struct MatchResult {
        pub fills: SmallVec<[Fill; 4]>,
        pub remainder: Option<Order>,    // unfilled portion stays on book (if Limit) or returned (if IOC)
        pub events: SmallVec<[MatchEvent; 8]>,
    }

    pub struct Fill {
        pub maker_id: OrderId,
        pub taker_id: OrderId,
        pub price: Price,                // maker's price (price-time priority)
        pub qty: Qty,
        pub ts: Monotonic,
    }

    pub enum MatchEvent {
        Accepted(OrderId),
        Filled(Fill),
        Cancelled(OrderId, CancelReason),
        Rejected(OrderId, RejectReason),
    }

    pub fn match_order(book: &mut OrderBook, mut incoming: Order) -> MatchResult {
        let mut result = MatchResult::default();
        result.events.push(MatchEvent::Accepted(incoming.id));

        // PostOnly: reject if would cross
        if incoming.kind == OrderKind::PostOnly && would_cross(book, &incoming) {
            result.events.push(MatchEvent::Rejected(incoming.id, CrossRejected));
            return result;
        }

        // FOK: pre-check if entire qty can fill; else reject
        if incoming.kind == OrderKind::FOK && !can_fill_completely(book, &incoming) {
            result.events.push(MatchEvent::Cancelled(incoming.id, FOKUnfillable));
            return result;
        }

        // Match loop: iterate opposite-side levels in best-price order
        match incoming.side {
            Buy => {
                while incoming.remaining > 0 {
                    let Some((&best_ask_price, level)) = book.asks.iter_mut().next() else { break; };
                    if incoming.price < best_ask_price && incoming.kind == Limit { break; }  // can't cross more
                    while incoming.remaining > 0 {
                        let Some(maker) = level.orders.front_mut() else { break; };
                        let fill_qty = incoming.remaining.min(maker.remaining);
                        let fill = Fill {
                            maker_id: maker.id,
                            taker_id: incoming.id,
                            price: maker.price,
                            qty: fill_qty,
                            ts: incoming.ts,
                        };
                        maker.remaining -= fill_qty;
                        incoming.remaining -= fill_qty;
                        result.fills.push(fill.clone());
                        result.events.push(MatchEvent::Filled(fill));
                        if maker.remaining == 0 {
                            level.orders.pop_front();
                            book.order_index.remove(&maker.id);
                        }
                    }
                    if level.orders.is_empty() {
                        book.asks.remove(&best_ask_price);
                    }
                }
            }
            Sell => { /* mirror */ }
        }

        // Place remainder on book if Limit
        if incoming.remaining > 0 && incoming.kind == OrderKind::Limit {
            book.add_limit_order(incoming.clone());
            result.remainder = Some(incoming);
        } else if incoming.remaining > 0 && (incoming.kind == IOC || incoming.kind == Market) {
            result.events.push(MatchEvent::Cancelled(incoming.id, IOCRemainder));
        }
        result
    }
    ```
    **Invariants**:
    - Price-time priority: best-price wins at level boundary; FIFO within level.
    - Fill price = MAKER's price (the resting order's price); regardless of taker's limit price.
    - Maker remaining decreases by fill_qty; if 0 → remove from book.
    - Atomic-per-order: a match operation EITHER produces all its fills OR (on error) none — but in practice errors here are panics (invariant violations).
    - Event log captures EVERYTHING: accepted, filled, cancelled, rejected.
  - **Build steps** (granular):
    1. (~25 min) MatchResult, Fill, MatchEvent types.
    2. (~30 min) match_order main loop for Buy side.
    3. (~25 min) Mirror for Sell side.
    4. (~20 min) PostOnly cross check (`would_cross`).
    5. (~20 min) FOK pre-check (`can_fill_completely`).
    6. (~15 min) IOC remainder cancel emission.
    7. (~15 min) Tests: simple 1×1 match; 1×N (one taker takes 3 makers); partial fill of taker; FOK unfillable rejected.
  - **Pitfalls** (named, determinism-critical):
    - *Maker-price vs taker-price bug*: fill at incoming's limit price instead of resting maker's price violates price-time priority. **Symptom**: trader gets worse fills than spec. **Fix**: `fill.price = maker.price` always.
    - *FOK partial commit*: starting to fill, encountering insufficient depth → MUST roll back fills. **Symptom**: FOK partially filled (spec violation). **Fix**: dry-run `can_fill_completely` BEFORE any fill; only commit fills if pre-check passes.
    - *Zero-qty fill emission*: arithmetic produces fill_qty = 0; emitting an Event with qty 0 pollutes log. **Symptom**: noise; downstream confused. **Fix**: skip event if fill_qty == 0 (shouldn't happen, but defense in depth).
    - *Cancel during match*: cross-shard cancel arrives mid-match. **Symptom**: order partially filled then "cancelled". **Fix v0.5**: matching is atomic — cross-shard messages queue until match completes; no preemption.
    - *Self-trade (maker.owner == taker.owner)*: depending on exchange rules, may be allowed (with self-trade-prevention) or rejected. **Symptom**: wash trades. **Fix v0.5**: defer; W74 adds self-trade-prevention flag.
  - **Test scenarios**:
    - 1 maker @ 100 qty=10; taker buy @ 101 qty=10 → 1 fill at 100 qty 10; book empty.
    - 3 makers @ 100, 101, 102 qty=10 each; taker buy @ 103 qty=25 → 3 fills (10@100, 10@101, 5@102).
    - FOK qty=100 when book has total qty=50 → no fills; FOK cancelled.
    - PostOnly buy @ 99 when ask=98 → reject (would cross).
    - Diff-test against simple sorted-Vec reference matcher: 10k random sequences, byte-exact match.
  - **Acceptance**: differential green; throughput ≥ 100k matches/sec single-core.
  - **Downstream**: W63 (v0.5 ship after diff test); W65 (multi-symbol); W66 (perpetuals adds margin checks before match).

- [ ] Implement EIP-4200 opcodes. (~120 min)
  - **Why**: Static relative jumps (RJUMP, RJUMPI, RJUMPV) replace legacy JUMP/JUMPI in EOF. The destination is a signed 16-bit offset embedded in the opcode — known at validation time → no runtime JUMPDEST check.

    fn rjump<H>(interp: &mut Interpreter, _: &mut H) {
        gas!(interp, BASE);  // 2 gas
        let offset = i16::from_be_bytes([interp.bytecode[interp.ip], interp.bytecode[interp.ip + 1]]);
        interp.ip = ((interp.ip + 2) as i32 + offset as i32) as usize;
    }
    fn rjumpi<H>(interp: &mut Interpreter, _: &mut H) {

        pop!(interp, condition);

            interp.ip = ((interp.ip + 2) as i32 + offset as i32) as usize;
        } else {
            interp.ip += 2;
        }
    }

- [ ] [HFT] **Build**: `crates/matching-engine/src/event_log.rs` — every order placed, cancel, fill, partial-fill emits
  a `MatchEvent` written via `wal::Wal`. Replay reconstructs full book state. (~150 min)
  - **Why (MAX DETAIL — determinism + recovery)**: The event log is the source of truth. The book is a projection. This separation enables: byte-exact replay (recovery, audit, debugging), state forks (test "what if order X cancelled?"), cross-DC replication via raft (W67+). TigerBeetle's design philosophy.
  - **Read first**: TigerBeetle `src/state_machine.zig` event log; QuickFIX recovery design; LMAX Disruptor whitepaper.
  - **Design**:
    ```rust
    pub struct EventLog {
        wal: wal::Wal,
        next_seq: u64,
    }
    #[derive(RlpEncodable, RlpDecodable)]
    pub enum LoggedEvent {
        OrderAccepted { seq: u64, order: Order },
        OrderCancelled { seq: u64, id: OrderId, reason: u8 },
        OrderFilled { seq: u64, fill: Fill, maker_remaining_after: Qty },
        OrderRejected { seq: u64, id: OrderId, reason: u8 },
        Tick { seq: u64, ts: Monotonic },  // heartbeat for liveness even when no orders
    }

    impl EventLog {
        pub fn append(&mut self, ev: LoggedEvent) -> Result<u64, _> {
            let seq = self.next_seq;
            self.next_seq += 1;
            let bytes = rlp::encode(&ev);
            self.wal.append(&bytes)?;
            Ok(seq)
        }
        pub fn fsync(&mut self) -> Result<(), _> { self.wal.fsync() }

        pub fn replay<F: FnMut(LoggedEvent)>(&self, mut apply: F) -> Result<u64, _> {
            for entry in self.wal.iter() {
                let ev: LoggedEvent = rlp::decode(&entry?)?;
                apply(ev);
            }
            Ok(self.next_seq)
        }
    }
    ```
    **Invariants**:
    - Sequence number `seq` monotonic and gap-free per symbol.
    - Every match emits BEFORE-state and AFTER-state implicitly: `maker_remaining_after` in OrderFilled lets replay verify book consistency.
    - WAL fsync called BEFORE returning success to client (durability).
    - Replay rebuilds book byte-exact: same sequence → same final state.
  - **Build steps** (granular):
    1. (~20 min) LoggedEvent enum with RLP derive.
    2. (~25 min) EventLog wraps wal::Wal; append/fsync/replay.
    3. (~30 min) Integrate into match_order: every accept/fill/cancel/reject → event.append.
    4. (~25 min) Replay function: read WAL, decode each event, apply to fresh OrderBook, verify state hash matches snapshot.
    5. (~30 min) Differential test: random sequence of 10k orders → log → replay → final book identical (SHA256 of book bytes match).
    6. (~20 min) Crash test: crash mid-sequence; recover; verify replay reaches last fsync'd seq, no further.
  - **Pitfalls**:
    - *Fsync per event kills throughput*: 100k orders/sec needs batched fsync. **Symptom**: 1k orders/sec. **Fix**: client-replication batches events; fsync once per batch.
    - *Replay state divergence*: same log → different book → bug. **Symptom**: rare data corruption. **Fix**: deterministic data structures (BTreeMap, not HashMap iter order); det_test harness (W60) catches.
    - *Schema evolution*: adding fields to LoggedEvent variants breaks replay of old logs. **Symptom**: prod can't read pre-upgrade log. **Fix**: only APPEND fields with `Option<_>`; never remove or reorder.
    - *Seq number reset on crash*: re-using a previously-used seq on restart corrupts log. **Symptom**: silent dup. **Fix**: on recovery, set `next_seq = last_seq_in_wal + 1`.
  - **Test scenarios**:
    - 10k orders → log → replay → state hash match.
    - Crash injection: 1k events, crash before fsync 999, recovery resumes at 999.
    - Schema-evolution: write log with v1; decode with v2 (which has extra Option field) → success, extra field = None.
  - **Acceptance**: 1M event/sec append throughput; replay reaches 10x append throughput (no fsync); crash-recovery exact.
  - **Downstream**: W63 (replay-based diff test + v0.5 ship); W67+ (raft replicates the event log); W90+ (ledger event log shares this design).

**Thursday — Functions (EIP-4750)**

- [ ] Implement CALLF, RETF, JUMPF in exec-vm. (~120 min)
  - **Why**: EOF functions (EIP-4750) replace the implicit "jump into the middle of code" pattern with explicit function-call semantics. CALLF pushes a return frame; RETF pops; JUMPF tail-calls (no return frame). Per-function stack validation (EIP-5450) is what enables removing runtime stack checks.
  - **Design**:
    ```rust
    pub struct ReturnStack {
        frames: SmallVec<[ReturnFrame; 16]>,  // max 1024 depth
    }
    pub struct ReturnFrame {
        pub return_ip: usize,
        pub return_section: u16,
        pub return_stack_floor: u16,
    }

    fn callf<H>(interp: &mut Interpreter, _: &mut H) {
        gas!(interp, 5);
        let target_section = u16::from_be_bytes([interp.bytecode[interp.ip], interp.bytecode[interp.ip + 1]]);
        // Push return frame
        interp.return_stack.push(ReturnFrame {
            return_ip: interp.ip + 2,
            return_section: interp.current_section,
            return_stack_floor: interp.stack_floor,
        });
        // Jump to target function
        interp.current_section = target_section;
        interp.ip = 0;
        // Update stack floor (per-function frame)
        let f = &interp.eof.types[target_section as usize];
        interp.stack_floor = interp.stack.len() - f.inputs as usize;
    }

    fn retf<H>(interp: &mut Interpreter, _: &mut H) {
        gas!(interp, 3);
        let Some(frame) = interp.return_stack.pop() else {
            interp.result = InvalidReturn; return;
        };
        interp.ip = frame.return_ip;
        interp.current_section = frame.return_section;
        interp.stack_floor = frame.return_stack_floor;
    }
    ```
    **Invariants**:
    - Return stack max depth 1024 (mirrors call stack depth).
    - JUMPF replaces tail-call: no return frame pushed; control transfers permanently.
    - Function outputs validated against type-section signature.
    - Stack-floor tracking prevents callee from popping caller's frame values.
  - **Build steps**:
    1. (~30 min) ReturnStack + ReturnFrame types.
    2. (~30 min) CALLF impl with input-validation against type section.
    3. (~20 min) RETF impl with output-validation.
    4. (~20 min) JUMPF impl (no return frame push).
    5. (~20 min) Tests: nested calls, recursion (within depth), invalid section index rejected at deploy.
  - **Pitfalls**: stack-floor management is the most error-prone; off-by-one allows function to read caller's locals.
  - **Acceptance**: EOF function reference vectors pass; deploy-time validation catches malformed section refs.
