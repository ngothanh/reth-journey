**Wednesday — Synthetic feed generator**

- [ ] **Build**: `crates/marketdata-kernelbypass/examples/synthetic_feed.rs` — generates realistic ITCH messages at
  configurable rate. (~105 min)
  - **Why**: The 2000-hr runtime milestone for M30 is *worthless* if the rig runs a trivial feed (e.g. one symbol,
    constant rate) — silent bugs hide. A *realistic* synthetic feed (Pareto-distributed inter-arrival, skewed symbol
    popularity, occasional message storms, crosses + cancels at production-realistic ratios) is what makes uptime
    *evidence* rather than *theater*. Pitfalls in synthetic generation (time-skew, RNG determinism, hardware variance)
    can mask correctness bugs for weeks.
  - **Read first**: NASDAQ ITCH 5.0 spec §4 (message types A/F/X/D/U/E/C/P); `arctic-stream/nasdaq-itch` (Rust ITCH
    parser used as a writer-reference); QuickFIX/J examples for FIX session-layer wrapping if applicable.
  - **Design**:
    ```rust
    pub struct SyntheticFeed {
        rng: rand_xoshiro::Xoshiro256PlusPlus, // seeded, deterministic across runs
        symbols: SymbolUniverse,               // Zipf-distributed popularity
        clock: SyntheticClock,                 // monotonic, advances by inter-arrival samples
        rate_target_msg_per_sec: u64,
        out: BumpyBoundedQueue<ItchMessage>,   // backpressure on the downstream consumer
        stats: FeedStats,
    }
    pub enum ItchMessage {
        AddOrder { ts_ns: u64, oid: u64, sym: SymId, side: Side, price: i64, qty: u32 },
        OrderExecuted { ts_ns: u64, oid: u64, exec_qty: u32, match_no: u64 },
        OrderCancel { ts_ns: u64, oid: u64, cancel_qty: u32 },
        OrderDelete { ts_ns: u64, oid: u64 },
        ReplaceOrder { ts_ns: u64, old_oid: u64, new_oid: u64, price: i64, qty: u32 },
        Trade { ts_ns: u64, match_no: u64, price: i64, qty: u32, sym: SymId },
        // ... (Cross, Halt, MWCB optional)
    }
    ```
    **Invariants**: (1) Generator is *deterministic for a fixed seed* — same seed → byte-identical feed.
    (2) Inter-arrival times are monotonic-non-decreasing (no negative jitter). (3) `oid` is unique across the run
    (use a per-symbol counter + symbol prefix). (4) Cancel/Execute messages only reference an `oid` that was previously
    Added and not yet Deleted (closed-world invariant).
  - **Build steps**:
    1. (~10 min) Symbol universe: 1024 symbols, Zipf(α=1.1) popularity weights (top symbol gets ~10% of all messages).
    2. (~20 min) Order-book shadow: per-symbol, track open `oid`s so Cancel/Execute references are valid.
    3. (~25 min) Message-mix: 60% AddOrder, 15% Cancel, 15% Execute, 5% Replace, 5% Delete; tune to match NASDAQ
       published ratios.
    4. (~20 min) Rate-shaping: target `rate_target` msg/sec; use `spin_sleep` (busy-wait the last <1ms) for sub-ms
       accuracy; *don't* use `tokio::time::sleep` (millisecond floor on Linux).
    5. (~15 min) Storm injection: every ~60s, generate a 100k-msg burst over 100ms (models cancel-storm or market-open).
    6. (~15 min) Smoke: emit 1M messages, verify all referential invariants hold (no Cancel of a never-Added oid).
  - **Pitfalls**:
    *NTPDrift*: **Symptom**: two-machine rig logs show negative latencies because Machine B's clock drifted +200ms
       relative to Machine A; uptime hour count is corrupted. **Fix**: deploy `chrony` configured with `makestep 0.1 3`
       and *internal* PTP if hardware supports; emit a per-machine `clock_drift_ms` metric every 10s; alert if
       |drift| > 50ms; for *uptime accounting*, derive elapsed-time from a single-machine monotonic clock not wall.
    *HardwareVariance*: **Symptom**: P99 latency on Machine A is 1.5μs, Machine B is 4μs — identical binary, identical
       config; cause is CPU frequency scaling or thermal throttling on Machine B. **Fix**: set `cpupower frequency-set
       -g performance` in the provisioning script; pin matching-engine threads to specific cores via `taskset`; disable
       turbo-boost for predictability; record `cpu_mhz` per shard in `/metrics`.
    *RNGDeterminismLost*: **Symptom**: replay of a "bug-triggering" recorded run does not reproduce the bug. **Fix**:
       seed every RNG (feed, jitter, storm-trigger) from a single per-run u64 seed; *never* use `thread_rng()`; log
       the seed at startup; checksum the first 1k messages and assert match across runs.
    *OffsiteMirrorMissing*: **Symptom**: rig drive dies, no backup; 700hr of audit logs lost. **Fix**: `rsync` ledger
       segments + audit logs to off-site (S3 + a separate physical drive) hourly; weekly `restic` snapshot;
       quarterly *test-restore* drill to verify the backup is actually replayable.
  - **Test scenarios** (adversarial): (a) inject a 5-second negative clock-step on Machine B during a burst — verify
    the feed rejects messages with non-monotonic ts and the alert fires; (b) run with two different seeds in parallel —
    verify outputs are *not* identical (sanity check that the seed is actually being used); (c) crash the consumer
    mid-storm — feed should backpressure without buffer-bloating.
  - **Acceptance**: sustains 1M msg/sec for ≥ 60 minutes with all referential invariants holding; identical SHA-256
    of first 10M messages across two runs with the same seed; clock-drift alert proved to fire within 30s of a
    50ms synthetic skew.
  - **Downstream**: this generator becomes the *baseline workload* for every uptime hour from W106 onward;
    ops-chaos injects faults during this feed; M30 bar-(c) audit cites the sustained-1M-msg/s claim from runs of
    this binary.
