  - *Mental model*: a `SyntheticFeed` is a deterministic state machine — one seed in, byte-identical ITCH stream out — that maintains a *shadow* of every open order so it can only emit referentially-valid Cancels/Executes, and that paces itself off a *synthetic clock* (not the wall clock) so timestamps are monotonic and reproducible. It exists because uptime + throughput claims are only credible if the workload is realistic AND replayable.

  - *Contract* (signature-level only — NEVER the solution body):
    ```rust
    pub struct SyntheticClock(AtomicU64); // ts_ns, advance-only
    impl SyntheticClock {
        pub fn now(&self) -> u64;
        pub fn advance(&self, delta_ns: u64) -> u64; // returns new ts; never moves backward
    }
    pub struct OrderBookShadow { /* per-symbol open oids */ }
    impl OrderBookShadow {
        pub fn add(&mut self, sym: SymId, oid: u64);
        pub fn remove(&mut self, sym: SymId, oid: u64) -> bool;       // false = orphan
        pub fn pick_open(&self, sym: SymId, rng: &mut impl RngCore) -> Option<u64>;
    }
    pub struct SyntheticFeed { /* clock, shadow, sub-stream RNGs, config */ }
    impl SyntheticFeed {
        pub fn new(seed: u64, cfg: &FeedConfig) -> Self;
        /// Fill `out` in place; returns bytes written. ZERO heap alloc per call.
        pub fn next_into(&mut self, out: &mut [u8]) -> usize;
    }
    ```
  - *Back-of-envelope* (bar (c) — Jeff-Dean numbers): target 1 M msg/s = **1 message every 1 µs = 1000 ns budget**. An ITCH AddOrder is ~36 bytes — encoding it into a caller buffer is a handful of `copy_nonoverlapping`s + a `to_be_bytes`, ~10-20 ns. That leaves headroom *only if the hot path allocates nothing*: one `malloc` ≈ 50 ns (5% of the budget) and `format!("{sym}")` is a malloc + memcpy + UTF-8 work ≈ 80-120 ns (8-12% of budget) — at 1 M msg/s that's **50-120 M allocs/s**, which thrashes the allocator and the L2 (cache-line eviction ~7 ns each). The Cancel path must pick an open oid in O(1) amortized; a `Vec::remove(idx)` shifts the tail (O(n), grows with book depth) — at 1 M msg/s with a 10k-deep book that's a 10k-element memmove (~10 µs) **per Cancel**, 10× over budget. Pacing cliff: `tokio::time::sleep` rounds up to the ~1 ms timer-wheel slot, so a requested 1 µs sleep actually sleeps ~1 ms = **1000× the intended pause**, capping throughput at ≈1000 msg/s (a 1000× cliff vs the 1 M target).

  - **Requirements** R1..R10 — write in `crates/marketdata-kernelbypass/notes/106_synthetic_feed_design.md`:
    - R1. Deterministic for a fixed `seed: u64` — two runs produce byte-identical streams (verified by SHA-256 of the first 10 M messages).
    - R2. Timestamps `ts_ns` are monotonic-non-decreasing across the entire run.
    - R3. `oid` is globally unique within a run (per-symbol counter + symbol prefix).
    - R4. Referential closed-world: every Cancel/Execute/Delete/Replace references an `oid` previously Added and not yet Deleted; an end-of-run smoke check asserts zero orphan references.
    - R5. Symbol popularity is Zipf(α=1.1); top symbol ≈10% of all messages, top-10 ≈50%.
    - R6. Message mix matches NASDAQ published ratios — 60% AddOrder, 15% Cancel, 15% Execute, 5% Replace, 5% Delete (tunable via config).
    - R7. Rate shaping: sustains `rate_target` msg/s to within ±2% over 10 s windows; busy-wait/`spin_sleep` below 1 ms (NEVER `tokio::time::sleep` on the hot path).
    - R8. Storm injection: every ~60 s emit a 100k-msg burst over 100 ms; `storm_count_total` metric tracks them.
    - R9. Backpressure: when the consumer stalls, the feed slows (bounded queue blocks/sheds) — it never buffer-bloats unbounded.
    - R10. Sustains 1 M msg/s for ≥60 min with all invariants holding, **zero heap allocation per message on the hot path** (verified by an allocation-counting test).

  #### Phase 3 — Make the tests pass, one failure at a time (~75 min)

  Ordered failure cards — newbie failures first, expert last — the ladder you actually walk.

  - **(NEWBIE) When `timestamps_monotonic_nondecreasing` finds a non-monotonic ts at position 8742:**
    - Symptom: `ts_ns[8742] < ts_ns[8741]`; a strict consumer rejects the message.
    - Why: the rate-shaper read `Instant::now()` (a hardware clock that can step backward across CPU migration on older kernels) OR the storm path used a separate clock that didn't advance the shared cursor.
    - Fix: maintain `clock: SyntheticClock(AtomicU64)` that only moves forward via `advance(delta_ns)`; every timestamp reads from it; pacing advances it exactly once per message.
    - Cost avoided: not a perf cost — a *correctness* cliff: a single backward ts silently corrupts the M30 uptime ledger's time axis.
    - Muscle: monotonic time in a simulator is a *synthetic clock*, never the wall clock — wall clock is a hardware detail you must not depend on. Reapplies at: W107 ops-chaos test clock, W109 VOPR clock model, W110-W112 perf-tune timestamping.

  - **(SENIOR) When `seed_determinism_byte_identical` reports the SHA-256 differs between two seed=42 runs:**
    - Symptom: same seed, two runs, different hash; `different_seeds_diverge` still passes (so the seed *is* partially used).
    - Why: a `rand::thread_rng()` got smuggled into one sub-path (jitter or storm trigger), seeded from OS entropy on first use per thread.
    - Fix: ALL randomness derives from one `Xoshiro256PlusPlus::seed_from_u64(seed)`; independent sub-streams via `jump()` (feed/jitter/storm); add a `clippy` deny rule on `thread_rng`.
    - Cost avoided: irreproducibility — you can't replay the bug that crashes the rig at hour 1900, so the M30 audit can't be defended.
    - Muscle: determinism = one seed source, zero implicit OS entropy; `thread_rng` is banned in reproducible simulators. Reapplies at: W107 ops-chaos seed handling, W109 VOPR scenario replay.

  - **(SENIOR) When `backpressure_no_unbounded_buffer` reports queue depth = 50 M after the 5 s consumer pause:**
    - Symptom: queue grows 1k → 50 M entries during the pause, then OOM.
    - Why: the feed→consumer hop was `crossbeam::channel::unbounded`; the producer never blocks.
    - Fix: use your W04 `BumpyBoundedQueue` (cap 100k); `push` returns `Err(Full)`; the feed treats Full as backpressure — sleeps a short jitter, re-attempts, and the rate naturally tracks consumer speed.
    - Cost avoided: an unbounded queue is an OOM bomb — one slow consumer kills the whole rig and zeroes the uptime clock.
    - Muscle: every producer-consumer pipeline needs a bounded queue + producer-side `Full` handling; back-pressure is correctness, not a tuning knob. Reapplies at: W105 tracing-bridge queue, W107 chaos queue, W108 fault-injection backpressure.

  - **(SENIOR) When `storm_injection_fires_periodically` reports 0 storms in 5 minutes:**
    - Symptom: `storm_count_total == 0`; no storm ever fired.
    - Why: the storm trigger compared against the wall clock, which the test's simulated time never advanced.
    - Fix: derive `next_storm_at` from the `SyntheticClock`; fire when `clock.now() >= next_storm_at`. Wall clock plays no role.
    - Cost avoided: untestable timed behavior — storms (the realistic stress) never exercise the order book under test.
    - Muscle: tests of timed events must be driven by the synthetic clock, never the wall clock. Reapplies at: W107 chaos timing tests, W109 VOPR scheduled events.

  - **(EXPERT / cross-primitive) When `closed_world_referential_check_under_storm` finds 142 Cancels referencing never-Added oids:**
    - Symptom: 142 orphan refs, all during storm bursts; base path (storms off) is clean.
    - Why: the storm path sampled oids directly from the RNG and emitted Cancels without consulting `OrderBookShadow` — it went *around* the model.
    - Fix: storm pre-allocates a window of oids, emits Adds for ALL of them through the shadow first, then emits Cancels/Executes picking only from `shadow.pick_open(sym, rng)`. Every emitted message updates the shadow.
    - Cost avoided: a feed that emits invalid sequences trains the order book against a fiction — bugs that fire in production stay hidden through all 2000 audit hours.
    - Muscle: closed-world invariants require a shadow model that EVERY emission path (including the fast storm path) routes through — no path may bypass the model. Reapplies at: W107 ops-chaos workload generation, W109 VOPR scenario invariants.

  - **(EXPERT, perf #1 — bar (c) violation) When `hot_path_zero_alloc` reports 1_000_000 allocs across 1 M messages:**
    - Symptom: exactly one alloc per message; `format!("{}", sym)` / `Vec::with_capacity` shows on the flamegraph.
    - Why: the encode path built a `String`/`Vec<u8>` per message instead of writing into the caller's buffer.
    - Fix: `next_into(&mut [u8]) -> usize` writes fields with `to_be_bytes` + `copy_from_slice` from a fixed `[[u8;8]; N_SYMBOLS]` symbol table; no owned allocation on the hot path.
