  - 🔧 **Why this matters**: Mirrors `revm::context::JournaledState`. Journaling is the EVM's transactional memory — every state mutation pushes a PRE-change undo record so REVERT / OOG / exceptional-halt can rewind to a checkpoint. The 4 specific traps: (1) the warm-set (EIP-2929) is itself journaled — a naive impl leaks sub-call warmth past revert, making gas cheaper than spec → consensus fork; (2) `commit` MERGES upward but a naive impl re-runs undo logic on commit, wiping committed balances; (3) entries must record PRE state, not POST — a naive `StorageChanged { new_value }` cannot undo; (4) transient storage (EIP-1153) journals on TSTORE only, never TLOAD. Downstream consumers: W55 (parity build reuses this verbatim), W53 (opcode suite), W62 (BundleState diff). **First-attempt impls fail ≥1 test below; the debug session IS the lesson.**

        pub fn commit_checkpoint(&mut self);                       // fold frame into parent
        pub fn revert_checkpoint(&mut self, cp: JournalCheckpoint); // replay frame in reverse

    }

  - *Back-of-envelope* (bar (b), informational): a `JournalEntry` is ~48–64 B (an enum with the largest variant `AccountDestroyed` carrying 2 addresses + 2 bools + U256). At the EIP-150 depth cap 1024, with gas naturally bounding entries per frame, the journal is O(gas) not O(depth²). A `Vec<JournalEntry>` push is amortized O(1) but a frame that reallocs from cap-0 → 8 → 16 costs a `malloc` (~50 ns) each grow; `with_capacity(8)` removes the first two reallocs. Not a bar gate here, but the W74 `wal` per-order undo log inherits this sizing decision.
  - **Requirements** R1..R7 — write in `notes/50_journal_design.md`:

    - R7: `AccountDestroyed` carries `was_destroyed: bool` (EIP-6780) so revert restores prior destroy status, not just liveness.

    fn commit_folds_up_so_outer_revert_undoes() {
        let mut j = JournaledState::new(SpecId::CANCUN);
        let (a, b) = (address!("0x00..0A"), address!("0x00..0B"));
        let outer = j.checkpoint();             // OUTER frame
        j.set_balance(a, U256::from(100));       // journaled in OUTER
        let inner = j.checkpoint();              // INNER frame (the committed sub-call)
        j.transfer(a, b, U256::from(30));        // BalanceTransfer{from:a,to:b,balance:30} in INNER

        //    (rejects "commit discards the frame" -> the BalanceTransfer entry would be gone and

        j.revert_checkpoint(outer);

        assert_eq!(j.balance(b), U256::ZERO,
            "outer revert restores b to 0; if commit had dropped the inner frame, b would still be 30");

  #### Phase 3 — Make the tests pass, one failure at a time (~110 min)
  Ordered failure cards, newbie first.

  - **(NEWBIE) When `revert_restores_storage_pre_value` reports `assertion: got 99, want 42`:**
    - Symptom: revert leaves the in-frame value instead of restoring the pre-frame one.
    - Why: `StorageChanged` recorded the NEW value (or nothing); reverse-replay has no PRE-value to write back.
    - Fix: record `had_value` at write time: `StorageChanged { address, key, had_value: old }`; `revert_entry` writes `had_value` back.
    - Muscle: an undo log stores the PRE-state; the new value is already in the map. Reapplies at: W55 exec-vm journal parity, W74 matching-engine per-order undo into `wal::Wal`, W41 txn savepoint.

  - **(SENIOR) When `warm_set_rolls_back_on_revert` reports `is_cold_after == false`:**
    - Symptom: parent re-reads the slot warm (gas 100) after the sub-frame reverted.
    - Why: `sload`/`load_account` flipped `is_cold` but pushed no `StorageWarmed`/`AccountWarmed`, so revert can't un-warm.
    - Fix: every access that flips cold→warm pushes a `Warmed` entry; `revert_entry(StorageWarmed{..})` removes the key from the warm set.
    - Muscle: warmth is journaled state — gas-relevant flags roll back exactly like values, or you charge under spec and fork. Reapplies at: W53 opcode-suite cold/warm gas tests, W62 storage-trie access-list, W55 journal parity.

  - **(SENIOR) When `commit_folds_up_so_outer_revert_undoes` reports `balance(b) == 0` right after commit:**
    - Symptom: committing a successful sub-call wiped the transfer (the first asserts fail).
    - Why: `commit_checkpoint` reused the revert loop (applied undo) instead of folding the frame up.
    - Fix: `commit` pops the frame and `parent.extend(entries)` — no `revert_entry` call. Only `revert_checkpoint` undoes.
    - Muscle: commit preserves and folds upward; revert replays. They are NOT symmetric code paths. Reapplies at: W41 txn 2PC commit vs rollback, W55 journal parity, W74 ledger event-log.

  - **(SENIOR) When `commit_folds_up_so_outer_revert_undoes` passes the first asserts but the OUTER revert reports `balance(a) == 70` / `balance(b) == 30`:**
    - Symptom: post-commit balances are correct (70/30), but the enclosing `revert_checkpoint(outer)` does NOT roll the transfer back — `a` stays 70, `b` stays 30.
    - Why: `commit_checkpoint` popped the inner frame and DISCARDED its entries (a tempting "commit = drop the frame" shortcut). The balance map was mutated directly, so the post-commit asserts pass by accident — but the `BalanceTransfer` undo record never folded into OUTER, so the outer revert has nothing to replay.
    - Fix: `commit` must `parent.extend(inner_entries)` (move the entries up), not drop them; only then can an enclosing revert replay them. This is exactly what nested CALL→commit→outer-REVERT depends on.
    - Muscle: commit FOLDS entries into the parent frame so an outer revert can still undo them — discarding a committed frame's undo records silently breaks nested rollback even when the direct balances look right. Reapplies at: W41 txn nested savepoint commit, W55 journal parity nested CALL, W94 block-stm re-exec boundary, W74 ledger event-log fold.

  - **(EXPERT) When `transient_storage_reverts_but_tload_not_journaled` reports `journal_top_len grew on TLOAD`:**
    - Symptom: a read-only TLOAD pushed a journal entry.
    - Why: the access path journals on every transient touch instead of only on mutation.
    - Fix: push `TransientStorageChange` in `tstore` only; `tload` is pure read. (Same split for `sload` vs `sstore` value-journaling, separate from warm-journaling.)
    - Muscle: journal mutations, never reads — a read that mutates a flag (warmth) is the lone exception, and that's a flag write, not a value write. Reapplies at: W55 journal parity, W62 access-list, W74 wal append-only discipline.

  - **(EXPERT) When `selfdestruct_recreate_then_outer_revert` reports `account_exists(a) == false`:**
    - Symptom: outer revert leaves the account destroyed.
    - Why: `AccountDestroyed` omitted `was_destroyed`/`had_balance`, so reverse-replay can't restore the prior live status (it just toggles a single "destroyed" bit).
    - Fix: record `AccountDestroyed { address, target, was_destroyed, had_balance }`; `revert_entry` restores both the destroy flag and the moved balance. EIP-6780: only same-tx-created accounts actually delete.
    - Muscle: an undo record must capture EVERY field the operation clobbered, not just the headline one. Reapplies at: W55 journal parity, W53 SELFDESTRUCT gas/refund tests, W62 trie deletion rollback.

  - **(perf, bar (b) optional) When the journal reallocs on the first 8 entries per frame:**
    - Symptom: `cargo bench --bench journal_throughput` shows extra `malloc` calls (visible via a `#[global_allocator]` counter) on short call frames.
    - Why: each frame `Vec` grows 0→4→8 with a realloc each step.
    - Fix: `Vec::with_capacity(8)` in `checkpoint()` — typical frames hold ≤8 entries; removes the first two reallocs.
    - Cost avoided: ~2 × `malloc` (~50 ns each) + a memcpy per shallow frame; at millions of frames/block it is measurable but NOT a bar gate here (exec-vm is bar (b)).
    - Muscle: size the container to the common case to skip the early reallocs. Reapplies at: W74 wal undo-log frame sizing, W58 dispatch table, W63 matching-engine order pool.

  - 🔧 **Why this matters**: Mirrors revm `crates/interpreter/src/instructions.rs` `instruction_table::<H, SPEC>()`. W58 will A/B match-dispatch vs jump-table vs computed-goto; that bench is only valid if dispatch is isolated behind one module boundary and every opcode is ONE fn referenced by both dispatchers. The 2 traps: (1) an opcode whose semantics are inlined into the match arm (not a free fn) can't be put in a jump-table without duplication → the W58 A/B compares different code; (2) a dispatcher that owns gas/stack state breaks the "dispatch is pure routing" invariant, so the jump-table variant silently diverges on gas. Downstream: W58 (1-day swap), W64 (perf-PR pattern). **First-attempt impls fail ≥1 test below.**

  #### Phase 3 — Make the tests pass (~75 min)
  - **(SENIOR) When `match_dispatch_matches_w17_suite` reports a mismatched opcode result:**
    - Symptom: one opcode diverges from the W17 inline behavior after lifting.
    - Why: the lift dropped a side effect that lived in the match arm (e.g. a `pc += 1` or a gas charge between arms).
    - Fix: move the per-opcode side effect INTO the `op_xxx` fn; the match arm must be pure routing.
    - Muscle: when you extract a body, the surrounding glue (pc, gas) must move with it or the behavior changes. Reapplies at: W58 jump-table, W64 perf PR, W53 opcode conformance.

  - **(EXPERT) When `op_add_is_a_free_fn_not_a_closure` won't compile (`expected fn pointer, found closure/inline`):**
    - Symptom: `op_add::<DummyHost>` doesn't coerce to `Instruction<H>`.
    - Why: the opcode logic is still inside the match arm (or a closure capturing locals), not a free generic fn.
    - Fix: make every opcode a top-level `fn op_xxx<H: Host>(&mut Interpreter, &mut H)` with no captures.
    - Muscle: a jump-table needs fn POINTERS — free fns, zero captures; closures with captures can't go in `[fn; 256]`. Reapplies at: W58 InstructionTable build, W64 dispatch perf PR.

  - **(SENIOR) When `dispatch_is_zero_sized` reports `size_of != 0`:**
    - Symptom: `MatchDispatch` carries fields (gas, stack, or a `pc`).
    - Why: the consolidation pulled per-execution state onto the dispatcher for convenience.
    - Fix: move all execution state to `Interpreter`; `MatchDispatch` is a unit struct.
    - Muscle: a dispatcher is a router — keep it stateless so swapping it (W58) can't change behavior. Reapplies at: W58 jump-table, W94 block-stm executor.

  - **(SENIOR) When `opcode_bench_lands_in_band` reports an out-of-band number:**
    - Symptom: throughput reads ~1e11 (dead-code-eliminated) or ~1e3 (a syscall in the loop).
    - Why: the bench's result isn't consumed (LLVM elides it) or the harness does I/O per op.
    - Fix: `std::hint::black_box` the result; hoist any setup out of the timed loop.
    - Muscle: a bench whose result is unobserved measures nothing — black_box it and sanity-check the band. Reapplies at: W58 dispatch A/B bench, W64 perf PR, W64 microbench discipline.
