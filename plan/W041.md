    - **P5**: list every Phase-2 test below you predict your first attempt will FAIL. (Compare against reality after tests run.)
  - *Mental model*: a `LeveledCompactor` keeps each level's SSTs key-disjoint (k≥1) so a point read touches ≤1 SST per level; compaction merges one over-target level down into the next, preserving disjointness. It exists to bound read amp at ~`#levels` instead of `#SSTs`.
  - *Contract* (signature-level — NEVER the body):
    ```rust
    pub struct LeveledCompactor { levels: Vec<Level>, fanout: u32, l1_target: u64 }
    struct Level { index: u32, index_tree: BTreeMap<Vec<u8>, SstId>, target: u64 }
    impl LeveledCompactor {
        fn level_target(&self, k: u32) -> u64;                 // fanout^(k-1) * l1_target
        fn overlapping(&self, k: u32, range: KeyRange) -> Vec<SstId>; // O(log N + hits)
        fn assert_key_disjoint(&self, k: u32);                 // debug invariant, k>=1
    }
    ```
  - *Back-of-envelope*: L4 holds ~3000 SSTs (fanout 10 over a few-TB DB). A linear overlap scan = 3000 × ~30 ns/key-cmp ≈ **90 µs/pick**, and pick runs every compaction tick (~10–100 Hz) → up to 9 ms/sec of pure scan, with the level snapshot-lock held the whole time, stalling foreground writes. A `BTreeMap` overlap query is `~log2(3000) ≈ 12` comparisons ≈ **~200–300 ns** → a **~300× cliff** (90 µs cold-scan vs 300 ns tree-probe). Manifest: 1 fsync ≈ ~5 ms on a consumer NVMe; 10 fsyncs/compaction + 50 fsyncs/flush is the durability bottleneck, not the bytes written.
  - **Requirements** R1..R7 — write in `crates/lsm-core/notes/41_lcs_design.md`:
    - R1. L_k target size = `fanout^(k-1) × l1_target`.
    - R2. **Key-disjoint invariant** for k ≥ 1: SSTs within a level have non-overlapping key ranges.
    - R3. **L0 special case**: L0 allows overlaps; an L0→L1 merge picks ALL overlapping L0 SSTs.
    - R4. **Range-tree overlap index** per level (`BTreeMap` keyed by `first_key`); O(log N) overlap query via `range(..end).next_back()` then linear-forward until `first_key > end`.
    - R5. **Batched manifest mutations**: one `CompactionResult { adds, removes }` record per compaction; one fsync covers the full atomic swap.
    - R6. Output SST sizes strictly bounded; split on target threshold.
    - R7. Read amp ≤ 3 (warm bloom); write amp ≤ 10; space amp ≤ 1.1×.
  - **Design walk-through** D1..D7 — answer in `notes/41_lcs_design.md` (no peeking at RocksDB source until Phase 3):
    - D1. Why LCS has higher write amp than STCS (~35× vs ~4×)? What does the user buy (read amp, space amp)?
    - D2. Key-disjoint invariant: write the post-compaction check (sort by `first_key`, assert each `last_key < next.first_key`).
    - D3. L0 special case: why does L0 allow overlaps but L1+ don't? What's the trade?
    - D4. **Primitive property table** — enumerate `Vec<SstReader>`, `BTreeMap<first_key, SstId>`, interval-tree, sorted-`Vec`+binary-search. Columns: overlap-query cost? insert cost on level-mutate? cache-friendly? Pick one and justify.
    - D5. Manifest batching: write the `CompactionResult` record format. Why one fsync per compaction event (not per SST)?
    - D6. **Pre-mortem (load-bearing)** — write the EXACT bad trace, two of them:
      - *linear-scan*: `pick() { for sst in level.ssts { if sst.range().overlaps(target) {...} } }` → at L4, 3000 iters × 30 ns = 90 µs, holding `levels.read()` the whole time; flush thread blocks on `levels.write()`.
      - *fsync-storm*: `flush() { for sst in outputs { manifest.append(Add(sst)); manifest.fsync(); } }` → 10 outputs = 10 × 5 ms = 50 ms, and a partial-visible window between records.
    - D7. **Anti-shortcut audit** — for each motivation name the obvious reach and why it's wrong HERE:
      - "just use `Vec<SstReader>` + `.iter().filter()`" → O(N) overlap, fails the 300 ns bench at L4.
      - "fsync after every `manifest.append`" → O(SST) fsyncs, fails the one-fsync bench + opens a crash window.
      - "store outputs unsorted, sort at read time" → breaks R2; read can no longer assume ≤1 SST/level.

  #### Phase 3 — Make the tests pass, one failure at a time (~80 min)
  Ordered newbie→expert — the ladder you actually walk.

  - **(NEWBIE) When `lcs_l0_overlapping_merge_into_l1` reports only 1 L0 SST as input:**
    - Symptom: L0 has 5 overlapping SSTs; pick grabs only 1; the other 4 stay; L0 read amp grows.
    - Why: L0 special-cased wrong — L0 *allows* overlaps; treating it like L_k≥1 (which assumes disjoint) breaks the algorithm.
    - Fix: branch the picker — `if level == 0 { all overlapping L0 + the L1 SSTs in their union range } else { one L_k victim + overlapping L_(k+1) }`.
    - Cost avoided: unbounded L0 depth → linear L0 read amp (50+ SSTs scanned per read); correctness, not just speed.
    - Muscle: **L0 is structurally different from L1+; every LCS needs an explicit L0 branch.** Reapplies at: W42 TWCS active-window special case, W95 mini-db.
  - **(NEWBIE) When `lcs_key_disjoint_invariant_after_compaction` panics on `L_k overlap`:**
    - Symptom: after a compaction, two L1+ SSTs share a key range; the windows assertion fires.
    - Why: outputs were written without splitting on key boundaries / not re-sorted into the level by `first_key`, so the level index admits overlap.
    - Fix: the SstBuilder splits outputs on `target_sst_size` *and* the merge is a single sorted stream, so outputs are naturally disjoint; insert each into `index_tree` keyed by `first_key`.
    - Cost avoided: a point read now touches >1 SST/level → read-amp guarantee silently broken.
    - Muscle: **a level's index is only trustworthy if every writer preserves its sort/disjoint invariant.** Reapplies at: W42 TWCS window index, W74 matching-engine price-level book.
  - **(SENIOR) When `bench_lcs_overlap_query_under_300ns` reports ~90 µs per query:**
    - Symptom: pick's overlap check walks 3000 SSTs × ~30 ns = ~90 µs; flamegraph shows `keys_cmp` dominant; foreground writes stall on the level-snapshot lock held across the scan.
    - Why: storing `Vec<SstReader>` per level and `.iter().filter()` for overlaps is O(N) per query.
    - Fix: per-level **range-tree index** (`BTreeMap` keyed by `first_key`); `range(..end).next_back()` finds the first overlapping SST in O(log N) (~12 cmps ≈ 250 ns at N=3000), then linear-forward until `first_key > end`. Build the index on level mutation, not per query.
    - Cost avoided: **~90 µs → ~300 ns ≈ 300× speedup**; compaction CPU drops below 5%; foreground p999 write tail < 10 ms holds.
    - Muscle: **store data in the access pattern's shape — range queries demand range trees, not vectors.** Reapplies at: W42 LockManager wait-graph range search, W74 matching-engine price-tree lookups, W95 mini-db range scans across SSTs.
  - **(SENIOR) When `bench_lcs_manifest_one_fsync_per_compaction` reports fsync count == 10:**
    - Symptom: a 10-output compaction emits 10 fsyncs ≈ 50 ms; combined with 50-SST flushes (~250 ms fsync/flush) the manifest dominates ingest; ingest shows sawtooth ~50 MB/s during flush vs ~500 MB/s between.
    - Why: every output calls `manifest.append(Add)` + fsync.
    - Fix: **batch** all adds+removes into one `CompactionResult` record, one fsync covers the atomic swap. Manifest fsyncs drop from O(SSTs) to O(1)/compaction.
    - Cost avoided: **~250 ms → ~5 ms per flush ≈ 50× reduction**; ingest recovers from sawtooth to flat ~400 MB/s.
    - Muscle: **fsync *count*, not byte count, is the durability bottleneck — batch every durability fence whose contents are atomic anyway.** Reapplies at: W42 txn group commit, W74 matching-engine WAL batching, W80 ledger journal commit.
  - **(EXPERT, negative-control) When `bench_overlap_query_band_is_physical` reports median 0 ns:**
    - Symptom: the band assertion fires with `0 ns`; the optimizer dead-code-eliminated the probe because its result was unused, so the 300 ns bench was passing on *nothing*.
    - Why: no `black_box` on the result; the level may also be empty if `synth_level4_disjoint` was stubbed.
    - Fix: `black_box` the returned `Vec<SstId>`; assert `hits >= 1` in the bench (already added); seed the synth level with real disjoint ranges.
    - Cost avoided: a green-but-meaningless bench that would let a real 90 µs regression ship — the negative control is what makes the other two benches trustworthy.
    - Muscle: **every perf assertion needs a physical-band negative control, or you don't know it measures anything.** Reapplies at: W42 TWCS bench, W74 matching-engine latency bench, W95 mini-db read-amp bench.

  - *Mental model*: pick-victim chooses, every tick, *which level* most needs compaction (score = size/target) and *which SST in it* wastes the least I/O (lowest overlap ratio into the next level). It exists so compaction work goes where it pays off most, fairly across levels.
  - *Contract*:
    ```rust
    pub struct VictimPicker<'a> { levels: &'a [LevelView], sizes: &'a [AtomicU64] }
    pub struct Pick { pub level: u32, pub victim: SstId, pub targets: Vec<SstId> }
    impl<'a> VictimPicker<'a> {
        fn level_score(&self, k: u32) -> f64;          // cached size / target, one atomic load
        fn pick_victim(&self) -> Option<Pick>;         // highest score; lowest overlap; age tiebreak
    }
    ```
  - *Back-of-envelope*: 7 levels × 1000 SSTs × ~50 ns/`size()` call = **~350 µs/tick**; at 100 Hz that's ~35 ms/sec of CPU *while idle*, plus it holds the level read-lock and blocks flush. A cached `AtomicU64` per level makes a score lookup **one ~5 ns atomic load** → 7 × 5 ns = **~350 ns/tick** = ~1000× cheaper. Tiebreak by sequence number is an integer compare ≈ 1 ns.
  - **Requirements** R1..R7 — write in `crates/lsm-core/notes/41_pickvictim_design.md`:
    - R1. Per-level score = `cached_size / target`; highest score wins (with L0 trigger folded in: `max(num_l0/l0_trigger, l0_size/l0_target)`).
    - R2. **Cached per-level size** (`AtomicU64`) updated on add/remove SST; score lookup is one atomic load.
    - R3. Within candidate level, rank SSTs by overlap ratio = `overlapping_L(k+1)_bytes / victim_bytes`; pick **lowest** (least wasted I/O).
    - R4. **Tiebreak by SST age** (older sequence number first) — integer compare.
    - R5. **No `format!`/alloc** in the hot path; per-tick budget ≤ 1 ms.
    - R6. **Snapshot levels for pick→run duration** so the overlap estimate doesn't go stale against a concurrent flush.
    - R7. **Fairness floor**: if any level's score > 2.0 (severely over target), pick it regardless of L0.
  - **Design walk-through** D1..D7 — answer in the design doc:
    - D1. Score math: why a ratio (`size/target`), not absolute size?
    - D2. Cached size: where does the `AtomicU64` live? Who does `fetch_add`/`fetch_sub` (add-SST/remove-SST events)?
    - D3. Overlap ratio: write the formula. Why **lowest** (not highest)?
    - D4. Tiebreak by age: write the comparison. Why does fairness need an explicit tiebreak at all?
