- [ ] [NEW v2] **Build**: `crates/lsm-core/src/compaction/lcs.rs` — `LeveledCompactor { levels: Vec<Level>, fanout: u32 }`. Each level Lk has ~10× the size of L(k-1). (~90 min)
  - **Why**: LCS (RocksDB default) trades higher write amp for far lower space amp and bounded read amp. Each level Lk has a target size 10×L(k-1); within Lk, SSTables have non-overlapping key ranges (except L0). A read touches at most one SST per level → read amp ~= number of levels (~7 for 1TB). Compaction always picks one Lk SST and merges it into the overlapping subset of L(k+1).
  - **Read first**: RocksDB `db/compaction/leveled_compaction_picker.cc`; the "Leveled Compaction" doc on the RocksDB wiki.
  - **Design**:
    ```rust
    pub struct LeveledCompactor {
        levels: Vec<Level>,
        fanout: u32, // 10
        l0_trigger: u32, // 4: trigger L0->L1 at 4 L0 SSTs
        l1_size_target: u64, // e.g., 256 MB
    }
    pub struct Level {
        ssts: Vec<SstReader>, // sorted by first key (except L0)
    }
    ```
    **Invariants**:
    - For k ≥ 1, SSTs in Lk have non-overlapping key ranges (key-disjoint).
    - Lk target size = fanout^(k-1) * l1_size_target.
    - Compaction picks the single Lk SST with most overlap into L(k+1).
  - **Build steps**:
    1. (~20 min) Level type with key-range index for fast overlap query.
    2. (~30 min) Pick logic: L0 → L1 if ≥l0_trigger SSTs; Lk → L(k+1) if level size exceeds target.
    3. (~30 min) Run: open input + overlapping L(k+1) SSTs; merge; output multiple SSTs sized to target_sst_size.
    4. (~10 min) Verify post-condition: L(k+1) key-disjoint invariant holds.
  - **Pitfalls**:
    - *Overlap miss*: incorrect overlap detection leaves orphaned data. **Symptom**: read amp explodes (now multiple SSTs per level). **Fix**: range-tree index per level, validated post-compaction.
    - *L0 special-cased wrong*: L0 allows overlaps; treating it like Lk≥1 breaks the algorithm. **Fix**: L0 merge picks ALL overlapping L0 SSTs into L1.
    - *Output SST sizes drift*: forgetting to split output causes huge L1 files. **Symptom**: subsequent L1→L2 reads 2GB. **Fix**: target_sst_size enforced strictly; split on threshold.
  - **Test scenarios**:
    - Random workload to 100M entries; verify key-disjoint invariant at every level after compaction.
    - Read-amp probe: 1000 random reads; count SSTs touched; ≤ num_levels.
  - **Acceptance**: read amp ≤ 3; write amp ≤ 10; space amp ≤ 1.1x.

- [ ] [NEW v2] **Build**: pick-victim: pick L0 → L1 if L0 has ≥4 SSTables OR L1 size > target. For Lk→L(k+1), pick file with most overlap. (~90 min)
  - **Why**: Victim selection determines write amp. RocksDB picks based on overlap ratio (fewer overlapping L(k+1) SSTs = less merge work) and age (older first, for fairness). The "most overlap" heuristic minimizes wasted I/O — compacting a victim that overlaps many L(k+1) SSTs blows up the read set; picking one that overlaps few is cheap.
  - **Read first**: RocksDB `leveled_compaction_picker.cc::PickFileToCompact`.
  - **Build steps**:
    1. (~25 min) Per-level "needs compaction" score = level_size / level_target.
    2. (~30 min) Within candidate level, rank SSTs by overlap ratio = overlapping_L(k+1)_bytes / victim_bytes; pick lowest.
    3. (~25 min) Tiebreak by SST age (older first).
    4. (~10 min) Test: synthetic levels with crafted overlaps; verify victim choice.
  - **Pitfalls**:
    - *Always picking L0*: if L0 score is always highest, deeper levels starve. **Symptom**: data piles up at L2+ over time, read amp grows. **Fix**: rotate or weight scores so all levels get attention.
    - *Stale overlap estimate*: overlap measured against pre-compaction L(k+1); concurrent flush changes it. **Fix**: lock levels snapshot for the duration of pick→run.
- [ ] [NEW v2] **Build**: execute LCS: merge L0 files into L1; merge Lk file into overlapping L(k+1) files. (~60 min)
  - **Why**: Execute step is the I/O-heavy phase. For Lk→L(k+1) (k≥1), the workflow is: open victim SST + all overlapping L(k+1) SSTs as a merge stream; write output SSTs (sized to target); atomic manifest swap; delete inputs.
  - **Build steps**:
    1. (~20 min) Compute input set: victim + L(k+1) overlapping.
    2. (~25 min) MergeIterator over inputs; pump into chain of SstBuilders (split on target size).
    3. (~10 min) Atomic manifest update: remove inputs, add outputs.
    4. (~5 min) Verify L(k+1) key-disjoint invariant in debug builds.
  - **Pitfalls**:
    - *Output SST size drift*: forgetting to split at target_size produces giant L(k+1) files. **Fix**: SstBuilder enforces strict size cap.
    - *Manifest update partial*: removing inputs in one tx but adding outputs in another → window where data is unreachable. **Fix**: atomic record in manifest log.
