- [ ] **Build**: `crates/eth-rlp/src/lib.rs` — `Encodable` and `Decodable` traits matching alloy's signatures. (~75 min)
  - *Mental model*: RLP (Recursive Length Prefix) is Ethereum's only serialization for consensus data — every
    header, tx, receipt, and trie node is RLP. `Encodable`/`Decodable` are the two traits every type implements;
    mirroring `alloy-rlp`'s exact signatures keeps your types drop-in compatible with the ecosystem.
  - *Contract*: `Encodable` = `fn encode(&self, out: &mut dyn BufMut)` + `fn length(&self) -> usize` (encoded byte
    length, so containers can size their header without encoding twice). `Decodable` = `fn decode(buf: &mut &[u8])
    -> Result<Self, Error>` — the `&mut &[u8]` lets the decoder advance the caller's cursor past what it consumed.
  - **Expect to hit #1 — `length()` by re-encoding**: a `length()` that encodes into a scratch buffer just to call
    `.len()`. Symptom: O(2^depth) encode time — a nested header tree takes seconds, not microseconds.
    - Fix: `length()` computes the size arithmetically; every impl provides it directly, never by encoding.
    - Muscle: encoded length is a computed property, never a measured one. Reapplies at: W6 Header encode, W9
      TxEnvelope, every RLP type.
  - **Expect to hit #2 — cursor not advanced**: `decode` produces a value but never reassigns `*buf` to the unread
    remainder. Symptom: the next field re-reads the same bytes; list decode loops or returns garbage.
    - Fix: every `decode` does `*buf = &buf[consumed..]` before returning `Ok`.
    - Muscle: a decoder's job is half "produce a value", half "advance the cursor". Reapplies at: W5 Wed list
      decode, W6 tx decode, W9 envelope decode.
  - **Expect to hit #3 — generic `encode` breaks object safety**: choosing `encode<B: BufMut>(&self, out: &mut B)`
    makes `Encodable` not object-safe. Symptom: `Box<dyn Encodable>` / `&[&dyn Encodable]` fail to compile weeks
    later when a container needs them.
    - Fix: take `&mut dyn BufMut` (exactly what alloy does) — object safety beats monomorphization here.
    - Muscle: a serialization trait used polymorphically must stay object-safe. Reapplies at: W9 exec-vm host
      trait objects.

**Tuesday — `Header` + scalar encoding**

- [ ] **Build**: `crates/eth-rlp/src/header.rs` — Header { list, payload_length }. Test against ethereumjs fixtures. (~60 min)
  - *Mental model*: the RLP "header" is the 1+ byte prefix that announces string-vs-list and the payload length.
    Every encode writes a Header then the payload; every decode reads a Header first. Get this one type right and
    everything else is plumbing.
  - *Contract*: `Header { list: bool, payload_length: usize }`. `Header::decode(buf) -> Result<Header>` reads and
    validates the prefix and advances `buf` to the payload start; `header.encode(out)` writes the prefix bytes.
  - **Expect to hit #1 — the header-less single byte**: a byte value in `0x00..=0x7f` IS its own complete encoding
    — no prefix. Symptom: you encode `0x0f` as `[0x81, 0x0f]` and it mismatches `cast`/Geth; or decode reads a
    phantom header off a `0x0f` byte.
    - Fix: encode emits no header when the payload is exactly one byte `< 0x80`; decode treats a leading byte
      `< 0x80` as "the value is this byte itself".
    - Muscle: RLP has a header-less case — handle it before the short/long-form logic. Reapplies at: W6 scalar tx
      fields, W10 trie node encoding.
  - **Expect to hit #2 — the 55/56-byte boundary**: an off-by-one between `<= 55` and `< 56` used inconsistently in
    encode vs decode. Symptom: 55-byte and 56-byte payloads round-trip asymmetrically; fixtures mismatch only at
    that exact size.
    - Fix: short form for `len <= 55` (prefix `0x80+len` / `0xc0+len`), long form for `len >= 56`; unit-test
      exactly 55 and 56.
    - Muscle: every short/long split needs both boundary values tested. Reapplies at: W5 Wed length_of_length, W6
      Header, W10 HashBuilder.
  - **Expect to hit #3 — non-canonical headers accepted on decode**: decode accepts long form for a length that
    fits short form, or a length with a leading zero byte. Symptom: two distinct byte strings decode to the same
    value — a consensus-split risk; "non-canonical" fixtures pass when they must error.
    - Fix: decode rejects long form when `payload_length <= 55`, and rejects length fields with a leading zero byte.
    - Muscle: a consensus codec has exactly one valid encoding per value — decode must enforce canonicity.
      Reapplies at: W6 tx decode, W10 trie proofs.
- [ ] **Build**: `crates/eth-rlp/src/encodable.rs` — impls for u8..u64, U256, bool, slices, Vec, String, Address, B256,
  Bytes. (~75 min)
  - *Mental model*: the leaf encoders — every composite RLP type bottoms out in these primitives, so a bug here
    corrupts everything above it.
  - *Contract*: one `impl Encodable`/`Decodable` per primitive. Integers, byte slices, and `Bytes` all encode as
    RLP *strings*; `bool` is a 1-byte integer (0/1).
  - **Expect to hit #1 — integers with leading zeros / fixed width**: encoding `u64` as a fixed 8-byte big-endian
    array. Symptom: `1u64` becomes `[0x88,0,0,0,0,0,0,0,1]` instead of `[0x01]`; every integer in every header is
    wrong.
    - Fix: encode integers as the *minimal* big-endian byte slice (strip leading zero bytes), then RLP-encode that
      slice as a string.
    - Muscle: RLP integers are minimal-length big-endian — no fixed widths. Reapplies at: W6 EIP-1559 fee fields,
      W6 Header number/gas/timestamp.
  - **Expect to hit #2 — zero is the empty string**: encoding integer `0` as `[0x00]`. Symptom: mismatch with Geth
    — `0x00` is the encoding of the *byte* 0, while the *integer* 0 has no bytes.
    - Fix: integer `0` → empty byte slice → `0x80`.
    - Muscle: in RLP "zero" and "empty" are the same string; the number 0 has no bytes. Reapplies at: W6 tx
      value/nonce fields, W8 receipt status.
  - **Expect to hit #3 — byte container encoded as a list**: encoding `Vec<u8>`/`&[u8]` as an RLP *list* of
    one-byte items. Symptom: `vec![1,2,3]` becomes `[0xc3,1,2,3]` (list) not `[0x83,1,2,3]` (string).
    - Fix: `Vec<u8>`, `&[u8]`, `Bytes` are RLP strings; only `Vec<T>` for non-byte `T` is a list.
    - Muscle: byte containers are strings, typed containers are lists — the element type decides. Reapplies at: W5
      Wed Vec<T>, W6 access list, W10 trie nodes.

- [ ] **Build (W4 follow-up)**: `crates/eth-primitives/src/bytes.rs` — redesign `Bytes` for zero-copy

  - *Mental model*: two ownership stories under one `Bytes` API — `Arc<[u8]>` for cheap clones (the
    common consumer case) and a raw `(ptr, len, cap)` owner for cheap freezes (the BytesMut handoff
    case). Discriminate via a `&'static Vtable` pointer, the same way upstream `bytes::Bytes` does —
    one extra word per Bytes; drop and clone dispatch to the right deallocator/refcounter.
  - *Contract*: `Bytes { ptr: NonNull<u8>, len: usize, data: AtomicPtr<()>, vtable: &'static Vtable }`
    where `Vtable { clone: unsafe fn(&AtomicPtr<()>, *const u8, usize) -> Bytes, drop: unsafe fn(&mut
    AtomicPtr<()>, *const u8, usize) }`. Three vtables: `STATIC_VTABLE` (clone = bitwise copy, drop =
    no-op — for `from_static`); `OWNED_VTABLE` (clone = promote to shared Arc + clone, drop = dealloc
    the raw `Layout::array::<u8>(cap)` block); `SHARED_VTABLE` (clone = bump Arc refcount, drop =
    decrement). `BytesMut::freeze` mints an `OWNED_VTABLE` Bytes whose `data` holds the original `cap`
    — no copy on the freeze path.
  - **Expect to hit #1 — owned → shared promotion race**: two threads clone the same `OWNED_VTABLE`
    Bytes simultaneously; both try to swap the vtable to `SHARED_VTABLE` and install an Arc. Symptom:
    double-init of the Arc — one clone holds a dangling Arc pointer; eventually a use-after-free.
    - Fix: CAS the `data: AtomicPtr<()>` from "owned cap" to "Arc pointer"; the loser drops its
      speculative Arc and reads the winner's pointer. Same pattern as `bytes::Bytes::promote_to_shared`.
    - Muscle: any lazy upgrade from owned-to-shared must be CAS-mediated. Reapplies at: W26 WAL frame
      shared-buffer promotion, W37 skiplist node share-on-clone.
  - **Expect to hit #2 — `BytesMut::freeze` Layout mismatch on owned-vtable drop**: the owned-vtable
    `drop` must rebuild the *same* `Layout::array::<u8>(cap)` that `BytesMut::new`/`reserve` used.
    Symptom: heap corruption — miri "incorrect layout on deallocation". This is W4 Thu pitfall #1
    crossing a crate boundary, which makes the failure harder to trace.
    - Fix: `data` field carries `cap` (cast through `AtomicPtr<()>` as `cap as *mut ()`); the
      owned-vtable drop reconstructs `Layout::array::<u8>(cap)` exactly. Document in a `//!` that
      `BytesMut` and the owned vtable share a layout contract.
    - Muscle: when ownership of a raw allocation crosses a type boundary, the layout contract must
      be a single source of truth that both ends import. Reapplies at: W26 WAL segment handoff to
      reader, W38 SSTable block handoff to cache.
  - **Expect to hit #3 — `Bytes` no longer `Default` / loses derived traits**: the redesign means
    `Bytes` is no longer just `Arc<[u8]>`; `#[derive(Default, Eq, Hash, PartialEq)]` may break.
    Symptom: every downstream type that derives via Bytes (block fields, tx data, log topics)
    suddenly fails to compile. Migration must be done in one pass.
    - Fix: hand-write `Default` (returns an empty `STATIC_VTABLE` Bytes); hand-write `Eq`/`Hash`/
      `PartialEq` to delegate to `&[u8]` (via the Deref impl). Mirror `bytes::Bytes`' trait impls.
    - Muscle: redesigning a foundational type means re-paving every derived trait. Reapplies at: W6
      Header redesign, W11 type-state block.

**Friday — `RlpEncodable` / `RlpDecodable` derive macros**

- [ ] **Build**: extend `crates/eth-primitives-derive/` with `#[derive(RlpEncodable, RlpDecodable)]`. Mirror
  alloy-rlp-derive API. (~75 min)
  - *Mental model*: a proc-macro that treats a struct as an RLP *list of its fields in declaration order* —
    exactly what `alloy-rlp-derive` does, so your derived types match alloy byte-for-byte.
  - *Contract*: `#[derive(RlpEncodable)]` on `struct S { a: A, b: B }` generates `impl Encodable for S` that emits
    a list header (payload = `a.length() + b.length()`) then encodes each field; `RlpDecodable` generates the
    inverse. Built with `syn` + `quote` on the W4 scaffold.
  - **Expect to hit #1 — field order is the wire format**: the macro emits fields in source order, so a cosmetic
    struct reorder silently changes the encoding. Symptom: no compile error — only a fixture/consensus mismatch
    after someone tidies the struct.
    - Fix: generated code iterates fields in declaration order; emit a doc-comment on derived structs that field
      order is load-bearing.
    - Muscle: with derive-based serialization, struct field order IS a wire contract. Reapplies at: W6 Header and
      tx structs, W8 Receipt.
  - **Expect to hit #2 — missing the enclosing list header**: generating per-field encodes but forgetting the
    struct itself is one RLP list. Symptom: the struct decodes as N separate values; any container holding it
    mis-frames.
    - Fix: generated `encode` writes `Header { list: true, payload_length: sum }` first; generated `length()`
      includes that header.
    - Muscle: a derived struct is one RLP list, not a loose field sequence. Reapplies at: W6 all consensus structs.
  - **Expect to hit #3 — decode accepts trailing bytes**: generated `decode` reads N fields but never checks they
    exactly fill the list payload. Symptom: a struct with extra trailing bytes decodes "successfully" — malformed
    input accepted.
    - Fix: decode reads the list Header, decodes exactly N fields, then asserts the cursor reached the payload end.
    - Muscle: structural decode must consume its whole frame — trailing bytes are an error (same rule as the
      `TrailingBytes` check in `eth-network-codec`, W3). Reapplies at: W9 envelope decode.
