- [ ] Implement ecrecover precompile in `exec-vm`. Test vectors. (~120 min)
  - **Why**: ecRecover (precompile 0x01) is the EVM's only signature-verify primitive — every account abstraction (EIP-7702), every multisig, every meta-tx forwarder calls it. It's also responsible for several historical CVEs (malleability via high-s, v=0/1 acceptance bugs, secp256k1 lib bounds violations). Critical for tempo-evm-ext later: P256/WebAuthn (TIP-1020) precompile mirrors ecRecover's shape.
  - **Read first**: `revm/crates/precompile/src/secp256k1.rs`; EIP-2 (low-s requirement for transaction-sig, NOT for ecRecover); k256 crate docs (`Signature::try_from`, `RecoveryId::try_from`).
  - **Design**:
    ```rust
    pub fn ec_recover(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        const GAS_COST: u64 = 3000;
        if gas_limit < GAS_COST { return Err(PrecompileError::OutOfGas); }

        // Pad input to 128 bytes if shorter (per spec):
        let mut padded = [0u8; 128];
        padded[..input.len().min(128)].copy_from_slice(&input[..input.len().min(128)]);

        let msg: [u8; 32] = padded[0..32].try_into().unwrap();
        let v = U256::from_be_bytes::<32>(padded[32..64].try_into().unwrap());
        let r = padded[64..96];
        let s = padded[96..128];

        // v must be exactly 27 or 28 (NOT 0/1; NOT 35+chain_id)
        if v != U256::from(27) && v != U256::from(28) {
            return Ok(PrecompileOutput::new(GAS_COST, Bytes::new()));
        }
        let recovery_id = (v.as_limbs()[0] - 27) as u8;

        // r, s ∈ (0, n) where n = secp256k1 order
        let signature = match Signature::from_scalars(r, s) {
            Ok(s) => s,
            Err(_) => return Ok(PrecompileOutput::new(GAS_COST, Bytes::new())),
        };

        let recid = RecoveryId::try_from(recovery_id)
            .map_err(|_| PrecompileError::Other(...))?;
        let recovered = VerifyingKey::recover_from_prehash(&msg, &signature, recid);

        let out = match recovered {
            Ok(pk) => {
                let pk_bytes = pk.to_encoded_point(false).as_bytes()[1..].to_vec();
                let mut hash = keccak256(&pk_bytes);
                hash[..12].fill(0);  // address = last 20 bytes
                Bytes::from(hash.to_vec())
            }
            Err(_) => Bytes::new(),
        };
        Ok(PrecompileOutput::new(GAS_COST, out))
    }
    ```
    **Invariants**:
    - Gas is constant 3000, charged whether sig is valid or not.
    - On invalid sig: return empty bytes (NOT error). Caller checks `returndatasize == 0`.
    - v ∈ {27, 28} ONLY. v=0/1 (compact) rejected. v=35+ (transaction-sig with chain_id) also rejected here — only valid for tx-sigs.
    - Output is 32 bytes: 12 zero bytes + 20-byte address (= keccak256(pubkey)[12..]).
    - Input shorter than 128 bytes is right-padded with zeros (Yellow Paper §I).

  - **Pitfalls** (named, crypto-critical):
    - *v=0/1 false accept*: some impls treat v=0,1 as compact form (valid in libsecp256k1). Spec says ONLY 27, 28 here. **Symptom**: extra valid signatures → replay attacks. **Fix**: explicit `if v != 27 && v != 28 { return empty; }`.
    - *r=0 or r=n*: k256 may panic on r=0 in some versions. **Symptom**: panic mid-tx → fork. **Fix**: explicit pre-check `r != 0 && r < N && s != 0 && s < N`.
    - *Padding direction*: spec says RIGHT-pad with zeros. Some impls LEFT-pad. **Symptom**: divergent results for short inputs. **Fix**: confirm via test vector with 64-byte input → padded to 128 by appending zeros.
    - *Address derivation MSB confusion*: keccak256(pubkey)[12..32] is the address. Mistaking endianness produces wrong addresses. **Symptom**: every signature returns wrong address. **Fix**: pubkey is 64 bytes (uncompressed, NO 0x04 prefix); hash; take BYTES 12..32 (low 20).
  - **Test scenarios**:
    - Mainnet test vector: r,s,v,msg → expected_address. Differential against revm.
    - v=26 → empty. v=29 → empty. v=35 → empty.
    - r=0 → empty. r=N → empty.
    - Short input (32 bytes) → padded; deterministic empty result (msg only, rest zero).

- [ ] **Build**: `crates/p2p/src/noise.rs` — Noise_XX_25519_ChaChaPoly_BLAKE2s handshake using `snow` crate. (~total 140 min across 3 phases)
  - 🔧 **Why this matters**: Noise Protocol is THE modern authenticated encrypted transport — post-quantum-ready primitives composable into well-defined patterns (XX, IK, KK). Used by WireGuard, Lightning Network, libp2p. Noise_XX specifically: mutual authentication, mutual identity hiding until handshake completes, 1.5 round trips, perfect forward secrecy via per-session DH. Every byte after handshake feeds W56 raft, W64+ bft, W76+ aeron control plane — get the buffer-ownership story wrong here and the aeron data plane bleeds 200 MB/s on allocator churn.

  #### Phase 1 — Problem, requirements, design (~40 min, no code yet)

  - **The problem this primitive solves**: a plaintext TCP socket between peers is trivially MitM'd by any router on the path; ECDSA-only auth without forward secrecy means one compromised key retroactively breaks every captured session. Noise_XX gives mutual auth + identity hiding + per-session fresh keys in 1.5 RTT.

  - **Requirements** — write in `crates/p2p/notes/54_noise_design.md`:
    - R1. Protocol name string: `Noise_XX_25519_ChaChaPoly_BLAKE2s` — exact, byte-for-byte. Any divergence = incompatible handshake.
    - R2. Three-message XX flow: initiator→`e`; responder→`e, ee, s, es`; initiator→`s, se`. After msg 3, both sides have `TransportState`.
    - R3. Per-direction 64-bit nonce, counted from 0. Rekey-or-close at message count ≥ 2^60 (safety margin).
    - R4. Identity binding: post-handshake `state.get_remote_static()` MUST be compared against expected `PeerId` (`PeerId::from_x25519_pubkey`); mismatch → reject + close.
    - R5. Hot-path send/recv take caller-owned buffers (`&[u8]` input, `&mut [u8]` output); zero alloc per send.
    - R6. Small-message batching: framing layer above Noise coalesces N pending small msgs into a single `write_message(frame_of_N)` per tick to amortize AEAD fixed cost.
    - R7. Tamper detection: any bit flip in ciphertext → AEAD verify fails → session aborted (no half-state).
    - R8. Handshake budget: ≤ 500 µs end-to-end on LAN (3 × ~100 µs Curve25519 + ~50 µs LAN RTT × 1.5).

  - **Design walk-through** — answer each:
    - D1. Why XX and not IK (initiator-knows-responder)? Walk through identity-hiding: in XX, both static pubkeys are transmitted encrypted under the chaining hash; a passive eavesdropper sees only ephemeral pubkeys. IK reveals initiator's static immediately. When does p2p want IK vs XX? (Hint: IK requires out-of-band knowledge of responder's pubkey — fine for known-peer dialing, wrong for first-discovery.)
    - D2. Prologue: Noise binds a `prologue` byte string into the chaining hash. What goes in yours? (Hint: protocol-version + crate name + magic bytes; bake into the spec doc so all downstream consumers agree.)
    - D3. Buffer ownership: write the `send`/`recv` signatures. Why is `fn recv(&mut self, ct: &[u8]) -> Result<Vec<u8>>` the obvious-and-wrong shape? Compute the cost: at 200k msgs/s (aeron data plane), ~50 ns malloc + ~30 ns dealloc + 1 KB cold-memcpy = ~200 ns saved per call × 400k call/s ≈ 80 ms/s CPU.
    - D4. Nonce-overflow handling: at 200k msgs/s, when does the 64-bit nonce wrap? (2^64 / 200k = ~93 trillion seconds = never in practice; BUT slow attacks or pathological loops could in years. Decision: hard-rekey at 2^60.)
    - D5. AEAD fixed cost: ChaCha20-Poly1305 per-call overhead is ~200 ns (nonce + AAD + 16-byte tag setup) regardless of payload size. For a 16-byte heartbeat, fixed cost is ~95% of the work. How does the framing layer batch? (Hint: length-prefixed inner framing inside one Noise message.)
    - D6. **Pre-mortem (load-bearing)**: write the 5-step MitM scenario where an eclipse-attacker presents a valid Noise handshake but a different remote pubkey than expected. Which line in your `dial` code MUST compare and reject? If you cannot write the bad path, you don't yet understand R4.
  - **Output**: `notes/54_noise_design.md` with R1–R8 + answers to D1–D6 + the 3-message handshake diagram with key-derivation arrows.

  #### Phase 3 — Make the tests pass, one failure at a time (~70 min)

  - **When `noise_send_recv_zero_alloc` reports ~200k allocs/sec on the transport hot path:**
    - Symptom: `dhat` shows per-msg allocs in the transport hot path; `tracing-tracy` flame shows `__GI___libc_malloc` competing with `chacha20poly1305::encrypt_in_place_detached` for time; backpressure trips spuriously at high msg rates.
    - Why: a wrapper that conveniently returns `Vec<u8>` (`fn recv(&mut self, ct: &[u8]) -> Result<Vec<u8>>`) allocates per-call. At 200k msgs/s × ~1 KB ≈ 200 MB/s allocator churn.
    - Fix: caller-owned scratch: `NoiseTransport::send(&mut self, pt: &[u8], ct_out: &mut [u8]) -> Result<usize>` and `recv(&mut self, ct: &[u8], pt_out: &mut [u8]) -> Result<usize>`. Wire to a per-connection `BytesMut` ring or a pooled buffer from the W12-W14 `bufpool` crate.
    - Cost avoided: ~50 ns malloc + ~30 ns dealloc + 1 KB cold-memcpy per call ≈ ~200 ns per send+recv; at 200k/s ≈ 80 ms/s CPU + ~200 MB/s allocator pressure eliminated.
    - Muscle: every transport-layer "encode/decrypt" returns into a borrowed slice, never owns the buffer. The buffer is owned by the connection (or bufpool), the codec is borrowed. **Reapplies at**: W55 gossip publish (encode once into shared `Bytes`), W56 raft AppendEntries wire encode, W76+ aeron fragment buffer is mandatory per-session.

  - **When `noise_small_msg_batching` reports 16× per-msg cost (not 4×):**
    - Symptom: heartbeat handler CPU 4-5× the bandwidth-proportional expectation; AppendEntries-empty messages feel slow; criterion bench on 16-byte msgs shows ~250 ns/msg instead of ~50 ns amortized.
    - Why: each 16-B msg pays snow's per-call overhead: nonce increment + AAD setup + 16-byte poly1305 tag ≈ 200 ns fixed + ~50 ns/KB actual ChaCha cost. For 16 B, fixed cost is ~95% of work.
    - Fix: batch in the framing layer above Noise: coalesce N pending small msgs into a single `write_message(frame_of_N)` per tick; the receive side splits on a length-prefixed inner framing. raft batches heartbeats with pending AppendEntries; bft batches votes.
    - Cost avoided: ~200 ns fixed × (N-1) per batch ≈ 80% of crypto cost reclaimed on small-msg workloads; at 200k 64-B msgs/s without batching = 40 ms/s CPU, with N=16 batching = ~5 ms/s.
    - Muscle: AEAD has a fixed per-message cost; batch small messages or pay it. **Reapplies at**: W56 raft heartbeat/AppendEntries coalesce, W76+ aeron `BatchProcessor`, W77+ aeron multicast.

  - **When `noise_peer_id_mismatch_rejected` accepts the wrong pubkey:**
    - Symptom: handshake completes; dialer proceeds with a session bound to wrong remote; silent MitM under eclipse.
    - Why: post-handshake code calls `into_transport()` directly without `get_remote_static()` comparison against the expected PeerId.
    - Fix: dialer-side: after `is_handshake_finished()` and before `into_transport()`, `let remote_pk = state.get_remote_static()?; let actual_id = PeerId::from_x25519_pubkey(&remote_pk); if actual_id != expected_id { return Err(PeerIdMismatch) }`.
    - Muscle: cryptographic auth gives you "talking to someone who knows a key"; identity check gives you "talking to the someone you expected." Both are required. **Reapplies at**: W56 raft NodeId verification, W64+ bft validator-cert pinning.

  - **When `noise_wrong_prologue_fails` succeeds (handshake somehow completes):**
    - Symptom: handshake doesn't fail; sessions established with mismatched prologue; future protocol-version bump silently breaks compat.
    - Why: `Builder::prologue(&[])` defaulted to empty on both sides because the protocol-spec didn't pin a specific prologue.
    - Fix: bake the prologue bytes into a const `const NOISE_PROLOGUE: &[u8] = b"p2p-v1/Noise_XX_25519_ChaChaPoly_BLAKE2s"`; both initiator and responder call `Builder::prologue(NOISE_PROLOGUE)`.
    - Muscle: prologue is a versioning hook — use it for protocol-version bumps so v1 ↔ v2 mismatches fail cleanly. Reapplies at: every TLS-like handshake the codebase grows.

  - **When `noise_nonce_overflow_rekey` keeps sending past 2^60:**
    - Symptom: nonce counter reaches 2^60 and the send loop continues; eventually wraps; catastrophic AEAD failure (key+nonce reused).
    - Why: no per-session message counter; `send` blindly delegates to `snow::write_message`.
    - Fix: track `messages_sent: u64` on `NoiseTransport`; on `send`, increment and check `>= REKEY_THRESHOLD (2^60)`; return `Err(NeedsRekey)` and let the connection layer either negotiate fresh handshake or close.
    - Muscle: AEAD nonce reuse is unrecoverable — track the count proactively, never trust the lib to refuse. Reapplies at: W76+ aeron stream rekey, W66 tempo-evm-ext signed-tx envelopes.

  - **5-year failure mode** (write in `notes/54_noise_followup.md` after green): when post-quantum KEMs (Kyber, ML-KEM) become standard, the `25519` part of the protocol name swaps to a hybrid like `25519+Kyber768`. Name the migration path: how does the `protocol_name` string become a runtime negotiable parameter without invalidating cached session metadata? Cite the deprecation window required for W56 raft and W76+ aeron consumers.
  - *Back-of-envelope* (bar (c) — every byte on the consensus/aeron data plane goes through this):
    - Handshake (3 msgs, 1.5 RTT) is **once per connection**: 3 × Curve25519 DH ≈ 3 × ~100 µs (snow's pure-Rust impl) = **~300 µs**; LAN RTT ~50 µs ⇒ handshake wall-time ~150 µs + 300 µs compute = **~500 µs once**. Tolerable; cache the resulting `TransportState`.
    - Steady-state per-message AEAD (ChaCha20-Poly1305): ~1.5 GB/s on a single core (snow with `chacha20poly1305` crate). For a 1 KB consensus msg: ~700 ns encrypt + ~700 ns decrypt = **~1.4 µs round-trip crypto**. For a 64 B vote: ~150 ns encrypt. AAD + nonce framing adds ~50 ns.
    - At raft heartbeat rates (≤ 50 ms × N peers, ~200 msgs/s/peer for an 8-peer cluster) the crypto cost is ~0.1% of CPU. At aeron data-plane rates (millions of msgs/s on the hot path) it becomes the dominant cost — and that's why W76+ aeron sometimes carries an `unauthenticated` IPC option.
    - Memory: each session ≈ 200 B `TransportState` (2 ChaCha20 keys + 2 nonces + chaining hash); 1000 peers = 200 KB ≈ fits in L2 fine.

  - **Design** — Noise_XX message flow:
    ```text
    Notation:
      s, e = static, ephemeral DH keypair
      es, se, ee = DH(initiator's *_key, responder's *_key) etc.
      [...] = AEAD-encrypted under current chaining key

    Handshake (3 messages, 1.5 RTT):
      → e                     # initiator sends ephemeral pubkey (plaintext)
      ← e, ee, s, es          # responder: eph, DH(e,e), encrypted(static-pubkey), DH(eph, s)
      → s, se                 # initiator: encrypted(static-pubkey), DH(s, e)

    After handshake:
      Each side derives two CipherStates: (cs_send_init, cs_send_resp).
      Symmetric key per direction. AEAD: ChaCha20-Poly1305.
    ```
    ```rust
    use snow::{Builder, HandshakeState, TransportState};

    pub struct NoiseHandshake {
        state: HandshakeState,
        is_initiator: bool,
    }

    pub struct NoiseTransport {
        state: TransportState,
    }

    impl NoiseHandshake {
        pub fn initiator(local_static: &[u8; 32]) -> Result<Self, NoiseError> {
            let builder = Builder::new("Noise_XX_25519_ChaChaPoly_BLAKE2s".parse()?);
            let state = builder
                .local_private_key(local_static)
                .build_initiator()?;
            Ok(Self { state, is_initiator: true })
        }
        // similar for responder
    }
    ```

    - PROTOCOL NAME: `Noise_XX_25519_ChaChaPoly_BLAKE2s` — exact, byte-for-byte. ANY change here means incompatible handshake.

    - After message 3, BOTH sides have `TransportState`; from then on each `write_message`/`read_message` increments per-direction nonce.
    - Nonce is 64-bit per direction, counted from 0. After 2^64 - 1 messages, MUST rekey.
    - Static-pubkey is encrypted inside the handshake → identity hiding from passive eavesdropper.

    - *Prologue mismatch*: Noise has a `prologue` field bound into the chaining hash.    
    ```rust
    pub fn sha256_run(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        let gas_cost = 60 + 12 * ((input.len() + 31) / 32) as u64;  // EIP-198 → simple linear
        if gas_limit < gas_cost { return Err(PrecompileError::OutOfGas); }
        let hash = sha2::Sha256::digest(input);
        Ok(PrecompileOutput::new(gas_cost, Bytes::from(hash.to_vec())))
    }

    pub fn ripemd160_run(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        let gas_cost = 600 + 120 * ((input.len() + 31) / 32) as u64;
        if gas_limit < gas_cost { return Err(PrecompileError::OutOfGas); }
        let hash = ripemd::Ripemd160::digest(input);
        let mut padded = [0u8; 32];
        padded[12..].copy_from_slice(&hash);  // left-pad to 32 bytes
        Ok(PrecompileOutput::new(gas_cost, Bytes::from(padded.to_vec())))
    }

    pub fn identity_run(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        let gas_cost = 15 + 3 * ((input.len() + 31) / 32) as u64;
        if gas_limit < gas_cost { return Err(PrecompileError::OutOfGas); }
        Ok(PrecompileOutput::new(gas_cost, input.clone()))
    }
    ```
    **Invariants**:
    - All three: gas = base + per_word * word_count, where `word_count = ceil(input.len() / 32)`.
    - SHA256: base=60, per_word=12. Output 32 bytes.
    - RIPEMD160: base=600, per_word=120. Output 32 bytes (20-byte hash LEFT-padded with 12 zero bytes).
    - IDENTITY: base=15, per_word=3. Output = input byte-for-byte.
  - **Build steps**:

**Wednesday — modexp + p2p connection state machine**

- [ ] Implement modexp (using num-bigint). (~120 min)
  - **Why**: MODEXP (precompile 0x05) computes b^e mod m for arbitrary-precision integers. It's the precompile with THE MOST complex gas formula (EIP-198, refined by EIP-2565). Used heavily by RSA-signature verifiers, zkSNARK glue, and bridge contracts. The gas formula has been the source of 2 mainnet hard-fork-required fixes.
  - **Read first**: EIP-198 (original); EIP-2565 (Berlin — fixed under-pricing); `revm/crates/precompile/src/modexp.rs`.
  - **Design**:
    ```rust
    pub fn modexp_run(input: &Bytes, gas_limit: u64, spec: SpecId) -> PrecompileResult {
        // Parse: 3 lengths (32 bytes each), then b, e, m.
        let bl = U256::from_be_bytes::<32>(input.get(0..32).map(slice_to_32).unwrap_or([0; 32]));
        let el = U256::from_be_bytes::<32>(input.get(32..64).map(slice_to_32).unwrap_or([0; 32]));
        let ml = U256::from_be_bytes::<32>(input.get(64..96).map(slice_to_32).unwrap_or([0; 32]));

        // Sanity: lengths must fit in u32 (no 4GB inputs)
        let (bl, el, ml) = (bl.as_u32_checked()?, el.as_u32_checked()?, ml.as_u32_checked()?);

        // Gas formula EIP-2565:
        //   gas = max(200, (multiplication_complexity * iteration_count) / 3)
        // where:
        //   multiplication_complexity = ceil(max(b, m) / 8)^2
        //   iteration_count = max(adjusted_exp_len, 1)  -- depends on first 32 bytes of e
        let gas_cost = compute_modexp_gas(bl, el, ml, &input[96..], spec);
        if gas_limit < gas_cost { return Err(PrecompileError::OutOfGas); }

        if ml == 0 {
            // mod 0 → empty output, gas as computed
            return Ok(PrecompileOutput::new(gas_cost, Bytes::new()));
        }

        let b = BigUint::from_bytes_be(&input[96..96+bl]);
        let e = BigUint::from_bytes_be(&input[96+bl..96+bl+el]);
        let m = BigUint::from_bytes_be(&input[96+bl+el..96+bl+el+ml]);
        let result = b.modpow(&e, &m);
        let mut out = vec![0u8; ml];
        let bytes = result.to_bytes_be();
        out[ml - bytes.len()..].copy_from_slice(&bytes);  // left-pad to ml bytes
        Ok(PrecompileOutput::new(gas_cost, Bytes::from(out)))
    }
    ```
    **Invariants**:
    - Input format: 32-byte b_len ‖ 32-byte e_len ‖ 32-byte m_len ‖ b ‖ e ‖ m. Short input zero-pads.
    - mod 0 case: return empty bytes (per EIP-198 spec).
    - Output is m_len bytes long, big-endian, left-padded with zeros if result < m's max.
    - Gas pre-Berlin uses EIP-198 formula; Berlin onwards uses EIP-2565 (lower). Fork-gated.
    - Minimum gas: 200 (post-EIP-2565); 0 (pre-Berlin, with bug).
  - **Build steps** (granular):
    1. (~15 min) Add `num-bigint` and `num-traits` deps.
    2. (~20 min) Parse 3 lengths, gracefully handling short input (zero-pad).
    3. (~25 min) Implement EIP-2565 gas formula. The hard parts: `adjusted_exp_len(e_len, e_first_32_bytes)` and `multiplication_complexity_eip2565(max(b_len, m_len))`. Use rev m as ground truth — port byte-for-byte from `revm/crates/precompile/src/modexp.rs::berlin_gas_calc`.
    4. (~15 min) Mod 0 short-circuit. Return empty bytes; charge full gas.
    5. (~20 min) `BigUint::modpow` for the actual computation. Beware: `num-bigint`'s `modpow` is slow for huge exponents; for production we want montgomery; but spec-correctness is the goal here.
    6. (~25 min) Test vectors: 100+ test cases from `ethereum/tests/GeneralStateTests/stPreCompiledContracts/modexp_*`. All must match exactly (output AND gas).
  - **Pitfalls** (named, consensus-critical):
    - *Pre-EIP-2565 (pre-Berlin) gas formula*: gives different (higher) gas. Replaying old blocks under EIP-2565 = consensus fork. **Symptom**: replay diverges. **Fix**: spec.is_enabled_in(BERLIN) gates between EIP-198 and EIP-2565 paths.
    - *e_first_32_bytes when e_len > 32*: `adjusted_exp_len = 8 * (e_len - 32) + bit_length(e_first_32_bytes_as_int)`. The bit-length sub-formula has off-by-one easy to miss. **Symptom**: ±1 gas. **Fix**: use exact revm byte sequence.
    - *Lengths overflowing u32*: input claims b_len = 2^33 → arithmetic UB. **Symptom**: panic or wraparound. **Fix**: explicit `u32` cap on lengths; reject above some safe limit (e.g., 1024 bytes per input).
    - *Output length mismatch*: result bytes < m_len; if you append (right-pad) instead of left-pad, output is wrong. **Symptom**: leading zeros wrong. **Fix**: `out[m_len - bytes.len()..]`.
    - *Mod 1*: b^e mod 1 = 0. Empty bytes when m_len > 0 fails. **Fix**: output m_len zero bytes, NOT empty.
  - **Test scenarios**:
    - Standard: 2^256 mod (2^256 - 1) = 1 → output [0..0, 1].
    - Edge: m=0 → empty output, gas as computed.
    - Edge: m=1 → m_len zero bytes.
    - Big: 1024-bit RSA verify (use OpenSSL vector).
    - Pre-Berlin vs Berlin: same input → different gas.
  - **Acceptance**: passes all 100+ Ethereum test vectors; differential against revm zero divergence; gas matches across forks.
  - **Downstream**: bridge contracts and RSA-signature precompile usage in production; tempo-evm-ext doesn't add new modexp variants.

  #### Phase 1 — Problem, requirements, design (~40 min, no code yet)

  - **The problem this primitive solves**: connections have phases (TCP-up, Noise-done, gossip-registered) with phase-specific operations. A "single enum + match" approach makes invalid calls (`send_data` on Handshaking) compile fine and panic at runtime. Type-state lifts the phase into the type system: `Connection<Open>::send_message` exists, `Connection<Handshaking>::send_message` doesn't compile.

  - **Requirements** — write in `crates/p2p/notes/54_connection_design.md`:
    - R1. Five states: `Disconnected`, `Handshaking`, `Authenticated`, `Open`, `Closed`. Each is a marker type with associated `Data`.
    - R2. State transitions CONSUME `self` and PRODUCE the new typed value. No `&mut self` transitions (those allow re-entrant bugs).
    - R3. Phase-specific methods exist ONLY on the matching state: `dial` on `Disconnected`, `drive` on `Handshaking`, `send_message`/`recv_message` on `Open`, `close` on `Open` → `Closed`.
    - R4. Generic parameter `S: ConnState` stays monomorphized through the entire call graph; NO `Box<dyn ConnState>`, NO `enum AnyConnection { ... }` on the hot path.
    - R5. Active-peers storage: `HashMap<PeerId, Connection<Open>>` holds ONLY open conns; pre-Open lives in a separate `pending: HashMap<PeerId, Connection<Handshaking>>`. State transitions MOVE the value between maps.
    - R6. Cancel-safety: cancelling an `await` mid-`drive` must NOT leave Noise state half-advanced. Partial progress lives IN the `Handshaking` data, not on the await stack.
    - R7. Memory budget: `Connection<Open>` ≈ 250 B (TcpStream fd + NoiseTransport ~200 B + GossipPeerScore ~32 B); 1000 peers ≈ 250 KB; fits in L2.

    - D1. Why consume `self` on transitions (not `&mut self`)? Walk through the reentrancy bug: with `fn drive(&mut self) -> Result<()>`, the caller holds a `&mut Connection<Handshaking>` across an await; another task could call a different method on the same value while drive is suspended. Consuming `self` makes that impossible.
    - D2. Associated-type `S::Data` vs separate per-state structs: write both versions. Which one keeps `Connection<S>` as ONE struct (vs five structs)? Why does that matter for HashMap storage?
    - D3. The "hot path" — `Connection<Open>::send_message`. List the operations: nonce increment, ChaCha20 encrypt, length-prefix frame, socket write. Total ~1 µs on warm cache. How many of those are bottlenecks of the type-state pattern? (Answer: zero.)

    ```rust
    pub fn bn128_add(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        let cost = if spec >= ISTANBUL { 150 } else { 500 };  // EIP-1108
        if gas_limit < cost { return Err(OutOfGas); }
        let p1 = parse_g1(&input[0..64])?;   // (x: U256, y: U256), validated on curve
        let p2 = parse_g1(&input[64..128])?;
        let sum = p1 + p2;
        Ok(PrecompileOutput::new(cost, encode_g1(sum)))
    }

    pub fn bn128_pairing(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        if input.len() % 192 != 0 { return Err(InvalidInput); }
        let k = input.len() / 192;
        let (base, per) = if spec >= ISTANBUL { (45_000, 34_000) } else { (100_000, 80_000) };
        let cost = base + (per * k as u64);
        if gas_limit < cost { return Err(OutOfGas); }
        let pairs: Vec<(G1, G2)> = parse_pairs(input)?;
        let result = compute_pairing_product(&pairs);   // ∏ e(g1_i, g2_i) ==? 1
        let out = if result == Fq12::one() { 1u8 } else { 0u8 };
        let mut buf = [0u8; 32];
        buf[31] = out;
        Ok(PrecompileOutput::new(cost, Bytes::from(buf.to_vec())))
    }
    ```
    **Invariants**:
    - All points must be ON CURVE (y^2 = x^3 + 3 over Fq). Off-curve → reject with empty/InvalidInput.
    - G2 points are over Fq^2 (two field elements per coordinate, 128 bytes per point).
    - Pairing input must be multiple of 192 bytes (64 for G1 + 128 for G2). Otherwise reject.
    - Pairing of empty input (k=0) returns 1 (∏ over empty = identity in Fq12).
    - Istanbul (EIP-1108) reduced gas by ~75%; pre-Istanbul replay needs old constants.

Gas formula is the simplest of all precompiles: 1 gas per round.
  - **Read first**: EIP-152; RFC 7693 (BLAKE2 spec); `revm/crates/precompile/src/blake2.rs`.
  - **Design**:
    ```rust
    pub fn blake2f_run(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        if input.len() != 213 { return Err(InvalidInput); }
        let rounds = u32::from_be_bytes(input[0..4].try_into().unwrap());
        let gas_cost = rounds as u64;
        if gas_limit < gas_cost { return Err(OutOfGas); }

        let mut h: [u64; 8] = parse_8_u64_le(&input[4..68]);
        let m: [u64; 16] = parse_16_u64_le(&input[68..196]);
        let t: [u64; 2] = parse_2_u64_le(&input[196..212]);
        let f = match input[212] { 0 => false, 1 => true, _ => return Err(InvalidInput) };

        blake2_f_compress(&mut h, &m, t, f, rounds as usize);
        Ok(PrecompileOutput::new(gas_cost, encode_8_u64_le(&h)))
    }
    ```
    **Invariants**:
    - Input MUST be exactly 213 bytes (4 + 64 + 128 + 16 + 1). Other lengths reject.
    - `f` final-block flag must be exactly 0 or 1. Other values reject.
    - All multi-byte fields are LITTLE-ENDIAN (BLAKE2 convention) — unlike most EVM (big-endian).
    - Output is 64 bytes (8 × u64 little-endian).
    - Gas = `rounds` (1 per round). Stated as u32 in input — can be 0..2^32-1.
  - **Build steps**:
    1. (~15 min) Add `blake2` dep OR vendor `blake2_f_compress` from revm.
    2. (~25 min) Parse 213-byte input; strict length + f-byte validation.

    5. (~15 min) Adversarial: 212-byte input rejects; f=2 rejects; rounds=0 is valid (0 gas, h unchanged); rounds=u32::MAX (gas overflow → OOG).

    - *Big-endian byte parsing*: EVM is usually big-endian but BLAKE2 is little. Mis-parsing makes all output garbage. **Symptom**: all test vectors fail. **Fix**: explicit `from_le_bytes`.

  - **Why**: KZG point-evaluation (precompile 0x0a, EIP-4844 Cancun) is the gateway to proto-danksharding.   - **Design**:
    ```rust
    pub fn kzg_point_evaluation_run(input: &Bytes, gas_limit: u64) -> PrecompileResult {
        const GAS: u64 = 50_000;
        if gas_limit < GAS { return Err(OutOfGas); }
        if input.len() != 192 { return Err(InvalidInput); }

        let versioned_hash: &[u8; 32] = (&input[0..32]).try_into().unwrap();
        let z: &[u8; 32] = (&input[32..64]).try_into().unwrap();    // BLS field element
        let y: &[u8; 32] = (&input[64..96]).try_into().unwrap();    // BLS field element
        let commitment: &[u8; 48] = (&input[96..144]).try_into().unwrap();  // G1 point compressed
        let proof: &[u8; 48] = (&input[144..192]).try_into().unwrap();      // G1 point compressed

        // (1) versioned_hash[0] == 0x01 (current blob versioning), rest = sha256(commitment)[1..32]
        let mut expected_hash = sha256(commitment);
        expected_hash[0] = 0x01;
        if versioned_hash != &expected_hash { return Err(InvalidInput); }

        // (2) verify KZG: e(commitment - y*G1, G2) == e(proof, X*G2 - z*G2)
        let ok = KZG_SETTINGS.verify_kzg_proof(commitment, z, y, proof)
            .map_err(|_| PrecompileError::BlsKzgError)?;
        if !ok { return Err(VerificationFailed); }

        // On success: return 2 32-byte field elements (FIELD_ELEMENTS_PER_BLOB || BLS_MODULUS)
        let mut out = [0u8; 64];
        out[0..32].copy_from_slice(&FIELD_ELEMENTS_PER_BLOB.to_be_bytes_32());
        out[32..64].copy_from_slice(&BLS_MODULUS.to_be_bytes_32());
        Ok(PrecompileOutput::new(GAS, Bytes::from(out.to_vec())))
    }
    ```
    **Invariants**:
    - Input MUST be exactly 192 bytes. Other lengths reject.
    - Gas is constant 50_000 (charged whether verification succeeds or fails).
    - `versioned_hash[0]` must be 0x01 (current blob version). Future versions will update.
    - Output on success is fixed 64 bytes: FIELD_ELEMENTS_PER_BLOB (= 4096) ‖ BLS_MODULUS (~2^254).
    - Verification uses pre-loaded trusted setup (KZG_SETTINGS) — initialized once at process boot.
  - **Build steps**:
    1. (~5 min) Add `c-kzg = "1.0"` dep with `ethereum-kzg-settings` feature OR use revm's vendored kzg.
    2. (~5 min) Load trusted setup at registry init (`KzgSettings::load_trusted_setup_file()`).
    3. (~10 min) Implement function with strict 192-byte length check.
    4. (~5 min) Versioned-hash check: must be 0x01 ‖ sha256(commitment)[1..].
    5. (~5 min) Test vector: known good (commitment, proof, z, y) tuple from EIP-4844 reference; assert success and output bytes.
  - **Pitfalls**:
    - *Trusted setup not loaded at boot*: every verify call returns false silently. **Symptom**: all blob txs fail. **Fix**: panic at registry init if KZG_SETTINGS::is_loaded() == false.
    - *versioned_hash check skipped*: accepting any 32-byte hash lets attacker submit garbage commitment with matching hash. **Symptom**: silent KZG bypass. **Fix**: explicit `versioned_hash != expected → reject`.
