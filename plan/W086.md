  - *Mental model*: io_uring is "submit a standing job that keeps emitting completions." A multi-shot recv SQE armed once tells the kernel to keep writing one CQE per datagram into the completion ring, each pointing at a buffer the kernel picked from a pre-registered ring — until the buffer ring drains or you cancel. With SQPOLL, a kernel thread polls the SQ so steady-state userspace issues *zero* syscalls. The receiver's job is to drain the CQ ring and hand back buffer ids. The bytes it hands up are the *same* bytes the `FeedParser` (Thu) will borrow and the matching engine (W74) will read — one borrow, end to end.

  - *Contract* (signature-level — never the body):
    ```rust
    pub struct IoUringReceiver { /* ring, buf_ring, fd, config */ }
    pub struct ProvidedBuf<'a> { ring: &'a BufRing, buf_id: u16, len: u16 }
    impl IoUringReceiver {
        pub fn new(socket: RawFd, cfg: RingConfig) -> io::Result<Self>; // probes kernel ≥5.19
        /// Drains ready CQEs into `out`; arms multi-shot recv if not yet armed. Returns count.
        pub fn recv_batch<'a>(&'a mut self, out: &mut ArrayVec<ProvidedBuf<'a>, N>) -> io::Result<usize>;
    }
    impl AsRef<[u8]> for ProvidedBuf<'_> { /* reads through the ring, no copy */ }
    impl Drop for ProvidedBuf<'_> { /* returns buf_id to io_uring_buf_ring_add */ }
    ```
    Implements `Transport` from W85 (`recv_batch`, GAT `Frame<'a> = ProvidedBuf<'a>`).

  - *Back-of-envelope* (bar (c), measured via `latency-lab` W24): packet budget at 10M pps = **100 ns/packet** total; at 50M pps = **20 ns/packet**. `io_uring_enter` ≈ **250 ns** (syscall ~300 ns Jeff-Dean, minus a little) — so one-SQE-per-recv costs 250 ns/packet, already **2.5× over budget at 10M and 12× over at 50M** (250 ns × 50M = 12.5 s of syscall per wall-second → impossible). Multi-shot + SQPOLL drops the inner cost to a **CQ-ring read + buf recycle ≈ 5 ns/packet** → ~50× headroom. Copying the 1500 B payload = `__memcpy_avx2` at ~10 GB/s/core effective with cache pollution; 1500 B × 50M = **75 GB/s**, over L3 bandwidth and evicting the matching engine's hot state. The cliff is **250 ns syscall vs 5 ns drain = 50× per packet** and **75 GB/s copy vs 0 = the whole L3**. Record both predictions and measured deltas in the `latency-lab` HdrHistogram.

  - **Requirements** R1..R7 — write in `crates/marketdata-kernelbypass/notes/86_io_uring_design.md`:
    - R1. ONE multi-shot recv SQE per socket, armed at startup; kernel emits a CQE per datagram until `CQE_F_MORE` clears. Never one SQE per packet.
    - R2. The provided-buffer ring is the ONLY allocation source — fixed-capacity, registered at `new()`; zero allocs on the recv path.
    - R3. `ProvidedBuf::drop` returns `buf_id` to the ring (`io_uring_buf_ring_add` + advance) — RAII; never a manual "remember to free."
    - R4. Zero-copy: `ProvidedBuf<'a>` borrows into the registered buffer; `AsRef<[u8]>` reads through it. Bytes live in the ring until the `ProvidedBuf` is dropped. (This is the borrow the parser and matching intake chain onto.)
    - R5. 10M pps single-thread loss-free (loss < 0.001%).
    - R6. ≥1.5× lower CPU than epoll `recvmmsg` at 5M pps (bar-(c) anti-shortcut threshold), measured with the `latency-lab` coordinated-omission guard so the number is honest under back-pressure.
    - R7. Min kernel 5.19 (`IORING_FEAT_FAST_POLL` + `IORING_OP_RECV_MULTISHOT`); probe via `io_uring_register_probe()` at `new()`; return an `Err` (not a panic, not a silent fallback that hides the cliff) on older kernels. Document `IORING_FEAT_NODROP`.

## Wednesday — io_uring: Phase 3 (make the tests pass) + reth feature impl

- [ ] [HFT] **Build (Phase 3)**: implement `io_uring.rs` and walk the failure ladder, newbie → expert. (~115 min)

  - **(NEWBIE) When `io_uring_drop_returns_buf_to_ring` reports `buffer not returned`:**
    - Symptom: `buf_ring_available()` stays at `before - 1` after `drop(out)`; after a few hundred packets the ring hits 0 and recv stalls with `-ENOBUFS`.
    - Why: `ProvidedBuf` has no `Drop`, or `Drop` runs but never calls `io_uring_buf_ring_add` + the ring advance — the buffer id is "checked out" forever.
    - Fix: `impl Drop for ProvidedBuf` → `self.ring.add(self.buf_id); self.ring.advance(1);`. One RAII drop, no manual free path.
    - Cost avoided: ring starvation → recv stall → 100% packet loss within milliseconds; classic "leaked buffer" outage (bar (c) violation — a stalled ingress drops the whole feed → a wrong book in the venue).
    - Muscle: when the kernel hands you a borrowed slot, return it in `Drop` — never in a code path the caller must remember. Reapplies at: W89 `UmemFrame` returns to AF_XDP fill ring on drop, W90 io_uring journal write-fixed buffer release, W77 messaging-aeron term-buffer slot release, W82 MBO feed publication slot.

  - **(SENIOR) When `io_uring_multi_shot_one_sqe_per_socket` reports `submitted 100000 recv SQEs`:**
    - Symptom: assertion fails with ~one SQE per packet; bench plateaus ~4M pps; `perf` shows `io_uring_enter` at ~95% CPU.
    - Why: the recv loop is `submit recv SQE → submit() → wait CQE → read → submit recv SQE` — io_uring driven like epoll. Each cycle is one `io_uring_enter` ≈ 250 ns.
    - Fix: arm ONE `opcode::RecvMulti` SQE per socket at startup; the kernel emits a CQE per datagram with no resubmission until `CQE_F_MORE` clears; re-arm only on clear. With `IORING_SETUP_SQPOLL` the steady-state path is zero syscalls — userspace just drains the CQ ring.
    - Cost avoided: 250 ns × 50M = 12.5 s of syscall per wall-second → ~5 ns/packet CQ drain; **~50× per packet (bar (c) violation)**.
    - Muscle: io_uring's perf model is "submit a standing job that keeps emitting completions"; treating each CQE as one-shot is the foot-gun. Reapplies at: W90 io_uring journal group-commit (one fsync-link chain), W89 AF_XDP RX-ring (the ring *is* the multi-shot mechanism), W90 ledger v1.0 io_uring journal.

  - **(SENIOR) When `io_uring_zero_copy_provided_buf_points_into_ring` reports payload outside the ring:**
    - Symptom: `__memcpy_avx2` dominates the profile; the matching engine's hot state gets evicted; P99 latency balloons; the payload pointer is on the heap, not in `[lo,hi)`.
    - Why: `let buf_id = cqe.flags >> 16; let frame: Vec<u8> = ring.buf(buf_id).to_vec();` — copying out "to make ownership easier." 1500 B × 50M = 75 GB/s, AND the borrow chain into the parser is now severed (every event downstream owns/copies too).
    - Fix: `ProvidedBuf<'a> { ring: &'a BufRing, buf_id, len }`; `AsRef<[u8]>` reads through the ring; `Drop` returns the id. Document: a `ProvidedBuf<'a>` cannot outlive the next `recv_batch` for its own buffer.
    - Cost avoided: ~75 GB/s memcpy eliminated; L1/L2 footprint freed; P99 drops 5–10× because cache misses dominate the tail (bar (c) violation).
    - Muscle: in any "kernel writes into a buffer you registered" architecture, the buffer IS the data — never copy. Reapplies at: W89 `UmemFrame<'a>`, W90 io_uring write-fixed buffers, W77 aeron term-buffer slots, W82 MBO publication slots, W87 `FeedParser::Event<'a>` borrows from this very buffer.

  - **(SENIOR) When `io_uring_buffer_exhaustion_then_recovery` hangs or drops:**
    - Symptom: under a stalled consumer the ring drains, recv returns `-ENOBUFS`, and on resume packets are silently missing (CQ overflowed) OR the test deadlocks.
    - Why: CQ sized = SQ default; multi-shot can emit a burst larger than the CQ between drains, and `IORING_FEAT_NODROP` wasn't asserted, so overflow drops CQEs invisibly.
    - Fix: size CQ ≥ 2× expected drain batch; assert `IORING_FEAT_NODROP` at `new()`; on `-ENOBUFS` re-arm the multi-shot SQE once buffers return (the kernel auto-disarms on exhaustion). Back-pressure is correctness here — surface the stall, don't hide it.
    - Cost avoided: silent CQE drops = silent market-data loss = a wrong book downstream (bar (c) violation; back-pressure-as-correctness).
    - Muscle: on a bounded ring, exhaustion must be observable and recoverable, never a silent drop. Reapplies at: W89 AF_XDP fill-ring exhaustion, W77 aeron flow control, W90 ledger journal back-pressure.

  - **Expect to hit (perf) #1 — SQPOLL idle burn (bar (c) violation):**
    - Symptom: a core sits at 100% with zero traffic; cloud bill / thermal budget blown; on a thread-per-core box this steals a worker.
    - Why: `IORING_SETUP_SQPOLL` always-on; the kernel poller spins even when the SQ is empty and no traffic arrives.
    - Fix: gate SQPOLL behind `RingConfig::sqpoll` with `sq_thread_idle` so the poller sleeps after N ms idle; use cooperative `submit_and_wait` for low-rate sockets.
    - Cost avoided: one whole core (~a full hardware thread) burned at idle; on a 16-core `runtime-thread-per-core` layout that's ~6% of venue capacity gone for nothing.
    - Muscle: a polling thread without an idle backoff is a heater; always pair busy-poll with an idle timeout. Reapplies at: W85 runtime-thread-per-core busy-poll loop, W89 AF_XDP busy-poll mode, W77 aeron media-driver poll.
