## Tuesday — Design + io_uring impl

- [ ] consensus-engine cross-subsystem feature design. (~30 min)
- [ ] **Build**: `crates/marketdata-kernelbypass/src/io_uring.rs` — `IoUringReceiver` using `io_uring` crate directly.
  Submit-queue / completion-queue patterns. Multi-shot read with fixed buffers. (~150 min)
  - **Why**: io_uring is the "modern Linux" ingress path: amortizes syscall cost (one enter syscall drives many I/O ops), supports kernel-side polling (IORING_SETUP_SQPOLL), and with multi-shot recv pre-registers buffers so the kernel writes packets without a userspace round-trip per recv. For 10M+ pps, io_uring should beat epoll by 2-5× on the same hardware. Mirror upstream `tokio-uring` patterns but stay non-async (lowest latency).
  - **Read first**: io_uring kernel docs `Documentation/man/io_uring*.7`, Jens Axboe's `liburing/examples/io_uring-cp.c`, `tokio-uring/src/runtime/driver.rs`, `io_uring` Rust crate's `src/lib.rs` and `src/squeue.rs`.
  - **Design**:
    ```rust
    pub struct IoUringTransport {
        ring: IoUring,                       // SQ + CQ ring pair
        sockets: ArrayVec<RawFd, MAX_SOCKETS>,
        buf_ring: BufRingProvided,           // IORING_REGISTER_PBUF_RING
        buf_ids: ArrayVec<u16, MAX_BUFS>,
        recv_multishot_active: BitSet,       // which sockets have multi-shot recv outstanding
    }
    impl Transport for IoUringTransport {
        type Frame<'a> = ProvidedBuf<'a>;
        fn recv_batch<'a>(&'a mut self, out: &mut ArrayVec<ProvidedBuf<'a>, N>) -> usize { /*...*/ }
    }
    pub struct ProvidedBuf<'a> { ring: &'a BufRingProvided, buf_id: u16, len: u16 }
    ```
    **Invariants**: (i) one multi-shot recv per socket — kernel keeps writing CQEs until cancelled, (ii) provided-buffer ring is the ONLY allocation source — fixed at startup, (iii) `ProvidedBuf` Drop returns buffer to ring (RAII), (iv) we never copy: bytes live in registered buffer until consumed.
  - **Build steps**: 1. (~15 min) check kernel version ≥ 5.19 for IORING_FEAT_FAST_POLL + IORING_OP_RECV_MULTISHOT; document min kernel. 2. (~15 min) construct ring with `IoUring::builder().setup_sqpoll(100).setup_coop_taskrun().build(4096)`. 3. (~20 min) provided-buffer ring setup: `io_uring_register_buf_ring()` with 2048 buffers × 2KB each. 4. (~20 min) submit IORING_OP_RECV_MULTISHOT with `IOSQE_BUFFER_SELECT` per socket. 5. (~20 min) implement `recv_batch`: drain CQ, for each completion extract buf_id from `cqe.flags >> 16`, construct `ProvidedBuf`. 6. (~15 min) handle `IORING_CQE_F_MORE` flag: if absent, multishot ended (e.g., kernel paused for buffer exhaustion) — resubmit. 7. (~15 min) handle `-ENOBUFS` cqe: buffer ring empty; export counter; reprime once consumer drains. 8. (~10 min) `Drop` of ProvidedBuf returns buf_id to ring via `io_uring_buf_ring_add()`. 9. (~10 min) bench `bench_iouring` mirroring `bench_epoll` for direct comparison. 10. (~10 min) feature-gate: `#[cfg(feature = "io-uring")]`.
  - **Pitfalls**: *SQE overflow*: **Symptom**: `io_uring_submit()` fails with -EBUSY when SQ full. **Fix**: size SQ ≥ 2× CQE batch; cap pending ops; respect `IORING_FEAT_NODROP`. *Kernel-version compat*: **Symptom**: kernel 5.10 doesn't have multi-shot recv, build fails at runtime. **Fix**: probe `io_uring_register_probe()` at startup, fallback to single-shot. *Provided-buffer leak*: **Symptom**: forgot to return buf_id, ring drains to 0, no more recvs. **Fix**: RAII Drop on ProvidedBuf; assertion that buf_id <= ring_capacity. *SQPOLL CPU burn*: **Symptom**: a core stays at 100% even idle. **Fix**: `IORING_SETUP_SQPOLL` only for high-rate workloads; for low-rate use cooperative mode. *Polling vs interrupt mismatch*: **Symptom**: latency spikes when NIC RX coalescing is high. **Fix**: tune `ethtool -C ifname rx-usecs 0`; or use AF_XDP for true poll-mode.
  - **Test scenarios**: 10M pps synthetic UDP → recv loss <0.001%; compare CPU% epoll vs io_uring at same pps target; deliberate exhaust provided-buffers (consumer pauses 100ms) → recover within 1ms after consumer resumes; kernel-version probe rejects build cleanly on <5.19.
  - **Acceptance**: 10M pps single-thread loss-free; 2-5× lower CPU% than epoll at 5M pps; bench file committed.
  - **Downstream**: feed_handler.rs (W87) treats this as preferred Transport on Linux; ledger v1.0 io_uring journal (W90) reuses ring-construction patterns.

## Saturday — Submit + marketdata: parser scaffold

- [ ] Submit Reth feature PR. (~30 min)
- [ ] **Build**: `crates/marketdata-kernelbypass/src/parse.rs` — generic `FeedParser` trait. Two reference impls:
  `ItchParser` (NASDAQ ITCH 5.0 subset), `FixParser` (FIX 4.4 binary subset). (~105 min)
  - **Why**: ingress bytes are useless without protocol decoding. ITCH and FIX are the two dominant real-world wire formats — ITCH for US equities/futures direct feeds (NASDAQ ITCH 5.0, ICE iMpact, CME MDP); FIX for FX/cross-asset (FIX 4.4 binary, FAST). Building both forces the parser interface to generalize past one format's idioms and lets matching-engine ingest either in W87.
  - **Read first**: NASDAQ ITCH 5.0 spec (publicly available PDF), FIX 4.4 binary spec + FIX/FAST encoding, `openitch-cpp` reference parser.
  - **Design**:
    ```rust
    pub trait FeedParser: Send {
        type Event<'a> where Self: 'a;          // GAT: zero-copy borrow from input
        type Err: Send + 'static;
        fn parse<'a>(&mut self, bytes: &'a [u8]) -> Result<(usize, Self::Event<'a>), Self::Err>;
        //                                                 ^bytes_consumed
    }
    pub struct ItchParser { state: ItchState }
    pub enum ItchEvent<'a> {
        SystemEvent(SystemEvent),
        StockDirectory(StockDirectory<'a>),
        AddOrder { ts_ns: u64, side: Side, qty: u32, sym: &'a [u8; 8], price: u32 },
        ExecOrder { /*...*/ },
        // 12-15 message types in the subset
    }
    pub struct FixParser { dict: Arc<FixDict> }
    pub enum FixEvent<'a> { MarketDataSnapshot { /*...*/ }, NewOrderSingle { /*...*/ }, /*...*/ }
    ```
    **Invariants**: (i) parse is zero-copy where possible — symbols/ids borrow from `bytes`, (ii) `bytes_consumed` returned so caller can advance buffer over multi-message frames, (iii) on parse error, parser internal state is "resettable" — call `reset()` to recover at next frame boundary, (iv) all numeric fields use fixed-precision integers (no float).
  - **Build steps**: 1. (~10 min) define `FeedParser` trait + GAT + error enum. 2. (~20 min) ITCH 5.0 subset enumeration: SystemEvent (4 bytes), AddOrder (40), AddOrderMPID (44), OrderExec (36), OrderCancel (28), OrderDelete (24), Trade (44), CrossTrade (40) — pick 8 core messages. 3. (~25 min) implement `ItchParser::parse` — read 2-byte length prefix + 1-byte type + dispatch. Use `byteorder::BigEndian` (ITCH is big-endian). 4. (~20 min) ITCH timestamp decoding (6-byte nanos-since-midnight) + symbol fields (8-byte right-padded ASCII). 5. (~15 min) `FixParser` skeleton with SOH-delimited tag=value pairs (FIX 4.4 tag dict subset: 35, 49, 56, 34, 52, 11, 38, 44, 54, 60, etc.). 6. (~10 min) FIX checksum verification (tag 10). 7. (~5 min) unit tests for one of each message type.
  - **Pitfalls**: *Big- vs little-endian mix-up*: **Symptom**: prices look like garbage. **Fix**: ITCH = big-endian always; const generic assert in build. *Symbol-padding semantics*: **Symptom**: "AAPL    " (trailing spaces) doesn't match "AAPL". **Fix**: store as `[u8; 8]` raw, trim only at display. *FIX SOH inside message*: **Symptom**: SOH (\x01) appears in repeating-group field. **Fix**: respect declared body length (tag 9) — don't scan for SOH. *Multi-message frame boundary*: **Symptom**: UDP datagram contains 3 ITCH messages, parser stops at first. **Fix**: caller loops while `bytes_consumed < bytes.len()`. *State leak between frames*: **Symptom**: error mid-parse leaves dictionary in inconsistent state. **Fix**: `reset()` clears in-progress allocations; FIX parser is stateless per message anyway. *Allocation in parse*: **Symptom**: dhat shows allocs in hot path. **Fix**: store decoded events as enum variants with `Copy`/borrowed fields; never `String::from`.
  - **Test scenarios**: parse golden ITCH capture (a recorded NASDAQ session file, public) — count of each message type matches reference; FIX golden capture from `fixtures/`; fuzz with arbitrary bytes → no panics, no reads past `bytes.len()`; multi-message frame: 3 events in one buffer, parser yields exactly 3.
  - **Acceptance**: parse 100M ITCH messages from capture file with 0 errors; allocator-free per-message; bench shows ≥30M msg/s single-thread.
  - **Downstream**: W87 Tuesday feed_handler.rs wires Transport→FeedParser→messaging-aeron Publication; matching-engine v1.5 (already shipped W82) consumes parsed events via the publication.
