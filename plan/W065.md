- [ ] [HFT] **Build**: `crates/matching-engine/src/shard.rs` —
  `SymbolShard { book: OrderBook, wal: wal::Wal, event_tx: broadcast::Sender<MatchEvent> }`.
  `Engine { shards: HashMap<Symbol, Arc<Mutex<SymbolShard>>> }`. (~150 min)
  - **Why (MAX DETAIL — concurrency)**: Multi-symbol is where the engine actually scales — single-symbol bench numbers are nice but production has 1000s of symbols. With runtime-thread-per-core v0.5 shipped (W60), we PIN each symbol-shard to a core, no locks needed within a shard. Inheritance: matching-engine reuses runtime's cross_shard, NUMA, det_test.
  - **Read first**: LMAX Disruptor single-writer principle; CME Globex's per-product sharding; runtime W60 cross_shard channel.
  - **Design**:
    ```rust
    pub struct SymbolShard {
        pub symbol: Symbol,
        pub book: OrderBook,
        pub event_log: EventLog,
        pub event_tx: tokio::sync::broadcast::Sender<MatchEvent>,
        pub risk: Box<dyn RiskCheck>,
        pub seq: u64,
    }

    pub struct Engine {
        pub shards: Arc<[Arc<RwLock<SymbolShard>>]>,  // size = num_shards (NOT num_symbols)
        pub symbol_to_shard: ahash::AHashMap<Symbol, usize>,
        pub runtime: Arc<runtime_thread_per_core::Runtime>,
    }

    impl Engine {
        pub fn route(&self, symbol: &Symbol) -> usize {
            *self.symbol_to_shard.get(symbol).unwrap_or_else(|| {
                // Hash routing: shard_id = hash(symbol) mod num_shards
                let h = ahash::RandomState::new().hash_one(symbol);
                &((h as usize) % self.shards.len())
            })
        }

        pub fn submit(&self, order: Order) -> Result<(), _> {
            let shard_id = self.route(&order.symbol);
            // Cross-shard via runtime: send to shard_id's mailbox
            self.runtime.submit_to(ShardId(shard_id), Box::new(move || {
                let shard = self.shards[shard_id].write();
                shard.process(order);
            }));
            Ok(())
        }
    }
    ```
    **Invariants**:
    - Per-symbol single-writer: only the owning shard processes any order for that symbol. No cross-shard locking on the book.
    - Symbol-to-shard mapping is STABLE — moving a symbol to another shard requires drain + transfer (rebalance).
    - Engine.shards length = num_shards (typically = num_cores or num_NUMA_local_cores), NOT num_symbols.
    - Cross-shard concerns: per-account risk (cross-margin across symbols) handled by separate risk shard (W90+ ledger integration).
  - **Build steps** (granular):
    1. (~25 min) SymbolShard with book + event log + risk per shard.
    2. (~30 min) Engine with symbol_to_shard routing.
    3. (~25 min) Runtime integration: each shard runs as a runtime task pinned to a core.
    4. (~30 min) Submit path: hash-route → submit_to shard's mailbox → shard dequeues → process.
    5. (~20 min) Cancel path: same routing (cancel for OrderId requires knowing its symbol — embed symbol in OrderId's reserved bits, OR maintain global OrderId → shard map).
    6. (~20 min) Tests: 16 symbols across 8 shards, 100k orders/symbol; verify all process correctly; throughput scales linearly with shard count.
  - **Pitfalls** (named, concurrency-critical):
    - *Symbol rebalance during live trading*: moving symbol X from shard 3 to shard 5 mid-trading: in-flight orders for X arrive at shard 3 → stale. **Symptom**: orders lost or processed against wrong book version. **Fix v0.5**: rebalance offline only (stop, persist, resume on new shard). **Fix v1**: drain protocol with epoch markers (W74+).
    - *Cross-symbol cross-margin requires cross-shard*: account A long BTC on shard 3, short ETH on shard 7 → which shard checks margin? **Fix**: dedicated risk-shard (separate process) computes cross-margin from event broadcast; either approves order pre-trade OR liquidates post-fill. v0.5: per-symbol margin only.
    - *Hot symbol overloads shard*: BTC-USDT routes to shard 5; 80% of volume goes through shard 5. **Symptom**: shard 5 saturates, others idle. **Fix v0.5**: manual override of routing for hot symbols (split BTC-USDT into BTC-USDT.0 and BTC-USDT.1, pre-shard). **Fix v1**: dynamic resharding (W74+).
    - *Lock contention via RwLock*: even with single-writer per shard, RwLock around SymbolShard introduces atomic-cmpxchg per access. **Fix**: shard owned by ONE task at a time; no Arc<RwLock<_>> needed if runtime guarantees single-execution-per-shard.
  - **Test scenarios**:
    - 16 symbols × 100k orders/symbol across 8 shards: linear scaling vs 1-shard baseline.
    - Skewed: 80% volume to one symbol; verify others not blocked.
    - Cross-symbol cancel: cancel order across many symbols; verify each routes to correct shard.
  - **Acceptance**: 8-shard throughput ≥ 6× single-shard (linear scaling within shadowing of contention).
  - **Downstream**: W66 perpetuals layer is per-symbol (no cross-shard impact); W90+ ledger handles cross-symbol via separate process.

**Wednesday — Proposal draft + consensus-bft prevote**

- [ ] **Build**: `crates/consensus-bft/src/prevote.rs` — prevote phase. 2f+1 prevotes for a value advance the validator
  to precommit. (~150 min)
  - **Why**: Prevote is the first vote phase. Validators announce their PROVISIONAL choice. Collecting 2f+1 same-value prevotes locks the validator on that value for the round.
  - **Design**:
    ```rust
    pub struct Prevote {
        pub height: u64,
        pub round: u32,
        pub value_hash: Option<Hash>,  // None = nil
        pub validator: NodeId,
        pub signature: Signature,
    }

    impl BftState {
        pub fn handle_prevote(&mut self, pv: Prevote) -> Result<(), _> {
            if pv.height != self.height { return Err(WrongHeight); }
            // Detect equivocation: same (height, round, validator) but different value
            if let Some(existing) = self.votes.find_prevote(pv.height, pv.round, pv.validator) {
                if existing.value_hash != pv.value_hash {
                    self.evidence.add_equivocation(pv.validator, existing, pv.clone());
                }
            }
            self.votes.add_prevote(pv.clone());

            // Check thresholds
            let total = self.validators.len();
            let threshold = 2 * (total / 3) + 1;  // 2f+1 where f = floor((N-1)/3)
            if let Some(value) = self.votes.has_2f1_prevotes_for_value(pv.height, pv.round) {
                // 2f+1 prevotes for a value → enter precommit with value
                self.valid_value = Some(value);
                self.valid_round = Some(pv.round);
                if self.step == Step::Prevote {
                    self.cast_precommit(Some(value));
                    self.step = Step::Precommit;
                }
            } else if self.votes.count_prevotes(pv.height, pv.round) >= threshold {
                // 2f+1 prevotes total, but no single value has majority → precommit nil
                self.cast_precommit(None);
                self.step = Step::Precommit;
            }
            Ok(())
        }
    }
    ```
    **Invariants**:
    - 2f+1 prevotes for SAME value V at round R → validator updates valid_value to V (Tendermint Annex A).
    - 2f+1 prevotes total (any mix of values + nil) without single-value majority → precommit nil.
    - Equivocation (two prevotes from same validator at same height/round) recorded as evidence.
  - **Build steps**:
    1. (~25 min) Prevote type with sig.
    2. (~25 min) VoteSet: per (h, r, step), bucket by validator; track total + per-value counts.
    3. (~30 min) handle_prevote with equivocation detection + threshold checks.
    4. (~30 min) Advance to precommit on 2f+1.
    5. (~25 min) Tests: 4-node, valid prevote round → all 4 precommit; 1 Byzantine prevotes nil → 3 honest still precommit value.
    6. (~15 min) Equivocation test: Byzantine sends two prevotes same (h,r); evidence captured.
  - **Pitfalls**: equivocation hash-based dedup must verify sig before adding; spoofed prevotes from non-validator must reject.
  - **Acceptance**: 4-node 1-Byzantine BFT simulation: commit per height in expected time.
  - **Downstream**: Sat precommit; W68 v0.5 ship.

- [ ] Storage or evm. (~30 min)
- [ ] **Build**: `crates/consensus-bft/src/precommit.rs` — precommit phase. 2f+1 precommits commits the block. (~150 min)
  - **Why**: Precommit is the binding vote — 2f+1 precommits = COMMIT. The validator's lock state updates here; locked_value/locked_round used in subsequent rounds.
  - **Design**:
    ```rust
    pub struct Precommit {
        pub height: u64,
        pub round: u32,
        pub value_hash: Option<Hash>,
        pub validator: NodeId,
        pub signature: Signature,
    }

    impl BftState {
        pub fn handle_precommit(&mut self, pc: Precommit) -> Result<(), _> {
            if pc.height != self.height { return Err(WrongHeight); }
            // Equivocation detection (same as prevote)
            if let Some(existing) = self.votes.find_precommit(pc.height, pc.round, pc.validator) {
                if existing.value_hash != pc.value_hash {
                    self.evidence.add_equivocation(pc.validator, existing, pc.clone());
                }
            }
            self.votes.add_precommit(pc.clone());

            // 2f+1 precommits for same value → COMMIT
            if let Some(value) = self.votes.has_2f1_precommits_for_value(pc.height, pc.round) {
                self.commit_block(value);
                self.height += 1;
                self.round = 0;
                self.step = Step::Propose;
                self.locked_value = None;
                self.locked_round = None;
                self.on_enter_propose();
                return Ok(());
            }
            // 2f+1 total precommits (mix) → advance round
            let threshold = 2 * (self.validators.len() / 3) + 1;
            if self.votes.count_precommits(pc.height, pc.round) >= threshold && self.step == Step::Precommit {
                // Set timer; on timeout, advance round
                self.set_timer(Step::Propose, self.precommit_timeout);
            }
            Ok(())
        }

        pub fn lock(&mut self, value: Hash, round: u32) {
            self.locked_value = Some(value);
            self.locked_round = Some(round);
        }
    }
    ```
    **Invariants**:
    - On 2f+1 precommits for V → COMMIT V, advance height. Locked state reset.
    - When validator casts precommit V (not nil), it sets locked_value = V, locked_round = round.
    - Subsequent rounds: validator prevotes for locked_value unless valid_round rule allows release.
  - **Build steps**:
    1. (~30 min) Precommit type + sig.
    2. (~30 min) handle_precommit with commit check.
    3. (~30 min) lock/unlock transitions.
    4. (~30 min) Tests: 4-node, all precommit V → commit V. 3 precommit V, 1 precommit nil → still commit (3 ≥ 2f+1).
    5. (~30 min) Round-advance test: 4-node, 2 precommit V, 2 precommit nil → no commit; round advances; new proposer.
  - **Pitfalls** (named):
    - *Commit on 2f+1 ANY (not same value)*: 2 commit V, 2 commit V' → no commit; advance round. **Symptom**: false commit. **Fix**: explicit same-value check.
    - *Lock-release missed*: validator stays locked on stale value through many rounds. **Symptom**: liveness loss. **Fix**: valid_round mechanism releases lock when newer round shows 2f+1 prevotes for new value.
    - *Lock not set on precommit*: validator precommits V but doesn't lock → can precommit V' next round → safety violation. **Symptom**: 2 validators commit different values. **Fix**: lock-set is atomic with precommit-cast.
  - **Acceptance**: 4-node 1-Byzantine BFT runs 10 heights without safety violation; commits average ≤ 2 rounds.
  - **Downstream**: W68 v0.5 ship; W73 v1.0 includes HotStuff-style linearity.
