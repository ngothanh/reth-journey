    ```rust
    struct SignedFrac { num: i128, denom: i128 }      // explicit denom; denom typically 1_000_000 (bps×1e6)
    impl SignedFrac { fn mul(self, x: i128) -> i128;  fn checked_mul(self, x: i128) -> Option<i128>; }
    struct LinearContract {
        symbol: Symbol, mark_price: i64, index_price: i64,
        funding_rate: SignedFrac, funding_interval: u64, next_funding_at: u64,
        open_interest: u64, tick_size: i64, contract_size: i64, max_leverage: u32,
        initial_margin_ratio: SignedFrac, maintenance_margin_ratio: SignedFrac,
    }                                                  // ≤ 2 cache lines (~128 B)
    struct Position { account: AccountId, symbol: Symbol, size: i64, entry_price: i64,
                      margin: u64, funding_paid_cum: i128 }   // signed size: +long / -short
    impl LinearContract {
        fn clamp_mark(&self, book_mid: i64) -> i64;            // clamp(book_mid, index ± max_basis)
        fn funding_rate_from(&self, mark: i64, index: i64) -> SignedFrac;  // clamped premium, pro-rated
        fn apply_funding(&self, pos: &mut Position);           // who-pays-whom by sign
        fn update_oi(&mut self, maker_opening: bool, taker_opening: bool, qty: u64); // 4-case truth table
    }
    ```

OI update target ≤ **5 ns** = one `u64` add on an already-warm cache line (an L1 hit is 0.5 ns; a HashMap lookup is a hash + ≥1 random L2/L3 fetch ≈ 7-70 ns — **the cliff is 5 ns warm-field vs ~50 ns map = 10×**). Mark clamp target ≤ **3 ns** = two integer compares (branch ~0.5 ns each, predicted). `f64::div` ≈ 10-30 cycles ≈ 3-10 ns vs `i64::div` ≈ 3-5 cycles ≈ 1-1.5 ns; at thousands of ops/fill the float tax is 50-200 ns = **5-20% of the entire fill budget** — before counting the determinism violation.

    - Why: sign confusion in `payment = size * mark * rate`. For longs (`size>0`, `rate>0`) payment>0 = they pay; for shorts (`size<0`) payment<0 = they receive — easy to flip.

  - *Contract* (signatures only — never the body):
    ```rust
    enum MarginMode { Isolated, Cross }
    struct Account { positions: [Option<Position>; N_MAX /*32*/], pooled_collateral: u64 }
    fn initial_margin(notional: i64, leverage: u32) -> i64;                 // notional / leverage
    fn maintenance_margin(notional: i64, c: &LinearContract) -> i64;        // tiered lookup
    fn margin_ratio(pos: &Position, c: &LinearContract, available_collateral: i64) -> SignedFrac;
    fn should_liquidate(pos: &Position, c: &LinearContract, mode: MarginMode, acct: &Account) -> bool;
    impl Account { fn sum_equity(&self, contracts: &Contracts) -> i64; }    // walks the contiguous array
    ```
  - *Back-of-envelope* (bar (c) — order-submit path, ≤ 500 ns p99 budget): the cross-margin sum walks all positions. `Vec<Box<Position>>` = 10 pointer-chases to scattered heap = 10 random L2/L3/mem fetches ≈ 70 ns warm, **~1 µs cold** (account idle for seconds — the COMMON case). A `[Option<Position>; 32]` = 32 contiguous lines = 2 KiB, one prefetch chain: ~32 × 5 ns = 160 ns warm; the first miss (~70-100 ns) is amortized by the hardware prefetcher across the rest. **The cliff is ~1 µs (Box) vs ~160-300 ns (array) = 3-6× on the cold path.** Tier lookup over 6 entries = linear scan ≈ 10 ns L1 (branch-predictor friendly). One `i64` divide for IM ≈ 3-5 cycles.
