- [ ] [HFT] **Build**: `crates/matching-engine/src/perps/contract.rs` —
  `LinearContract { mark_price, index_price, funding_rate, open_interest }` per TigerBeetle-style determinism. (~150 min)
  - **Why (MAX DETAIL — derivatives internals)**: Perpetual futures (perps) are the volume leader on crypto exchanges (Binance/Bybit/dYdX). Linear contracts: PnL settles in quote currency. Index price = external oracle (FTX-style TWAP). Mark price = blend of index + book mid-price (anti-manipulation). Funding rate = periodic payment longs↔shorts to anchor mark to index. Open interest = total outstanding notional. Determinism via TigerBeetle-style ledger semantics: every action emits an event; replay reconstructs.
  - **Read first**: dYdX V4 contract spec; Binance perpetual contract docs; "Perpetual Swap Pricing" papers; TigerBeetle's ledger semantics.
  - **Design**:
    ```rust
    pub struct LinearContract {
        pub symbol: Symbol,
        pub mark_price: Price,           // current "true" price for liquidation/funding
        pub index_price: Price,          // from external oracle
        pub funding_rate: SignedFrac,    // per-funding-interval rate (e.g., 8 hours)
        pub funding_interval: Duration,  // typically 8 hours
        pub next_funding_at: Monotonic,
        pub open_interest: u64,          // total long qty (= total short qty)
        pub tick_size: Price,
        pub contract_size: u64,
        pub max_leverage: u32,
        pub initial_margin_ratio: SignedFrac,   // e.g., 0.05 (20× leverage)
        pub maintenance_margin_ratio: SignedFrac, // e.g., 0.025
    }

    pub struct Position {
        pub account: AccountId,
        pub symbol: Symbol,
        pub size: i64,                   // positive = long, negative = short, units = contract_size
        pub entry_price: Price,
        pub margin: u64,                 // collateral allocated
        pub funding_paid_cum: SignedQty, // cumulative funding payments
    }
    ```
    **Invariants**:
    - Σ size across all positions for a contract = 0 (longs = shorts).
    - mark_price = clamp(book_mid, index ± max_basis); where max_basis = 0.5%.
    - funding_rate computed from premium = (mark - index) / index; clamped to ±0.75%.
    - Open interest only increases on new-position trades (not in-position offset).
    - All fields integer (no f64).
  - **Build steps** (granular):
    1. (~25 min) LinearContract + Position types.
    2. (~30 min) mark_price calc: clamp book mid to [index*(1-0.005), index*(1+0.005)].
    3. (~30 min) funding_rate calc: `rate = clamp(premium, -0.75%, 0.75%) * (1/8 hr / funding_interval)`.
    4. (~30 min) Apply funding: every funding_interval, for each position: payment = position.size * mark * funding_rate; longs pay if rate > 0.
    5. (~20 min) Open interest update: post-fill, if both maker and taker are opening (not offsetting), OI += fill_qty.
    6. (~15 min) Tests: long pays short when premium positive; OI invariant Σ size = 0.
  - **Pitfalls** (named, derivatives-critical):
    - *Mark-price manipulation*: attacker thin-books to push mark away from index → triggers cascade liquidations. **Symptom**: liquidation cascade event (LUNA, FTX scenarios). **Fix**: clamp to index ± 0.5%; use multi-exchange index TWAP.
    - *Funding rate sign error*: premium > 0 → longs pay shorts (not reverse). **Symptom**: arbitrage opportunity; OI drains. **Fix**: explicit unit test on sign.
    - *Open interest drift*: closing trades wrongly increment OI. **Symptom**: OI inflates without real position growth. **Fix**: pre-trade, check both sides' position direction; OI += only if NEW exposure.
    - *Funding-payment + position-close race*: position closes during funding tick → who owns the payment? **Fix**: funding applies to positions OPEN AT funding_at moment, not post-close.
    - *Cross-margin contagion*: positions in different symbols share margin; liquidation of one cascades. **Fix**: portfolio-margin logic in W74+ ledger.
  - **Test scenarios**:
    - Premium positive: long position pays short; balances move correctly.
    - Funding tick during open position: balance debited by exact amount.
    - OI conservation: 1000 trades, sum of long sizes = sum of short sizes.
    - Mark-price clamp: book pushes mid +5%, mark clamps at +0.5% above index.
  - **Acceptance**: 1k random trades + funding ticks → ledger balances correct (Σ = 0); OI consistent.
  - **Downstream**: W74+ matching v1.0 integrates margin checks pre-trade; W90+ ledger applies funding settlements.

**Wednesday — Continue + [HFT] perpetuals margin**

- [ ] Reth feature. (~30 min)
- [ ] [HFT] **Build**: `crates/matching-engine/src/perps/margin.rs` — initial-margin / maintenance-margin formulas.
  Cross vs isolated. (~150 min)
  - **Why**: Margin determines WHO can take a position and WHEN they get liquidated. Get margin formulas wrong → exchange eats the loss on liquidation underwater. Standard formulas: initial_margin (open) and maintenance_margin (liquidate threshold), with cross-margin (account collateral pooled) vs isolated-margin (per-position collateral).
  - **Design**:
    ```rust
    pub enum MarginMode {
        Isolated,    // collateral assigned to this position only
        Cross,       // collateral pooled across all positions
    }

    pub fn initial_margin(notional: u64, leverage: u32) -> u64 {
        // initial_margin_ratio = 1 / leverage
        // e.g., 10× leverage → 10% IM
        notional / (leverage as u64)
    }

    pub fn maintenance_margin(notional: u64, contract: &LinearContract) -> u64 {
        // Tiered: MM% rises with position size to prevent gaming
        let tier_mmr = lookup_mm_tier(notional, &contract.mm_tiers);
        (notional * tier_mmr.numer) / tier_mmr.denom
    }

    pub fn margin_ratio(position: &Position, contract: &LinearContract, available_collateral: u64) -> SignedFrac {
        let notional = (position.size.unsigned_abs() as u64) * contract.mark_price.0;
        let unrealized_pnl = compute_unrealized(position, contract.mark_price);
        let equity = position.margin as i64 + unrealized_pnl + available_collateral as i64;
        // margin_ratio = equity / maintenance_margin
        SignedFrac::ratio(equity, maintenance_margin(notional, contract) as i64)
    }

    pub fn should_liquidate(position: &Position, contract: &LinearContract, mode: MarginMode, account_balance: u64) -> bool {
        match mode {
            MarginMode::Isolated => margin_ratio(position, contract, 0).lt(SignedFrac::ONE),
            MarginMode::Cross => margin_ratio(position, contract, account_balance).lt(SignedFrac::ONE),
        }
    }
    ```
    **Invariants**:
    - initial_margin > maintenance_margin always (gives room for adverse move before liquidation).
    - Tiered MM rates: larger positions → higher MM (e.g., < $50k: 0.4%, $50k-$250k: 0.5%, etc.). Prevents whales from holding massive thin-margin positions.
    - Liquidation triggers at maintenance_margin breach; position closed at MARK price (not last-trade).
  - **Build steps**:
    1. (~30 min) Initial-margin formula.
    2. (~30 min) Maintenance-margin tier table + lookup.
    3. (~30 min) margin_ratio for cross + isolated.
    4. (~30 min) should_liquidate predicate.
    5. (~20 min) Tests: position at 10× leverage with 10% adverse move → maintenance breach → liquidate.
    6. (~10 min) Cross-margin: account with 2 positions, 1 underwater + 1 profitable → cross saves it; isolated triggers liquidation of the underwater.
  - **Pitfalls**: liquidation price uses MARK not last-trade (anti-manipulation); during high vol, mark price clamping (W66 Tue) protects against false liquidations.
  - **Acceptance**: tier table matches Binance reference; isolated vs cross behavior different on multi-position accounts.
  - **Downstream**: W74+ matching v1.0 pre-trade margin check; W90+ ledger updates margin atomically with fills.

- [ ] [Tempo] 3 hrs split across the day: **`tempo-tx-envelope` v0.1.0 build**. Mirror `tempoxyz/tempo`'s primitives
  crate. Define `TempoTransaction` (EIP-2718 type 0x76) struct with fields: chain_id, nonce, max_fee_per_gas,
  max_priority_fee_per_gas, gas, calls: Vec<Call>, fee_token: Address, valid_before: Option<NonZeroU64>, valid_after:
  Option<NonZeroU64>, auth: Authorization. Use eth-rlp derive (W5). Reuse eth-primitives types. valid_before/valid_after
  timestamps source from `time::HybridLogicalClock`. (~180 min)
  - **Why**: EIP-2718 typed transactions are the framework Ethereum uses to introduce new tx types (0x01 = access-list, 0x02 = EIP-1559, 0x03 = blob, 0x04 = EIP-7702). Tempo's 0x76 envelope extends this — multiple Calls per tx (batched UX), fee_token (pay gas in any ERC-20), validity windows, and authorization (delegation). Designing a custom tx-type requires precise RLP layout AND careful EIP-2930 access-list compatibility.
  - **Read first**:
    - EIP-2718 spec (typed-tx framework)
    - EIP-1559 (max_fee + priority_fee model)
    - EIP-7702 (set-code authorizations)
    - tempoxyz/tempo source (for the actual 0x76 layout)
    - alloy-rs `crates/consensus/src/transaction/eip*.rs` (production typed-tx impls)
  - **Design**:
    ```rust
    #[derive(Clone, Debug, RlpEncodable, RlpDecodable)]
    pub struct TempoTransaction {
        pub chain_id: u64,
        pub nonce: u64,
        pub max_fee_per_gas: U256,
        pub max_priority_fee_per_gas: U256,
        pub gas: u64,
        pub calls: Vec<Call>,                       // batched calls — key Tempo feature
        pub fee_token: Address,                     // pay gas in any ERC-20
        pub valid_before: Option<NonZeroU64>,       // timestamp ceiling (HLC ns)
        pub valid_after: Option<NonZeroU64>,        // timestamp floor (HLC ns)
        pub auth: Authorization,                    // EIP-7702-style delegation
    }

    #[derive(Clone, Debug, RlpEncodable, RlpDecodable)]
    pub struct Call {
        pub to: Address,
        pub value: U256,
        pub data: Bytes,
    }

    #[derive(Clone, Debug, RlpEncodable, RlpDecodable)]
    pub struct Authorization {
        pub chain_id: u64,
        pub delegate: Address,                       // contract address taking auth
        pub nonce: u64,
        pub y_parity: u8,
        pub r: U256,
        pub s: U256,
    }

    pub const TEMPO_TX_TYPE: u8 = 0x76;

    impl TempoTransaction {
        pub fn encode_for_signing(&self) -> Bytes {
            let mut out = vec![TEMPO_TX_TYPE];
            let rlp = rlp::encode(self);
            out.extend_from_slice(&rlp);
            out.into()
        }
        pub fn hash_for_signing(&self) -> B256 {
            keccak256(&self.encode_for_signing())
        }
    }
    ```
    **Invariants**:
    - First byte of encoded tx is 0x76 (the type tag). Followed by RLP of struct.
    - chain_id mandatory; replay-protected.
    - calls is ordered; execution applies them in order; revert of any rolls back all.
    - valid_before/valid_after enforce a time-window during which the tx is valid; sourced from `time::HybridLogicalClock` to ensure consensus-friendly across nodes.
    - fee_token = 0x0 means pay gas in native ETH (default).
  - **Build steps** (granular):
    1. (~30 min) `crates/tempo-tx-envelope/` workspace member; deps eth-rlp, eth-primitives, time, eth-consensus.
    2. (~40 min) TempoTransaction + Call + Authorization with RLP derive.
    3. (~30 min) Encode-for-signing path: prefix 0x76 + RLP.
    4. (~30 min) Hash + sign via secp256k1; verify recovers correct from-address.
    5. (~30 min) Test: hand-construct a tx with known fields, verify encoded bytes match a fixture from tempoxyz/tempo's test data.
    6. (~20 min) Validity-window enforcement: at tx-pool admission, compare to current `HybridLogicalClock::now()`; reject if out-of-window.
  - **Pitfalls** (named, consensus-critical):
    - *Wrong RLP field order*: tempoxyz/tempo defines a SPECIFIC order; deviating breaks compatibility. **Symptom**: tx bytes don't match testnet acceptance. **Fix**: copy field order EXACTLY from upstream; treat RLP layout as wire-protocol-stable.
    - *Type prefix not included in signing*: signing the RLP without the 0x76 prefix → cross-type signature replay (0x02 EIP-1559 tx with same RLP could be valid as 0x76). **Symptom**: cross-type replay attack. **Fix**: hash MUST include type byte.
    - *valid_before timestamps in seconds vs nanoseconds*: HLC is nanoseconds; if you use seconds, time-window math is wrong by 1e9. **Symptom**: txs rejected as out-of-window. **Fix**: explicit unit documentation; type-wrap as `Timestamp(u64 /* ns */)`.
    - *Authorization replay*: same auth used across chains. **Symptom**: cross-chain delegation hijack. **Fix**: chain_id field in Authorization; signature MUST cover it.
    - *Batch atomicity*: calls[0] succeeds, calls[1] reverts — must rollback calls[0]. **Symptom**: partial-execution state corruption. **Fix**: execute all calls in single transaction frame; revert rolls back everything (W50 journaling).
  - **Test scenarios**:
    - Encode tx with hard-coded fields; bytes match tempoxyz/tempo's test fixture.
    - Sign + recover: signer matches expected address.
    - valid_before in past → reject.
    - calls[1] reverts → calls[0] rolled back.
  - **Acceptance**: byte-exact match with tempo test fixture; sign/verify roundtrip green.
  - **Downstream**: W66+ Tempo testnet acceptance; exec-vm wires this as a registered tx type via the precompile-registry-style extension hook (W54 Friday).
