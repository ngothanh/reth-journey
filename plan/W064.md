- [ ] **Build**: `crates/consensus-bft/src/lib.rs` with module headers: `propose.rs`, `prevote.rs`, `precommit.rs`,
  `lock.rs`, `evidence.rs`. (~150 min)
  - **Why**: BFT (Tendermint-style) has 3 vote phases: propose → prevote → precommit. Each phase needs 2f+1 votes (out of 3f+1 nodes). Lock state ensures safety across rounds; evidence captures Byzantine misbehavior for slashing.
  - **Design** (Tendermint state machine):
    ```text
    For each height H, sequence of rounds R = 0, 1, 2, ...
    Round R:
      Phase 1: PROPOSE
        - Proposer for round R = (H + R) mod N
        - Broadcasts Proposal { height: H, round: R, value, valid_round }
        - All validators wait propose_timeout
      Phase 2: PREVOTE
        - Each validator broadcasts Prevote { height, round, hash_of_value or nil }
        - On collecting 2f+1 prevotes for same value V:
            - validator locks on V (locked_value = V, locked_round = R)
            - moves to PRECOMMIT phase with V
        - On collecting 2f+1 prevotes for nil OR timeout: prevote nil, advance phase
      Phase 3: PRECOMMIT
        - Each validator broadcasts Precommit { height, round, hash_of_value or nil }
        - On collecting 2f+1 precommits for same value V:
            - COMMIT V at height H. Advance to height H+1.
        - On timeout: precommit nil, advance round
    ```
    ```rust
    pub struct BftState {
        pub height: u64,
        pub round: u32,
        pub step: Step,                   // Propose | Prevote | Precommit | Commit
        pub locked_value: Option<Hash>,
        pub locked_round: Option<u32>,
        pub valid_value: Option<Hash>,
        pub valid_round: Option<u32>,
        pub validators: Vec<NodeId>,
        pub votes: VoteSet,                // per (height, round, step) → votes
    }
    ```
    **Invariants** (BFT safety, paper §4):
    - **Validity**: committed value must be proposed by SOME validator in SOME round.
    - **Agreement**: no two correct validators commit different values at same height (provable assuming < f Byzantine).
    - **Liveness**: assuming < f Byzantine and bounded message delay, eventually some height commits.
    - **Lock semantics**: once a validator locks on V at round R, it cannot precommit any V' ≠ V at later rounds UNLESS it sees 2f+1 prevotes for V' (lock-release rule).

    - *Equivocation handling*: Byzantine validator votes for two values in same (height, round, step). **Symptom**: confuses honest validators. **Fix**: collect ALL votes; if see two prevotes from same validator in same (h, r) → Evidence; slash. evidence.rs collects.
    - *Fork-choice tie-break*: two proposers in same round (shouldn't happen but...). **Symptom**: split prevotes. **Fix**: only one proposer per (height, round) per deterministic formula; reject other proposals.
    - *View-change DoS*: Byzantine validators repeatedly cause round advance without commit. **Symptom**: liveness loss. **Fix**: exponential-backoff on propose_timeout; eventually network synchrony restored.
    - *Lock-release wrong*: releasing lock prematurely → safety violation. **Symptom**: 2 nodes commit different values. **Fix**: STRICTLY require 2f+1 prevotes for new value before unlocking.

- [ ] **Build**: `crates/consensus-bft/src/propose.rs` — round R proposer broadcasts proposal. Validators wait
  `propose_timeout` then vote. (~150 min)
  - **Why**: The propose phase is the only place a NEW value enters the protocol. Get this wrong (e.g., proposer picks unfair value, or two proposers same round) and you've broken validity.
  - **Design**:
    ```rust
    pub struct Proposal {
        pub height: u64,
        pub round: u32,
        pub value: Hash,         // hash of proposed block/value
        pub valid_round: i32,    // -1 if first proposal; else round at which 2f+1 prevoted
        pub signature: Signature,
    }

    pub fn proposer_for(height: u64, round: u32, validators: &[NodeId]) -> NodeId {
        // Round-robin: validators[(height + round) % validators.len()]
        validators[((height + round as u64) as usize) % validators.len()]
    }

    impl BftState {
        pub fn on_enter_propose(&mut self) {
            if self.is_proposer() {
                let value = self.locked_value.unwrap_or_else(|| self.create_proposal());
                let proposal = Proposal {
                    height: self.height,
                    round: self.round,
                    value,
                    valid_round: self.locked_round.map(|r| r as i32).unwrap_or(-1),
                    signature: self.sign(&value),
                };
                self.broadcast(RaftRpc::Proposal(proposal));
            }
            self.set_timer(Step::Prevote, self.propose_timeout);
        }

        pub fn handle_proposal(&mut self, p: Proposal) -> Result<(), _> {
            // 1. Verify proposer is correct for (height, round)
            if p.height != self.height || p.round != self.round { return Err(BadRound); }
            let expected = proposer_for(p.height, p.round, &self.validators);
            if self.signer_of(&p) != expected { return Err(WrongProposer); }
            // 2. If valid_round != -1, verify we saw 2f+1 prevotes for p.value at p.valid_round
            // 3. Verify signature
            // 4. If matches our lock OR no lock OR valid_round-rule, prevote p.value; else prevote nil
            if self.locked_value.is_none() || self.locked_value == Some(p.value) {
                self.cast_prevote(Some(p.value));
            } else if let Some(vr) = (p.valid_round >= 0).then(|| p.valid_round as u32) {
                if self.locked_round.unwrap_or(0) < vr {
                    self.cast_prevote(Some(p.value));
                } else {
                    self.cast_prevote(None);  // nil
                }
            } else {
                self.cast_prevote(None);
            }
            Ok(())
        }
    }
    ```
    **Invariants**:
    - Exactly one valid proposer per (height, round). Other proposals rejected.
    - valid_round mechanism (Tendermint Annex A) preserves liveness through asynchrony.
    - Validator prevotes locked value EVEN if proposer suggests different (lock priority).
  - **Build steps**:
    1. (~25 min) Proposal type with RLP+sig.
    2. (~25 min) proposer_for round-robin.
    3. (~30 min) on_enter_propose dispatching.
    4. (~40 min) handle_proposal with valid_round logic.
    5. (~30 min) Tests: 4-node, propose, prevote, advance; Byzantine proposer sends invalid value → honest prevote nil.
  - **Pitfalls**:
    - *Proposer-skew DoS*: round-robin proposer can be unavailable; cluster stalls awaiting their proposal. **Fix**: propose_timeout → prevote nil → next round different proposer.
    - *Signature verify slow*: cryptographic sig verify on every message → CPU bottleneck. **Fix**: aggregate signatures (BLS) at v1.0+ (W73).
    - *Lock-override by proposer*: a Byzantine proposer with cooperating validators tricks an honest validator to prevote a value the validator is locked against. **Fix**: lock check first; valid_round mechanism handles legitimate switch.
  - **Test scenarios**: 4-node BFT with 1 Byzantine → honest 3 still commit (3 > 2f+1 = 3 for f=1).
  - **Acceptance**: 4-node sim with 1 byzantine → eventual commit per height.
