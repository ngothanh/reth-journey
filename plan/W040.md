**Monday — STCS theory + implementation start**

- [ ] **Build**: `crates/lsm-core/src/compaction/stcs.rs` — Size-Tiered. Trigger when level i has ≥4 similarly-sized
  SSTs. Merge them via MergeIterator into level i+1. (~150 min)
  - **Why**: STCS is the simplest compaction strategy and the canonical baseline. Trigger: when N (=4) "similarly-sized" SSTables accumulate at any level, merge them into one larger SSTable at the next level. Trade-off vs LCS: STCS has lower write amplification (~N) but higher space amplification (up to 2x — old and new live simultaneously). It's the right default for write-heavy workloads and the easiest to reason about for correctness.
  - **Read first**: Cassandra `SizeTieredCompactionStrategy.java`; `mini-lsm` Week 2 Day 1-2.
  - **Design**:
    ```rust
    pub struct StcsCompactor {
        levels: Vec<Vec<SstReader>>, // levels[0] = L0; levels[i] = Li
        threshold: u32,              // 4
        size_ratio_tolerance: f64,   // 0.5 = within 2x is "similar"
        manifest: Arc<Manifest>,
    }
    impl StcsCompactor {
        pub fn pick_compaction(&self) -> Option<CompactionTask>;
        pub fn run(&mut self, task: CompactionTask) -> Result<()>;
    }
    pub struct CompactionTask {
        level: u32,
        input_ssts: Vec<SstId>,
        output_level: u32,
    }
    ```
    **Invariants**:
    - On compaction: input SSTs are merged via MergeIterator (newer source wins); output is one or more L(i+1) SSTs.
    - Tombstones survive into L(i+1) UNLESS this is the bottom level and the tombstone has no descendants → elide.
    - Manifest update is atomic: input SSTs removed, output SSTs added in one record.
  - **Build steps**:
    1. (~25 min) `pick_compaction`: scan levels, find ≥4 similar-sized SSTs; produce task.
    2. (~50 min) `run`: open input SSTs as iterators; create N-way MergeIterator (with source_idx = newest first); feed into SstBuilder targeting L(i+1).
    3. (~30 min) Tombstone elision logic: at bottom level, drop tombstones; at intermediate levels, retain.
    4. (~25 min) Atomic manifest update: remove inputs, add outputs; fsync; only then delete input files.
    5. (~20 min) Tests.
  - **Pitfalls**:
    - *Output sized too large*: merging 4×64MB = 256MB output; if L(i+1) target is 256MB, this fills L(i+1) and immediately re-triggers compaction (cascade). **Symptom**: compaction storm. **Fix**: output respect L(i+1)'s target SST size; split into multiple outputs.
    - *Tombstone elision too eager*: eliding a tombstone at L1 while L2 still holds the value causes resurrection. **Symptom**: deleted key reappears. **Fix**: only elide at the deepest level OR confirm no overlap range in lower levels.
    - *Compaction races flush*: flush adds to L0 while compaction reads L0; the new flush is missing from compaction inputs. **Symptom**: lost writes. **Fix**: snapshot levels at task pick time; new flushes go to a future compaction.
    - *Input deletion before manifest fsync*: deleting input SST files before manifest sync → recovery sees deleted refs in manifest. **Fix**: manifest fsync first, file delete second.
  - **Test scenarios**:
    - 100 random put bursts → many L0 flushes → compaction cascade → final state has same logical content.
    - Tombstone correctness: insert+delete on key K; force compaction to bottom level; key K not present.
    - Crash sim: kill mid-compaction; recovery sees pre-compaction state (manifest not yet fsynced).
  - **Acceptance**: write amp ≤ N (=4); space amp ≤ 2x; recovery is correct after kill-9 mid-compaction.
  - **Downstream**: scheduler (Tue); W41 LCS comparison; W95 mini-db default compaction.

**Tuesday — Compaction scheduler**

- [ ] **Build**: `crates/lsm-core/src/compaction/scheduler.rs` — background thread runs compaction picks. Throttling via
  the same `backpressure::CreditFlowControl` matching-engine will use. (~150 min)
  - **Why**: Compaction is I/O-and-CPU-intensive; running it inline with writes craters write latency. A background scheduler decouples: writers enqueue "this level may need attention" signals; scheduler picks tasks under backpressure budgets (so compaction can't starve foreground writes). The shared `CreditFlowControl` reuse is intentional — the same primitive that throttles matching-engine fills throttles compaction here.
  - **Read first**: RocksDB `db/compaction/compaction_picker.cc` scheduling logic; mini-lsm Week 2 Day 4.
  - **Design**:
    ```rust
    pub struct CompactionScheduler {
        compactor: Box<dyn Compactor>, // STCS or LCS
        signal: Arc<Notify>,
        credit: Arc<backpressure::CreditFlowControl>,
        handle: JoinHandle<()>,
    }
    impl CompactionScheduler {
        pub fn start(...) -> Self;
        pub fn notify_level_changed(&self);
        pub fn shutdown(self);
    }
    ```
    **Invariants**:
    - At any time, ≤1 compaction task running per level (no overlap).
    - Scheduler can be paused via credit exhaustion; resumes when credit returns.
    - Graceful shutdown drains current task; no orphaned files.
  - **Build steps**:
    1. (~25 min) Thread spawn; loop on `signal.notified().await`.
    2. (~30 min) Pick task; check `credit.try_acquire(estimated_cost)`; if no credit, wait.
    3. (~40 min) Run task; on completion, return credit; signal scheduler again (cascading compactions).
    4. (~30 min) Per-level concurrency lock: HashMap<level, Arc<Mutex<()>>> ensures no overlap.
    5. (~15 min) Graceful shutdown: set shutdown flag; drain pending; join.
    6. (~10 min) Tests.
  - **Pitfalls**:
    - *Compaction starves writes*: scheduler greedily takes all I/O credit; writes stall. **Symptom**: write latency spike during compaction. **Fix**: credit limit caps compaction throughput; writes have priority budget.
    - *Cascading storm*: each compaction triggers next-level overflow → infinite cascade. **Symptom**: 100% CPU on compaction, no progress on writes. **Fix**: rate-limit cascade depth per cycle; round-robin across levels.
    - *Shutdown leaves .tmp files*: if shutdown kills mid-compaction, tmp SSTs accumulate. **Symptom**: disk fills over time. **Fix**: cleanup pass on startup removes orphaned .tmp files older than manifest's max id.
  - **Test scenarios**:
    - 16 writer threads + scheduler; verify writes never block > 100ms.
    - Pause via credit exhaustion; writes continue; resume; compactions catch up.
    - Kill scheduler mid-task; restart; orphaned .tmp removed; manifest consistent.
  - **Acceptance**: write tail latency p999 < 10ms under sustained compaction load.
  - **Downstream**: W41 LCS uses same scheduler; W74 matching-engine uses same backpressure primitive.
