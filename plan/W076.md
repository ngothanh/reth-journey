  #### Phase 3 — Make the tests pass, one failure at a time (~80 min)

  Newbie cards first, expert last.

  - **(NEWBIE) When `driver_handles_add_publication_round_trip` hangs forever:**
    - Symptom: test exceeds the 1000-tick budget; `poll_reply()` never returns.
    - Why: conductor wrote the reply to the *to_driver* ring (the inbound one) instead of *to_clients*; client polls the right ring and sees nothing.
    - Fix: route replies to `to_clients`; assert the two ring handles are distinct at `launch`.
    - Cost avoided: a wiring bug, not a perf one — but it masks every downstream test; fix first.
    - Muscle: SPSC duplex needs two named, directional rings; never one ring used both ways. Reapplies at: W77 term-buffer publication/consumption rings, W84 archive replay request/response.

  - **(SENIOR) When `conductor_poll_zero_syscalls_under_steady_load` reports ~10k epoll_wait/sec:** (bar (c) violation)
    - Symptom: `strace -c` shows ~10k `epoll_wait(timeout=0)`/sec; P99 cmd latency jumps 1 µs → 15 µs on quiet symbols; `perf stat` context-switches climb under low load.
    - Why: naive conductor calls `epoll_wait(timeout=0)` every iteration even on an empty ring — 300 ns/syscall × 10 kHz = 3 ms/sec AND each syscall evicts the conductor's ~30 KiB L1 working set.
    - Fix: idle strategy is the W4 Tue Backoff ladder — (1) `core::hint::spin_loop()` for ~100 polls (~10 ns/iter), (2) `thread::yield_now()` for ~10 polls, (3) park via the W4 Thu Parker only after sustained idleness. Match Aeron `BackoffIdleStrategy`. The hot path NEVER syscalls; only the cold-park path does.
    - Cost avoided: ~300 ns × 10 kHz = 3 ms/sec/core; restores L1 residency; P99 tail collapses 15 µs → <2 µs.
    - Muscle: a hot poll loop must NEVER syscall on the fast path. Reapplies at: W77 term buffer poll, W77 flow-control tick, W78 NAK tick, W83 runtime reactor::poll(), W108 cluster-VOPR scheduler.

  - **(SENIOR) When `cnc_layout_head_tail_cache_line_isolated` reports `tail - head == 8`:** (bar (c) violation)
    - Symptom: `offset_of!(CncHeader, tail) - offset_of!(CncHeader, head) == 8` (back-to-back u64s); `perf c2c` flags the first cache line of the mmap as the HITM hotspot.
    - Why: header stored `head: AtomicU64`, `tail: AtomicU64`, and records all within a 64 B span. Client's `tail` write invalidates driver's cached `head`; driver's `head` write invalidates client's cached `tail`. ~7 ns L2 fetch × 2 sides × 1M ops/s = ~14 ms/sec cross-core MESI.
    - Fix: `head: CachePadded<AtomicU64>` (W4), `tail: CachePadded<AtomicU64>` on a separate line, records start on the next line boundary; `#[repr(C)]` so the padding is load-bearing (W4 SENIOR card). Pin client + conductor to sibling cores, same NUMA node.
    - Cost avoided: ~7 ns × 2 × 1M ops/s = ~14 ms/sec L2 traffic; restores per-side L1 residency.
    - Muscle: in an SPSC ring, head + tail must be on different cache lines from each other and from records. Reapplies at: W77 term-buffer tail, W84 archive recorder lag counter, W103 perp-dex-core inter-node ring.

    - Why: `RefreshRule::Random` called `thread_rng()` → OS entropy → different per replica.
    - Fix: PRNG seeded from `(order_id, op_num)` — deterministic input → deterministic output; every replica computes the same size for the same event on the one VSR log.

    - Symptom: P99 refresh 8 µs vs 1 µs target; flame graph shows `core::ptr::copy` dominating (~70%).

    - Muscle: every emit path on a bar-(c) crate uses a buffer pool, never `Vec::new`. Reapplies at: W77 aeron offer, W79 MBO feed publish, W80 oracle-mark publish, W84 archive recorder.
