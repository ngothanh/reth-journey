## Tuesday — Lighthouse Engine API client + messaging-aeron media driver

- [ ] Read Lighthouse's side of Engine API. (~45 min)
- [ ] **Build**: `crates/messaging-aeron/src/media_driver.rs` —
  `MediaDriver { shm_dir: PathBuf, conductor: ConductorThread }`. Conductor owns subscription/publication state. (~105 min)
  - **Why**: MediaDriver is Aeron's control plane — the daemon that owns all transport state, exposes a CnC (Command-and-Control) file over shared memory, and routes publication/subscription commands. Clients are thin libraries that talk to the driver via the CnC file. This separation lets multiple processes share the network with zero-copy.
  - **Read first**: Aeron `aeron-driver/src/main/java/io/aeron/driver/DriverConductor.java`. CnC file layout: `aeron-client/src/main/java/io/aeron/CncFileDescriptor.java`. Martin Thompson's "Mechanical Sympathy" talk on the conductor-receiver-sender thread split.
  - **Design**:
    ```rust
    pub struct MediaDriver {
        pub shm_dir: PathBuf,
        pub cnc_file: Mmap,                    // command-and-control file
        pub conductor: ConductorThread,        // command processing
        pub sender: SenderThread,              // outbound UDP
        pub receiver: ReceiverThread,          // inbound UDP
        pub publications: AHashMap<PublicationId, Publication>,
        pub subscriptions: AHashMap<SubscriptionId, Subscription>,
    }
    pub struct CncFile {
        pub to_driver_buffer: RingBuffer,      // clients → driver commands
        pub to_clients_buffer: RingBuffer,     // driver → clients events
        pub counters_metadata: Mmap,
        pub counters_values: Mmap,
        pub error_log: Mmap,
    }
    pub enum DriverCmd {
        AddPublication { channel: String, stream_id: i32, correlation_id: i64 },
        AddSubscription { channel: String, stream_id: i32, correlation_id: i64 },
        RemovePublication { id: PublicationId },
        RemoveSubscription { id: SubscriptionId },
    }
    impl ConductorThread {
        // Polled at ~10kHz (no async); reads to_driver_buffer, processes, writes to_clients_buffer
        pub fn poll(&mut self) -> usize { /* ops processed */ }
    }
    ```
    **Invariants**: (i) Conductor is single-threaded — no locks needed inside. (ii) CnC file uses lock-free SPSC ring buffers (one per direction). (iii) Sender and Receiver are separate threads pinned to dedicated cores; they communicate with conductor via ring buffers, never shared mutex state. (iv) Driver lifetime owns shm files — drop ⇒ unlink (graceful) or stale (recovery on next start).
  - **Build steps**: 1. (~15 min) `MediaDriver` struct + builder. 2. (~25 min) CnC file mmap layout (4 KiB header + 1 MiB rings + counters + error log). 3. (~25 min) `ConductorThread::poll` skeleton — read to_driver_buffer, dispatch on DriverCmd. 4. (~20 min) `AddPublication` handler — creates a term buffer (stub for Mon), allocates id, replies via to_clients_buffer. 5. (~20 min) `RemovePublication` cleanup. 6. (~Tests in W77.)
  - **Pitfalls** (named, 3):
    - *Stale shm files*: **Symptom**: driver crash leaves shm files behind; restart sees them, gets confused about what's owned. **Fix**: driver writes its pid + boot-time to CnC header; on startup, check pid liveness — if dead, recover (unlink + recreate). Aeron uses `cncVersionStatus` field for this handshake.
    - *Ring-buffer overflow*: **Symptom**: client floods to_driver_buffer faster than conductor polls; commands lost. **Fix**: ring buffer returns `WouldBlock` on full; client backs off + retries. Conductor polls at 10 kHz minimum (Aeron's `idle_strategy.spinning`).
    - *Cross-process mmap alignment*: **Symptom**: 32-bit client mmaps file aligned to its page size; 64-bit driver expects different alignment → SIGBUS. **Fix**: enforce 64-bit only via `compile_error!` if `target_pointer_width != 64`. Aeron supports both but with painful overlap; v0.5 punts.
  - **Test scenarios**: (a) Start driver, client connects, AddPublication → publication id returned. (b) Kill client mid-session → driver cleans up publication via heartbeat timeout. (c) Driver restart while client running → client sees disconnect, reconnects after driver returns.
  - **Acceptance**: command throughput ≥1M cmd/s through CnC ring. Conductor polling latency P99 < 100µs. Inheritance: time::Monotonic for timeouts, bufpool for ring storage.
  - **Downstream**: W77 term_buffer.rs builds on `AddPublication` to allocate the actual term storage. W78 transport_udp.rs sender uses the conductor to route outbound publications.

## Wednesday — Prysm perspective + [NEW v2] consensus-vsr state transfer

- [ ] Read Prysm equivalent (less depth). (~45 min)
- [ ] [NEW v2] **Build**: `crates/consensus-vsr/src/state_transfer.rs` — lagging replica catches up via GetState/NewState
  messages. (~3 hrs)
  - **Why**: A replica that's been offline (or behind due to slow disk) longer than the leader's truncated log range cannot rejoin via NormalOperation — it needs the *full state* shipped in chunks. State transfer is VSR's analog of Raft InstallSnapshot. Bar (c) — without it, replicas that fall behind become permanently dead.
  - **Read first**: Liskov-Cowling 2012 §6 (State Transfer). TigerBeetle `vsr/replica.zig::on_request_start_view`, `on_recovery`, the state-sync logic. Compare to Raft InstallSnapshot (W67) — VSR variant uses op_num cuts instead of log indexes.
  - **Design**:
    ```rust
    pub enum StateTransferMsg {
        GetState {
            view_num: ViewNum,
            op_num: u64,            // requester's current op_num
            from: ReplicaId,
        },
        NewState {
            view_num: ViewNum,
            op_num: u64,             // sender's op_num (recipient catches up to this)
            commit_num: u64,
            log_suffix: Vec<Op>,     // ops (requester.op_num + 1 ..= sender.op_num)
            // If suffix exceeds threshold → ship snapshot instead
            snapshot: Option<StateMachineSnapshot>,
            to: ReplicaId,
        },
    }
    pub struct StateMachineSnapshot {
        pub op_num: u64,                 // last op included
        pub view_num: ViewNum,
        pub state_bytes: Bytes,
        pub checksum: Blake3Hash,
    }
    impl Replica {
        pub fn request_state_transfer(&mut self) {
            // Triggered when on_prepare gets a gap (received op_num >> self.op_num + 1)
            let target = self.view.leader();  // ask current leader
            self.send_to(target, GetState {
                view_num: self.view.view_num,
                op_num: self.op_num,
                from: self.id,
            });
        }
        pub fn on_get_state(&mut self, m: GetState) -> NewState {
            if m.view_num > self.view.view_num { /* requester ahead; ignore or trigger view-change */ }
            let suffix_size = self.op_num - m.op_num;
            if suffix_size <= MAX_LOG_SUFFIX {
                NewState { log_suffix: self.log.range(m.op_num+1..=self.op_num), snapshot: None, .. }
            } else {
                let snap = self.state_machine.snapshot();
                NewState { log_suffix: vec![], snapshot: Some(snap), .. }
            }
        }
        pub fn on_new_state(&mut self, m: NewState) {
            if m.view_num < self.view.view_num { return; }
            if let Some(snap) = m.snapshot {
                assert_eq!(snap.checksum, blake3::hash(&snap.state_bytes));
                self.state_machine.restore(snap.state_bytes);
                self.op_num = snap.op_num;
                self.commit_num = snap.op_num;
            }
            for op in m.log_suffix {
                self.op_num += 1;
                self.log.append(self.op_num, op.clone());
                if self.op_num <= m.commit_num {
                    self.state_machine.apply(op);
                    self.commit_num = self.op_num;
                }
            }
        }
    }
    ```
    **Invariants**: (i) Snapshot's `op_num` ≤ sender's `commit_num` — never ship uncommitted state. (ii) State transfer is *idempotent* — repeated NewState messages with same op_num are no-ops. (iii) Checksum-verified — corrupted snapshot rejected. (iv) Recipient sets `op_num` and `commit_num` together; gap between them after restore is forbidden.
  - **Build steps**: 1. (~25 min) Types + serde. 2. (~30 min) `request_state_transfer` trigger from on_prepare gap path. 3. (~35 min) `on_get_state` — log-suffix vs snapshot decision. 4. (~40 min) Snapshot creation: state_machine.snapshot() + checksum. 5. (~30 min) `on_new_state` — restore + apply suffix, idempotent. 6. (~20 min) Chunking for large snapshots (>4 MiB) — multi-message NewState with `done: bool`. (~Tests across W77.)
  - **Pitfalls** (named, 3):
    - *State transfer during view change*: **Symptom**: replica is in ViewChange, but receives NewState (which is for Normal) → confuses phases, applies stale ops. **Fix**: state transfer only valid when `status == Normal`. During ViewChange, lagging replicas catch up via the merged log in StartView (W75) instead.
    - *Concurrent NewStates*: **Symptom**: replica requests state from two peers, both respond, recipient applies both → ops appended twice. **Fix**: track outstanding `GetState` request id; only process matching NewState. Aeron-style correlation_id.
    - *Snapshot of partial state*: **Symptom**: state_machine.snapshot() called mid-apply, snapshot misses an op. **Fix**: snapshot is only allowed at commit_num boundary; assert `state_machine.applied_op_num == commit_num` before calling snapshot.
  - **Test scenarios**: (a) Replica offline for 100 ops, rejoins, log-suffix transfer. (b) Replica offline for 1M ops (beyond MAX_LOG_SUFFIX) — snapshot transfer. (c) Corrupted snapshot bytes → checksum reject + retry. (d) Concurrent requests dedup correctly. (e) Cross-replica: rebuilt replica's state_machine hash matches existing replicas bit-identical.
  - **Acceptance**: snapshot transfer 100MB state < 5s loopback. Property test: 100 random offline/rejoin sequences, state always converges. Inheritance: wal (snapshot durable on recipient), bufpool, blake3.
  - **Downstream**: W76 Thursday's tag `consensus-vsr v0.5.0` audit confirms state_transfer in scope. W83+ ledger-deterministic relies on state-transfer for adding new replicas to production clusters. Interview: "if a TigerBeetle replica is offline 24h, how does it rejoin?" → state transfer mechanics here.

- [ ] [NEW v2] **Build**: `crates/matching-engine/src/iceberg.rs` —
  `IcebergOrder { total: u64, display: u64, refresh_rule }`. Only `display` qty visible in book; when filled, refresh
  from hidden. (~3 hrs)
  - **Why**: Iceberg (or "reserve") orders let a large trader hide most of their interest, showing only a small tip ("display qty") at a time. Reduces market-impact for size traders. Every Tier-A venue ships them. The visibility/refresh semantics are subtle — interview load-bearing: "how does iceberg interact with MBO market data?"
  - **Read first**: Nasdaq INET specification, "Reserve Order" type R. CME Globex iceberg semantics (`max_show` field). LIST `IcebergMatcher` from QuickFIX. Real-world bug example: "Knight Capital's iceberg refresh race" 2012 (no specific bug — but generic algorithm-deployment trap, useful framing).
  - **Design**:
    ```rust
    pub struct IcebergOrder {
        pub id: OrderId,
        pub account: AccountId,
        pub symbol: Symbol,
        pub side: Side,
        pub px: Price,
        pub total_remaining: u64,         // includes hidden
        pub display_remaining: u64,       // visible to MBO/MBP
        pub display_qty: u64,             // original display size (refresh target)
        pub refresh_rule: RefreshRule,
    }
    pub enum RefreshRule {
        OnFullDisplay,                    // refresh when display_remaining == 0
        OnAnyFill,                        // refresh after every fill
        Random { min: u64, max: u64 },    // randomize refresh qty to obfuscate (anti-detection)
    }
    impl Engine {
        // After a partial/full fill against the iceberg's display portion
        fn after_fill(&mut self, ice: &mut IcebergOrder, fill_qty: u64) -> Option<OrderEvent> {
            ice.total_remaining -= fill_qty;
            ice.display_remaining -= fill_qty;
            if ice.total_remaining == 0 {
                return Some(OrderEvent::Filled);
            }
            match ice.refresh_rule {
                RefreshRule::OnFullDisplay if ice.display_remaining == 0 => {
                    let new_display = ice.display_qty.min(ice.total_remaining);
                    ice.display_remaining = new_display;
                    // CRITICAL: refreshed order goes to BACK of price-time queue
                    self.book.requeue_iceberg(ice.id, new_display);
                    Some(OrderEvent::Refresh { new_visible: new_display })
                }
                RefreshRule::OnAnyFill if ice.display_remaining < ice.display_qty => {
                    let needed = ice.display_qty - ice.display_remaining;
                    let refresh = needed.min(ice.total_remaining - ice.display_remaining);
                    ice.display_remaining += refresh;
                    self.book.requeue_iceberg(ice.id, ice.display_remaining);
                    Some(OrderEvent::Refresh { new_visible: ice.display_remaining })
                }
                _ => None,
            }
        }
    }
    ```
    **Invariants**: (i) `display_remaining <= display_qty <= total_remaining` always. (ii) Refreshed display qty is *requeued at the back* of price-time priority — fairness rule per CME/Nasdaq. (iii) `total_remaining = 0` ⇒ order terminal (Filled). (iv) MBO publishes only `display_remaining`-sized adds/cancels; hidden portion never appears on the wire (this is the *defining property*).
  - **Build steps**: 1. (~25 min) Types + RefreshRule enum. 2. (~35 min) `after_fill` decision tree. 3. (~30 min) Book interaction: `requeue_iceberg` — remove from queue, re-insert with new qty at price-time tail. 4. (~30 min) MBO publishing rules — when refresh fires, publish (Cancel old visible) + (Add new visible). 5. (~30 min) STP interaction (W75): iceberg's hidden portion participates in STP if mode is total-based (CME-style) or excluded if visible-based (Nasdaq-style); make pluggable. 6. (~30 min) Tests.
  - **Pitfalls** (named, 4):
    - *Refresh ordering after cancel*: **Symptom**: trader cancels iceberg while a fill is mid-processing → cancel races with refresh; ends up with phantom display in book. **Fix**: process fill → refresh atomically inside Engine.apply (single thread). Cancel observed after must see post-refresh state. With raft replication (W74), fill+refresh is one log entry.
    - *FIX visibility leak*: **Symptom**: ExecutionReport (35=8) reports total_remaining instead of display_remaining → counterparty deduces hidden size. **Fix**: ExecutionReport's `LeavesQty(151)` = `display_remaining` for the visible portion; reserved `MaxShow(210)` exposes the total only to the account that owns the order. Audit every wire emission.
    - *MBO MBP equivalence break*: **Symptom**: MBP (Market-By-Price) aggregates Adds/Cancels from MBO; if MBO leaks hidden refresh adds, MBP totals inflate beyond actual liquidity. **Fix**: MBO emits Refresh as `Cancel(old_display_qty) + Add(new_display_qty)`; the cancel of the old display has the same total impact as the prior add — net effect on MBP visible book is just the new display.
    - *Random refresh determinism*: **Symptom**: `RefreshRule::Random` uses `thread_rng` → divergence across raft replicas. **Fix**: deterministic PRNG seeded from `(order_id, op_num)` — every replica computes the same "random" refresh size.
  - **Test scenarios**: (a) 1000-lot iceberg with 100-lot display, 10 takers of 100 each → 10 fills visible at 100, then Filled. (b) Cancel mid-refresh → order fully cancelled, no phantom. (c) STP interaction: same-account incoming meets visible 100, with hidden 900 → CME-style cancels all 1000, Nasdaq-style only visible 100. (d) MBO replay: feed event stream to replica MBO consumer; reconstructed book matches engine's display layer exactly. (e) Replicated determinism: 3-replica with same input order stream → identical book states.
  - **Acceptance**: refresh latency P99 < 1µs (single ptr swap + queue tail insert). Property: MBO replay invariant — sum of all (Add - Cancel) qty per price level equals current visible depth, for 100k random scenarios. Inheritance: bufpool, AHashMap.
  - **Downstream**: W77 stop_ladder.rs interacts (a stop-trigger may unhide iceberg's hidden portion as a new resting limit). W79 mbo_feed.rs publishes iceberg events with hidden-portion correctly excluded. Interview: "describe how iceberg orders publish to MBO without leaking" — refresh-as-Cancel+Add idiom.
