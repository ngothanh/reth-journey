- [ ] **Concurrency drill #19 of 28 — hazard pointers on a Treiber stack (Maged Michael 2004)** — `crates/concurrent/src/treiber.rs` + `crates/concurrent/src/hazard.rs`. (solo, ~total 250 min across 3 phases = 70+80+100)
  - 🔧 **Why this matters**: hazard pointers are the fundamental memory-reclamation pattern for lock-free
    structures — mirrors `haphazard`/`folly::HazardPointers`. Without them (or EBR, drill #23) a CAS-based
    `pop` can free a node another thread is about to dereference: ABA in disguise. Three traps: (1) protect
    AFTER load instead of protect-then-reload-verify; (2) retire-without-scan leaks; (3) scan reads a slot
    racily. First-attempt impls fail the loom UAF test below — that debug session IS the lesson. Downstream:
    W33 EBR (the alternative this compares against), W37 skiplist tower retirement, W42 deadlock-detector
    wait-for-graph nodes, and **W14 pin.rs sentinel (Friday)** silently requires reclamation discipline (the
    CAS-to-sentinel in `pin.rs` is the same protect-then-verify shape).

  #### Phase 1 — Problem, prediction, design (~70 min, no code yet)

  - *Mental model*: a hazard pointer is a per-thread published "I am about to dereference this address" slot;
    a reclaiming thread refuses to free any address currently published. It trades a store + scan for the
    right to free safely.
  - *Contract*: `TreiberStack<T> { head: AtomicPtr<Node<T>> }` with `push(&self, v: T)` / `pop(&self) ->
    Option<T>`; `HazardRegistry` with `protect(&self, p: *mut Node<T>) -> HazardGuard`, `retire(&self, p)`,
    `scan_and_reclaim(&self)`. NEVER write the protect-loop body in this doc.
  - *Back-of-envelope*: `protect` = 1 release store to a per-thread slot in L1 (~0.5ns) + a re-load + compare
    (~1ns). `scan_and_reclaim` walks ≤ `num_threads` slots (≤64 × L1 ≈ 32ns) per retired batch. UAF cost if
    you skip it: undefined behavior — unbounded, a crash or silent corruption, not "slow".
  - **Requirements** R1..R6 in `crates/concurrent/notes/14_drill19_design.md`:
    - R1. `pop` never returns a node freed by a concurrent `pop`.
    - R2. No node is freed while any thread's hazard slot points at it.
    - R3. Every retired node is EVENTUALLY freed (no permanent leak).
    - R4. `protect` uses protect→reload-head→verify-unchanged→retry (publish before deref, re-validate after).
    - R5. `retire` appends to a per-thread retire list; `scan_and_reclaim` frees only addresses absent from
      all slots.
    - R6. Build the UNPROTECTED Treiber first and prove UAF under loom, THEN add protection.

  #### Phase 3 — Make the tests pass, one failure at a time (~100 min)
  - **(NEWBIE) When `treiber_unprotected_loom_uaf` does NOT report a UAF:**
    - Symptom: loom passes the unprotected stack — green where it must be red.
    - Why: your `Node::drop` poison or the deref check is missing, so loom can't observe the violation.
    - Fix: add `freed: AtomicBool` set in `Drop`; have `pop` assert `!freed.load(Acquire)` immediately after
      reading `head`. Now loom finds the free-then-deref order.
    - Muscle: a safety test must be able to FAIL on the broken impl — instrument the violation before you fix
      it. Reapplies at: W26 wal torn-write detector, W33 EBR drop-counter, W42 txn lost-update probe.
  - **(SENIOR) When `hazard_retire_without_scan_leaks_then_scan_drains` shows freed == 0 with 100 retired:**
    - Symptom: retire-list len == 100 and stays there — the drop-counter never moves until the explicit
      `scan_and_reclaim` call, which then drains all 100 in one pass (the test's second half).
    - Why: `retire` only QUEUES the node on the per-thread retire list — it is a *promise* to free, not a
      free. Nothing reclaims until a scan compares the retired addresses against every hazard slot; an impl
      that never triggers a scan leaks bounded-only-by-retire-rate.
    - Fix: trigger `scan_and_reclaim` automatically at a retire-list size threshold R (Michael 2004 uses
      R ≈ 2× total slot count; drill #20 measures the tradeoff curve), so reclamation cost amortizes and the
      list stays bounded.
    - Muscle: reclamation ≠ retirement — retire defers, scan pays; every deferred-reclamation scheme needs a
      bounded trigger. Reapplies at: W33 EBR (the epoch advance is the scan analog), W37 epoch-gc tower
      retirement.
  - **(SENIOR) When `treiber_protected_loom_no_uaf_no_double_free` double-frees:**
    - Symptom: drop-counter > push-count; two threads retire+scan the same node and both free it.
    - Why: `scan_and_reclaim` lacks a "claim" step — both scanners see A absent from all slots and free it.
    - Fix: retire lists are PER-THREAD; only the owning thread frees its own retired nodes. A node is retired
      by exactly one thread (the popper that unlinked it).
    - Muscle: reclamation ownership is single-writer — the thread that unlinks owns the free. Reapplies at:
      W26 wal segment unlink, W37 epoch-gc, W42 lock release, **W14 pin.rs sentinel** (one evictor owns the frame).
  - **(EXPERT) When `hazard_protect_blocks_reclaim` frees a protected node:**
    - Symptom: T1's guard is live but T2 frees A; T1 derefs garbage.
    - Why: T1 protected A AFTER reading head; between read and publish, A was already unlinked — protect-after
      is too late.
    - Fix: protect→reload head→verify still == A→only then deref; if changed, retry. Publish-before-deref +
      re-validate — AND the slot publish must be a `SeqCst` store (equivalently: a store-load fence between the
      hazard-slot store and the head reload); a `Release` publish alone leaves the store-load pair unordered,
      which is exactly the failure the next card walks.
    - Muscle: hazard protection must publish BEFORE the deref and re-validate the pointer didn't change.
      Reapplies at: W33 EBR pin-then-load, W37 skiplist hand-over-hand, **W14 pin.rs CAS-pin-then-recheck-gen**.
  - **(EXPERT) When `hazard_scan_seqcst_prevents_missed_publication` (or the protected loom model) STILL finds
    a UAF with protect-then-verify correctly in place:**
    - Symptom: loom prints a schedule where T1 stores slot ← A, reloads `head` and sees A unchanged, derefs —
      yet T2's scan freed A. The scanner read T1's slot BEFORE the slot-store became visible to it.
    - Why: missing store-load fence between the hazard-slot store and the head reload. `Release` store /
      `Acquire` load only orders store→load *acquire-of-that-store* pairs; T1's slot-store and T1's head-load
      form a store-then-load sequence that both x86 (StoreLoad reordering) and the C++ model allow to
      pass each other, so T2's slot scan can read the stale (empty) slot and free the just-protected node.
    - Fix: `SeqCst` store on the hazard-slot publish + `SeqCst` load in the scanner's slot walk, per
      Michael 2004 §4 — the single total order forces either T1's head reload to see the unlinked head
      (retry, no deref) or T2's scan to see the published slot (skip the free). One or the other, never neither.
    - Cost avoided: ~5–20ns/protect for the fence — the price of safety; skipping it buys back those ns and
      pays in UAF (unbounded: crash or silent corruption, not "slow").
    - Muscle: protect-then-verify is only sound with a store-load fence between publish and re-validate —
      Release/Acquire cannot order a store against a later load. Reapplies at: W33 EBR pin fence (the epoch
      pin has the identical store-load shape), W14 Fri `pin.rs` CAS-to-sentinel handshake.
  - **5-year failure mode** (`notes/14_drill19_followup.md`): hazard pointers don't scale to structures with
    many live internal pointers (each needs a slot). Trigger: W37 skiplist tower walk needs per-level
    protection. Migration: switch to EBR (drill #23), which amortizes per-epoch instead of per-pointer.
