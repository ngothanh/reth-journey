  - *Mental model*: the mark price is a **manipulation-resistant, deterministic scalar** — it is deliberately NOT the last trade. It is a clamped median of independent sources so no single source (especially the manipulable `last`/book) can drag it. It must be a pure integer function of its inputs so the VSR cluster computes it bit-identically on every replica.
  - *Contract*: `fn compose_mark(index: Price, basis_ema: Basis, book_mid: Price, last: Price, max_dev_bps: u32, basis_cap_bps: u32) -> Price` where `Price(i64)` is integer ticks and `Basis(i64)` is the fixed-point EMA state (R8); returns `clamp(median3(index + clamp(basis_ema, ±basis_cap), book_mid, last), index.bps_band(max_dev_bps))` — the clamped basis-EMA is a candidate **INPUT to the median** (it basis-adjusts the index candidate), NOT a second mark formula. **There is exactly ONE mark output — `compose_mark`'s return — and that single number is what drives liquidation (W100/W101) and margin (W90).** No `f64`, no allocation, no source-enumeration-order dependence.
  - *Back-of-envelope* (bar (c)): mark is recomputed on every mark tick (~10/s in v1.0, per-trade under stress) and read by 100k accounts' margin checks. A `median3` over 3 integers = ~3 compares + 1 clamp ≈ 5 ns, 0 allocs. An `f64` path adds nothing in latency but is a **correctness cliff**: cross-arch divergence is unbounded (silent). Cliff: integer median (deterministic, ~5 ns) vs float median (non-deterministic across replicas — disqualifying).
