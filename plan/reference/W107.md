This is the plane the liquidation/margin path reads. (~total 200 min across 3 phases)
  - 🔧 **Why this matters**: this is §4A capstone acceptance #5, the principal v3 deliverable of the week. The risk engine (W90/W99) and liquidation engine (W100/W102) must read mark prices and positions that reflect **every op committed up to the read point** — a stale tick produces a *wrong liquidation* (you liquidate a healthy account or fail to liquidate a bankrupt one). The naive instinct is to serve risk reads from a consumer-group offset (the Kafka pattern from W84) or to do a fresh consensus read — the first is *bounded-stale* (wrong plane → correctness bug), the second adds a consensus RTT per read and throttles throughput (§9 risk row). The correct answer is the TigerBeetle pattern: the risk plane reads its own snapshot of the VSR-**applied** log on the leader shard, so the read is *already* read-after-commit by construction, with zero round-trip. First-attempt impls fail ≥1 test below because they conflate "committed" (quorum durable) with "applied" (deterministically reflected in local state) — and the debug session teaches you why read-after-commit is an *apply-time* property, not a commit-time one. Downstream: W108 cluster-VOPR asserts this plane never served a stale tick under partition; W117 gate cites acceptance #5 as proven here.

The applied-state snapshot needs O(1) copy-on-write (you built it for the matching-engine snapshot, W74); the op-number high-water mark needs a single-writer monotonic counter (no `Instant`); the read path needs zero-alloc; cross-replica determinism of *which* op is "the read point" needs the same `SequenceClock`/op_num discipline as the apply path.   fn control_read_zero_alloc() {

  // (EXPERT) wait-free apply under read storm: the apply loop must not stall while readers hammer.
  // A RwLock-based impl lets a read storm starve the apply writer; ArcSwap does not.
  #[test]
  fn apply_loop_not_starved_by_read_storm() {
      let sm = Arc::new(LeaderShard::up());
      let readers: Vec<_> = (0..16).map(|_| { let s = sm.clone();
          std::thread::spawn(move || for _ in 0..5_000_000 { let _ = s.control().read_at_commit(Key::mark("BTC-PERP")); }) }).collect();

      for op in 1..=100_000u64 { sm.apply_shared(op, sample_mark()); }   // must complete promptly despite readers
      assert!(t.elapsed() < Duration::from_secs(2), "apply loop starved by read storm — RwLock writer starvation; use ArcSwap");
