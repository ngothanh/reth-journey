**Friday — Token bucket as custom `Future` + per-peer rate limiting**

> **Why this exists**: a rate limiter caps how fast one peer can make the node do work (decode frames, serve
> requests), so a noisy or malicious peer can't saturate it. Token-bucket is the standard algorithm; this file is
> the seed of the `backpressure` crate extracted at W11. Upstream mirrors: `tower::limit::rate::RateLimit`, `governor`.

- [X] **Build**: `crates/eth-network-codec/src/rate_limit.rs` — `TokenBucket` as a custom `Future`. (~60 min)
  - *Mental model*: a bucket holds up to `capacity` tokens; tokens refill continuously at `refill_per_sec`. One
    rate-limited action costs one token — if one is ready, proceed now; if not, wait until one accrues.
  - *Back-of-envelope* (the budget that drives every architectural choice — bar (c) is downstream at W11):
    1k peers × ≈10 acquire/sec steady, ≈100k acquire/sec under burst. Per-acquire budget **< 1 µs**. Therefore:
    **zero allocations on the hot path** (one malloc ≈ 50 ns ≈ 5% of budget — gone); **integer arithmetic only**
    (float ≈ 10–30 cycles + non-bit-reproducible across CPUs — disqualifies the bar-(c) downstream `backpressure`
    W11 and `ledger-deterministic` W80+); `TokenBucket` ≤ 1–2 cache lines (`size_of` audit it); **no syscall in
    the steady-state acquire path** (only the timer-wheel registration on Pending, sub-100 ns).
  - *State to track*: capacity, current token count (**integer ticks, not float — see perf pitfall #2**), refill
    rate (as a `refill_period_ns: u64`), the `Instant` of the last refill calculation, and a timer for when
    you're waiting (**pre-allocated and reset in place, not re-`Box::pin`'d — see perf pitfall #1**).
  - *Contract*: a poll-style entry point — `poll_acquire(&mut self, cx) -> Poll<()>` — returning `Ready(())` once
    it has consumed a token, `Pending` otherwise. "Custom Future" = wrap that poll logic in a type that
    `impl Future`; whether the bucket *is* the future or hands out `Acquire` futures is your design call.
  - *poll, roughly*: (1) add tokens accrued since `last_refill`, clamp to `capacity`; (2) if ≥1 token, consume one,
    return `Ready`; (3) else work out time-to-next-token, arrange to be polled again then, return `Pending`. Step 3
    is the real exercise.
  - **Expect to hit #1 — lost wakeup**: step 3 returns `Pending` but never registers a `Waker`. Symptom: the
    future hangs forever — throughput flatlines to zero, no panic, no error.
    - Fix: hold a `tokio::time::Sleep` set to the next-token deadline and poll *it*; a `Sleep` that returns
      `Pending` registers the waker for you — only return `Pending` after it does.
    - Muscle: a `Pending` future must guarantee the task gets woken, or it is lost. Reapplies at: W11
      `backpressure` crate, W58 runtime timer wheel + io_uring timers.
  - **Expect to hit #2 — timer re-armed every poll**: a fresh `Sleep` is created on each `poll`, so its deadline
    keeps resetting. Symptom: the future stays `Pending` far longer than the configured wait, or never fires.
    - Fix: store the `Sleep` as a field; recreate it only after it fires or after a token is consumed.
    - Muscle: timer state must outlive a single `poll` call. Reapplies at: W58 runtime timer wheel, W59 runtime
      backpressure scheduling.
  - **Expect to hit #3 — wall-clock refill / unbounded accrual**: using `SystemTime` for elapsed time, or letting
    the token count grow past `capacity` while idle. Symptom: refill jumps or stalls when the system clock is
    adjusted; or after an idle gap a peer gets a burst far bigger than `capacity`.
    - Fix: use the monotonic `Instant` clock; clamp accrued tokens with `min(capacity, …)`.
    - Muscle: rate math uses monotonic time and a bounded reservoir. Reapplies at: W11 `backpressure`, W59 runtime
      backpressure scheduling.
  - **Expect to hit (perf) #1 — heap allocation on every wait cycle (bar (c) violation downstream)**:
    `Box::pin(sleep(...))` re-allocates a fresh `Sleep` (~50 ns malloc + a cache line of allocator metadata +
    `Box` drop on the next Ready) every time the bucket re-enters the wait branch. At 100k acquire/sec aggregate
    burst, that's **100k mallocs/sec on the hot path** — visible in `cargo flamegraph` as `jemalloc::malloc` /
    `<Sleep as Future>::poll` on the critical path.
    - Fix: hold a `Pin<Box<Sleep>>` field, allocated **once on the first wait**. On subsequent waits,
      `sleep.as_mut().reset(deadline)` re-arms it in place — zero allocation, zero `Box` drop. Do **not**
      `self.delay = None;` on Ready — that defeats the reuse and re-introduces the per-cycle alloc.
    - Cost avoided: ~50 ns malloc + 1 cache line + allocator-lock contention per acquire. At 100k/s = ~5 ms/s of
      pure malloc overhead removed; at 1M/s aggregate (across many peers) that's the difference between
      "matches the budget" and "blows it by 50×".
    - Muscle: in any `poll` loop, allocate at **construction** (or on first miss) — **never per `Pending`**.
      `Box::pin(...)` inside a hot-path `poll` body is always wrong. Reapplies at: W11 `concurrent::bounded`
      `recv` parking, W26 `wal` group-commit oneshot ack, W58 matching-engine command future, W77
      messaging-aeron subscriber `Sleep`, W80+ `ledger-deterministic` apply-loop futures.
  - **Expect to hit (perf) #2 — float math = non-determinism + trampoline (bar (c) violation)**:
    `Duration::from_secs_f64(remaining / rate)` is a float division, and the round-trip
    `(1/rate → Duration → elapsed → × rate)` can land at `0.999…` due to ULP rounding. Two distinct costs:
    (a) **non-bit-reproducibility** across CPUs (different FMA / rounding modes / SIMD lowering) — this alone
    disqualifies the bar-(c) downstream (`backpressure` W11 inherits the strategy, `ledger-deterministic` W80+
    must be byte-identical for VOPR replay W88); (b) **trampoline**: `tokens >= 1.0` fails on the rounding
    boundary, the code allocates *another* tiny `Sleep`, returns Pending, gets woken in microseconds, finally
    acquires — one observable acquire actually costs **2 allocations + 2 `Pending` round-trips + 1 spurious
    waker registration**.
    - Fix: integer ticks throughout. `current_token_count: u64`, `refill_period_ns: u64`. `>= 1` is bit-exact.
      Deadline = `last_refill + Duration::from_nanos(refill_period_ns)` — integer-only, monotonic, exact.
    - Cost avoided: ~10–30 cycles per float op on the hot path + the entire trampoline (the bigger win) +
      **non-determinism debt** (would have to be re-engineered before W11 backpressure ships, then again
      before W80 ledger).
    - Muscle: **hot paths and any code flowing into a deterministic SM use integer arithmetic.** Float math is
      slower than integer, non-bit-reproducible, AND carries hidden trampoline risk on the boundary — three
      strikes. Reapplies at: W4 `chain_head` SeqLock counter (already integer — good), W11
      `concurrent::bounded` seq counter (already integer), W42 `txn` timestamp ordering, W58 matching-engine
      **price math as fixed-point i64** (not f64 — this is the single most-cited HFT codebase rule), W80+
      `ledger-deterministic` apply-loop, W88 VOPR replay determinism.
  - **Expect to hit (perf) #3 — struct layout straddling a cache line + per-peer false sharing**: at ~56 B
    with naive field order, `TokenBucket` can wedge hot fields (`current_token_count`, `last_refill`) across a
    64 B cache-line boundary on some alignments — doubling L1 fetches per acquire. Worse: with per-peer
    buckets (a `Vec<TokenBucket>` or per-shard arrangement) touched by different threads, **adjacent buckets
    share lines** and false-share, costing 30–70% throughput under contention.
    - Fix: `#[repr(C)]` + arrange hot fields first (`current_token_count`, `last_refill`, `refill_period_ns`,
      `capacity`, `delay`); `const _: () = assert!(size_of::<TokenBucket>() <= 64);` to guarantee the
      single-line property. For multi-thread per-peer use, wrap in `CachePadded<TokenBucket>` (the primitive
      built W4 Mon). Verify with `cargo asm` that the hot read path is one load.
    - Cost avoided: 1 cache-line fetch per touch (~7 ns L2, ~100 ns memory) on straddle; ~30-70% throughput
      regression on the false-sharing case.
    - Muscle: any frequently-polled struct pays a cache tax when it crosses a 64 B (or 128 B on Apple Silicon)
      boundary; cross-thread adjacency adds a false-sharing tax. `repr(C)` to fix layout, `CachePadded` for
      cross-thread access. Reapplies at: W4 `chain_head` SeqLock, W58 matching-engine `PriceLevel`, W65
      Disruptor cursor/claim pair, W77 messaging-aeron term rotation counters.
  - *Pin note*: `tokio::time::Sleep` is `!Unpin` — holding one as a field makes your struct `!Unpin`, so you must
    pin-project it (`pin_project_lite`, `#[pin]`). Same lesson as Wednesday's `MessageStream`; reuse that shape.

- [X] **Build**: `RateLimitedStream<S: Stream>` (same file). (~75 min)
  - *Mental model*: wraps an inner `Stream` and only yields an item once the bucket grants a token — same wrapper

  - *poll_next, roughly*: poll the bucket's `poll_acquire`; if `Pending`, return `Pending`; once `Ready`, poll the

    `Pending` or `None`, so the token bought nothing. Symptom: effective rate drifts below the configured limit;

**Saturday — `BackpressureStrategy` + tag v0.1.0**

> **Why this exists**: Friday's rate limiter caps how fast items *leave*; it says nothing about the backlog that
> piles up when a peer produces faster than the limiter releases. A bounded buffer governed by a
> `BackpressureStrategy` is the answer — when the buffer is full, the strategy picks who loses: the oldest queued
> item, the newest arrival, or the producer (forced to wait). This enum is the seed of the `backpressure` crate
> extracted at W11. Upstream mirrors: `tokio::sync::mpsc` bounded channel (`Block`), drop-oldest channels like
> `tokio::sync::broadcast` (`DropOldest`), `tower::buffer::Buffer`.

- [X] **Build**: `crates/eth-network-codec/src/backpressure.rs` — `BackpressureStrategy` enum + a **synchronous**
  `BoundedBuffer<T>` that applies it. **[NEW]** Doc-comment the enum: "extracted into `backpressure` crate W11." (~60 min)
  - *Mental model*: a fixed-capacity queue sits between a fast producer and a slow consumer. While it has room,
    `try_push` just enqueues. Once full, the strategy decides the overflow policy — `DropOldest` evicts the front
    then enqueues the new item (freshness wins), `DropNewest` rejects the arrival (queue contents win), `Block`
    surfaces `Full` so the caller knows nothing was dropped. The W003 buffer is *synchronous* — it never parks the
    producer; the blocking form of `Block` is deferred to W11 (see the deferral note below).
  - *State to track*: a `VecDeque<T>`, a `capacity`, and the chosen `BackpressureStrategy`. Nothing else — no
    `Notify`/semaphore; the W003 buffer is synchronous (the wakeup machinery belongs to W11's concurrent channel).
  - *Contract*: `enum BackpressureStrategy { DropOldest, DropNewest, Block }`. A `BoundedBuffer<T>` with a sync
    `try_push(&mut self, item: T) -> PushOutcome<T>`, where `PushOutcome<T>` is `Accepted` (item in, nothing
    displaced) / `AcceptedEvicting(T)` (item in, this old item evicted — `DropOldest`) / `Rejected(T)` (item not
    in, dropped per policy — `DropNewest`) / `Full(T)` (item not in, buffer full under `Block` — the synchronous
    caller decides; W003 does not auto-block). Plus a sync `pop(&mut self) -> Option<T>` for the consumer side.
    The four-way split tells the caller unambiguously whether *their* item landed — a single `Dropped(T)` could not.
  - **Expect to hit #1 — `DropNewest` accepts instead of rejecting**: implementing `DropNewest` by evicting an
    existing item and/or placing the new one — i.e. accidentally writing `DropOldest`. `DropNewest` means the
    *newest arrival* loses. Symptom: `try_push` reports `AcceptedEvicting` when it should report `Rejected`; the
    buffer's contents churn when they should be stable.
    - Fix: on full + `DropNewest`, do **not** touch the buffer — return `Rejected(item)`, handing the arrival
      straight back. The queue is left exactly as it was.
    - Muscle: an overflow policy that "rejects" must leave the container untouched. Reapplies at: W11
      `backpressure` crate.
  - **Expect to hit #2 — `DropOldest` drops but doesn't insert**: evicting the front then forgetting to enqueue the
    new item, or enqueuing first and then evicting the item you just added. Symptom: the buffer steadily shrinks, or
    the newest items vanish while stale ones survive.
    - Fix: on full + `DropOldest`, `pop_front()` *then* `push_back(item)`; the invariant `len == capacity` must hold
      after every overflow.
    - Muscle: overflow policies must preserve the capacity invariant. Reapplies at: W11 `backpressure` crate.
  - **Expect to hit #3 — backpressure conflated with rate-limit `Pending`**: treating Friday's `poll_acquire`
    returning `Pending` as a buffer-overflow event. Symptom: drop counters tick up when the limiter is merely pacing
    output, not when the buffer is actually full — the metrics lie.
    - Fix: keep the two distinct — rate limiting paces *output*, the buffer absorbs *input* backlog; a drop is only
      ever a full-buffer event.
    - Muscle: name each backpressure mechanism by where it acts (source vs. sink vs. pacing). Reapplies at: W11
      `backpressure` crate, W74 matching-engine raft wire.
  - *Deferred to W11 — the blocking `Block`*: a producer that *parks* until a slot frees needs the buffer
    *shared* between producer and consumer tasks. A `&mut self`-API `BoundedBuffer` cannot do that — an
    `async push(&mut self)` holds `&mut self` across its `.await`, so the consumer can never get `&mut` to call
    `pop`; the wakeup never fires and `Block` deadlocks. The blocking form therefore lands at **W11**, where
    `BackpressureStrategy` attaches to `concurrent::bounded` — a real lock-free MPMC channel built for concurrent
    producer/consumer. W003 ships the *enum* (the artifact extracted at W11) plus the synchronous `BoundedBuffer`;
    W11 supplies the concurrency and the blocking `push`.
