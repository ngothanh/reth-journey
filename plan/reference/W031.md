        nodes_by_hash: mdbx::TableHandle, // key: [u8;32] keccak(rlp), val: rlp bytes

        fn insert(&mut self, path: Nibbles, node: Node);  // stages into dirty

  #### Phase 3 — Make the tests pass, one failure at a time (~90 min)

  Ordered newbie→expert — the ladder you actually walk.

  - **(NEWBIE) When `insert_get_round_trip_10k` returns `None` for just-staged paths:**
    - Symptom: every assert fails pre-commit; reads return `None` for paths you just inserted.
    - Why: `get` queried `nodes_by_path` (MDBX) directly; staged writes live only in `dirty` until commit.
    - Fix: `get` checks `dirty` first (`Some(node) → Some`, `Some(None) → None tombstone`), falls through to MDBX on miss.
    - Muscle: a write-buffering store reads its overlay before its backing store; skip the overlay and you read stale committed state. Reapplies at: W42 txn read-your-writes, W92 block-stm pre-commit reads.

  - **(SENIOR) When `tombstone_suppresses_read_pre_and_post_commit` resurrects the deleted node:**
    - Symptom: post-commit `get` returns the old node; the tombstone vanished.
    - Why: commit drained `Some(node)` entries to the path table but skipped `Some(None)` (tombstones), so the underlying MDBX entry was never deleted.
    - Fix: commit handles both arms — `Some(node)` → `put`, `None` → `del` on BOTH tables.
    - Muscle: a tombstone is a first-class write, not the absence of one; commit must materialize deletes. Reapplies at: W39 LSM-core delete markers, W42 txn delete, W80 ledger tombstone records.

  - **(SENIOR) When `hash_path_table_consistency_after_modify` finds a stale hash entry:**
    - Symptom: `nodes_by_hash[keccak(A.rlp())]` still present after `p` was modified A→B; ~8% of modified paths leak old hash entries.
    - Why: commit wrote the new path entry + new hash entry but never deleted the OLD hash entry for the replaced node (insert-only thinking; modify ≠ insert).
    - Fix: commit reads the prior path value before overwriting; if it changed, `del` the old `keccak(old.rlp())` from `nodes_by_hash`, then `put` the new path + new hash — all in one MDBX write tx.
    - Muscle: a derived index must be updated WHENEVER its source changes; partial (insert-only) updates leak old state. Reapplies at: W42 txn 2-table commit, W67 raft log compaction, W80 ledger account-index update.

  - **(EXPERT, cross-primitive) When `cursor_result_outlives_tx_is_uaf` segfaults / Miri reports UAF:**
    - Symptom: with the borrow return, process crashes (or Miri reports use-after-free) when the cursor's bytes are touched after `tx.commit()`.
    - Why: the cursor's `&'tx [u8]` borrows into the memory-mapped B+tree; the borrow outlives the tx that pinned the mapping page.
    - Fix: `get`/cursor return `Bytes` via `Bytes::copy_from_slice(cursor_slice)` — Arc-backed, independent of the tx. The copy is acceptable on the trie cold path; the `into_tx()` consume makes the borrow-escape variant fail to compile.
    - Muscle: MDBX cursor returns are tied to the tx lifetime; storage-layer APIs return OWNED bytes, never borrows. Reapplies at: W42 txn cursor results, W92 block-stm parallel reads, W95 mini-db block cursor.

  - **(SENIOR) When `hp_encoding_no_collision` reports identical keys for the two paths:**
    - Symptom: `[1,2]` and `[1,2,0]` both encode to `0x12`; the second insert overwrites the first.
    - Why: the encoder packs nibbles two-per-byte with no length signal; a trailing zero nibble is indistinguishable from "no further nibbles."
    - Fix: Hex-Prefix encoding (Yellow Paper §C) — first byte carries a flag nibble (leaf/extension + odd-length bit) and, if odd, the first data nibble; remaining nibbles pack two-per-byte. `[1,2]` (even, 2 nibbles) and `[1,2,0]` (odd, 3 nibbles) differ in the flag byte → distinct keys.
    - Muscle: variable-length nibble keys MUST use length-aware (HP/compact) encoding; bare packing collides. Reapplies at: W21 RLP trie encoders, W31 mmap-queue wire schema (next, length-prefix framing), W32 proof verification.

  - **(SENIOR) When `restart_persistence` loses all 10k after reopen:**
    - Symptom: reopen the env, every `get` returns `None`.
    - Why: `commit` updated `dirty` housekeeping but never wrote to MDBX (or the env tx was abort-on-drop and `commit()` was never called).
    - Fix: `commit` opens an MDBX write tx, drains the sorted `dirty` into both tables, and `tx.commit()`s; clear `dirty` only on success.
    - Muscle: durability is the explicit commit's job; staging buffers vanish on drop. Reapplies at: W42 txn durability, W26 wal group-commit (the source of this discipline).
