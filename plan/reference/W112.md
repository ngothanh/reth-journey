  - **Section arc (the draft's skeleton — mirror the build's 3-phase discipline in prose):**
    - **§1 The problem the engine solves.** A single-instrument isolated-margin checker is a spreadsheet; a real venue must net risk across instruments per mark tick across every account, deterministically, fast enough to liquidate before insolvency. Name all three hardnesses (capacity / latency / domain) and assert the convergence-cell claim.
    - **§2 The capacity decision (jeff-dean).** The naïve full recompute = ~100k accounts × ~10 ticks/s = ~1M recomputes/s; at ~1µs/account that's ~1 CPU-second/second single-threaded, and any higher mark cadence blows it. *Therefore* incremental margin is mandatory, not a fallback; full recompute is reserved for circuit-breaker / param-change events; reads come from local applied state on the leader shard (no consensus round-trip); shard-by-account on `runtime-thread-per-core`.     - **§5 The determinism spine.** Integer-only math (no `f64` → cross-arch byte-identical); BTreeMap not HashMap (deterministic iteration → byte-identical snapshots); SequenceClock not wall-clock; the whole risk/liquidation core replays bit-identically across replicas because non-determinism is pushed to the edges. This is *why* the fund-never-runs-dry claim is checkable.
    - **§6 What I did NOT build, on purpose (the seams).** RWA-aware oracle seam; rolling-correlation / full-SPAN deferred to v1.5 behind the wired trigger; ADL/socialized-loss deferred to the tripwire seam. Each deferral framed as judgment.
    - **§7 Inheritance.** `risk-engine` consumes `oracle-mark` + `ledger-deterministic` + `runtime-thread-per-core`; `liquidation-engine` consumes `risk-engine` + `matching-engine` + `ledger-deterministic`. No primitive twice.
