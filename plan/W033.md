**[NEW] crate scaffolded**: `crates/epoch-gc/`. Mirror of `crossbeam-epoch`. **Epoch-based memory reclamation (EBR) is the foundation for every lock-free data structure that hands out pointers** — the skiplist memtable (W37), the lock-free price level (W74), txn MVCC version slots (W42), the runtime cross-shard retire queue (W84). EBR is the hardest piece of crossbeam. Plan budget: W33 Wed-Fri scaffold v0.1 (`Atomic`/`Owned`/`Shared`/`Guard`/`Collector` + loom + bench) → W37 Mon ship + the adversarial-loom consumer test.

**Why EBR exists** (the one-paragraph model — re-read before Wednesday): in any lock-free DS, removing a node creates a problem — other threads may still hold pointers to it. Free too early → use-after-free. Never free → leak. EBR tags each in-progress operation with a global epoch counter; a freed pointer is reclaimed only once every thread has either left its current epoch or advanced to a new one (a 3-epoch slack window E → E+2). The cost: per-thread bookkeeping + a 3-epoch lag on actual frees. The alternative — hazard pointers — uses per-thread "I'm reading this pointer" slots: simpler model, but every read pays a publish-and-fence. Crossbeam picks EBR for read-heavy structures. You build EBR here; you should be able to state both.

- [ ] **Build**: `crates/storage-trie/src/trie/path_compress.rs` — collapse single-child branch chains into extension nodes with hex-prefix encoding; expand on insert that splits a compressed path. (~total 180 min across 3 phases)
  - 🔧 **Why this matters**: mirrors `alloy-trie` / `reth-trie` extension-node handling. Path compression is what keeps the state trie's node count (and therefore the keccak-hash count per root computation) proportional to the number of *distinct prefixes*, not the key length. The 2-4 traps: (1) the hex-prefix flag byte off-by-one between leaf and extension and between even/odd nibble counts — a single wrong bit changes the node's keccak and so the **state root** (consensus-breaking); (2) splitting a compressed path on insert and forgetting to re-emit the residual extension; (3) round-trip RLP decode of a compressed path losing the odd-nibble marker. Downstream: W34 pruning walks compressed paths, W35-W36 state commitment hashes them, W43-W44 `storage-trie` v1.0 ships them. A wrong flag byte here is a wrong state root in three later crates — first-attempt impls fail ≥1 test below and the debug session is the lesson.

  #### Phase 3 — Make the tests pass, one failure at a time (~50 min)

  - **(NEWBIE) When `hex_prefix_four_cases_exact` reports `ext-odd high nibble 0x10` instead of `0x11`:**
    - Symptom: even-case bytes pass; odd cases off — the first nibble isn't packed into byte 0.
    - Why: you emitted the flag byte then started nibbles at byte 1 for *all* cases; the hex-prefix spec packs the first nibble into byte 0's low half when the count is odd.
    - Why precisely: `0x11` = flag nibble `0x1` (ext-odd) `|` first data nibble `0x1`.
    - Fix: branch on `nibbles.len() & 1`; for odd, `byte0 = (flag << 4) | nibbles[0]` and start the loop at index 1.
    - Muscle: a length-parity bit changes byte layout, not just metadata — encode it INTO the bytes, never alongside. Reapplies at: W34 pruning path encode, W43 `storage-trie` v1.0 node serialization.

  - **(SENIOR) When `insert_split_preserves_subtree` reports `get(old) == None`:**
    - Symptom: after the diverging insert, the original key is gone; only the new key resolves.
    - Why: `compress`/insert overwrote the extension's single `child` with the new branch instead of pushing the old child down into the new branch — exactly the D3 pre-mortem trace.
    - Fix: on divergence at depth `k`, emit `extension(common[..k]) → branch{ nibble[k_old]: old_child_with_residual, nibble[k_new]: new_leaf }`; re-wrap the old child in an `extension(residual)` if its residual is non-empty.
    - Muscle: splitting a compressed path is push-down, not overwrite — the existing subtree must descend into the new branch. Reapplies at: W37 skiplist tower split, W43 trie node restructuring.

  - **(EXPERT) When `compressed_root_equals_reference` reports `root diverged at seed 137`:**
    - Symptom: a specific seed's compressed root ≠ oracle root; most seeds pass.
    - Why: an edge case in R5 (empty residual after split, or a leaf vs extension flag) produced a structurally valid but canonically wrong node — its keccak differs.
    - Fix: handle the degenerate split (residual length 0 → child attaches directly to the branch slot, no extension node emitted); re-run the failing seed in isolation with a node-dump diff.
    - Cost avoided: a divergent state root is consensus-breaking — your node forks off mainnet on the first affected block. (bar (b): correctness, not latency — but a hard fork is the worst correctness bug in the stack.)
    - Muscle: trie equivalence is root-equality, and the canonical form has exactly one node shape per key set — degenerate cases must collapse to it. Reapplies at: W35-W36 state commitment, W43-W44 `storage-trie` v1.0 root verification.

    - Why: T2's re-pin reads `global_epoch` non-atomically with T1's advance; T2 thinks it's pinned in E while T1 has already freed E-1, T2's last-seen protection.
    - Fix: pinning reads `global_epoch` under SeqCst; if T2 observes the NEW epoch it's protected against prior-epoch frees. The pin-store / global-load order is load-bearing; T2's load must be SeqCst, not Acquire.
    - Cost avoided: a re-pin-race UAF that the W37 adversarial loom would surface at ~iteration 3000 — soak-only otherwise. **(bar (c) violation)**
    - Muscle: every "global coordinator + per-thread state" design has a quiescence-detection race — read the global state under the same ordering the coordinator writes it. Reapplies at: W74 matching-engine snapshot publish, W67 consensus-raft log-compaction barrier.

  - **(EXPERT) When `concurrent_advance_no_skipped_generation` reports a jump E→E+2:**
    - Symptom: two threads each successfully bump `global_epoch` (E→E+1 and E+1→E+2), but the second's quiescence check used the stale E view; a Local pinned in E+1 sees E+1's bag freed.
    - Why: **double-advance.** Both observe quiescence at E independently; both CAS succeed because they target different `expected` values; the second's check was pre-CAS.
    - Fix: `loop { quiescence_check(); CAS E→E+1; if ok { re-validate against any Local that re-pinned during the CAS } else { backoff; continue } }` — the re-validate after winning is the load-bearing line.
    - Cost avoided: a skipped generation frees a still-protected bag — UAF across all consumers; nondeterministic. **(bar (c) violation)**
    - Muscle: a coordinator CAS loop must re-validate AFTER winning the CAS, not only before. Reapplies at: W42 txn next-id allocation under burst, W67 consensus-raft compaction barrier.

  - **(EXPERT) When `guard_caches_local_pointer` shows ~50 ns/pin instead of ≤15 ns:**
    - Symptom: bench reports ~50 ns/pin; asm shows a TLS lookup (`__tls_get_addr` on Linux / segment-relative on macOS) at the top of every `pin()`.
    - Why: `pin()` calls `ThreadLocal::get()` on every invocation; TLS lookup is ~20-40 ns and dominates on a primitive consumers hit 10 M times/sec.
    - Fix: cache the `Local*` raw pointer in the `Guard` (or a TLS-stored `LocalHandle`) on first acquisition; subsequent pins use the cached pointer — one atomic store on a known address. TLS lookup happens once per Guard, not per pin.
    - Cost avoided: ~35-40 ns × 10 M/sec ≈ **0.35-0.4 of a core burned on TLS lookups**; this is the difference between EBR being free and EBR being the bottleneck. **(bar (c) violation)**
    - Muscle: TLS lookup is too slow for a hot-path primitive — cache the per-thread pointer in the RAII handle. Reapplies at: W42 txn per-thread state, W74 matching-engine per-shard state, W84 per-core reactor state.

  - **(EXPERT) When `sustained_load_bounded_memory` reports unbounded growth (RSS +100% over 60 s):**
    - Symptom: a thread pins, accumulates 10 MB into its bag, never unpins; advance can never reclaim; RSS climbs.
    - Why: a worker holds a guard across an `await` (or forgets to drop it); the local bag accumulates; advance is blocked on this Local's pin.
    - Fix: ship `Guard::flush()` to push the bag to the collector mid-pin; document "never hold a guard across `await`"; for delete-heavy paths (W37 skiplist) call `flush()` every ~1024 ops.
    - Cost avoided: OOM under sustained churn — a memory-leak class bug that a 60 s soak catches but a unit test never does. **(bar (c) violation)**
    - Muscle: EBR amortization assumes short-lived guards; long-lived guards need an explicit drain hook. Reapplies at: W37 delete-heavy workloads, W42 MVCC under long txns.
