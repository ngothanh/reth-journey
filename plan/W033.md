**[NEW] crate scaffolded**: `crates/epoch-gc/`. Mirror of `crossbeam-epoch`. **Epoch-based memory reclamation is the
foundation for every lock-free data structure that hands out pointers** — the skiplist memtable (W37 → W38), the
lock-free price level (W74), and any future "give me a pointer, I'll defer-free it when nobody's looking" primitive.
EBR is the hardest piece of crossbeam. Plan budget: W33 Wed-Fri scaffold + W37 Mon ship.

**Why EBR exists** (read before Wednesday): in any lock-free DS, removing a node creates a problem — other threads
may still hold pointers to it. Free too early → UAF. Never free → leak. EBR solves this by tagging each "in-progress
operation" with a global epoch counter; a freed pointer is only reclaimed once every thread has either left its
current epoch or advanced to a new one. The cost: per-thread bookkeeping plus a 3-epoch lag on actual frees. The
alternative — hazard pointers — uses per-thread "I'm reading this pointer" slots; simpler model, but every read pays
a fence-and-publish overhead. Crossbeam picks EBR for read-heavy data structures; you should understand both.

  #### Phase 1 — Problem, requirements, design (~45 min, no code yet)

  - **The problem this primitive solves**: every lock-free DS hands out pointers from a `load()` that callers then
    dereference; the GC must prove the pointer is still live at the moment of dereference. Lifetimes are that proof
    — `Shared<'g, T>` carries the guard's lifetime so the borrow checker rejects any deref past `drop(guard)`. Get
    the lifetime plumbing wrong and you've replaced miri with hope.

  - **Requirements** — write in `crates/epoch-gc/notes/33_atomic_design.md`:
    - R1. `Atomic<T>::load(&'g Guard) -> Shared<'g, T>` — the load is gated on a guard, the result borrows the
      guard's lifetime.
    - R2. `Shared<'g, T>::deref(&self) -> &'g T` — the deref result outlives `&self` and is bound to `'g`. Code
      that drops the guard then derefs the `Shared` MUST fail to compile.
    - R3. Tagged-pointer support: low 2-3 bits of the pointer encode user data (e.g. "marked for deletion"). Every
      deref/CAS masks the tag before issuing the actual load/store; the masked address must satisfy
      `align_of::<T>()`.
    - R4. `Owned<T>` is a single-owner heap pointer; `Atomic<T>::compare_and_set(curr, Owned<T>, ord)` consumes
      `Owned` by value on success and returns it on failure. Reusing the same `Owned` after a successful CAS MUST
      fail to compile.
    - R5. `Shared<'g, T>` is `Copy` (it's a borrow); `Owned<T>` is NOT `Copy` (it owns).
    - R6. CAS via `compare_exchange_weak` with explicit `Ordering` parameters — no defaults; callers pick.
    - R7. miri-clean: `cargo +nightly miri test -p epoch-gc atomic` — zero UB on the deref/CAS test suite.

  - **Design walk-through** — answer each in your design doc; *no peeking* at `crossbeam_epoch::atomic` until Phase 3:
    - D1. The lifetime `'g` lives where? On `Shared`, on `Guard`, on `Atomic`? Draw the relationship: which type
      produces `'g`, which type carries it, which type consumes it.
    - D2. Why is `Shared: Copy` correct but `Owned: !Copy` correct? What invariant does each preserve?
    - D3. Tagged pointer layout: how many tag bits can you steal from a `T` with `align_of::<T>() == 8`? What
      about `align_of::<T>() == 4`? Where do you mask, where do you set?
    - D4. The CAS API: write the exact signature of `Atomic<T>::compare_and_set(&self, current: Shared<'g, T>,
      new: Owned<T>, ord: (Ordering, Ordering)) -> Result<Shared<'g, T>, (Owned<T>, Shared<'g, T>)>`. Why is
      `new` consumed? Why does the error case return `Owned<T>` back to the caller?
    - D5. **Pre-mortem (the load-bearing question)**: write the 5-step UAF interleaving showing exactly what
      lines of code dereference a freed pointer when `Shared::deref` returns `&T` instead of `&'g T`. If you
      cannot write it, you do not yet understand the safety story — go back to R2.
    - D6. Why does `compare_exchange_weak` (vs `_strong`) belong in this primitive? When would you escalate to
      `_strong`?

  #### Phase 3 — Make the tests pass, one failure at a time (~125 min)

  - **When `deref_after_drop_guard_fails_to_compile` PASSES (i.e. compiles successfully when you expected it to fail):**
    - Symptom: `trybuild` reports the test compiled; the load-bearing invariant doesn't exist. UAF visible at
      runtime via miri.
    - Why: `Shared::deref(&self) -> &T` instead of `&'g T`. The `'g` is on the type but not propagated to the
      return; the result borrows `&self`, not the guard.
    - Fix: write `impl<'g, T> Shared<'g, T> { fn deref(&self) -> &'g T { unsafe { &*self.masked_ptr() } } }`. The
      lifetime annotation on the return is the load-bearing safety net.
    - Muscle: lifetimes are the proof system for "this pointer is reclaim-safe right now." If your `unsafe`
      block can't be expressed as "I have a `&'g`-tagged thing, so the guard must still be alive," your
      reclamation is unsound. Reapplies at: skiplist node access (W37), price-level order traversal (W74), any
      future lock-free DS.

  - **When `tagged_pointer_round_trip` reports a miri "unaligned access" error:**
    - Symptom: miri fires "memory access at address …with alignment 1, but alignment 8 is required"; the deref
      tried to load through the still-tagged pointer.
    - Why: `deref` (or CAS) used the raw pointer without masking the tag bits. Crossbeam steals the low bits;
      a deref of `0x1234_5678_ABCD_EF01` (last hex digit has tag bits) targets an unaligned `T`.
    - Fix: every deref starts with `let ptr = self.0 & !TAG_MASK;`. Same for the CAS `expected`/`new`
      arguments — mask both before issuing `compare_exchange_weak`. Provide `Shared::tag()` and
      `Shared::with_tag(usize)` as explicit accessors so callers never touch the raw `usize`.
    - Muscle: tag bits live in the pointer's low bits; they MUST be masked at every deref/CAS boundary.
      Reapplies at: W37 skiplist tower entry's marker bit, W42 MVCC version slot's lock bit, W74
      matching-engine order-state flag bit.

  - **When `cas_success_consumes_owned` PASSES (the test that should fail to compile actually compiles):**
    - Symptom: `trybuild` reports the test compiled; you can reuse an `Owned` after a successful CAS.
    - Why: `compare_and_set` takes `&Owned<T>` (by reference) instead of `Owned<T>` (by value), so the caller's
      `Owned` is not consumed. On success, the heap pointer is now owned by the `Atomic` AND still in the
      caller's `Owned` — double-free at the next drop.
    - Fix: `fn compare_and_set(&self, current: Shared<'g, T>, new: Owned<T>, …) -> Result<Shared<'g, T>,
      (Owned<T>, Shared<'g, T>)>` — `new` is consumed by value; on success it's gone; on failure it's returned
      in the Err. The compiler enforces the ownership transfer.
    - Muscle: ownership-transferring APIs consume by value; reuse-after-transfer is a type error, not a runtime
      bug. Reapplies at: W37 skiplist Node insertion (Owned → Atomic), W42 MVCC version chain extension.

  - **5-year failure mode** (write in `notes/33_atomic_followup.md` after green): when `crossbeam-epoch` adopts
    hazard pointers as an alternative reclamation strategy (already in development), the `Shared<'g, T>` lifetime
    bound is replaced by a per-thread hazard slot. State the migration: `Shared` becomes parameterized on a
    reclamation strategy `S: ReclaimStrategy` instead of a guard lifetime.

  #### Phase 1 — Problem, requirements, design (~45 min, no code yet)

  - **The problem this primitive solves**: a `Guard` is the proof-of-protection that EBR hands out to readers.
    Pinning publishes "I'm reading in epoch E"; the collector cannot reclaim anything freed in E until all
    pinners observe E+2. Without the SeqCst fence between pin-store and pointer-read, the CPU reorders the
    pointer read above the pin store — the collector sees no pin, frees the data, the reader UAFs.

  - **Requirements** — write in `crates/epoch-gc/notes/33_guard_design.md`:
    - R1. `pin() -> Guard` registers the current thread in the global epoch counter. Drop unpins.
    - R2. **Fence discipline**: the pin store and any subsequent `Atomic<T>::load` must be separated by a SeqCst
      fence. Loom under SeqCst model finds the UAF if missing; loom under Acquire/Release hides it.
    - R3. **Defer placement**: `Guard::defer_destroy(Shared)` enqueues the destroy into the **current** epoch's
      bag (E), drained when global epoch advances to E+2 (3-bag rotation). Defers into E+1 or E-1 are UAF-prone.
    - R4. **Reentrant pins**: `pin()` may be called nested (outer fn pins, inner helper pins again). The inner
      drop must NOT unpin while the outer is still holding. Pin is a per-thread counter, not a flag.
    - R5. **Tagged pointer hygiene**: `defer_destroy` masks tag bits before scheduling the free. A
      `dealloc(misaligned_ptr)` is UB.
    - R6. `Guard: !Send + !Sync` — a Guard's protection is bound to the thread that pinned. Cross-thread move is
      UB.
    - R7. Loom-green under SeqCst model: 4-thread defer/pin/advance race shows zero UAF + zero double-free.

  - **Design walk-through** — answer each:
    - D1. What atomics back the pin counter? A per-thread `AtomicUsize` ("currently pinned in epoch X, or
      unpinned") + a global `AtomicUsize` (the current epoch). Draw the read/write pattern.
    - D2. Why SeqCst between pin-store and Atomic-load? Write the bad reordering as a 5-step interleaving;
      identify the line that the CPU reorders.
    - D3. The 3-bag rotation: name them (current, prior, prior-prior) and write the rule for which bag a defer
      goes into at epoch E, and which bag is drained at epoch E+2.
    - D4. Reentrant pin counter — `pin()` increments per-thread counter, decrements on drop; only the
      0→1 transition publishes the pin in the global view, only the 1→0 transition publishes the unpin. What
      type holds this? Why must it be thread-local, not shared?
    - D5. **Pre-mortem (load-bearing)**: write the 5-step interleaving showing a UAF when the SeqCst fence is
      missing from `pin()`. Then write a second interleaving showing the bug when defers go into epoch E+1
      instead of E.
    - D6. `Guard: !Send` enforcement — is `PhantomData<*mut ()>` enough? Or does the type need an explicit
      `impl !Send`?
  - **Output**: `notes/33_guard_design.md` with R1–R7, D1–D6, both bad interleavings.

  #### Phase 3 — Make the tests pass, one failure at a time (~125 min)

  - **When `loom_pin_then_load_no_uaf` reports a 5-7 step UAF interleaving:**
    - Symptom: loom prints `[T1: store pin=E] → [T2: load global_epoch=E (no pinners yet visible)] → [T2:
      advance to E+1 → free X] → [T1: load Atomic → X (UAF)]`. The pin-store hasn't propagated by the time T2
      checks for pinners.
    - Why: **the missing fence.** Pinning store and the global-epoch read are separated only by program order,
      not a SeqCst barrier. The CPU (or compiler) reorders the Atomic load above the pin-store, so the
      collector observes no pin.
    - Fix: `pin()` does `epoch.store(active_epoch, SeqCst); fence(SeqCst);`. Both pieces are load-bearing — the
      Release store alone is insufficient because the global-epoch load on the collector side needs the
      transitive ordering. **No shortcut**.
    - Muscle: SeqCst is expensive but here it's *correctness*, not perf. Weakening EBR's pin/advance fences is
      the single most common EBR bug in the wild. Reapplies at: every future EBR-protected DS, the lock-free
      price level (W74).

  - **When `loom_defer_into_current_epoch_safe` reports a UAF during the defer's execution:**
    - Symptom: loom shows thread A defers a destroy at epoch E; the collector immediately advances to E+1; A's
      defer fires while thread B is still pinned in E and dereferencing the same pointer.
    - Why: **defer into the current epoch, not the next.** You queued the defer into the bag for E+1, which
      gets drained at E+3 — but the safety window was supposed to be "drained no earlier than E+2".
      Effectively, the defer fired one epoch too early relative to the global view.
    - Fix: defers always go into the *current* epoch's bag (the one for E); that bag is only drained two epochs
      later (E+2). The "3 garbage bags rotating" pattern exists for exactly this reason — slack so observers
      can drain.
    - Muscle: EBR's safety window is E → E+2; defer placement determines the start of that window. Reapplies
      at: every future EBR-protected DS (W37 skiplist, W42 MVCC).

  - **When `reentrant_pin_counter` shows the observer-after-drop-inner sees unpinned:**
    - Symptom: outer `pin()` returns guard A; inner `pin()` returns guard B; drop B; observer thread now sees
      this thread as unpinned even though A still exists. A's protected pointer is freed underneath A.
    - Why: pin is a boolean flag rather than a counter. The inner `pin()` was a no-op set; the inner drop
      published "unpinned" prematurely. The outer code reads a UAF.
    - Fix: pin is a per-thread counter (TLS `Cell<u32>`). `pin()` increments; only the 0→1 transition does the
      global-epoch publication. Drop decrements; only the 1→0 transition does the unpublication.
    - Muscle: any RAII handle that can be reentrantly acquired needs a counter, not a flag. Reapplies at: W42
      txn nested begin/commit, W74 matching-engine nested order-book lock.

  - **When `defer_destroy_masks_tag_bits` reports miri "deallocation on misaligned pointer":**
    - Symptom: `defer_destroy(Shared::with_tag(3))` schedules a free of the tagged address; miri fires on
      `dealloc(0x...0003)` with "alignment 8 required".
    - Why: the tag bits are still set; the destroy callback runs `dealloc` on the tagged pointer.
    - Fix: mask the tag before scheduling free: `defer_destroy(s)` does `defer_unchecked(|| unsafe {
      Box::from_raw(s.masked_ptr() as *mut T) })`. Belt-and-suspenders: `debug_assert!(masked_ptr.is_aligned())`
      at defer-time.
    - Muscle: tag bits at every API boundary (deref, CAS, **and** defer_destroy) — mask everywhere or pay UB
      somewhere. Reapplies at: W37 skiplist mark-delete defer, W42 MVCC version-slot defer.

  - **5-year failure mode** (write in `notes/33_guard_followup.md` after green): when wait-free EBR (or
    hazard pointers) replaces the global-epoch design, the SeqCst fence is replaced by a per-thread
    publish-then-fence on a hazard slot. State the migration: `Guard` carries a hazard-slot index instead of
    a pin counter; the fence is per-load, not per-pin.

  #### Phase 1 — Problem, requirements, design (~45 min, no code yet)

  - **The problem this primitive solves**: how does a global coordinator know when "every thread has left epoch
    E" so it can safely reclaim E's bag? Quiescence detection. The naive approach (one thread checks all locals,
    bumps global) breaks under concurrent advancers; the CAS-loop approach must re-check quiescence after winning
    the CAS, otherwise it skips a generation.

  - **Requirements** — write in `crates/epoch-gc/notes/33_internal_design.md`:
    - R1. `global_epoch: AtomicUsize` is monotonically increasing; advances by exactly 1 per success.
    - R2. `advance()` runs quiescence check (every Local's pin-epoch is either unpinned or equals
      global_epoch), then CAS-bumps global_epoch, then re-validates (a Local can pin between the check and the
      CAS).
    - R3. **No skipped generations**: two threads calling `advance()` concurrently must collectively advance by
      1 (not 2). Otherwise some Local pinned in the skipped epoch UAFs.
    - R4. **No unbounded bag growth**: if a thread pins forever (or holds a guard across `await`), the system
      must still bound memory. `Guard::flush()` is the escape hatch; document the failure mode.
    - R5. **TLS lookup not on hot path**: `Local*` pointer is cached in the Guard, not re-looked-up per pin.
      The hot path is one atomic store + one fence (R2 from guard task).
    - R6. **Quiescence races re-pin**: a thread observed as unpinned can re-pin before advance fires. The new
      pin must observe the NEW epoch (or quiescence re-check catches it).
    - R7. Bounded memory under sustained workload: 60 s of 100k ops/sec with churn keeps RSS within 10% of
      steady-state.

  - **Design walk-through** — answer each:
    - D1. The quiescence check: write it in pseudocode. What does it return? What does it iterate? How
      expensive is it (count atomic loads)?
    - D2. The CAS loop: write `advance()` as `loop { check_quiescence(); CAS global from E to E+1; if success
      { re-validate; break } else { backoff; continue } }`. Why the re-validate?
    - D3. The double-advance bad interleaving: two threads see all locals quiescent at E; both attempt CAS
      E→E+1; one wins, one loses. The loser **must** retry from quiescence check, not retry the CAS to E+1
      (which would now advance E+1→E+2 with a possibly-stale check).
    - D4. The "pin between check and CAS" interleaving: T_advancer checks (all quiescent), T_pinner pins in
      epoch E, T_advancer CAS-bumps to E+1, drains E-1's bag. T_pinner reads pointer freed in E-1's bag.
      Where does the re-validation catch this?
    - D5. `Guard::flush()` semantics: drain the current bag into the global queue; subsequent defers go into
      the next epoch's bag. When is this necessary? Why is "hold a guard across `await`" the canonical bug?
    - D6. `ThreadLocal<Local>`: explain the access cost. Why is `Local*` raw-pointer cached in `Guard`?
    - D7. **Pre-mortem (load-bearing)**: write the double-advance interleaving (R3) as a 7-step trace
      showing exactly how `global_epoch` skips from E to E+2 and which Local's bag becomes a UAF.

  - **When `loom_advance_vs_pin_re_pin_safe` reports a UAF on the re-pin path:**
    - Symptom: loom prints `[T1: check quiescence (T2 unpinned)] → [T2: pin in epoch E] → [T1: advance E→E+1
      and drain E-1's bag] → [T2: load pointer from E-1 — freed]`. The unpinned-but-about-to-pin thread.
    - Why: T2's re-pin reads `global_epoch` non-atomically with T1's advance. T2 thinks it's pinned in E, but
      T1 has freed E-1's bag — and T2 was last seen with E-1 protection.
    - Fix: pinning reads `global_epoch` *under SeqCst*; if T2 observes the new epoch (E+1), it's protected
      against frees from prior epochs (E-1 was the freed bag). The pin-store / global-load order is
      load-bearing. T2's load of `global_epoch` must be SeqCst, not Acquire.
    - Muscle: every "global coordinator + per-thread state" design has a quiescence-detection problem. EBR's
      advance is the canonical case. Reapplies at: matching-engine snapshot publishing (W74), consensus-raft
      log compaction barrier (W67).

  - **When `sustained_load_bounded_memory` reports unbounded growth (RSS climbs 100%+ over 60 s):**
    - Symptom: a thread pins, allocates 10 MB into its garbage bag, never unpins; memory grows unbounded;
      `advance()` can never reclaim.
    - Why: the worker holds a guard across an `await` (or simply forgets to drop it); the local bag
      accumulates; advance is blocked on this Local's pin.
    - Fix: ship a `Guard::flush()` API that pushes the bag to the collector mid-pin; document the failure mode
      for callers who hold guards across `await` points (don't). For known-quiesced paths (W37 skiplist
      delete-heavy), call `flush()` every ~1024 ops.
    - Muscle: EBR's reclamation amortization assumes guards are short-lived; long-lived guards need explicit
      drain hooks. Reapplies at: W37 skiplist delete-heavy workloads, W42 MVCC version reclamation under long
      txns.

  - **When `guard_caches_local_pointer` shows ~50 ns/pin instead of ~10 ns:**
    - Symptom: bench reports ~50 ns/pin; asm shows a TLS lookup (`__tls_get_addr` on Linux, segment-relative
      on macOS) at the top of every `pin()`.
    - Why: `pin()` looks up `Local` via `ThreadLocal::get()` on every call. TLS lookup is ~20-40 ns; on the hot
      path of a primitive that callers invoke 10 M times/sec, this dominates EBR overhead.
    - Fix: cache the `Local*` raw pointer in the `Guard` struct on first acquisition. Subsequent pins in the
      same scope (reentrant pins, fast-path no-ops) use the cached pointer — one atomic store on a known
      address. The TLS lookup happens once per Guard, not once per pin.
    - Muscle: TLS lookup is too slow for hot-path primitives — cache the per-thread pointer in the RAII
      handle. Reapplies at: W42 txn manager per-thread state, W74 matching-engine per-shard state.

  - **When `concurrent_advance_no_skipped_generation` reports a jump from E to E+2:**
    - Symptom: 4 threads call `advance()`; two threads each successfully bump `global_epoch` — one E→E+1 and
      one E+1→E+2 — but the second's quiescence check was based on the E view (stale). A Local still pinned in
      E+1 now sees E+1's bag freed.
    - Why: **double-advance.** Two threads observe quiescence at E independently; both attempt CAS; both
      succeed because they targeted different `expected` values (E→E+1 and E+1→E+2). The second's quiescence
      check was based on the pre-CAS view; it's stale.
    - Fix: `advance()` is `loop { quiescence_check(); CAS global E→E+1; if success { re-validate against any
      Local that re-pinned during the CAS } else { backoff; continue } }`. The re-validate after success is the
      load-bearing line; without it, the second advancer races ahead with stale info.
    - Muscle: a coordinator CAS loop must re-validate after winning the CAS, not before. Reapplies at: W42 txn
      next-id allocation under burst, W67 consensus-raft log-compaction barrier.
