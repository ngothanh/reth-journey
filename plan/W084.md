  - *Mental model*: replay re-derives state from the durable Archive by streaming recorded frames byte-identically; mmap IS the data, so the iterator hands out borrowed slices, never copies. Used by VOPR crash-replay and follower catch-up.
  - *Contract*: `struct ReplayStream<'cycle>` holding `Arc<RotationIndex>` + cursor; `fn replay(&self, from: ArchiveOffset, to: ArchiveOffset) -> Result<ReplayStream, ReplayErr>` (rejects mid-frame offsets at construction, R4); `impl Iterator for ReplayStream { type Item = Result<&[u8], ReplayErr>; }` where the slice borrows the underlying mmap (R6). `to == LATEST` follows the recording head (R9).
  - *Back-of-envelope* (bar (c)): target 1.5M frames/s. A 256 B memcpy ≈ 80 ns (AVX2, ~1 byte/cycle warm) → at 1.5M frames/s = ~120 ms/sec spent copying = a hard 12% tax, and it evicts the real mmap data from L1. Per-frame `madvise` math: one `madvise` syscall ≈ 300 ns; a 300 ns/frame syscall ALONE caps at 1e9/300 ≈ 3.3M frames/s — but it does not run alone. Combined per-frame cost = read+decode (~150 ns: a cold-ish mmap touch + len/header decode) + memcpy (~80 ns) + madvise (~300 ns) ≈ 530 ns/frame → 1e9/530 ≈ **1.9M f/s ceiling**, and once readahead misses (no SEQUENTIAL hint persisting) page-fault stalls pull the realized rate down to **~1M f/s** — below the 1.5M target. Per-frame madvise is ~450 ms/sec of pure syscall (300 ns × 1.5M) on top of the read, so it dominates the budget. Cliff ratio: per-frame madvise (300 ns) vs once-per-file amortized (~0 ns/frame) = the whole gap between bandwidth-bound (≥1.5M f/s) and syscall-bound (~1M f/s).
  - **Requirements** R1..R10 — write in `crates/messaging-aeron/notes/84_replay_design.md`:
    - R1. `replay(from, to)` yields exactly frames in [from, to) — no skip, no dup.
    - R2. Byte-identical to original publication bytes (including header).
    - R3. Replay is read-only — never mutates Cycle; safe concurrent with recording.
    - R4. ArchiveOffset falling between frame boundaries rejected at construction (`BadOffset`).
    - R5. Replay throughput ≥1.5M frames/s on M2 NVMe.
    - R6. Zero-copy: `Iterator::Item = Result<&[u8], ReplayErr>` returns slice INTO mmap.
    - R7. `madvise(SEQUENTIAL)` called ONCE per Cycle file, not per `next()`.
    - R8. Cross-rotation cursor transparent: switch underlying Cycle file at boundary.
    - R9. Tail-of-recording vs hot-recording: if `to == LATEST`, follow recording head.
    - R10. Replay during retention purge: rotation index pins files referenced by active replays.
  - **Design walk-through** D1..D7 — answer in the design doc; no peeking at the upstream Aeron source until Phase 3:

Property table for the payload-return primitive: `&[u8] into mmap` (Sync? borrows mmap; latency 0 copy; allocs 0; blocking no) vs `Vec<u8>` (owns; +malloc ~50 ns; allocs 1/frame) vs `&self.scratch[..len]` (borrows scratch; +memcpy ~80 ns; allocs 0 but L1-polluting).
    - D2. **Pre-mortem (memcpy into scratch) — load-bearing:** write the 4-5 line trace. `next()`: read len at cursor → `ptr::copy_nonoverlapping(mmap+cursor+8, scratch, len)` → return `&scratch[..len]` → cursor += 8+len. At 256 B that copy is ~80 ns; at 1.5M f/s = ~120 ms/sec, and scratch is hot in L1 while the real mmap data (read once) is not.
    - D3. **Pre-mortem (madvise per next) — load-bearing:** trace. `next()`: `madvise(ptr, page, MADV_SEQUENTIAL)` (~300 ns syscall) → read frame. At 1.5M f/s = ~450 ms/sec pure syscall; throughput caps ~1M f/s.
    - D4. **Pre-mortem (cursor accuracy):** caller passes `from` landing mid-frame; `next()` reads a "len" from payload bytes → garbage length → out-of-bounds or absurd slice. Snap-or-reject: reject with `BadOffset` at construction (R4).
    - D5. **Pre-mortem (partial frame at boundary) — cross-primitive with W77:** replay concurrent with recording reads a frame whose len is stored but payload not yet flushed → dereferences unwritten bytes. Recorder writes payload BEFORE len with `Release`; reader `Acquire`-loads len; partial encoded as negated-length sentinel (the SAME pattern as W77 term_buffer).
    - D6. **Pre-mortem (cross-rotation cursor):** replay spans a rotation; reader holds the old file mmap. `ReplayStream` holds `Arc<RotationIndex>`; on hitting end-of-cycle, mmap the next Cycle file transparently (R8); this is the ONE place scratch is legitimately needed (a frame straddling two files).
    - D7. **Pre-mortem (retention purge):** replay reading file F while retention deletes F → UAF on mmap. Rotation index pins files referenced by active replays (refcount via the `Arc`), retention skips pinned files (R10).
    - Dy. **Anti-shortcut audit:** "obvious reach" for payload = `Vec<u8>` (1 malloc/frame, disqualifying); for prefetch = `madvise` per read (300 ns/frame, disqualifying); for partial-frame = "just check len != 0" (races, torn reads). Each is wrong HERE because the bar is 1.5M f/s zero-alloc.

  #### Phase 3 — Make the tests pass, one failure at a time (~140 min)

  Ordered newbie→expert — the ladder you actually walk.

  - **(NEWBIE) When `replay_bad_offset_rejected` reports garbage iteration instead of `BadOffset`:**
    - Symptom: test panics with an absurd slice length (e.g. 3.8 GB) or OOB, not a clean `Err(BadOffset)`.
    - Why: `replay()` accepted a mid-frame offset; the first `next()` read payload bytes as a length header.
    - Fix: validate at construction — walk/index the frame table to confirm `from` and `to` sit on frame boundaries; return `Err(ReplayErr::BadOffset)` otherwise.
    - Cost avoided: a malformed-length read → OOB slice → process crash (availability incident in VOPR replay).
    - Muscle: validate cursor positions against structure at the boundary, never trust a caller offset mid-stream. Reapplies at: W87 VOPR replay-from-seed offsets, W92 ledger io_uring replay cursor.

  - **(SENIOR, perf) Expect to hit (perf) #1 — `replay_zero_copy_returns_slice_into_mmap` reports a scratch pointer (bar (c) violation):**
    - Symptom: assertion fails — frame ptr is outside mmap; bench shows ~8M f/s "internal" but the zero-copy test fails; flame graph shows `__memcpy_avx2_unaligned`.
    - Why: naive `next()` reads len then `ptr::copy_nonoverlapping` into `self.scratch`, returns `&self.scratch[..len]` — ~80 ns memcpy/frame at 256 B; at 1.5M f/s = ~120 ms/sec, and scratch is hot in L1 while the real mmap data is wasted L1 footprint.
    - Fix: return `&[u8]` directly into mmap — `let payload = unsafe { slice::from_raw_parts(self.cycle.as_ptr().add(self.cursor.0 + 8), len) };`. Lifetime ties the slice to the iterator; caller must not hold it across `next()`. Scratch is used ONLY for the cross-rotation straddle case (D6).
    - Cost avoided: ~80 ns/frame × 1.5M f/s = ~120 ms/sec (12% tax) + restores L1 to the mmap data (bar (c) violation: copy on the replay hot path).
    - Muscle: replay is zero-copy by construction — mmap IS the data, never buffer to copy from. Reapplies at: W83 archive recording (write into mmap directly), W90 marketdata-kernelbypass receive (zero-copy AF_XDP), W92 ledger v1.0 io_uring replay reads.

  - **(EXPERT, perf) Expect to hit (perf) #2 — `replay_madvise_once_per_file_not_per_next` reports per-frame madvise (bar (c) violation):**
    - Symptom: madvise-counter shows ≈100k calls for 1 file; `strace -c` has `madvise` dominating; throughput caps at ~1M f/s despite a warm mmap.
    - Why: per-frame `madvise(ptr, page, MADV_SEQUENTIAL)` is a ~300 ns syscall per frame; at 1.5M f/s = ~450 ms/sec syscall.
    - Fix: call `madvise(MADV_SEQUENTIAL)` ONCE per Cycle file at `ReplayStream` construction over the whole mmap range; the kernel keeps the hint for the mmap lifetime — readahead persists.
    - Cost avoided: ~300 ns × 1.5M = ~450 ms/sec; restores replay to NVMe-bandwidth-bound throughput (bar (c) violation: syscall in the inner loop).
    - Muscle: kernel hints amortize over LARGE ranges, never per-element (the W77 Mon `madvise WILLNEED` lesson). Reapplies at: W84 cross-rotation file transition (madvise once per NEW file), W92 ledger v1.0 io_uring (register buffers ONCE, reuse forever).

  - **(EXPERT, cross-primitive) When `replay_concurrent_with_recording_no_torn_frame` reports torn frames:**
    - Symptom: 10s run shows ~5 frames with a corrupt header (len set but payload not yet flushed); intermittent.
    - Why: recorder writes len BEFORE payload (or with no memory ordering); reader sees the len, dereferences payload pointer to unwritten bytes.
    - Fix: recorder writes payload BEFORE len with `Release` on the len-store; reader `Acquire`-loads len; partial frame encoded as a negated-length sentinel → reader spins/retries. Same negated-length sentinel as W77 term_buffer.
    - Cost avoided: silent state corruption in VOPR replay — a torn frame fed to the SM produces a divergent (and unreproducible) history.
    - Muscle: any concurrent reader/writer over shared bytes uses a negated-length sentinel + Release/Acquire. Reapplies at: W77 term-buffer reader, W82 Image position cursor, W83 archive frame integrity (the symmetric write side).

  - **(EXPERT) When `replay_during_retention_purge_pinned_files` UAFs or deletes a live file:**
    - Symptom: replay returns garbage / segfaults mid-stream when retention runs concurrently; miri/ASan flags use-after-munmap.
    - Why: retention deleted (munmap+unlink) a Cycle file an active `ReplayStream` still holds a cursor into.
    - Fix: `ReplayStream` holds `Arc<CycleFile>`; retention checks `Arc::strong_count`/a pin-set and skips files referenced by active replays (R10).
    - Cost avoided: UAF crash under the exact ops condition (replay + retention) you can't reproduce in unit tests.
    - Muscle: lifetime of a borrowed resource outlives its reclaimer — pin via refcount, never delete under a live reader. Reapplies at: W88 consensus-vsr follower catch-up vs log truncation, W92 ledger snapshot purge vs replay.
