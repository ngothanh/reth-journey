  #### Phase 1 — Problem, requirements, design (~60 min, no code yet)

  - **Requirements** — write in `crates/messaging-aeron/notes/84_replay_design.md`:
    - R1. `replay(from, to)` yields exactly frames in [from, to) — no skip, no dup.
    - R2. Byte-identical to original publication bytes (including header).
    - R3. Replay is read-only — never mutates Cycle; safe concurrent with recording.
    - R4. ArchiveOffset falling between frame boundaries rejected at construction.
    - R5. Replay throughput ≥1.5M frames/s on M2 NVMe.
    - R6. Zero-copy: `Iterator::Item = Result<&[u8], ReplayErr>` returns slice INTO mmap.
    - R7. madvise(SEQUENTIAL) called ONCE per Cycle file, not per next().
    - R8. Cross-rotation cursor transparent: switch underlying Cycle file at boundary.
    - R9. Tail-of-recording vs hot-recording: if `to == LATEST`, follow recording head.
    - R10. Replay during retention purge: rotation index pins files referenced by active replays.

  - **Design walk-through**:
    - D1. Sketch ReplayStream + ArchiveOffset.
    - D2. **Pre-mortem (memcpy into scratch):** naive next() reads len then memcpy payload into scratch; ~80 ns/frame at 256 B AVX2. At 1.5M frames/s = ~120 ms/sec memcpy. Walk through zero-copy `&[u8]` directly into mmap.
    - D3. **Pre-mortem (madvise per next):** ~300 ns syscall per page; at 1.5M frames/s = ~450 ms/sec. Walk through once-per-file madvise.
    - D4. **Pre-mortem (position cursor accuracy):** caller passes offset landing mid-frame; replay returns malformed bytes. Snap to nearest frame boundary OR reject with BadOffset.
    - D5. **Pre-mortem (partial frame at boundary):** replay concurrent with recording reads frame whose len is set but payload not yet flushed. Recorder writes payload BEFORE len with Release ordering; reader uses Acquire on len.
    - D6. **Pre-mortem (cross-rotation cursor):** replay spans rotation; reader holds old file open after rotation. ReplayStream holds Arc<RotationIndex>; mmap next file transparently.
    - D7. **Pre-mortem (retention purge):** replay reading file F while retention deletes F. Rotation index pins files referenced by active replays.

  - **Output**: `notes/84_replay_design.md` with R1–R10 + D1–D7.

  #### Phase 3 — Make the tests pass, one failure at a time (~140 min)

  - **When `replay_zero_copy_returns_slice_into_mmap` reports memcpy:**
    - Symptom: bench shows 8M frames/s replay; flame graph shows `__memcpy_avx2_unaligned`.
    - Why: naive next() reads len + memcpy payload into self.scratch + returns `&self.scratch[..len]` — ~80 ns memcpy/frame at 256 B; at 1.5M frames/s = ~120 ms/sec memcpy. Scratch hot in L1 but actual mmap data being read sequentially (wasted L1 footprint).
    - Fix: return `&[u8]` directly into mmap — `let payload: &[u8] = unsafe { from_raw_parts(self.cycle.as_ptr().add(self.cursor.0 as usize + 8), len) };`. Zero-copy. Caller must NOT hold slice across next() calls (lifetime constrained to iterator). Scratch ONLY used for cross-rotation case.
    - Cost avoided: ~80 ns/frame × 1.5M frames/s = ~120 ms/sec; restores L1 cache to mmap data.
    - Muscle: replay is zero-copy by construction — mmap IS the data, never buffer to copy from. Reapplies at: W83 archive recording (write into mmap directly), W92 ledger v1.0 io_uring replay reads, W90 marketdata-kernelbypass receive (zero-copy AF_XDP).

  - **When `replay_madvise_once_per_file_not_per_next` reports per-frame madvise:**
    - Symptom: strace -c shows madvise dominating; replay throughput caps at 1M frames/s despite mmap warm.
    - Why: per-frame `madvise(ptr, page_size, MADV_SEQUENTIAL)` = syscall (~300 ns) per frame; at 1.5M frames/s = ~450 ms/sec syscall.
    - Fix: call `madvise(MADV_SEQUENTIAL)` ONCE per Cycle file at ReplayStream construction (for entire mmap range), not per-next. Kernel maintains hint internally — readahead persists for mmap lifetime.
    - Cost avoided: ~300 ns × 1.5M = ~450 ms/sec; restores replay to NVMe-bandwidth-bound throughput.
    - Muscle: W77 Mon `madvise WILLNEED` lesson — kernel hints amortize over LARGE ranges, never per-element. Reapplies at: W84 cross-rotation file transition (madvise once per new file), W92 ledger v1.0 io_uring (register buffers ONCE, reuse forever).

  - **When `replay_concurrent_with_recording_no_torn_frame` reports torn frames:**
    - Symptom: 10s run shows ~5 frames with corrupt header (len set but payload not flushed).
    - Why: recorder writes len BEFORE payload (or no memory ordering); reader sees len, dereferences payload pointer to unwritten bytes.
    - Fix: recorder writes payload BEFORE len with `Release` ordering on len-store; reader uses `Acquire` on len-load; if len indicates partial (e.g., negated sentinel), spin/retry. Same negated-length sentinel pattern from W77 term_buffer.
    - Muscle: any concurrent reader/writer over shared bytes uses negated-length sentinel + Acquire/Release. Reapplies at: W77 term buffer reader, W82 Image position cursor, W83 archive frame integrity (this is the symmetric side).

  - **5-year failure mode** (write in `notes/84_replay_followup.md`): when replay rates exceed local NVMe bandwidth (multi-TB Archive, distributed replay), need parallelized replay across ranges. Migration: ReplayStream becomes async generator; multiple workers drain different ranges.

  #### Phase 3 — Make the tests pass, one failure at a time (~70 min)

  - **When `det_harness_history_chunked_no_realloc` reports ~50 ms reallocs:**
    - Symptom: scenario wall-time variance huge (some 2s, some 7s); `perf` shows `__memcpy_avx2` in 10% samples.
    - Why: `Vec<DetEvent>::push` reallocates during long scenarios; Vec doubles capacity logarithmically (0 → 4 → ... → 16M); each realloc is `malloc(new_cap × 32 B) + memcpy(old) + free(old)` = ~50 ms at 16M capacity. At 10M scenarios/day with ~20 doublings/scenario × ~5 ms = ~10 hr/day pure realloc.
    - Fix: pre-allocate history with expected capacity at harness construction; for unknown bounds, use chunked structure (SegQueue-style with 16k-event segments — no reallocation, just push new segment when full). Also expose `history_mode: Off | Sparse | Full`.
    - Cost avoided: ~10 hr/day realloc; restores scenario throughput variance to <10%.
    - Muscle: any "history"/log data structure on determinism harness uses chunked segments, not Vec — reallocation forbidden during runs. Reapplies at: W87 VOPR scenario log, W88 consensus-vsr VOPR run log, W92 ledger v1.0 SHIP VOPR scenarios.

  - **When `det_harness_not_sync_compile_check` reports Mutex on PRNG:**
    - Symptom: history-equivalence test fails sporadically on multi-core builds; mutex contention shows in `perf lock`.
    - Why: PRNG exposed via `Mutex<SmallRng>`; mutex acquire ~25 ns uncontended + cache-line ping-pong; under contention serializes PRNG → non-deterministic order across runs.
    - Fix: PRNG owned by harness (no Mutex, no Arc) — harness itself is `!Sync` to compile-time-prevent sharing. Each scenario runs on its OWN harness instance with own seeded PRNG. Parallelism = N harnesses on N threads, each seeded differently.
    - Muscle: deterministic harness is single-threaded by construction — Send OK, Sync forbidden. Reapplies at: W87 VOPR scenario PRNG, W88 consensus-vsr VOPR PRNG, W92 ledger v1.0 SHIP.

  - **When `det_harness_no_instant_now_leak_lint` finds a leak in dependency:**
    - Symptom: clippy fires on transitive call to `Instant::now`.
    - Why: a library internally calls `Instant::now` for retry timer or rate limiter.
    - Fix: cargo-deny `disallowed-methods = ["Instant::now", "SystemTime::now"]` in deterministic crate; runtime panic shim via re-exported time module.
    - Muscle: deterministic systems enforce "no wall clock" at compile + runtime; one leak invalidates entire VOPR. Reapplies at: W88 VSR vopr_integration, W92 ledger v1.0 SHIP determinism gate.

  - **5-year failure mode** (write in `notes/84_det_harness_followup.md`): when io_uring's CQE delivery becomes the dominant async I/O mechanism, the IoCompletionOracle needs to model CQE batches. Migration: IoOracle abstraction; epoll model and io_uring model.
