  #### Phase 3 — Make the tests pass, one failure at a time (~30 min)
  - **(NEWBIE) When `stack_fits_one_l1_way_and_is_aligned` reports `align == 8`:**
    - Symptom: align assert fails; struct aligned to `U256`'s natural 8/16 B, not 64.
    - Why: no `#[repr(align(64))]`; the allocator may return cache-aligned memory by luck but the *type* doesn't guarantee it.
    - Fix: `#[repr(align(64))] pub struct Stack {...}` — alignment is a type property, not an allocation accident.
    - Cost avoided: head of `data` straddling a line → +7 ns L2 on the first push of every call into the interpreter; with cold frames that recurs constantly.
    - Muscle: alignment that matters is encoded in the type, never left to the allocator. Reapplies at: W60 `book.rs` PriceLevel layout, W74 lock-free price-level node, W77 aeron term-buffer.
  - **(EXPERT) When `push_actually_inlined` still finds a `call push`:**
    - Symptom: IR shows a `call` to `push`; bench shows ~0% gain.
    - Why: `#[inline(always)]` is a hint LLVM refuses when the body is too large or address-taken; you "verified" by reading source, not IR.
    - Fix: shrink the body (<~20 IR instructions; split the cold overflow into a separate `#[cold] #[inline(never)]` fn so the hot path is tiny), then re-emit IR and re-grep.
    - Cost avoided: a non-eliminated call (~1–2 ns + spill) per stack op × millions = the entire expected 5-10% gain, silently lost.
    - Muscle: inlining is verified in emitted IR/asm, never by eyeballing attributes. Reapplies at: W64 SIMD memcpy path, W74 hot match loop, W77 aeron claim fast path.
  - **(SENIOR) When `overflow_path_is_cold` shows the error block inline:**
    - Symptom: the `StackOverflow` return sits between hot instructions; the happy path carries an extra not-taken branch in cache.
    - Why: missing `#[cold]` on the error fn and no `std::hint::unlikely` on the guard.
    - Fix: `if std::hint::unlikely(self.len >= 1024) { return cold_overflow(); }` with `#[cold] fn cold_overflow()`.
    - Cost avoided: I-cache pollution + a BTB slot on every push; ~2-5% on tight arith loops.
    - Muscle: rare branches are `cold` so the hot path stays dense. Reapplies at: W66 risk-check reject path, W74 PostOnly would-cross guard, W83 ledger insufficient-funds path.
  - **#### 5-year failure mode** (`notes/60_stack_followup.md` after green): when EIP raises/removes the 1024 stack cap (or a parallel-EVM variant runs many small stacks), the inline `[U256;1024]` (32 KiB) becomes too large to keep one-per-shard hot. TRIGGER: stack-cap const changes OR >256 concurrent interpreters per core. Migration: pool stacks in a `bufpool` (W14) and reuse, keeping only the active frame's stack hot.
