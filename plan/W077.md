  - *Mental model*: a term buffer is one slot of a 3-slot rotating mmap ring. The writer FAA-bumps a shared `tail_offset`, claims `[offset, offset+len)`, writes a negated-length header, fills the payload, then Release-stores the positive length to "publish." The reader Acquire-loads length, spins while negative. Durability is explicitly NOT here — that is the Archive's job (W83).
  - *Contract*:
    - `TermBuffer::new(buf: &mut [u8]) -> Self` (buf is an mmap slice, len = TERM_LEN).
    - `fn try_claim(&self, len: usize) -> Result<Claim<'_>, ClaimError>` — `ClaimError::TermFull` triggers rotation; `Claim` derefs to `&mut [u8]` payload region.
    - `fn commit(claim: Claim)` — Release-store positive length.
    - `fn poll(&self, cursor: &mut i32) -> Option<&[u8]>` — Acquire-load, spin-while-negative, skip PAD via roll-to-next.
    - `FrameHeader: #[repr(C)]`, 32 bytes, `length: i32`, `frame_type: u8` (DATA/PAD), term/session/stream ids.
    - NEVER expose the solution body.
  - *Back-of-envelope* (bar (c)): budget 10M msg/s × 128 B = 1.28 GB/s single producer. At 10M ops/s the per-op budget is **100 ns**. A torn-read spin is ~5 ns; an Acquire-load is ~0.5 ns L1; a FAA on a contended line is ~25-40 ns. The cliff: a stray `msync(MS_SYNC)` is ~5 ms = **5,000,000 ns** = a 50,000× blowup over the 100 ns budget. A `tail_offset` sharing a line with payload costs a ~7 ns L2 cross-fetch PER op × 10M = ~70 ms/sec of pure coherence traffic (cliff: cached-tail 0.5 ns vs ping-ponged 7 ns = 14×).
  - **Requirements** R1..R9 — write in `crates/messaging-aeron/notes/77_term_buffer_design.md`:
    - R1. Throughput ≥10M msg/sec single-producer at 128 B payload sustained 60s.
    - R2. Publish p50 ≤50 ns, p99 ≤200 ns, p99.9 ≤2 µs, p99.99 ≤20 µs.
    - R3. Per-publication scaling: N=8 publications aggregate ≥7× N=1 (each its own term region).
    - R4. Zero heap allocs on publish path steady state (dhat).
    - R5. Loom-green: 1 writer + 1 reader, 4 publishes; reader sees ONLY positive-length headers + complete payload under the negated-length sentinel + Acquire/Release pair.
    - R6. `tail_offset` cache-line isolated: STATIC `offset_of!` distance ≥ line (CachePadded on its own line, in a `repr(C)` `LogMetadata`) AND no HITM on the tail line under a sustained `perf c2c` runtime run (verified against a co-located negative-control).
    - R7. Term rotation correct: 100M+ publishes across 1000+ rotations; 0 messages lost, 0 readers stuck on PAD, no torn rotation.
    - R8. Zero syscalls on publish hot path (`strace -c`: fsync/msync/futex = 0).
    - R9. Graceful degradation: when consumer lags and the 3rd term fills, publisher backpressures via flow control (W77 Tue); NEVER silently overwrites.

  #### Phase 3 — Make the tests pass, one failure at a time (~110 min)

  Read each card AFTER you see the failure. Newbie first, expert last — the ladder you actually walk.

  - **(NEWBIE) When `term_buffer_misaligned_payloads_handled` SIGBUS-es on aarch64 at a 31 B payload:**
    - Symptom: bus error reading the next FrameHeader on Apple Silicon; x86 silently slow.
    - Why: frames not rounded up to 32-byte alignment; the next header straddles an unaligned address that ARM faults on for aligned loads.
    - Fix: `aligned_len = (HEADER + payload + 31) & !31;` always advance tail by the aligned length.
    - Cost avoided: hard crash on ARM + a ~2× penalty from split loads on x86.
    - Muscle: frame strides must be aligned to the header alignment — never trust the payload length. Reapplies at: W78 UDP frame parse, W83 archive frame layout, W82 Image reassembly, **W79 `oracle-mark` tick frame layout**.

  - **(NEWBIE) When `term_buffer_zero_alloc_on_publish_hot_path` reports allocs per publish:**
    - Symptom: dhat shows a 128 B alloc per call; bench at ~3M msg/s.
    - Why: you serialized the payload into a temporary `Vec<u8>` then copied it into the slot.
    - Fix: `try_claim` returns `&mut [u8]`; write the payload IN PLACE; no temporary.
    - Cost avoided: ~100 ns/op × 10M/s ≈ 1 s/sec of allocator work — the alloc path alone exceeds the per-op budget, so a temporary Vec makes the 10M/s target impossible; (bar (c) violation).
    - Muscle: claim-then-write-in-place; the slot IS the buffer. Reapplies at: W77 Fri IPC `BufferClaim`, W79 MBO publish, W80 ledger journal write, **W79 `oracle-mark` mark-tick publish**.

  - **(SENIOR) When `term_buffer_loom_no_torn_header` reports reader seeing `length = -64`:**
    - Symptom: a loom interleaving lands the reader's `header.length` load between the writer's negate-write and Release-store; reader consumes the negated sentinel as data.
    - Why: reader doesn't spin on negative length; consumed the in-progress value.
    - Fix: reader `length` load is `Acquire`; `while length < 0 { spin_loop(); reload }`; writer's final store is `Release` so payload writes are visible to the reader's subsequent reads.
    - Cost avoided: silent data corruption in production (the worst bar (c) violation — green correctness tests, RED under concurrency).
    - Muscle: a negated-length sentinel REQUIRES Acquire-load + spin-while-negative on the reader and a Release publish on the writer. Reapplies at: W77 flow-control sequence counter, W82 Image position cursor, W83 archive frame integrity.

  - **(SENIOR) When `term_buffer_loom_test_must_be_slow` reports the loom run took 2 ms:**
    - Symptom: negative-control fails; the model explored ~0 interleavings.
    - Why: the test used real `std::sync::atomic` (compiled without `--cfg loom`) or had no shared-state branch points, so loom had nothing to permute.
    - Fix: import atomics from `loom::sync::atomic` under `#[cfg(loom)]`; run with `RUSTFLAGS="--cfg loom"`; ensure the writer/reader actually share the tail + header.
    - Cost avoided: a false sense of safety — a green loom test that verified nothing.
    - Muscle: every loom model needs a slow-negative-control or you don't know it ran. Reapplies at: W78 NAK loom, W79 subscription loom, every future `#[cfg(loom)]` model.

  - **(SENIOR) When `term_buffer_term_rotation_100m_messages` reports a stuck reader on a PAD frame:**
    - Symptom: reader cursor parked on a PAD frame in the dirty term; never advances.
    - Why: PAD detection missed; treated PAD as a length-0 data frame and spun for a valid length forever.
    - Fix: reader checks `frame_type == PAD` → roll cursor to the next term's start; release the dirty term for recycling.
    - Cost avoided: a permanently wedged subscriber (liveness failure in production).
    - Muscle: a rotating ring needs explicit terminal-frame (PAD) handling via roll-to-next, never a length-loop. Reapplies at: W79 subscription term-boundary, W82 Image session rotation, W83 archive cycle rotation.

  - **(SENIOR) When `term_buffer_n8_publications_aggregate_7x_n1` reports only 4× scaling:**
    - Symptom: 8 publications hit ~4× a single publication's throughput; flame graph shows a shared mmap region contended.
    - Why: all 8 publications backed by the SAME mmap file; the page-cache lock serializes; NUMA cross-socket if writers land on different sockets.
    - Fix: each publication gets its OWN mmap region (file per session+stream); pin writer + reader to the same NUMA node (Aeron's `image` model).
    - Cost avoided: ~2× aggregate throughput loss; (bar (c) violation under fan-out).
    - Muscle: per-publication isolation = separate mmap regions + NUMA affinity, never a shared file. Reapplies at: W77 Fri IPC (file per publication), W79 fan-out, W82 v1.5 SHIP.

  - **(EXPERT, perf) When `term_buffer_perf_c2c_no_hitm_on_tail` flags `tail_offset` as HITM at runtime (bar (c) violation):**
