  #### Phase 3 — Make the tests pass, one failure at a time (~25 min)

  - **(SENIOR) When `script_refuses_non_release_binary` profiles a debug binary anyway:**

  - **(SENIOR) When `provisioning_check_blocks_when_turbo_on` runs anyway:**
    - Symptom: IPC varies 30%+ across runs; absolute numbers are unquotable.
    - Why: turbo boost active — clock floats, so cycle-denominated metrics are meaningless.
    - Fix: assert `/sys/devices/system/cpu/intel_pstate/no_turbo == 1` and governor == `performance`; refuse otherwise.
    - Muscle: pin the clock before you trust any cycle count. Reapplies at: W111 Thu bench rig, W113 ARM CI gate provisioning.

  - **(EXPERT) When `flamegraph_top3_stable_across_3_runs` reports 3 disjoint top-3 sets:**
    - Symptom: run1=[A,B,C], run2=[D,E,F], run3=[G,H,I]. The profile is pure noise.
    - Why: the bench core wasn't isolated — `ksoftirqd`/kworker preempted on it; samples landed in kernel functions you never tested. `taskset` alone does not stop the kernel from scheduling there.
    - Fix: kernel-boot `isolcpus=4-7 nohz_full=4-7 rcu_nocbs=4-7`; mask `/proc/irq/*/smp_affinity` off bench cores; `taskset -c 4` the SUT; assert `mpstat -P 4 1` shows `nr_running == 1` for the whole run.
    - Cost avoided: two wasted days optimizing a function whose "60%" was contention, not work — the worst HFT-profiling failure. (bar (c) violation: an un-isolated rig disqualifies every number it produces.)
    - Muscle: profile noise is almost always a rig-provisioning failure; fix the rig before blaming the code. Reapplies at: W111 Thu bench harness, W113 hot-path PR review, W120 production profile capture.

  - **(EXPERT) When `freq_997_vs_4001_agree_on_top3` shows disjoint top-3:**
    - Symptom: `-F 997` = [match_and_execute, push_back, find_by_oid]; `-F 4001` = [match_and_execute, total_qty_update, peek_head].
    - Why: at one frequency, samples aliased with a periodic op (10ms metric flush). The frequency-unique hot function is artifact, not signal.
    - Fix: trust only functions in BOTH frequencies' top-5; cross-check with `-F 4999` if ambiguous; optimize only what's robust across sampling.
    - Cost avoided: optimizing a function that consumes ~0% of real work — pure wasted effort.
    - Muscle: sampling artifacts hide in single-frequency profiles; always cross-validate with two primes. Reapplies at: W113 PR-review benchmarks, W120 regression detection.

  - **(EXPERT) When `ipc_meets_threshold_or_alert` shows IPC = 1.2:**
    - Symptom: per-cycle throughput is ~half of a modern x86 ceiling; you are cache-bound, not compute-bound.
    - Why: the hot path is dominated by L1/L2 misses on the order-book traversal (per-level VecDeque indirection).
    - Fix (this week): Tue's ring redesign collapses the indirection; Wed's seqlock removes reader/writer lock contention — both target IPC ≥ 2.0 as a side effect.
    - Cost avoided: ~50% of cycles spent stalled on memory instead of matching — the dominant cost at 1M orders/sec. (bar (c) violation if shipped.)
    - Muscle: IPC < 2.0 on Skylake+ means memory-bound; cache-line-aware redesign is the lever, not micro-op tuning. Reapplies at: W111 Tue ring, W113 hot-path PR optimization.

**Tuesday — Order-book price level: ring vs VecDeque**

- [ ] **Build**: `crates/matching-engine/src/price_level.rs` — replace per-level `VecDeque<Order>` with a fixed-size ring `PriceLevel { orders: [Slot; 64], head: u8, tail: u8, total_qty: u32, .. }` (cache-friendlier). (~total 80 min across 3 phases)
  - 🔧 **Why this matters**: mirrors `crossbeam-deque`'s fixed-buffer ring discipline applied to the matching-engine hot path. VecDeque has two cache-unfriendly properties at HFT scale: (a) head/tail wraparound forces a branch on every `push_back`, and (b) an empty level still holds an 8-byte heap pointer + cap/len metadata (24B), bloating the BTreeMap node and adding cache lines per level traversal. A fixed-size ring (`[Slot; 64]` + u8 head/tail in one cache line) packs more orders per line and removes the heap indirection on the inner loop — but introduces classic foot-guns: false sharing on head/tail across adjacent levels, spillover when a level exceeds CAP, tombstone accumulation under cancel-heavy flow, and a recomputed `total_qty` that silently defeats the cache win. First-attempt impls fail ≥1 test below (most commonly `wrap_compiles_to_and` because CAP was a `let` not a `const`, or `no_false_sharing_adjacent_levels` because the struct wasn't `repr(align(64))`). Downstream consumers: W111 Wed lock-free top-of-book reads this layout's `total_qty` in a single load; W113+ matching-engine optimization PRs build on it; M30 bar-(c) zero-alloc audit cites this layout.

  #### Phase 1 — Problem, prediction, design (~25 min, no code yet)

  - 🎯 **Pre-prediction prompt (do this BEFORE reading Phase 2)** — write sealed answers in `crates/matching-engine/notes/111_price_level_prediction.md`:
    - P1. Name the type you'd reach for first if you didn't know "ring." Write the field declaration line you'd type from memory.
    - P2. Predict `size_of::<PriceLevel>()` for `[Slot; 64]` with a 24-byte Slot plus head/tail/total_qty (one number) and `align_of` (one number).
    - P3. Predict whether `idx & (CAP-1)` compiles to a single `and` or a `div`/`rem` if `CAP` is declared `let CAP = 64;` vs `const CAP = 64;`. Two answers; no commentary.
    - P4. Predict the `ring_p99 / vecdeque_p99` ratio at 500k orders/sec on your rig (one number). Reference: a pure-indirection win on a memory-bound loop is typically 1.1–1.4×; don't over-claim.
    - P5. Of the Phase-2 tests below, list every test name you predict your first attempt will fail.
  - *Mental model*: a price level is a FIFO queue of resting orders at one price; the ring stores them inline in a cache-line-aligned fixed array so traversal hits L1, with `total_qty` kept as a running aggregate so top-of-book never walks slots. It exists because per-level heap indirection is the dominant cost at 1M orders/sec across thousands of levels.
  - *Contract*: `push_back(Order) -> Result<(), Spilled>`, `pop_front() -> Option<Order>`, `cancel(oid) -> bool` (tombstone), `total_qty() -> u32` (single load, no walk), `len()`. Invariant: `total_qty == sum(live slot qty)` after every mutation; `len == (tail - head) mod CAP`. NEVER expose raw slot indices; the ring owns its wrap arithmetic.
  - *Back-of-envelope* (bar (c)): `[Slot; 64]` × 24B = 1536B = 24 cache lines per level. A VecDeque level adds one pointer-chase = ~100ns LLC miss on a cold level; the ring keeps the hot fields (head/tail/total_qty) in the *first* cache line, so top-of-book and the common short-level case touch 1 line ≈ 1.5ns (L1) vs ~100ns (miss) = **~65× cliff**. Wrap as AND not modulo saves a 10–30-cycle integer divide per `push_back`; at 1M/sec that divide alone is ~10–30 Mcycles/sec ≈ 0.3–0.9% of one 3.5GHz core. False sharing on adjacent levels' head/tail = MESI ping-pong ≈ 100–200ns per contended write = a 4–5× hot-path regression.
  - **Requirements** R1..R7 — write in `crates/matching-engine/notes/111_price_level_design.md`:
    - R1. `PriceLevel` is `#[repr(align(64))]` and `size_of::<PriceLevel>() % 64 == 0` (`const_assert!`).
    - R2. CAP is a power-of-two `const` (default 64); wrap is `idx & (CAP - 1)`; compiler proves it → AND in `cargo asm`.
    - R3. Slots occupy `[head..tail) mod CAP`; `len = (tail - head) mod CAP`.
    - R4. Spillover: when `len == CAP`, FIRST eager-compact the ring (sweep tombstones, slide live slots to head=0); only if still full, allocate a heap overflow `Vec<Slot>` and emit `price_level_spill_total`; if spill > 10% of CAP, emit `price_level_spill_alert_total`.
    - R5. Middle-removal is O(1) via tombstone (`Slot.flags |= TOMBSTONE`); lazy compaction skips leading tombstones on `pop_front`; full compaction when tombstone ratio > 50%.
    - R6. `total_qty: u32` aggregate stays in sync — updated atomically with every slot mutation (add/cancel/pop/partial-fill) via a single `mutate(|slots, total_qty| ...)` choke point; top-of-book reads it in one load.
    - R7. Bench A/B vs VecDeque baseline: P99 drops ≥ 15%, LLC-miss% drops ≥ 5pp, dTLB-miss drops ≥ 20%; no correctness regression in matching-engine VOPR.
  - **Design walk-through** D1..D8 — answer in the design doc; no peeking at `crossbeam-deque` until Phase 3:
    - D1. Enumerate every container (VecDeque, `Vec`+manual head, `[Slot; N]` ring, intrusive linked list, slab) with a property table (heap allocs? branch-on-wrap? cache lines/level? O(1) middle remove?). Pick the ring and justify.
    - D2. Why u8 for head/tail not usize? What does it cost (CAP ≤ 256), what does it buy (cache-line packing)?
    - D3. Slot layout = 24B. Why not pad to 32 (cache-line-friendly)? Trade-off (waste vs straddle).
    - D4. Cache-line walk: which fields live in cache line 0? Why must head/tail/total_qty be there?
    - D5. False-sharing scenario: write the 4-step trace where two adjacent `PriceLevel`s share a line, thread A writes head of level N, thread B writes head of N+1, both ping-pong. Convince yourself align(64)+size%64==0 prevents it.
    - D6. Tombstone vs memmove: argue tombstone+compact beats memmove for matching semantics (cancels cluster).
    - D7. **Pre-mortem (load-bearing):** write the 5-step trace where (a) you switch to ring, (b) `cargo asm` confirms `idx & (CAP-1)` is a single AND, (c) bench shows zero improvement, (d) you discover `total_qty()` walks all slots every call, defeating the cache win, (e) R6's single-load aggregate fixes it. Convince yourself R6 catches this.
    - D8. **Anti-shortcut audit:** (a) `let CAP = 64;` "it's still 64" — runtime value, compiler can't prove power-of-two → emits `div`; (b) "just `#[repr(align(64))]`, skip the size assert" — alignment without size%64 still lets the *next* level start mid-line → false sharing; (c) "recompute total_qty, it's only 64 slots" — defeats the entire redesign on the hot path.
  - **Output**: `notes/111_price_level_design.md` with R1–R7, D1–D8, the struct byte-offset diagram, the cache-line walk, the false-sharing + total_qty traces.

- [ ] **Build**: `crates/matching-engine/src/top_of_book.rs` — lock-free seqlock-backed `TopOfBook` for single-writer, multi-reader access to top bid/ask. (~total 80 min across 3 phases)
  - 🔧 **Why this matters**: mirrors Linux `include/linux/seqlock.h` reader/writer protocol, applied to matching-engine's per-shard single-writer threading model. Top-of-book is hit by *every* market-data tick and *every* incoming aggressive order; at 1M orders/sec even a 100ns spinlock acquire dominates. If readers (quote dissemination, risk checks, internal subscribers) and the writer (matching engine) contend on a `Mutex`, you see P99.9 spikes when the writer holds the lock through a full level traversal. A seqlock lets readers complete in ~10ns and writers in ~30ns — and exposes a correctness property (readers may catch a write-in-flight and must retry, detected by the seq counter). First-attempt impls fail ≥1 test below — most commonly the loom model with a torn read because field stores used `Relaxed` without the Release-on-close-seq / Acquire-on-load-seq pairing, or `single_writer_enforced` because the invariant was assumed but not checked.   #### Phase 3 — Make the tests pass, one failure at a time (~25 min)

  - **(NEWBIE) When `bench_records_seed_in_json` finds no seed field:**
    - Symptom: `result.json` has quantiles but no `seed`; historical comparison is apples-to-oranges.
    - Why: the bench seeded the RNG but never wrote the seed to the result.
    - Fix: thread the fixed seed into the result struct and serialize it.
    - Muscle: a bench result without its seed is not reproducible. Reapplies at: W113 PR-review bench protocol, W120 SLO history.

  - **(EXPERT — perf) When `bench_uses_corrected_recording` shows `record` was called (bar (c) violation):**
    - Symptom: bench does `hist.record(dt)`; reported P99 = 1µs; real-world P99 = 50ms.
    - Why: coordinated omission — when the feed queues 100 messages in a 5ms burst, the bench records each `process(msg)` at ~1µs but never accounts for the last message's 5ms queue wait.
    - Fix: `hist.record_corrected_with_max_interval(dt, 2000)` (expected interval = 1e9 / 500_000); HdrHistogram synthesizes the missing samples.
    - Cost avoided: quoting a P99 ~5000× rosier than production — the number you defend in an interview until an outage proves it wrong.
    - Muscle: latency benches under load REQUIRE coordinated-omission correction; uncorrected P99 is fantasy. Reapplies at: W113 PR-review benches, W120 production SLO measurement.

  - **(EXPERT — perf) When `bench_achieved_rate_within_5pct` shows actual rate = 1.2M/sec (bar (c) violation):**
    - Symptom: target was 500k; bench ran flat-out; HdrHistogram recorded 2M samples in 10s.
    - Why: `b.iter(|| me.process(msg))` runs as fast as possible — a "max throughput" measurement, not a "500k/sec sustained" one.
    - Fix: `b.iter_custom(|iters| { for _ in 0..iters { spin_sleep::sleep(Duration::from_nanos(2000)); record(process(msg)) } })`.
    - Cost avoided: a P99 measured under a load profile that never occurs in production — wrong by construction.
    - Muscle: rate-shaped benches are the only benches that match production; "max throughput" measures a different quantity. Reapplies at: W113 production-like bench design (and reuses Mon's rig).

  - **(SENIOR) When `bench_p50_stable_across_runs` shows 18% variance:**
    - Symptom: P50 = 250ns run 1, 295ns run 2.
    - Why: warmup was 5k iters; first-touch page faults still landed in the histogram.
    - Fix: warmup ≥ 50k; verify stability by running 3× and asserting ≥ 2 within 5%.
    - Muscle: warmup adequacy = stability across repeated runs; pick the warmup that stabilizes. Reapplies at: W111 Mon perf rig, W113 PR-review bench protocol.

  - **(SENIOR — perf) When `bench_compiled_without_tracing` finds `tracing` in `cargo tree` (bar (c) violation):**
    - Symptom: `cargo tree --bench single_symbol_p99` shows `tracing`; the hot path pays ~200ns/op for `info_span!`.
    - Why: matching-engine's main code uses tracing and the bench inherited the dep tree with spans active.
    - Fix: feature-gate hot-path emission — `#[cfg(feature = "trace")] info_span!(...)`; bench profile uses `--no-default-features --features=bench` which excludes `trace`.
    - Cost avoided: ~200ns/op = 10% of the 2µs budget measured on the dev hot path instead of the production hot path.
    - Muscle: hot-path instrumentation is feature-gated; benches measure the production hot path, not the dev one. Reapplies at: W105 metric-emit feature flags, W113 hot-path discipline.

  - **(EXPERT) When `bench_regression_10pct_fails_ci` doesn't fail at 12%:**
    - Symptom: bench reports a 12% P99 regression; CI marks green.
    - Why: the comparator did `current > baseline * 1.1` in floating point and rounded `2250.0 > 2200.0...` away.
    - Fix: integer gate — `if current_p99_ns > baseline_p99_ns * 110 / 100 { return Err(..) }`; print both numbers + delta.
    - Muscle: regression gates need explicit integer thresholds with an audit trail; never trust float comparison for budget enforcement. Reapplies at: W113 PR-review gates, W120 SLO regression.
