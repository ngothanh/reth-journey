- [ ] **Build**: `p2p::gossip` push path with bounded fanout (8 peers default), IHAVE pull-back. (~105 min)
  - **Why**: W52 Sat sketched gossip; this is the production push path. Bounded fanout prevents amplification; IHAVE pull-back reduces redundant deliveries when peers already have the message.
  - **Read first**: W52 Sat enrichment; gossipsub-v1.1 spec §3 (mesh management).
  - **Design**:
    ```rust
    impl<T: Encodable + Decodable + Clone> GossipBroadcast<T> {
        pub fn publish(&mut self, msg: T) {
            let id = self.msg_id(&msg);
            self.seen.put(id, ());
            self.app_deliver(&msg);
            for peer in self.peers.iter().take(self.fanout) {
                self.send_to_peer(*peer, GossipMsg::Message(msg.clone()));
            }
        }
        pub fn on_recv(&mut self, from: PeerId, gmsg: GossipMsg<T>) {
            match gmsg {
                GossipMsg::Message(m) => {
                    let id = self.msg_id(&m);
                    if self.seen.contains(&id) { return; }
                    self.seen.put(id, ());
                    self.app_deliver(&m);
                    for peer in self.peers.iter().filter(|p| **p != from).take(self.fanout) {
                        self.send_to_peer(*peer, GossipMsg::Message(m.clone()));
                    }
                }
                GossipMsg::Have(id) => {
                    if !self.seen.contains(&id) {
                        self.send_to_peer(from, GossipMsg::Want(id));
                    }
                }
                GossipMsg::Want(id) => {
                    if let Some(m) = self.cache.get(&id) {
                        self.send_to_peer(from, GossipMsg::Message(m.clone()));
                    }
                }
            }
        }
    }
    ```
    **Invariants**:
    - Fanout fixed at 8 (configurable). Higher = faster propagation but more BW; lower = slower but cheaper.
    - Always exclude `from` when forwarding (don't echo).
    - IHAVE summaries piggybacked every 1s (W58 timer wheel will tick this).
  - **Build steps**:
    1. (~20 min) Refine W52 skeleton: add `cache: lru::LruCache<B256, T>` (separate from `seen`; cache holds the actual msgs for Want responses, size 1000).
    2. (~20 min) Implement `publish` and `on_recv` per design.
    3. (~25 min) Peer-score: track `(delivered_first, delivered_dup, invalid_count)` per peer. Eject if `invalid > 0.1 * delivered_first`.
    4. (~25 min) Backpressure: bounded send queue per peer via `backpressure::Queue`; drop oldest if peer slow.
    5. (~15 min) Tests: 50-peer sim, publish msg, 100% delivery within 5 rounds.
  - **Pitfalls**:
    - *Cache too small*: Want arrives for evicted msg → no response → starvation. **Fix**: cache > seen size × safety factor.
    - *Backpressure drops new msgs first*: DropOldest is correct for gossip (newer = more relevant). DropNew would silence the latest update. **Fix**: use `BackpressureStrategy::DropOldest` explicitly.
    - *Fanout exclusion*: forgetting `peer != from` causes immediate echo + amplification. **Fix**: explicit filter.
  - **Test scenarios**: 50-peer net, 1 publish → 100% delivery within ~log2(50) rounds; 10% peers slow → DropOldest activates, no propagation stall; Byzantine 5% peers send invalid → ejected within 1 min.
  - **Acceptance**: integration test green; bench: 10k msgs/sec sustainable per node.
  - **Downstream**: W56+ raft votes propagate; W64+ bft block proposals; W76+ aeron control plane.

**Wednesday — Storage journal + p2p tag v0.5**

- [ ] Track storage changes in exec-vm. (~30 min)
  - **Why**: Storage journaling is the more error-prone half. Each SSTORE pushes `StorageChanged { address, key, had_value }`; the SSTORE refund accounting (EIP-3529) reads `original_value` (the value at TX START, not call-frame start) — easy bug source.
  - **Build steps**:
    1. (~10 min) `StorageChanged` undo: restore `had_value` to `state[address].storage[key]`.
    2. (~5 min) Track `original_value` per (address, key) per-TX (NOT per-frame): in `Account::storage`, each slot is `EvmStorageSlot { original_value, present_value, is_cold }`.
    3. (~5 min) StorageWarmed undo: removes (address, key) from `warm_storage`.
    4. (~10 min) Test: SSTORE k=1 v=42, REVERT → storage[1] = 0; SLOAD k=1 in next sub-call must be cold again.
  - **Pitfalls**: EIP-2200 refund formula reads original_value; if you mis-scope to frame instead of tx, refund is wrong.
  - **Acceptance**: differential green for SSTORE-heavy contracts.
