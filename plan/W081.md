- [ ] [NEW v2] **Build**: `crates/matching-engine/src/circuit_breaker.rs` — LULD-style price bands per symbol; 5% band,
  10s reference window. Halt + auction on band breach. (~3 hrs)
  - **Why**: Circuit breakers protect against erroneous orders, fat-fingers, and runaway algorithms by halting trading when price moves beyond a band. SEC-mandated LULD (Limit Up-Limit Down) bands cover all US listed stocks since 2012; every venue ships them. Without circuit breakers, a single 100x fat-finger order can cascade-execute through the book, executing thousands of trades before humans intervene.
  - **Read first**: SEC Rule 608 LULD plan. NYSE LULD specification. CME's Velocity Logic + Stop Logic. CBOE "Trading Halts and LULD" docs. Real-world: 2010 Flash Crash post-mortem; 2015 Aug 24 ETF dislocations.
  - **Design**:
    ```rust
    pub struct CircuitBreakerConfig {
        pub upper_band_bps: u32,             // e.g., 500 = 5%
        pub lower_band_bps: u32,
        pub reference_window: Duration,       // 10s default
        pub halt_duration: Duration,          // 5 min default
        pub auction_at_resume: bool,
    }
    pub struct CircuitBreaker {
        pub cfg: CircuitBreakerConfig,
        pub reference_px: Price,              // rolling mean over window
        pub samples: VecDeque<(Monotonic, Price)>,
        pub state: BreakerState,
        pub halted_at: Option<Monotonic>,
    }
    pub enum BreakerState {
        Trading,
        BandBreachPending { since: Monotonic, side: BreachSide },  // "limit state"
        Halted { resume_at: Monotonic },
        InAuction,
    }
    impl CircuitBreaker {
        pub fn on_trade(&mut self, now: Monotonic, px: Price) -> Action {
            self.samples.push_back((now, px));
            self.evict_older_than(now - self.cfg.reference_window);
            self.reference_px = self.compute_mean();
            let upper = self.reference_px * (1.0 + self.cfg.upper_band_bps as f64 / 10_000.0);  // integer math
            let lower = self.reference_px * (1.0 - self.cfg.lower_band_bps as f64 / 10_000.0);
            match self.state {
                Trading if px > upper => self.transition_to_limit(now, BreachSide::Up),
                Trading if px < lower => self.transition_to_limit(now, BreachSide::Down),
                BandBreachPending { since, side } if (now - since) >= HALT_AFTER_LIMIT_DURATION => {
                    self.state = Halted { resume_at: now + self.cfg.halt_duration };
                    Action::Halt
                }
                Halted { resume_at } if now >= resume_at => {
                    self.state = if self.cfg.auction_at_resume { InAuction } else { Trading };
                    if self.cfg.auction_at_resume { Action::TriggerAuction } else { Action::Resume }
                }
                _ => Action::Continue,
            }
        }
    }
    ```
    **Invariants**: (i) Reference is *rolling* over window — adapts to long-term trend. (ii) "Limit state" is a soft warning: when trades print at the limit, breaker enters Pending; only after sustained Pending (15s) does Halt fire. (iii) Halt → auction → trading transitions are deterministic. (iv) All math integer-based (use bps); avoid f64 for cross-replica determinism.
  - **Build steps**: 1. (~25 min) Types + config. 2. (~30 min) Sample collection + reference computation (cumulative mean over window). 3. (~40 min) State machine transitions. 4. (~30 min) Integration: Engine consults breaker on each match attempt; if Halted, reject new orders + emit Halt event on MBO. 5. (~30 min) Auction-at-resume hook: on Halt-end, instruct auction module (W78) to run uncrossing. 6. (~25 min) Tests Tuesday.
  - **Pitfalls** (named, 4):
    - *Reference-price drift*: **Symptom**: rapid one-directional move; reference adjusts but slower than market; bands keep relaxing → circuit breaker effectively never trips. **Fix**: use median (more robust to outliers) or VWAP. Cap how fast reference can move (e.g., ±2% per window). Cite the 2015 Aug 24 incidents.
    - *Halt-auction race*: **Symptom**: halt declared, but a stop order in stop_ladder (W77) was triggered just before; the new market order tries to execute during halt → undefined behavior. **Fix**: on Halt entry, freeze stop_ladder; any pending triggers become orders queued for auction. After auction completes, ladder resumes against new reference.
    - *Band recalc under stale samples*: **Symptom**: low-volume symbol has 1 sample/min; reference is stale and tight; bands trigger spurious halts. **Fix**: minimum sample count threshold (e.g., ≥5 samples in window) before applying breaker; below that, use long-term reference (prior session close).
    - *Float drift in bps math*: **Symptom**: bps computation uses f64 → cross-arch divergence → replicas halt at different times. **Fix**: integer-only: `band = ref * bps / 10_000` using u64 math; round half-to-even consistently.
  - **Test scenarios** (Tue): (a) Stable price (e.g., 100 trades all at 100) → no breach. (b) Rapid 5% move from 100 to 106 → breach detected, limit-state entered. (c) Sustained 15s at limit → Halt declared. (d) Halt expires → auction triggered; uncrossing produces resume price; trading resumes. (e) Same scenario on 3-replica raft → all replicas halt identically (determinism).
  - **Acceptance**: deterministic across replicas. Bench: per-trade breaker check < 100 ns. Property: same trade stream → same halt sequence across replicas (10k random scenarios).
  - **Downstream**: W78 auction.rs is invoked at halt-resume — composition. W82 v1.5 SHIP audit confirms breaker in scope. Tier-A interview: "explain LULD vs market-wide circuit breakers" → LULD per-symbol, MWCB cross-market (S&P 7%/13%/20%); this exercise builds LULD; market-wide is similar pattern at index level.
- [ ] [NEW v2 aeron v0.7] **Build**: SSM (Source-Specific Multicast) — subscriber filters by (source-IP, group-IP). (~90 min)
  - **Why**: ASM (Any-Source Multicast) allows any sender to publish on a group → spoofing risk + DDoS amplification. SSM restricts subscribers to a specific (source, group) channel — kernel-level filtering by source IP. Required by financial regulators in some jurisdictions; standard at CME, NYSE for data integrity. Builds on IGMPv3 / MLDv2 protocols.
  - **Read first**: IETF RFC 4607 (SSM). RFC 3376 (IGMPv3). Linux kernel: `setsockopt(IP_ADD_SOURCE_MEMBERSHIP)` man page. CME ITCH SSM deployment guide.
  - **Design**:
    ```rust
    pub struct SsmSubscription {
        pub socket: UdpSocket,
        pub source: Ipv4Addr,                  // SSM filter
        pub group: SocketAddrV4,                // 232.0.0.0/8 reserved for SSM
        pub interface: Ipv4Addr,
    }
    impl SsmSubscription {
        pub fn join(group: SocketAddrV4, source: Ipv4Addr, iface: Ipv4Addr) -> Result<Self> {
            // SSM groups should be in 232.0.0.0/8 (IETF-reserved SSM range)
            assert!(group.ip().octets()[0] == 232, "SSM groups must be in 232/8");
            let socket = UdpSocket::bind((Ipv4Addr::UNSPECIFIED, group.port()))?;
            socket.set_reuse_port(true)?;
            // IP_ADD_SOURCE_MEMBERSHIP: { multiaddr, interface, source }
            socket.join_multicast_v4_with_source(&group.ip(), &iface, &source)?;
            Ok(SsmSubscription { socket, source, group, interface: iface })
        }
        pub fn change_source(&self, new_source: Ipv4Addr) -> Result<()> {
            self.socket.leave_multicast_v4_with_source(&self.group.ip(), &self.interface, &self.source)?;
            self.socket.join_multicast_v4_with_source(&self.group.ip(), &self.interface, &new_source)?;
            Ok(())
        }
    }
    ```
    **Invariants**: (i) SSM group addresses MUST be in 232.0.0.0/8 (IETF reservation). Outside that range = ASM. (ii) Only IGMPv3 / MLDv2 supports SSM; IGMPv2 falls back to ASM. (iii) Source filtering happens at kernel — userspace doesn't see filtered packets. (iv) Failover: change source via `change_source` for primary/backup feed switching (common pattern: A-feed + B-feed).
  - **Build steps**: 1. (~15 min) SsmSubscription type. 2. (~25 min) `join` with `join_multicast_v4_with_source`. 3. (~20 min) `change_source` for failover. 4. (~15 min) Detection: check `getsockopt(IPV6_FILTER_INCLUDE)` or per-OS API to confirm SSM active. 5. (~15 min) Integration with existing MulticastSubscription — make source filter optional.
  - **Pitfalls** (named, 3):
    - *Legacy IGMPv2 fallback*: **Symptom**: switch only supports IGMPv2 → SSM join silently downgrades to ASM, source filter ignored. **Fix**: explicit check via `getsockopt(IPV6_FILTER_INCLUDE)`; if not supported, fall back loudly with warning + metric. Aeron logs this.
    - *SSM-aware switches required*: **Symptom**: end-host joins SSM, but switch/router doesn't snoop IGMPv3 → traffic flooded to all ports anyway. **Fix**: deployment-time check; document IGMP snooping requirement (Cisco IGMPv3 mode, etc.). Cite CME deployment guide.
    - *Source address spoofing*: **Symptom**: malicious actor on same network spoofs source IP → SSM filter passes the spoofed traffic. **Fix**: SSM provides *plausible deniability*, not authentication. Layer encryption / MACsec for true integrity. Document limitation.
  - **Test scenarios**: (a) Subscriber joins (source=10.0.0.1, group=232.1.1.1); publisher at 10.0.0.1 sends → receives. (b) Publisher at 10.0.0.2 sends to same group → subscriber filters out. (c) `change_source(10.0.0.2)` → swaps filter; now receives 10.0.0.2's traffic.
  - **Acceptance**: SSM join succeeds; source-filtering verified by sending from two sources on lo (requires aliased IP). Inheritance: builds on multicast.rs (W80).
  - **Downstream**: W82 Image module integrates per-source loss detection (multi-source SSM groups). Production market-data deployment: A-feed (primary source) + B-feed (backup source), client SSM-subscribes to A, falls over to B on loss.

- [ ] [HFT] **Build**: `crates/ledger-deterministic/src/journal.rs` — every `apply(op)` writes a `JournalRecord` to wal
  BEFORE mutating state. recovery::Recovery replays journal on open. Output: a state machine that survives crashes
  byte-identically. (~105 min)
  - **Why**: A journaled state machine survives crashes *byte-identically* — the canonical durability discipline behind TigerBeetle, FoundationDB, SQLite WAL mode. This is bar (c) for ledger-deterministic; the entire safety story of the ledger rests on this primitive.
  - **Read first**: TigerBeetle `vsr/journal.zig`. SQLite's WAL mode (`https://sqlite.org/wal.html`). PostgreSQL physical WAL (xlog). Atul Adya "Generalized Isolation Level Definitions" — crash-recovery semantics framework.
  - **Design**:
    ```rust
    pub struct JournalRecord {
        pub seq: u64,                       // monotonic per ledger
        pub timestamp_monotonic: u64,        // SeqClock-driven, NOT wall
        pub op: Op,                          // CreateAccount, Transfer, etc.
        pub checksum: u32,                   // crc32c of (seq, op_bytes)
    }
    pub struct JournaledStateMachine {
        pub sm: StateMachine,                // pure, deterministic
        pub wal: WalHandle,                  // append-only durable log
        pub applied_seq: u64,
    }
    impl JournaledStateMachine {
        pub fn apply(&mut self, op: Op) -> Result<OpResult> {
            let seq = self.applied_seq + 1;
            let record = JournalRecord { seq, timestamp_monotonic: self.sm.clock(), op: op.clone(), checksum: 0 };
            let bytes = bincode::serialize(&record)?;
            let cksum = crc32c::crc32c(&bytes);
            let record = JournalRecord { checksum: cksum, ..record };
            self.wal.append(&bincode::serialize(&record)?)?;
            self.wal.fsync()?;                // critical: durable BEFORE mutation
            let result = self.sm.apply(op)?;  // pure
            self.applied_seq = seq;
            Ok(result)
        }
        pub fn recover(wal: WalHandle) -> Result<Self> {
            let mut sm = StateMachine::empty();
            let mut applied_seq = 0;
            for entry in wal.iter() {
                let record: JournalRecord = bincode::deserialize(&entry)?;
                let cksum = compute_checksum(&record);
                if cksum != record.checksum { /* truncate at corruption */ break; }
                assert_eq!(record.seq, applied_seq + 1, "journal gap");
                sm.apply(record.op)?;
                applied_seq = record.seq;
            }
            Ok(JournaledStateMachine { sm, wal, applied_seq })
        }
    }
    ```
    **Invariants**: (i) wal append + fsync HAPPENS BEFORE state mutation; on crash, in-progress journal entry may be incomplete but state is consistent. (ii) Journal entries are contiguous (seq starts at 1, no gaps); recovery truncates at corruption. (iii) Checksum protects against torn writes, bit rot. (iv) `apply` is deterministic AFTER recovery — replay produces identical state.
  - **Build steps**: 1. (~15 min) JournalRecord + crc32c integration. 2. (~25 min) `apply` — wal append + fsync + mutate. 3. (~25 min) `recover` — iterate, verify checksum, replay. 4. (~15 min) Corruption handling: truncate wal at first bad checksum, log warning, continue from there. 5. (~15 min) Integration with state_machine.rs (W80 Sat). 6. (~10 min) Stub test: 100 ops, kill mid-apply, recover, verify state.
  - **Pitfalls** (named, 4):
    - *Order: mutate-before-fsync*: **Symptom**: state mutated before fsync; crash → state ahead of journal → recovery applies op again → double-apply. **Fix**: strict order — wal append AND fsync MUST complete before state mutation. Loom test the ordering.
    - *Torn writes mid-append*: **Symptom**: power loss during wal write; last record is partial. **Fix**: checksum detects; recovery truncates wal at corruption boundary. wal segment design (built earlier in plan) handles this via segment-level integrity.
    - *Determinism violation in op*: **Symptom**: op uses `time::wall()` or rand → replay produces different state. **Fix**: only `SeqClock` (monotonic, op-counter-driven) allowed; lint `disallowed-types` for std::time::SystemTime, rand, etc.
    - *Recovery performance*: **Symptom**: 10 GiB wal takes hours to replay. **Fix**: periodic snapshots — at every N ops, snapshot SM state to file with checksum; recovery loads latest snapshot + replays log_suffix only. Implemented in v1.0 via consensus-vsr's state-machine snapshot.
  - **Test scenarios**: (a) 1000 ops → fsync → kill -9 process → restart → state matches. (b) Inject partial-write corruption mid-record → recovery truncates + warns. (c) Determinism: same wal replayed on 2 machines → identical state hash. (d) Property: apply-then-crash-then-recover-then-apply-more = pure apply-all sequence (recovery is transparent).
  - **Acceptance**: 100% recovery from `kill -9` injection at 1000 random points. Replay throughput ≥ 10× apply throughput (recovery is fast). Inheritance: wal, recovery::Recovery, time::SeqClock, crc32c.
  - **Downstream**: W83+ ledger-deterministic v0.5+ builds on this. v1.0 adds snapshot. consensus-vsr's `state_transfer.rs` (W76) snapshot uses this SM serialization. Tier-A interview: "describe how TigerBeetle achieves durable state" → journal + monotonic SM + recovery — this exact pattern.
