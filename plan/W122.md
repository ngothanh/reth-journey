This is a light career/triage week — there are NO Build exercises and none should be manufactured. The deliverable
is a clean, categorized inbound pipeline (so W125 applications and W123 intro calls start from data, not memory) plus
unbroken interview-prep cadence so the rust-skill edge built over 121 weeks does not decay right before interview
rounds. Every item below names its file and an Output line; learning/recall items carry a hardened-acceptance and a
mental model for why the item exists *now*.

**Monday — Inbound triage**

- [ ] **Triage inbound from the flagship post** → `notes/W122_inbound_pipeline.md` (private). For each person who reached
  out via the W121 flagship post (DMs, email, GitHub, blog comments), record: name, channel, firm, role-hint, and a
  category — `hiring-HFT` / `hiring-crypto` / `curiosity` / `sales-pitch (ignore)`. One row per contact in a markdown
  table. (~40 min)
  - 🎯 Hardened acceptance: every inbound message from the W121 post is represented as exactly one row; each row has a
    non-empty category; `sales-pitch` rows are tagged `ignore` and excluded from the W123 call shortlist. Output:
    `notes/W122_inbound_pipeline.md` exists with a contacts table; count of `hiring-*` rows is stated at the top.
  - *Mental model*: the flagship post (W121) was the public artifact built specifically to generate inbound. Triaging it
    into a categorized table NOW — while the post is fresh and replies are arriving — means W123 intro calls and W125
    applications work from a concrete pipeline, not from scrolling DMs under deadline pressure. Zero inbound is a valid,
    informative outcome: if the table is empty, that is the signal to pivot to outbound (W125) earlier.
- [ ] **Draft per-category reply templates** → append to `notes/W122_inbound_pipeline.md`. Three short reply stubs:
  `hiring-HFT` (lead with matching-engine + messaging-aeron + marketdata work), `hiring-crypto` (lead with reth/Tempo
  PRs + consensus work), `curiosity` (warm thanks + link, no ask). (~20 min)
  - 🎯 Hardened acceptance: 3 reply templates exist; the HFT and crypto templates each name ≥2 concrete shipped artifacts
    (crate or merged PR) by name, not generic claims. Output: templates appended under a `## Reply templates` heading.
  - *Mental model*: recruiters reply-rate collapses with latency; pre-writing per-category stubs means Tuesday's
    scheduling and any same-day responses go out in minutes, not hours.
- [ ] Commit notes (private repo). (~10 min)

**Tuesday — Schedule intro calls**

- [ ] **Schedule 30-min intro calls into W123-W124** → update `notes/W122_inbound_pipeline.md` with a `## Scheduled calls`
    section. For every `hiring-HFT` / `hiring-crypto` row, send the matching reply template and propose two W123-W124
    slots (account for destination-timezone offset — the recon trip is in-region). Log each: contact, proposed slots,
    sent-timestamp, status. (~40 min)
  - 🎯 Hardened acceptance: every `hiring-*` contact has a sent reply and ≥1 proposed slot logged; proposed slots fall
    within W123-W124 and are stated in BOTH local and destination timezones. Output: `## Scheduled calls` table with
    one row per `hiring-*` contact, status column populated.
  - *Mental model*: the W123-W124 recon trip is the chance to convert inbound into in-person/in-timezone conversations —
    far higher signal than a cold W125 application. Scheduling now (a week ahead) respects recruiter calendars and lets
    the trip itinerary form around real meetings.
- [ ] Commit notes. (~10 min)

**Wednesday — Interview prep: algorithms + systems design**

- [ ] **Daily timed algorithm rep** → `notes/interview_prep_log.md` (running log, continued from W118-W120). One
  LeetCode medium/hard, 35-min timer, Rust solution committed to `scratch/interview/src/bin/`. Log: problem, time-to-AC,
  approach, and one failure if any. (~45 min)
  - 🎯 Hardened acceptance: one problem solved under the 35-min cap; Rust solution compiles and passes the provided cases;
    log row records time-to-AC and the data structure used. Output: new `scratch/interview/src/bin/W122_wNN.rs` compiles
    (`cargo build -p interview-scratch` green) + log row appended.
  - *Mental model*: 121 weeks of systems Rust does not automatically translate to whiteboard-speed algorithm fluency
    under a timer; HFT/crypto loops still screen on this. The daily cadence (started W118) must NOT lapse the week before
    interview rounds — a skipped week here is measurable decay at exactly the wrong time.
- [ ] **One systems-design drill** → `notes/systems_design_drills.md`. Pick a prompt adjacent to shipped work (e.g.
  "design a low-latency order-matching service" or "design a deterministic ledger") and write a 1-page design: API,
  data model, latency budget with Jeff-Dean numbers, failure modes, back-pressure strategy. (~45 min)
  - 🎯 Hardened acceptance: design names a concrete latency budget (µs/ns) justified with at least two Jeff-Dean numbers,
    and lists ≥2 failure modes with mitigations. Output: dated section appended to `notes/systems_design_drills.md`.
  - *Mental model*: pulling design prompts from your OWN shipped crates (matching-engine W58-74, ledger W80-83,
    messaging-aeron W76-79) means the interview answer cites lived design decisions and measured numbers — the exact
    differentiator the flagship post advertises. This is also rehearsal for the inbound calls scheduled Tuesday.
- [ ] Commit. (~10 min)
