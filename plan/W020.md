**Monday — MPT deeper theory + `BranchNodeCompact`**

- [ ] Re-read ethereum.org MPT docs + 2-3 blog explanations. (~45 min)
- [ ] **Build**: `crates/eth-trie/src/branch_compact.rs` — BranchNodeCompact mirroring reth_trie. (~105 min)
  - **Why**: A naive MPT branch node carries 16 child hashes (16 × 32 = 512 bytes). 90%+ of branches are sparse (≤4 children). reth_trie introduced `BranchNodeCompact` — a bitmask-indexed representation that stores only present children — to cut intermediate-trie storage by ~4×. This single representation choice dominates trie-db size.
  - **Read first**: reth `crates/trie/trie/src/nodes/branch.rs` (search for `BranchNodeCompact`). Also `alloy_trie::nodes::BranchNode` for the un-compact form. Yellow paper §C and the Wood-Buterin "Modified Merkle Patricia Trie" doc.
  - **Design**:
    ```rust
    pub struct BranchNodeCompact {
        /// 16-bit mask: bit i set iff child[i] exists
        pub state_mask: u16,
        /// 16-bit mask: bit i set iff child[i] is an intermediate (stored in DB) not embedded
        pub tree_mask: u16,
        /// 16-bit mask: bit i set iff child[i]'s hash must be retained for proofs
        pub hash_mask: u16,
        /// Only the hashes for bits set in hash_mask, in nibble order
        pub hashes: SmallVec<[B256; 4]>,
        /// If this branch's root hash was retained (top-of-trie path)
        pub root_hash: Option<B256>,
    }
    ```
    **Invariants**:
    - `hash_mask.count_ones() == hashes.len()`.
    - `tree_mask & !state_mask == 0` (can't reference children that don't exist).
    - `hash_mask & !state_mask == 0` (same).
    - Decoded RLP must round-trip byte-identical (canonical encoding).
  - **Build steps**:
    1. (~15 min) Struct + invariant-asserting constructor `try_new(state, tree, hash, hashes)`.
    2. (~20 min) `rlp_encode` and `rlp_decode` — branch is 17-item list: 16 child slots + value. Empty slots = `0x80`.
    3. (~20 min) `compact_encode` / `compact_decode` for the DB form: 3 u16 masks + Vec<B256>.
    4. (~15 min) `iter_children` returning `(nibble, ChildSlot)` honoring nibble order.
    5. (~15 min) `set_child(nibble, hash_or_embedded)` keeping masks consistent.
    6. (~10 min) Tests against fixed reth_trie fixtures.
    7. (~10 min) Property: encode → decode → encode produces same bytes.
  - **Pitfalls**:
    - *Nibble ordering*: child[0]..child[15] is MSB-first nibble order. Off-by-one fails every state-root check. **Symptom**: state root diverges from genesis. **Fix**: explicit `assert_eq!(nibble_low_to_high_order, ...)` test against `eth_getProof` fixture.
    - *Embedded vs hashed child*: children with RLP encoding < 32 bytes are embedded inline, not hashed. **Symptom**: state root mismatch on shallow tries. **Fix**: when encoding, branch on `child.encoded_len() < 32` → inline raw bytes; else hash.
    - *17th slot (value)*: MPT branch nodes have a 17th slot for values terminating at this branch. **Symptom**: state root for accounts at trie depth 0 wrong. **Fix**: include the value slot in `rlp_encode`; in practice it's almost always empty.
    - *SmallVec inline size*: `[B256; 4]` keeps the common case heap-free. Bump it past 4 and node size blows up. **Symptom**: alloc traffic regression. **Fix**: profile branch occupancy; 90% have ≤4 hashes after compaction.
  - **Test scenarios**:
    - Round-trip every node from a 10k-account fixture trie.
    - Property: random `(state, tree, hash, hashes)` tuples obeying invariants → encode/decode roundtrip.
    - Adversarial: corrupted mask (state_mask = 0 but hashes non-empty) → constructor rejects.
    - Mainnet vector: known account at known state root produces known proof.
  - **Acceptance**:
    - Inheritance ratio ≥ 0.95 vs reth_trie BranchNodeCompact (field-for-field + RLP impl).
    - Encode/decode bench: ≥ 5 M nodes/sec.
  - **Downstream**: W20 ProofRetainer holds these; W22+ MerkleStage reads/writes them from DB; W31 persistent MPT serializes them to MDBX as the intermediate-trie table.

**Tuesday — `TrieStorage` abstraction over `StateCache`**

- [ ] **Refactor**: split TrieStorage into HashedNodeStorage + IntermediateStorage. (~60 min)
  - **Why**: A persistent MPT stores TWO physically distinct kinds of nodes: (a) the hashed-state leaves (one row per account/slot) and (b) the intermediate branch/extension nodes computed during state-root building. Conflating them in one trait forces every consumer to wade through the same K/V soup. reth's split allows MerkleStage to rebuild intermediate nodes incrementally from hashed state, never touching account-leaf storage.
  - **Read first**: reth `crates/trie/trie/src/trie_cursor/mod.rs` — `TrieCursorFactory` returns separate cursors for `account_trie_cursor` and `storage_trie_cursor`. Also `crates/storage/db-api/src/tables/mod.rs` table list (HashedAccounts, HashedStorages, AccountsTrie, StoragesTrie).
  - **Design**:
    ```rust
    pub trait HashedNodeStorage {
        fn get_account(&self, hashed: B256) -> Option<Account>;
        fn get_storage(&self, account: B256, slot: B256) -> Option<U256>;
        fn account_cursor(&self) -> impl Cursor<Key = B256, Value = Account>;
        fn storage_cursor(&self, account: B256) -> impl Cursor<Key = B256, Value = U256>;
    }
    pub trait IntermediateStorage {
        fn get_branch(&self, path: Nibbles) -> Option<BranchNodeCompact>;
        fn put_branch(&mut self, path: Nibbles, node: BranchNodeCompact);
        fn delete_branch(&mut self, path: Nibbles);
        fn account_trie_cursor(&self) -> impl Cursor<Key = Nibbles, Value = BranchNodeCompact>;
        fn storage_trie_cursor(&self, account: B256) -> impl Cursor<Key = Nibbles, Value = BranchNodeCompact>;
    }
    ```
    **Invariants**:
    - `IntermediateStorage` is *rebuildable* from `HashedNodeStorage` (this is the single most important property).
    - Keys in `account_trie_cursor` are nibble-prefix-ordered (lex by `Nibbles`).
    - On any write path, hashed table is the source of truth; intermediate is a derived index.
  - **Build steps**:
    1. (~15 min) Define both traits in `eth-trie/src/storage/mod.rs`.
    2. (~15 min) Provide a `MemoryHashed` and `MemoryIntermediate` test-impl backed by `BTreeMap`.
    3. (~15 min) Migrate existing `eth-trie` callers to the new split — every test/example.
    4. (~10 min) Verify `cargo build --all-features` and `cargo test -p eth-trie` green.
    5. (~5 min) Document the split in the crate-root doc comment with a 5-line diagram.
  - **Pitfalls**:
    - *Conflating account-trie with storage-trie cursors*: each account has its OWN storage trie; a single `storage_trie_cursor()` makes no sense. **Symptom**: state root computation produces one mega-trie instead of nested. **Fix**: `storage_trie_cursor(account: B256)` parameterized.
    - *Mutability split*: reads must be `&self` (so multiple readers can hold the trait); writes `&mut`. **Symptom**: deadlock when MerkleStage wants to read while another thread writes. **Fix**: separate `HashedRead`/`HashedWrite` traits, or accept Send+Sync wrappers — defer to W22 stage design.
    - *Lifetime leakage of cursors*: returning `impl Cursor + 'a` ties storage to the cursor; nested loops cannot share. **Symptom**: borrow-checker hell in MerkleStage. **Fix**: cursors take `&self` and return owned `Item` clones; reth does this.
  - **Test scenarios**:
    - Insert 10k accounts via Hashed; rebuild Intermediate from scratch; compare derived to incrementally-maintained version.
    - Property: any sequence of (insert, delete) on Hashed, followed by full rebuild of Intermediate, yields the same root as incremental maintenance.
    - Adversarial: empty hashed → intermediate must be empty (root = EMPTY_ROOT_HASH = keccak(rlp(b"")) ).
  - **Acceptance**:
    - All `eth-trie` tests pass with both `Memory*` test impls.
    - Inheritance ratio 1.0 vs reth's `TrieCursorFactory` shape.
  - **Downstream**: W22 MerkleStage consumes both traits; W27+ storage-trie::mdbx implements both atop MDBX tables; W92 block-stm reads via parallel `HashedNodeStorage` snapshots.

**Wednesday — `TrieWalker` cursor**

- [ ] **Build**: `crates/eth-trie/src/walker.rs` — TrieWalker<S: TrieStorage> streaming traversal. (~105 min)
  - **Why**: Building a state root requires touching every dirty account's trie path AND only those paths — not the whole trie. TrieWalker is the streaming cursor that yields paths in lex order, skipping subtrees that haven't changed. This is the algorithm that makes incremental MerkleStage tractable on a 700M-account state.
  - **Read first**: reth `crates/trie/trie/src/walker.rs` (TrieWalker struct + advance/next logic) and `crates/trie/trie/src/prefix_set.rs` (PrefixSet — the set of dirty paths driving the walker). Yellow paper section on trie root computation.
  - **Design**:
    ```rust
    pub struct TrieWalker<'a, C: TrieCursor> {
        cursor: C,
        stack: Vec<StackItem>,            // (Nibbles, BranchNodeCompact, child_index)
        current_key: Option<Nibbles>,
        skip_state_root: bool,
        changes: &'a PrefixSet,           // dirty-path filter
        // Buffered next-to-yield to enable lookahead
        next_unprocessed: Option<Nibbles>,
    }
    impl<'a, C: TrieCursor> TrieWalker<'a, C> {
        pub fn advance(&mut self) -> Option<Nibbles>;
        pub fn hash(&self) -> Option<B256>;        // hash of current intermediate node
        pub fn children_are_in_trie(&self) -> bool; // tree_mask bit at current child
    }
    ```
    **Invariants**:
    - Walker yields paths in strict lex (nibble-prefix) order.
    - Walker skips subtrees not in `changes` (the prefix set).
    - `hash()` reflects the cached hash of the *current* branch node when its children are clean.
    - Walker never visits a path that doesn't exist in storage.
  - **Build steps**:
    1. (~20 min) `Nibbles` type with `extend(child: u8)`, `pop()`, `as_slice()`. Use an inline `SmallVec<[u8; 64]>` (max trie depth ≈ 64 nibbles).
    2. (~25 min) `PrefixSet` — sorted Vec of dirty paths; `contains_prefix(nibbles) -> bool` via binary search.
    3. (~35 min) `advance()` body: pop empty stack frames, push deeper branches when in changes, yield path.
    4. (~15 min) `hash()` and `children_are_in_trie()` accessors reading current stack top.
    5. (~10 min) Tests: walker over a 100-account in-memory trie with 5 dirty accounts yields exactly those 5 paths plus ancestors.
  - **Pitfalls**:
    - *Off-by-one in nibble extend/pop*: walker descends one nibble at a time but branch nodes carry one nibble per child; missing/extra nibble corrupts every path. **Symptom**: walker visits ghost paths. **Fix**: every push of a branch frame must extend current_key by exactly one nibble.
    - *Stale stack frames*: when stack drains, current_key must shrink. **Symptom**: walker emits paths starting with the previous run's prefix. **Fix**: on pop, `current_key.truncate(stack.len())`.
    - *Empty trie corner*: walker on empty cursor must return `None` immediately, NOT panic. **Symptom**: panic on first advance of fresh trie. **Fix**: `cursor.first().is_none() ⇒ done`.
    - *Cursor invalidation*: if you mutate the underlying trie while walking, cursor positions may invalidate. **Symptom**: missed or repeated nodes. **Fix**: walker holds exclusive cursor; rebuild on writes.
  - **Test scenarios**:
    - Empty trie: advance returns `None`.
    - Single-leaf trie: walker yields just the leaf path.
    - 10-account trie with 3 dirty (random selection): yields exactly the 3 ancestor-paths.
    - Property: walker output is monotone in nibble-lex order.
    - Stress: 1M-account trie with 1k dirty paths — walker walks ~30k ancestor branches (log-bounded).
  - **Acceptance**:
    - Inheritance ratio ≥ 0.9 vs reth `walker.rs`.
    - Bench: 1k dirty paths in 100M-leaf trie → walker completes in <50 ms.
  - **Downstream**: ProofRetainer (Thursday) consumes walker output; StateRoot orchestrator (Friday) drives walker for incremental root; W22 MerkleStage glues walker + DB cursor.

**Thursday — `ProofRetainer` + EIP-1186 proofs**

- [ ] **Build**: `crates/eth-trie/src/proof/retainer.rs` — ProofRetainer mirroring alloy_trie. (~105 min)
  - **Why**: EIP-1186 (`eth_getProof`) demands a Merkle proof of a specific account/slot. Naive approach: rebuild the trie, log every node. Real approach: during state-root walk, *retain* only the nodes on the requested path. ProofRetainer is the side-channel observer of the hash builder that captures these nodes.
  - **Read first**: alloy `crates/trie/src/proof/retainer.rs` (it's small, ~150 lines). Also EIP-1186 spec for proof format. Compare with reth's account-proof variant in `crates/trie/trie/src/proof.rs`.
  - **Design**:
    ```rust
    pub struct ProofRetainer {
        /// Nibble prefixes we want proofs for, sorted lex.
        targets: Vec<Nibbles>,
        /// Map from path → RLP-encoded node on that path.
        proofs: BTreeMap<Nibbles, Bytes>,
    }
    impl ProofRetainer {
        pub fn new(targets: Vec<Nibbles>) -> Self { ... }
        pub fn retain(&mut self, prefix: &Nibbles, encoded: &[u8]) {
            // Retain if prefix is an ancestor of any target.
            if self.targets.iter().any(|t| t.has_prefix(prefix)) {
                self.proofs.insert(prefix.clone(), Bytes::copy_from_slice(encoded));
            }
        }
        pub fn into_proof(self) -> Vec<Bytes> {
            // Flatten in lex order; client decodes from root to leaf.
            self.proofs.into_values().collect()
        }
    }
    ```
    **Invariants**:
    - For each target, the proof contains every node on the root→target path, lex-ordered.
    - Nodes are RLP-encoded (the wire form), not BranchNodeCompact (the DB form).
    - Embedded children (<32 bytes) are NOT separately retained — they live inside the parent's encoding.
    - Proof verifier needs only the root hash + the proof + the leaf key/value to validate.
  - **Build steps**:
    1. (~10 min) `Nibbles::has_prefix` and binary-search helpers.
    2. (~25 min) `ProofRetainer::retain` with the "ancestor-of-any-target" filter. Use sorted targets + bsearch for O(log T) per node.
    3. (~25 min) Wire into hash builder hook: every time the hash builder emits an intermediate node's encoding, call `retain`.
    4. (~20 min) `into_proof()` flatten with deterministic ordering.
    5. (~15 min) Tests: known mainnet account proof (eth_getProof response) decoded as fixture, regenerate, compare.
    6. (~10 min) Storage-proof variant for a slot inside an account's storage trie.
  - **Pitfalls**:
    - *Retain at the wrong level*: retaining BranchNodeCompact (DB form) instead of RLP-encoded (wire form). **Symptom**: client can't verify proof — hash mismatches. **Fix**: hash builder emits RLP bytes; retain those, not the compact form.
    - *Missing leaf node*: targets that are *exact* paths need the leaf node retained too. **Symptom**: proof one node short. **Fix**: hash builder emits leaf encoding; retainer retains if any target equals (not just has_prefix) this path.
    - *Non-existence proofs*: EIP-1186 also proves an account *doesn't* exist (returns empty value + path to nearest divergence). **Symptom**: client rejects the proof. **Fix**: retainer must capture the branch where the path diverges — handled if you retain every ancestor-of-any-target prefix.
    - *Order non-determinism*: BTreeMap iteration order is lex, but if you swap to HashMap, proofs become non-deterministic. **Symptom**: flaky tests, non-canonical RPC responses. **Fix**: stick with BTreeMap; document the contract.
  - **Test scenarios**:
    - Mainnet block 12,000,000, vitalik.eth account — round-trip eth_getProof response.
    - 1k accounts, 100 random targets → 100 valid proofs, each ≤ 9 nodes deep.
    - Non-existence: request proof for an account never inserted — proof terminates at branch with no matching child.
    - Storage proof: account with 5 storage slots, prove slot 0x3 — proof has account+storage proof chains.
  - **Acceptance**:
    - Inheritance ratio ≥ 0.9 vs alloy `proof/retainer.rs`.
    - Pass EIP-1186 official test vectors.
  - **Downstream**: Friday's StateRoot orchestrator drives retainer alongside walker; Phase 5 RPC `eth_getProof` wraps this.

**Friday — `StateRoot` orchestrator**

- [ ] **Build**: `crates/eth-trie/src/state_root.rs` — StateRoot<S> with compute(). Heart of MerkleStage. (~105 min)
  - **Why**: This is *the* algorithm that determines whether your node accepts or forks. Every block has a 32-byte `state_root` in its header — your node must compute byte-identical bytes. reth's StateRoot orchestrates: walker (which paths to visit) + hash builder (state machine that emits node hashes) + ProofRetainer (optional side-channel). One bug here = chain halt.
  - **Read first**: reth `crates/trie/trie/src/state_root.rs` (the orchestrator) and `crates/trie/trie/src/hash_builder.rs` (the state machine — read this *first*, it's the heart). Also yellow paper §C and "Modified Merkle Patricia Trie Specification" (ethereum/wiki).
  - **Design**:
    ```rust
    pub struct StateRoot<S: HashedNodeStorage, I: IntermediateStorage> {
        hashed: S,
        intermediate: I,
        prefix_sets: TriePrefixSets,
        retainer: Option<ProofRetainer>,
    }
    impl<S, I> StateRoot<S, I> {
        pub fn compute(self) -> Result<(B256, TrieUpdates), Error> {
            let mut hb = HashBuilder::new();
            let mut walker = TrieWalker::new(self.intermediate.account_trie_cursor(), &self.prefix_sets.account_changes);
            let mut hashed_cursor = self.hashed.account_cursor();
            loop {
                // 1. Advance walker (intermediate trie).
                // 2. For each non-dirty subtree, feed cached hash into hb.
                // 3. For each dirty leaf, advance hashed_cursor, compute storage root for accounts, feed into hb.
                // 4. Done when walker exhausted.
            }
            let root = hb.root();
            (root, hb.into_updates())
        }
    }
    ```
    **Invariants**:
    - Computed root MUST equal `EMPTY_ROOT_HASH` for an empty trie (a known 32-byte constant).
    - Hash builder must process leaves in nibble-lex order.
    - Account leaves' value = RLP(Account { nonce, balance, storage_root, code_hash }) — order matters.
    - Storage roots are sub-trie roots, computed by the SAME algorithm recursively per account.
  - **Build steps**:
    1. (~20 min) `HashBuilder` state machine — 4 internal states (Updated, Hashed, Left, Right). Mirror reth.
    2. (~30 min) `compute()` body — interleave walker + hashed_cursor; this is the trickiest 40 lines you'll write this month.
    3. (~20 min) Per-account storage-root computation (recursive `compute` for storage subtree).
    4. (~15 min) `TrieUpdates` — set of (path, new_node) pairs the caller persists.
    5. (~15 min) Hook ProofRetainer between hash builder and consumer.
    6. (~10 min) Test: empty trie → EMPTY_ROOT_HASH.
    7. (~10 min) Test: genesis block reconstruction.
  - **Pitfalls**:
    - *Storage root for empty storage*: empty storage trie's root is `EMPTY_ROOT_HASH`, *not* zero. **Symptom**: accounts with no storage have wrong state root. **Fix**: storage root computation must return EMPTY_ROOT_HASH on empty cursor.
    - *Account RLP encoding order*: must be `(nonce, balance, storage_root, code_hash)`, not alphabetical, not the order you'd guess. **Symptom**: every state root wrong. **Fix**: derive macro with explicit field order; double-check against yellow paper appendix.
    - *Walker/cursor desync*: hashed cursor and trie cursor must advance in lockstep on dirty leaves. **Symptom**: hash builder receives leaves out of order, builds wrong tree. **Fix**: every walker.advance() that yields a leaf-prefix path triggers hashed_cursor.seek_exact(path-to-key).
    - *Forgotten intermediate clean subtree*: walker yields paths in `tree_mask` — feed their cached hash to hash builder without descending. **Symptom**: state root recompute touches every leaf — 30 min for full state. **Fix**: `walker.children_are_in_trie() == true` means feed cached hash, skip descent.
    - *Code hash for accounts with no code*: must be `keccak256("")`, not zero. **Symptom**: EOAs have wrong state root. **Fix**: `Account::default().code_hash == KECCAK_EMPTY`.
  - **Test scenarios**:
    - Empty trie → EMPTY_ROOT_HASH = `0x56e81f171bcc55a6ff8345e692c0f86e5b48e01b996cadc001622fb5e363b421`.
    - Single account at genesis: known state root from a public genesis JSON.
    - Mainnet block 1: from genesis state, apply block-1 changes, compute root, compare with header.state_root.
    - 1000 random accounts: insert all, compute root, delete half, recompute, insert them back, root matches original.
    - Property: order of inserts doesn't affect final root (commutative under set semantics).
  - **Acceptance**:
    - Pass EthereumTests' `TrieTests` (small) AND mainnet block 1 root reconstruction (the inheritance milestone).
    - Inheritance ratio ≥ 0.9 vs reth `state_root.rs`.
  - **Downstream**: W22 MerkleStage wraps `StateRoot::compute` for staged-sync; W27+ persistent backend swap; W31 storage-trie MPT integration; W92 block-stm validates parallel exec by comparing state roots.
