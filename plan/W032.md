**Monday — MPT proof generation**

- [ ] Implement Merkle proof generation. Unit tests. (~120 min)
  - **Why**: EIP-1186 Merkle proofs are the consensus-critical artifact that lets light clients verify state without downloading the trie. The proof is the ordered list of RLP-encoded nodes along the path from root to leaf. Proof generation correctness is bit-exact — any deviation in encoding (extension vs. branch ordering, even-length vs odd-length nibble HP prefix) yields a verifier rejection. This must mirror Reth byte-for-byte.
  - **Read first**: `reth/crates/trie/trie/src/proof.rs` (`Proof::compute_proof`) and EIP-1186 spec. Also go-ethereum's `core/types/hashing.go` for the canonical reference.
  - **Design**:
    ```rust
    pub struct ProofRetainer {
        target_keys: BTreeSet<Nibbles>,
        proofs: HashMap<Nibbles, Vec<Bytes>>, // path -> ordered RLP nodes
    }
    impl ProofRetainer {
        pub fn retain(&mut self, path: &Nibbles, node: &Node);
        pub fn into_proofs(self) -> HashMap<Nibbles, Vec<Bytes>>;
    }
    ```
    **Invariants**:
    - Proof list is ordered root-first; verifier walks in this order.
    - Every node in the proof is RLP-encoded canonically (no leading zeros in integers).
    - For a missing-key proof (proof of absence), the proof terminates at the last branch where the path diverges.
  - **Build steps**:
    1. (~20 min) Hook a `ProofRetainer` into the trie walker: when walker visits a node whose path is an ancestor of any target key, retain.
    2. (~40 min) Encode each retained node via the existing eth-trie RLP encoder; do NOT re-implement encoding.
    3. (~30 min) Exclusion proof support: detect divergence at branch/extension; retain the terminal node + sibling hashes.
    4. (~20 min) Property test: random key sets, generate proof for each, verify via separate verifier.
    5. (~10 min) Vector tests against Ethereum testdata.
  - **Pitfalls**:
    - *Nibble HP encoding direction*: leaf-vs-extension flag bit collides with even/odd-length flag if you swap them. **Symptom**: verifier rejects with "invalid HP prefix". **Fix**: nibble HP encoding table per Yellow Paper Appendix C; copy from eth-trie tests.
    - *Skipped extension-after-branch*: when an extension node's child is a single branch slot, the encoder may inline; proof must retain the inlined form not the expanded. **Symptom**: proof verifies to wrong root. **Fix**: retain the byte slice the trie wrote, not a recomputed form.
    - *Mutable trie underfoot*: retainer reads paths while another writer mutates. **Symptom**: nondeterministic proofs. **Fix**: proof gen takes a snapshot (MdbxTrieStorage read txn).
  - **Test scenarios**:
    - 100 random insertions, generate proofs for all 100 keys; verifier accepts all.
    - Exclusion proof: generate proof for a non-existent key; verifier confirms absence.
    - Vector test: ethereum/tests trie_test.json all pass byte-identical.
  - **Acceptance**: proof gen <100μs p99 for a 10k-account trie; verifier rejects all 1-bit-mutated proofs.
  - **Downstream**: W36 snapshot sync verifies via these proofs; light-client mode in mini-db (W95).
- [ ] Commit + log (~10 min)

**Tuesday — MPT proof verification**

- [ ] Standalone proof verification. (~30 min)
  - **Why**: The verifier is the consensus surface — it's run by every light client and every state-witness consumer. Verifier code must be (a) zero-allocation on the happy path (proof size is bounded), (b) total — every malformed input is rejected with a typed error, no panics.
  - **Read first**: EIP-1186 `eth_getProof` algorithm; `reth/crates/trie/trie/src/proof_verifier.rs`.
  - **Design**:
    ```rust
    pub fn verify_proof(
        root: B256, key: &[u8], expected: Option<&[u8]>, proof: &[Bytes],
    ) -> Result<(), ProofError>;

    pub enum ProofError {
        RootMismatch, NodeNotInProof, UnexpectedExtension, BadNibblePrefix,
        BadEncoding(rlp::Error), HashMismatch { at: usize },
    }
    ```
    **Invariants**:
    - First node in `proof` must hash to `root`.
    - Each subsequent node's hash must appear in the prior node's children.
    - Final node either contains `expected` (inclusion proof) or proves absence by diverging path.
  - **Build steps**:
    1. (~10 min) Top-level dispatch: keccak the first node, compare to `root`.
    2. (~10 min) Walk: at each branch, follow nibble; at each extension, validate prefix matches.
    3. (~10 min) Inclusion path: terminal leaf value matches `expected`; exclusion path: terminal proves no leaf at key.
  - **Pitfalls**:
    - *Panic on malformed RLP*: untrusted input feeds into a panicking decoder. **Symptom**: DOS via crafted proof. **Fix**: every RLP decode must `?`-propagate; no `unwrap`.
    - *Confusing inclusion of empty value*: in MPT, an "empty value" (`b""`) is distinct from "no entry"; verifier conflates → rejects valid proofs. **Fix**: encode the distinction in `expected: Option<&[u8]>`.
  - **Test scenarios**:
    - Fuzz target: random byte sequences as proof; never panic, always typed error or accept.
    - All Ethereum reference proofs pass; bit-flipped versions all fail.
  - **Acceptance**: zero panics under cargo-fuzz 1M iter; <50μs per verify.
  - **Downstream**: light-client mode (W95 mini-db variant); snapshot-sync integrity (W36).
- [ ] Commit + log (~10 min)

**Wednesday — MPT delete**

- [ ] MPT delete with rebalancing. (~30 min)
  - **Why**: MPT delete is the most error-prone trie operation because it triggers structural collapse — removing a leaf from a branch with two children leaves one child, which must collapse into an extension+leaf or a single leaf. Get this wrong and the root hash diverges. This is where Reth/geth implementations historically had bugs.
  - **Read first**: `reth/crates/trie/trie/src/trie.rs` delete logic; go-ethereum `trie/trie.go::delete`.
  - **Design**:
    ```rust
    fn delete(&mut self, path: &Nibbles) -> Result<Option<Bytes>, TrieError>;
    // Returns prior value if existed; rebalances tree on the way back up.
    ```
    **Invariants**:
    - After delete, no branch node has fewer than 2 children unless it's the root.
    - Extension chains never have a single-child branch (collapsed into one extension).
    - Empty trie after deleting last leaf has root = `KECCAK_EMPTY_ROOT`.
  - **Build steps**:
    1. (~10 min) Recursive descent; locate leaf; remove from branch slot.
    2. (~10 min) Post-recursion rebalance: if branch now has 1 child + value=None → collapse into extension+(child key) or leaf.
    3. (~10 min) Merge adjacent extension nodes (consolidate prefixes).
  - **Pitfalls**:
    - *Forgetting branch-with-value*: a branch with a value and one child still needs the value preserved when collapsing. **Symptom**: data loss on delete of sibling. **Fix**: check `branch.value.is_some()` before collapse.
    - *Extension-of-extension*: post-collapse, an extension whose child is an extension should merge prefixes. **Symptom**: root diverges from reference impl. **Fix**: recursive normalize on the rebuilt path.
    - *Empty trie sentinel*: deleting the last leaf must reset root to empty-root sentinel (`KECCAK_EMPTY_ROOT`), not produce a dangling empty branch.
  - **Test scenarios**:
    - Random insert-then-delete: 1k random keys, delete in random order; root after each step matches a reference impl.
    - All-delete: insert N, delete all; root == empty root.
    - Ethereum trietest: delete sequences in trie_test_anyorder.json.
  - **Acceptance**: byte-identical roots vs go-ethereum on every test vector.
  - **Downstream**: W42 (txn rollback emits deletes via undo); state pruning (W34).
