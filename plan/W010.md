- [ ] **Build**: `crates/eth-trie/src/nibbles.rs` — `Nibbles(SmallVec<[u8; 64]>)`. Hex-prefix encoding. (~105 min)
  - *Mental model*: a trie addresses values by the keccak256 of the key, walked one **4-bit nibble at a time** —
    16 child slots per branch. `Nibbles` is that unpacked nibble path: a 32-byte hash becomes a 64-element
    `[0..=15]` sequence. Hex-prefix (HP) / compact encoding is how a node's *partial path* is packed back into
    bytes for RLP, with a flag nibble announcing odd/even length and leaf-vs-extension.
  - *Contract*: `Nibbles` wraps `SmallVec<[u8; 64]>` (max trie depth = 64 nibbles, heap-free). Key methods:
    `unpack(bytes: &[u8]) -> Nibbles` (each byte → high then low nibble), `pack(&self) -> SmallVec<[u8;32]>`
    (the inverse), `common_prefix_len(&other) -> usize`, `slice(start..end)`, `push(nibble: u8)`, `get(i)`. HP
    codec: `encode_path_leaf(&self, is_leaf: bool) -> SmallVec` and a matching `decode` that returns
    `(Nibbles, is_leaf)`.
  - *encode_path_leaf, roughly*: (1) pick a flag value from `{leaf, extension} × {odd, even}` — 4 cases; (2) if
    the nibble count is **odd**, the first output byte is `flag_nibble << 4 | first_data_nibble` and remaining
    nibbles pair up cleanly; if **even**, the first output byte is `flag_nibble << 4 | 0` (a full zero-padding
    nibble) and all data nibbles pair up after it. Step 2 — getting odd/even alignment right — is the real
    exercise.
  - **Expect to hit #1 — the flag nibble packs two booleans, not one**: HP's leading nibble encodes BOTH
    leaf-vs-extension AND odd-vs-even length, as `2*is_leaf + is_odd` (values 0/1/2/3). Treating it as a single
    leaf bit, or XOR-ing the two, mislabels every node. Symptom: decode reads an extension as a leaf (or vice
    versa); the trie walk terminates early or descends into garbage; root hash is wrong.
    - Fix: flag nibble = `0` ext-even, `1` ext-odd, `2` leaf-even, `3` leaf-odd — table per Yellow Paper Appendix C.
    - Muscle: HP's first nibble is a 2-bit field, not a flag — decode it as `(flag>>1, flag&1)`. Reapplies at:
      W20 branch/extension RLP encode, W31 nibble-path key encoding, W32 proof HP-prefix verification.
  - **Expect to hit #2 — odd-length nibble misalignment**: an odd nibble count means one nibble shares the flag
    byte; an even count means a full padding nibble follows the flag. Mixing the two (e.g. always padding) shifts
    every subsequent nibble by 4 bits. Symptom: a 3-nibble path round-trips as 2 or 4 nibbles; node hashes
    diverge only for odd-length partial paths — passes half your tests.
    - Fix: branch on `nibbles.len() % 2`; odd → first data nibble rides in the flag byte's low half; even → emit a
      zero low half, data starts in byte 2.
    - Muscle: HP packs 2 nibbles/byte, so an odd count must consume the flag byte's spare nibble. Reapplies at:
      W31 variable-length nibble keys, W32 proof generation.
  - **Expect to hit #3 — `unpack` byte/nibble order**: emitting the low nibble before the high nibble of each
    byte. Symptom: every keccak path is bit-reversed within each byte; the trie builds but no root ever matches a
    fixture — looks like a hashing bug, is actually a nibble-order bug.
    - Fix: for each byte, high nibble (`b >> 4`) first, low nibble (`b & 0x0f`) second; `pack` does the inverse.
    - Muscle: nibble order is big-endian within each byte — high then low, always. Reapplies at: W10 Wed
      HashBuilder, W20 TrieWalker path math, W31 path key encoders.

**Tuesday — `Node` enum + insert/get**

- [ ] **Build**: `crates/eth-trie/src/node.rs` — Node enum (Empty, Leaf, Extension, Branch). (~105 min)
  - *Mental model*: the four MPT node shapes. `Empty` = no entry. `Leaf` = a key-suffix + value, the path ends
    here. `Extension` = a shared key-prefix shortcut pointing at one child (path compression). `Branch` = a
    16-way fan-out (one slot per nibble) plus a 17th slot for a value that terminates exactly at this node.
  - *Contract*: `enum Node { Empty, Leaf { path: Nibbles, value: Bytes }, Extension { path: Nibbles, child:
    Box<NodeRef> }, Branch { children: [Option<Box<NodeRef>>; 16], value: Option<Bytes> } }`. A `NodeRef` is
    either an inline `Node` or a 32-byte hash (see HashBuilder Wed). Operations: `get(&self, path: &Nibbles) ->
    Option<&Bytes>` and `insert(self, path, value) -> Node` (returns the rewritten subtree — nodes are immutable,
    insert rebuilds the path).
  - *insert, roughly*: (1) at a `Leaf`/`Extension`, compute `common_prefix_len` with the new path; (2) if the
    prefixes fully agree, recurse/replace; (3) if they diverge, split into an `Extension` (shared part) above a
    new `Branch` whose two slots hold the old and new tails. Step 3 — the split that introduces a Branch — is the
    real exercise.
  - **Expect to hit #1 — the 17th slot (the branch's own value)**: a `Branch` has 16 child slots **plus** one
    value slot, for keys that terminate exactly at the branch path. Modelling it as `[_; 16]` with no value field
    silently drops any value whose nibble path is a prefix of a longer key. Symptom: in `[("do",..),("dog",..)]`
    `"do"`'s value vanishes — `get("do")` returns `None`; root hash wrong for any prefix-of-prefix key set.
    - Fix: `Branch { children: [Option<…>; 16], value: Option<Bytes> }` — the value slot is mandatory, usually
      `None`.
    - Muscle: an MPT branch is 16+1 slots — the 17th holds a value that ends at the branch itself. Reapplies at:
      W10 Wed HashBuilder branch encode, W20 BranchNodeCompact, W32 MPT delete rebalance.
  - **Expect to hit #2 — leaf/extension confusion on insert split**: when two keys diverge mid-path, the shared
    prefix must become an `Extension` and the divergence point a `Branch`; reusing a `Leaf` for the shared part,
    or forgetting the `Extension` when the shared prefix is empty, mis-shapes the trie. Symptom: a child slot
    points at the wrong node type; `get` walks off the path; structural mismatch vs reference trie.
    - Fix: shared-prefix length 0 → go straight to a `Branch`; length > 0 → wrap the `Branch` in an `Extension`
      carrying that prefix; a terminating path → `Leaf`.
    - Muscle: Extension = shared prefix shortcut, Leaf = terminal suffix, Branch = divergence — never substitute
      one for another. Reapplies at: W32 MPT delete (the inverse collapse), W20 TrieWalker descent.
  - **Expect to hit #3 — mutating a node in place instead of rebuilding the path**: treating insert as `&mut self`
    surgery. MPT nodes are content-addressed (hashed) — an in-place edit changes a node's hash without updating
    its parent's reference, orphaning the subtree. Symptom: child hash in the parent no longer matches the child;
    proofs fail; with persistence, reorgs corrupt shared structure.
    - Fix: `insert` consumes `self` and returns a new `Node`; every node on the root→leaf path is rebuilt; only
      the touched path changes.
    - Muscle: a Merkle trie is persistent (in the data-structure sense) — mutation rebuilds the path, never edits
      a node. Reapplies at: W11 HashedPostState/TrieUpdates, W31 persistent MPT, W32 delete rebalance.
- [ ] **Build**: `crates/eth-trie/src/storage.rs` — `TrieStorage` trait. Initial impl `MemoryStorage`. (~105 min)
  - *Mental model*: the trie is content-addressed — nodes ≥32 bytes are referenced by their `keccak256` hash, not
    held inline. `TrieStorage` is the hash→node store that makes that indirection real; `MemoryStorage` is the
    `HashMap`-backed test impl that later swaps for an MDBX-backed one without the trie code changing.
  - *Contract*: `trait TrieStorage { fn get(&self, hash: &B256) -> Option<Node>; fn insert(&mut self, hash: B256,
    node: Node); fn remove(&mut self, hash: &B256); }`. `MemoryStorage(HashMap<B256, Node>)` implements it. The
    trie holds `S: TrieStorage` and dereferences a `NodeRef::Hash` through `get`.
  - **Expect to hit #1 — storing the hash, not the node, or vice versa as the key**: the table is keyed by the
    node's hash and valued by the node; swapping them, or computing the key from the wrong bytes (hash of the
    `Node` struct rather than `keccak256` of its RLP encoding), makes every lookup miss. Symptom: `get` returns
    `None` for a node you just inserted; trie walk dead-ends one level down.
    - Fix: key = `keccak256(rlp_encode(node))`; insert and lookup must use the *same* encoding-then-hash function.
    - Muscle: content addressing means the key is `keccak256(canonical_encoding)` — derived, never the in-memory
      layout. Reapplies at: W31 `nodes_by_hash` MDBX table, W32 proof node lookup.
  - **Expect to hit #2 — no node ever gets removed (unbounded growth)**: an insert-only store. Each insert
    rebuilds the path (see node.rs #3), so old node versions accumulate; without `remove`/refcounting the
    `HashMap` grows on every write. Symptom: memory climbs steadily under an insert/update workload; fine for the
    3-key test, a leak at scale.
    - Fix: provide `remove`; the trie drops references to superseded nodes — full GC/refcounting is deferred, but
      the trait must expose deletion now so W31 can implement it.
    - Muscle: a content-addressed store needs a deletion path or it leaks every superseded version. Reapplies at:
      W31 MdbxTrieStorage tombstones, W33 epoch-gc.

- [ ] **Build**: `crates/eth-trie/src/hash_builder.rs` — HashBuilder. Stream-builds root via keccak256 of RLP-encoded
  nodes. (~105 min)
  - *Mental model*: the state root is `keccak256` of the RLP of the trie's root node — recursively, of every
    node. `HashBuilder` computes it **without materializing the whole trie**: feed it leaves in nibble-lex order
    and it folds completed subtrees into hashes as it goes, keeping only the current root-to-leaf path in memory.
    This is reth's `hash_builder.rs` and the heart of W20's `StateRoot`.
  - *Contract*: `HashBuilder` with `add_leaf(&mut self, key: Nibbles, value: &[u8])`, `add_branch(&mut self, key:
    Nibbles, hash: B256, ...)` (feed an already-hashed clean subtree), and `root(&mut self) -> B256`. Internally
    a stack of partial nodes plus a "current key" cursor; each `add_*` may flush completed siblings.
  - *root, roughly*: (1) compare the incoming key with the previous key to find where they diverge; (2) everything
    in the stack *below* the divergence point is complete — RLP-encode it, hash it, fold it into its parent's
    child slot; (3) push the new leaf. Step 2 — deciding which stack frames are now complete and collapsing them
    correctly — is the real exercise.
  - **Expect to hit #1 — the <32-byte inlining rule**: a node whose RLP encoding is **< 32 bytes** is embedded
    *inline* in its parent, not referenced by a 32-byte hash; only nodes whose RLP is ≥ 32 bytes are replaced by
    `keccak256`. Always-hash, or always-inline, both diverge. Symptom: root hash mismatches reference fixtures
    only for shallow tries / small values — deep tries pass, the 3-key test fails.
    - Fix: per child, compute `rlp.len()`; `< 32` → splice the raw RLP bytes into the parent; `>= 32` → splice
      `keccak256(rlp)` as a 32-byte string.
    - Muscle: a trie node is referenced by hash only when its RLP is ≥ 32 bytes — otherwise it lives inline.
      Reapplies at: W20 BranchNodeCompact embedded-vs-hashed, W20 ProofRetainer (inline children not retained
      separately), W32 proof generation.
  - **Expect to hit #2 — the branch's 17-slot RLP layout**: a branch RLP-encodes as a **17-item list** — 16 child
    slots then the value slot; an empty child is the empty string `0x80`, NOT omitted. Encoding 16 items, or
    skipping empty slots, or putting the value first, all shift the layout. Symptom: branch hash wrong → every
    ancestor hash wrong → root wrong; the encoding is one item short or misordered.
    - Fix: emit exactly 17 RLP items in order: child[0..16] then value; absent child → `0x80`, absent value →
      `0x80`.
    - Muscle: a branch is always a 17-item RLP list with empty slots present as `0x80`. Reapplies at: W20
      BranchNodeCompact `rlp_encode`, W32 proof node encoding.
  - **Expect to hit #3 — leaves fed out of nibble-lex order**: the streaming algorithm assumes monotonically
    increasing keys — it folds a subtree the moment the next key leaves it. An out-of-order (or duplicate) key
    re-opens a subtree already hashed. Symptom: the builder collapses the wrong frames; root is wrong with no
    panic, or a debug assert fires on a non-monotone key.
    - Fix: require sorted, deduplicated input; assert `key > prev_key` on every `add_*`; the caller (W20's
      walker) guarantees order.
    - Muscle: a streaming hash builder is correct only on a strictly increasing key sequence. Reapplies at: W20
      StateRoot walker/cursor lockstep, W31 persistent root regression suite.
  - **Expect to hit #4 — empty trie root is a constant, not zero**: `root()` on an empty builder must return
    `EMPTY_ROOT_HASH = keccak256(rlp(b"")) = 0x56e81f17…b421`, not `B256::ZERO`. Symptom: empty accounts /
    empty-storage tries get a zero root; state root mismatches the genesis block.
    - Fix: special-case the empty builder to return the `EMPTY_ROOT_HASH` constant.
    - Muscle: the empty trie has a defined non-zero root — `keccak256(rlp(""))`. Reapplies at: W20 StorageRoot
      empty-storage case, W32 MPT delete-to-empty.

**Saturday — `peer-keepalive` state machine on `eth-network-codec`**

- [ ] **Build**: peer-keepalive ping/pong oscillator inside eth-network-codec. (~60 min)
  - *Mental model*: a devp2p connection is silent between requests, so a dead or stalled peer looks identical to
    an idle one. Keepalive periodically sends a `Ping`, expects a `Pong` within a deadline, and tears the
    connection down if none arrives — a liveness watchdog, mirroring devp2p's RLPx ping/pong.
  - *Contract*: a state machine `enum KeepAlive { Idle, AwaitingPong { sent_at: Instant }, Dead }` driven by two
    inputs — a `poll`/`tick(now: Instant)` that may emit `Action::SendPing` or `Action::Disconnect`, and an
    `on_pong()` event. Two configured durations: `ping_interval` (Idle → send Ping) and `pong_timeout`
    (AwaitingPong → Dead).
  - *tick, roughly*: (1) in `Idle`, if `now - last_activity >= ping_interval` → emit `SendPing`, move to
    `AwaitingPong { sent_at: now }`; (2) in `AwaitingPong`, if `now - sent_at >= pong_timeout` → emit
    `Disconnect`, move to `Dead`; (3) `on_pong` from `AwaitingPong` → back to `Idle`. Wiring the timeout race in
    step 2/3 correctly is the real exercise.
  - **Expect to hit #1 — lost-pong / timeout race**: a `Pong` that arrives in the same tick window the timeout
    fires, or a *stale* `Pong` from a previous ping cycle, is mishandled — either a timely peer is killed, or a
    late peer is kept alive by an old reply. Symptom: healthy peers dropped under load; or a half-dead peer never
    times out because each cycle's stale Pong resets the clock.
    - Fix: tag each ping with a monotonically increasing nonce; `on_pong(nonce)` only clears `AwaitingPong` when
      the nonce matches the in-flight ping; check the timeout before accepting a same-tick Pong.
    - Muscle: a request/response watchdog must correlate the reply to the *specific* outstanding request by
      nonce, not just by type. Reapplies at: W11 Connection state machine, W56 consensus-raft heartbeat, W73
      Engine API liveness.
  - **Expect to hit #2 — interval re-armed by inbound traffic, or never armed**: resetting `last_activity` on
    *any* received frame means a chatty peer is never pinged (a stalled-but-chatty peer slips through); resetting
    on nothing means a healthy busy peer gets pinged needlessly. Symptom: keepalive either never fires or fires
    constantly; the watchdog tests pass only because real traffic masks the bug.
    - Fix: decide deliberately — devp2p arms the interval from the last *sent or received* frame so an active
      connection skips redundant pings; document the choice.
    - Muscle: a keepalive timer's reset condition is a design decision — pick it and write down why. Reapplies
      at: W11 Connection idle handling, W56 raft election timer.
