  - **Spec**: derive cap=N must be power-of-two from the modulo cost. Invariants for SPSC: no two values

  - **Compare**: open `rtrb::RingBuffer` source. They pad head/tail AND use a separate `tail_cached` /

  - **Symptom card**: name the perf cliff (cross-core MESI invalidation tax of ~7 ns per access); rule

- [ ] **Build**: `crates/eth-trie/src/nibbles.rs` — `Nibbles(SmallVec<[u8; 64]>)`. Hex-prefix encoding. (~total 150 min across 3 phases)
  - 🔧 **Why this matters**: `Nibbles` is THE primitive every MPT operation uses. HP encoding's flag-nibble
    (4 distinct values for leaf/ext × odd/even) is the most error-prone part of MPT — one bug means every
    fixture mismatches. Downstream: W10 Tue (Node), W10 Wed (HashBuilder), W20 (TrieWalker), W31 (persistent),
    W32 (proofs).

  #### Phase 1 — Problem, requirements, design (~30 min)

  - **Requirements** — write in `notes/10_nibbles_design.md`:
    - R1. `Nibbles(SmallVec<[u8; 64]>)` — max trie depth 64, heap-free.
    - R2. `unpack(bytes) -> Nibbles`: each byte → high nibble first, then low nibble.
    - R3. `pack(&self) -> SmallVec`: inverse — high then low into each byte.
    - R4. `common_prefix_len(&other)`, `slice(range)`, `push`, `get`, `len`.
    - R5. HP encoding flag nibble = `2*is_leaf + is_odd` (0=ext-even, 1=ext-odd, 2=leaf-even, 3=leaf-odd).
    - R6. Odd length: first data nibble rides in flag byte's low half. Even: zero padding in low half.

  - **Design**:
    - D1. Walk through `unpack(&[0xAB, 0xCD])`. Output? `[0xA, 0xB, 0xC, 0xD]`.
    - D2. HP encode for `Nibbles([0xA])` as leaf-odd. Output bytes?
    - D3. **Pre-mortem**: contributor uses XOR for HP flag. What test catches?

  #### Phase 2 — Failing tests (~30 min)

  - [ ] `nibbles_unpack_high_first` — `unpack(&[0xAB])` returns `[0xA, 0xB]`, not `[0xB, 0xA]`.
  - [ ] `nibbles_pack_round_trip` — `pack(unpack(&bytes))` == bytes.
  - [ ] `nibbles_hp_encode_leaf_odd` — leaf with `[0xA]`: flag = 3; first byte = `0x3A`.
  - [ ] `nibbles_hp_encode_leaf_even` — leaf with `[0xA, 0xB]`: flag = 2; bytes = `[0x20, 0xAB]`.
  - [ ] `nibbles_hp_encode_ext_odd` — extension with `[0xA]`: flag = 1; first byte = `0x1A`.
  - [ ] `nibbles_hp_decode_round_trip` — for each of 4 flag cases, round-trip preserves bytes.
  - [ ] `nibbles_common_prefix_len` — `Nibbles([1,2,3]).common_prefix_len(&[1,2,4])` = 2.

  #### Phase 3 — One failure at a time (~90 min)

  - **When `nibbles_hp_encode_leaf_odd` produces wrong flag:**
    - Symptom: leaf-odd encodes with flag=2 or flag=1; should be 3.
    - Why: you treated `is_leaf` and `is_odd` as separate booleans, not a 2-bit field.
    - Fix: `flag = (is_leaf as u8) * 2 + (is_odd as u8)`. Table: 0/1/2/3.
    - Muscle: HP's first nibble is a 2-bit field, not a flag — decode as `(flag>>1, flag&1)`. Reapplies at:
      W20 branch/extension RLP encode, W31 nibble-path key encoding, W32 proof HP-prefix verification.

  - **When `nibbles_hp_encode_leaf_even` produces 1 byte instead of 2:**
    - Symptom: even-length leaf skipped the zero-padding nibble; bytes are off by 4 bits.
    - Why: you always packed first data nibble into flag byte's low half.
    - Fix: branch on `nibbles.len() % 2`. Odd: flag byte holds `[flag, data[0]]`. Even: flag byte holds
      `[flag, 0]`; data starts at byte 1.
    - Muscle: HP packs 2 nibbles/byte; odd count must consume the flag byte's spare nibble. Reapplies at:
      W31 variable-length nibble keys, W32 proof generation.

  - **When `nibbles_unpack_high_first` returns `[0xB, 0xA]`:**
    - Symptom: every keccak path is nibble-reversed within each byte.
    - Why: low nibble emitted before high.
    - Fix: `for b in bytes { push(b >> 4); push(b & 0x0F); }`. High then low, always.
    - Muscle: nibble order is big-endian within each byte. Reapplies at: W10 Wed HashBuilder, W20 TrieWalker,
      W31.

  - **5-year failure mode** (`notes/10_nibbles_followup.md`): when paths grow beyond 64 nibbles (deep
    storage tries), SmallVec spills to heap. Migration: bump inline capacity to 128 OR use a custom
    NibblePath type with explicit bit-packing for hot paths.

- [ ] **Build**: `crates/eth-trie/src/node.rs` — Node enum (Empty, Leaf, Extension, Branch). (~total 150 min across 3 phases)
  - 🔧 **Why this matters**: the 4-shape Node enum is the geometric core of MPT. Three traps: missing 17th

  #### Phase 1 — Problem, requirements, design (~30 min)

  - **Requirements** — write in `notes/10_node_design.md`:
    - R1. `enum Node { Empty, Leaf{path,value}, Extension{path,child:Box<NodeRef>}, Branch{children:[_;16],
      value:Option<Bytes>} }`. The Branch has 17 slots total.

    - R3. Insert split logic: 0-length shared prefix → straight Branch; longer → Extension wrapping Branch.
    - R4. `get(&self, path) -> Option<&Bytes>` walks down (returns reference, no clone).
    - R5. `NodeRef = Inline(Box<Node>) | Hash(B256)`; the hash variant requires storage lookup.

  - **When `node_branch_has_value_slot` returns None for "do":**
    - Symptom: in `[("do","v1"),("dog","v2")]`, "do" lookup returns None. The 17th slot was missing.
    - Why: Branch modeled as `[_;16]`.
    - Fix: `Branch { children: [Option<…>; 16], value: Option<Bytes> }`. The value slot is mandatory.
    - Muscle: MPT branch is 16+1 slots — 17th holds value that ends AT the branch. Reapplies at: W10 Wed

    - Muscle: Merkle trie is persistent — mutation rebuilds the path, never edits. Reapplies at: W11

**Wednesday — `HashBuilder` + root hash + concurrency drill #12**

- [ ] **Concurrency drill #12 of 28 — SPSC ring loom verification (capacity-2 wraparound)** (solo, ~5 hrs).
  Drill #11 measured perf. This drill verifies correctness under loom's exhaustive interleaving search at
  the smallest possible ring (capacity 2), which forces wraparound on every push and exposes the
  off-by-one-at-wrap bug class.
  Extend drill #11's `SpscRing` with a `#[cfg(loom)]` harness: 1 producer pushes 4 values, 1 consumer pops
  4 values, asserts (a) all 4 unique values received, (b) in order, (c) no double-pop. Capacity=2 means
  every 3rd push wraps.
  Constraints: no peek at `rtrb` source or `crossbeam_channel::SpscRb` until COMPARE.
  - **Spec**: invariants for the wraparound case specifically. The naive index check is `tail == head`
    (empty) vs `(tail + 1) % N == head` (full). One of these breaks when N is hit; predict which schedule
    breaks the naive check.
  - **Build**: implement with both head and tail as `AtomicUsize` (unbounded counters, mask only on indexing).
    The unbounded-counter trick avoids the empty-vs-full ambiguity — explain why in your notes.
  - **Loom**: the harness above. Iterate ordering one change at a time; max 3. If loom passes too fast (<100
    iterations), strengthen the assertion (add an FIFO order check using a per-slot seq number).
  - **Compare**: open `rtrb::RingBuffer` and `crossbeam_queue::ArrayQueue` (used for SPSC by convention)
    sources. Both use the unbounded-counter trick. What additional bookkeeping do they do for the
    `wraparound = counter / N != prev_counter / N` case?
  - **Symptom card**: bug shape ("consumer popped wraparound boundary value out-of-order"); rule (unbounded
    counters resolve empty/full ambiguity but require the producer's Release on tail-bump to publish the
    payload before the consumer's Acquire on tail-load); reapplies at: W11 MPMC, W26 WAL ring, W77 aeron
    term buffer.
  - **Numbers**: at capacity=2, every push is a wraparound. Predict loom exploration time (small — ~1000
    interleavings for 4 ops/thread). Predict the % of those interleavings that exercise the wrap path
    (~100% — that's the point of cap=2).
  - **5-year failure mode**: unbounded `AtomicUsize` counter wraps at 2^64; at 10G op/sec that's ~58 years
    — fine. But at 10T op/sec (future ML systems): ~58 days. Trigger: extreme throughput. Fix: explicit
    wrap-safe modular arithmetic, never assume "won't wrap in my lifetime".
  - **Production handoff**: the unbounded-counter-with-mask trick lands at W11 MPMC, W26 WAL ring, W77
    aeron tail_offset. The wraparound correctness AT the cap-2 corner is exactly what loom-greens you for
    cap=8192 in production — small loom proof scales.
