This is a **light week** (interview rehearsal, no shippable crate). There are no Build exercises and none are
manufactured. Every item instead carries: the notes file it produces, an **Output** line that proves it done, a
🎯 **Hardened acceptance** pass criterion (a no-help/time-boxed bar, not "I looked at it"), and a *Mental model*
of why this rehearsal exists now. Reps are timed and logged so the green/red signal is objective — a problem you
solved by reading the editorial is a RED, not a pass.

Logging convention for the week: keep one running log `notes/118_interview_log.md` with, per problem, a row
`{date, topic, problem, time-to-AC, no-help? (Y/N), bug-class-if-any}`. The bug-class column is the real payload:
it surfaces the *recurring* mistake (off-by-one in binary search, wrong DP base case, forgetting visited-set in
BFS) that a single solve hides.

**Monday — Graph algorithms (DFS/BFS, Dijkstra, A\*, Union-Find)**

- [ ] Refresh the five graph workhorses, one timed problem-set per algorithm, writing reusable templates as you
  go. Files: `notes/118_graph_templates.md` (the 5 templates), `notes/118_interview_log.md` (timed rows).
  Targets: DFS/BFS (grid + adjacency), Dijkstra (binary-heap), A\* (Dijkstra + admissible heuristic),
  Union-Find (path compression + union by rank). 5 LeetCode problems per algorithm = 25 problems. (~180 min)
  - 🎯 **Hardened acceptance**: all 5 templates compile and are copy-paste-ready (no per-problem rewrite);
    ≥20/25 problems reach AC; ≥18/25 are *no-help* (no editorial, no hint). Every non-no-help solve gets a
    bug-class entry in the log. Union-Find template MUST do both path compression AND union-by-rank — a version
    missing either is RED (it degrades to O(n) and that is exactly the trap an interviewer probes).
  - *Mental model*: graph traversal is the single most-asked HFT/infra screen category because order books,
    dependency DAGs, and consensus quorum graphs all reduce to it. The goal isn't "can I do DFS" — it's "can I
    reach for the right one in <30s and not reimplement the visited-set bug." Dijkstra here is the same
    binary-heap mental model you used in `crates/matching-engine` price-level priority; say that out loud in the
    interview.
- [ ] Commit notes. (~10 min)

**Tuesday — Dynamic programming patterns**

- [ ] Drill the top DP patterns, classifying each problem by pattern BEFORE coding (state, transition, base case,
  order of evaluation). Files: `notes/118_dp_patterns.md` (one section per pattern with the state/transition
  formula), `notes/118_interview_log.md`. Patterns to cover: 1D linear (house-robber class), 0/1 knapsack,
  unbounded knapsack, LCS/edit-distance (2D grid), interval DP (matrix-chain/burst-balloons), DP-on-subsets
  (bitmask/TSP), DP-on-trees. ≥2 problems per pattern = ~16 problems. (~180 min)
  - 🎯 **Hardened acceptance**: for each pattern, the state/transition/base-case is written down as a formula
    FIRST, then code; ≥13/16 reach AC, ≥11/16 no-help. A solve where you got AC but could not afterward state
    the recurrence in one line is RED — that's pattern-matching from memory, which collapses on a twist.
  - *Mental model*: DP is the category that separates "memorized 150 problems" from "can derive." Interviewers
    twist a known problem precisely to break recall; the only defense is fluency in naming state + transition.
    The bitmask-DP rep doubles as prep for the W119 "design a task scheduler" systems-design question.
- [ ] Commit notes. (~10 min)

**Wednesday — String algorithms (KMP, Z-algorithm, rolling hash, suffix arrays)**

- [ ] Implement and rehearse the string-matching toolkit, then apply each to ≥3 problems. Files:
  `notes/118_string_algos.md` (annotated reference impls of KMP failure function, Z-array, polynomial rolling
  hash with double-mod, suffix-array via sort), `notes/118_interview_log.md`. (~180 min)
  - 🎯 **Hardened acceptance**: KMP failure-function impl passes a hand-traced 3-case test in the notes (e.g.
    `ababaca` → `[0,0,1,2,3,0,1]`); rolling hash uses **two** moduli (single-mod is RED — interviewers will
    hand you an anti-hash collision case and a single 64-bit mod is forgeable); ≥9/~12 problems no-help.
  - *Mental model*: rolling hash is the same Rabin-fingerprint family you built in `crates/bloom` reasoning
    about hash collisions — mapping the interview question onto a crate you shipped is the strongest possible
    "I've done this in production" signal. KMP rarely appears verbatim but its failure-function mindset (reuse
    prior work to avoid recomputation) is the DP-adjacent muscle interviewers reward.
- [ ] Commit notes. (~10 min)

**Thursday — Segment trees + lazy propagation + Fenwick (BIT)**

- [ ] Build a reusable generic segment tree (point + range update via lazy propagation) and a Fenwick tree, then
  one problem per query pattern. Files: `notes/118_segtree.md` (the generic template + when to pick Fenwick vs
  segtree vs sqrt-decomposition), `notes/118_interview_log.md`. Patterns: range-sum + point-update (Fenwick),
  range-min/max + range-assign (lazy segtree), range-add + range-sum (lazy segtree). (~180 min)
  - 🎯 **Hardened acceptance**: lazy-propagation template correctly defers AND pushes-down on query (a version
    that updates without push-down is RED — it silently returns stale aggregates, the classic lazy-segtree bug);
    each of the 3 query patterns solved once with a correctness assertion in notes; the "Fenwick vs segtree"
    decision rule is written in one sentence.
  - *Mental model*: range-aggregate-with-update is the data-structure question for any "real-time analytics /
    order-flow imbalance over a sliding window" HFT prompt. It rarely shows in a 45-min screen but DOES show in
    the take-home / onsite tier W122-126 targets — Thursday is the "harder than screen" buffer day.
- [ ] Commit notes. (~10 min)

**Friday — Mock: 2 LeetCode Hard back-to-back, strict 45 min each**

- [ ] Run a realistic timed mock: 2 LeetCode Hard, 45 min each, narrating out loud (record audio or rubber-duck),
  no IDE autocomplete on first pass. Pick one graph/DP Hard and one string/segtree Hard so the week's full
  surface is tested. File: `notes/118_mock_friday.md` (per problem: approach-narration transcript-or-notes,
  time-to-first-correct-approach, time-to-AC, bugs hit). Total wall-clock 90 min + 20 min retro. (~110 min)
  - 🎯 **Hardened acceptance**: BOTH solved fully no-help within the 45-min box to count as a green signal. One
    solved / one not = AMBER (log the failed one's bug-class and re-attempt cold next week). The narration must
    state the complexity bound BEFORE coding — an AC with no stated Big-O is RED for interview purposes because
    that's the first follow-up question.
  - *Mental model*: the screen is not a correctness test, it's a *communication-under-time-pressure* test.
    Friday rehearses the exact failure mode that sinks strong engineers — going silent while thinking. Two
    Hards back-to-back also rehearses stamina for the onsite gauntlet in W122-126.
- [ ] Commit notes. (~10 min)
