- [ ] **Build**: `crates/vector-db/src/segment.rs` — `SegmentManager` orchestrates sealed (immutable) and active
  (mutable) segments. Sealed segments are mmap'd snapshots; active is the current insert target. Merge policy
  consolidates small segments. (~120 min)
  - **Why**: A single HNSW graph degrades with churn (deletes leave tombstones, updates fragment adjacency).
    Segments let you build small, immutable graphs and federate search across them. This is **the Qdrant
    architecture** and the modern vector-db default. Without segments, deletes effectively can't be reclaimed and
    search performance degrades over time. NET-NEW v2 feature.
  - **Read first**: Qdrant `lib/segment/src/` — the entire crate is the reference. Specifically
    `segment_constructor/segment_builder.rs` (build), `segment_manager.rs` (lifecycle), `holders/segment_holder.rs`
    (concurrent access); Lucene's segment architecture (the original — Lucene `IndexWriter`); RocksDB's
    LSM/level concept is conceptually similar (also segments).
  - **Design**: ```rust
    pub struct SegmentManager<const D: usize> {
        active: parking_lot::RwLock<Arc<MutableSegment<D>>>,
        sealed: parking_lot::RwLock<Vec<Arc<SealedSegment<D>>>>,
        config: SegmentConfig,
        merge_handle: Option<std::thread::JoinHandle<()>>,
        shutdown: Arc<AtomicBool>,
    }

    pub struct SegmentConfig {
        pub max_active_bytes: usize,       // seal active when reached (e.g., 256 MB)
        pub max_segments: usize,           // trigger merge when exceeded
        pub merge_min_segments: usize,     // merge at least this many small segments at once
        pub merge_size_ratio: f32,         // only merge segments within this size ratio
    }

    pub struct MutableSegment<D> {
        graph: HnswGraph<D>,
        payload: PayloadStore,
        wal: wal::Wal,
        size_bytes: AtomicUsize,
    }

    pub struct SealedSegment<D> {
        persisted: PersistedHnsw<D>,
        deleted: roaring::RoaringBitmap,  // tombstoned IDs (rebuilt on next merge)
        size_bytes: usize,
    }

    impl<const D: usize> SegmentManager<D> {
        pub fn insert(&self, vec: Vector<D>, payload: serde_json::Value) -> Result<GlobalId> {
            let active = self.active.read().clone();
            let local_id = active.insert(vec, payload)?;
            let bytes = active.size_bytes.load(Ordering::Relaxed);
            if bytes > self.config.max_active_bytes {
                drop(active);
                self.seal_active()?;
            }
            Ok(GlobalId::new(active.segment_id, local_id))
        }

        pub fn search(&self, q: &Vector<D>, k: usize, ef: usize, filter: Option<&dyn Filter>)
            -> Vec<(GlobalId, f32)>
        {
            // Federated search: each segment returns top-k, merge to global top-k.
            let active = self.active.read().clone();
            let sealed = self.sealed.read().clone();
            let mut all: Vec<(GlobalId, f32)> = Vec::with_capacity((sealed.len() + 1) * k);
            for s in sealed.iter() {
                let local = s.persisted.search_filtered(q, k, ef, filter);
                all.extend(local.into_iter().filter_map(|(id, d)| {
                    if s.deleted.contains(id) { None } // skip tombstoned
                    else { Some((GlobalId::new(s.segment_id, id), d)) }
                }));
            }
            let local_active = active.graph.search_filtered(q, k, ef, filter);
            all.extend(local_active.into_iter().map(|(id, d)| (GlobalId::new(active.segment_id, id), d)));
            all.sort_unstable_by(|a, b| a.1.partial_cmp(&b.1).unwrap());
            all.truncate(k);
            all
        }

        fn seal_active(&self) -> Result<()> {
            let old_active = {
                let mut w = self.active.write();
                let old = w.clone();
                let new_active = Arc::new(MutableSegment::new(self.config.clone())?);
                *w = new_active;
                old
            };
            // Persist old_active to disk as sealed.
            let dir = self.segment_dir(old_active.segment_id);
            PersistedHnsw::save(&old_active.graph, &dir)?;
            let sealed = Arc::new(SealedSegment::load(dir)?);
            self.sealed.write().push(sealed);
            self.maybe_trigger_merge();
            Ok(())
        }

        fn merge_loop(&self) {
            while !self.shutdown.load(Ordering::Relaxed) {
                std::thread::sleep(Duration::from_secs(10));
                self.try_merge_one().ok();
            }
        }

        fn try_merge_one(&self) -> Result<()> {
            // Tiered merge policy: pick the smallest N segments within size_ratio.
            let sealed = self.sealed.read().clone();
            let candidates = Self::pick_merge_candidates(&sealed, &self.config);
            if candidates.len() < self.config.merge_min_segments { return Ok(()); }
            // Build new merged segment by re-inserting all vectors (skip tombstoned).
            // ALTERNATIVE: incremental graph merge per Qdrant — out of scope v0.5.
            let mut merged = MutableSegment::new(self.config.clone())?;
            for s in &candidates {
                let p = &s.persisted;
                for id in 0..p.node_count() {
                    if s.deleted.contains(id as u32) { continue; }
                    let v = p.vector(id);
                    let payload = p.payload_for(id)?;
                    merged.insert(v, payload)?;
                }
            }
            let dir = self.segment_dir(merged.segment_id);
            PersistedHnsw::save(&merged.graph, &dir)?;
            let new_sealed = Arc::new(SealedSegment::load(dir)?);
            // ATOMIC swap: remove merged inputs, add new sealed.
            let mut w = self.sealed.write();
            w.retain(|s| !candidates.iter().any(|c| Arc::ptr_eq(s, c)));
            w.push(new_sealed);
            // Schedule deletion of old segment dirs (after grace period for in-flight queries).
            for c in &candidates { self.gc_segment_dir(c.segment_id); }
            Ok(())
        }
    }
    ```
    **Invariants**:
    - Exactly one active segment at any time; sealed are immutable.
    - GlobalId = (segment_id, local_id); local_id space is per-segment, segment_id is globally monotone.
    - Search federates: each segment returns top-k, global merge picks top-k of those.
    - Delete is a tombstone in the sealed segment's bitmap (active uses graph's own tombstoning); merged
      segments drop tombstoned nodes.
    - Merge is async background; queries during merge see both old and new (atomic Arc swap at end).
    - Old segment dirs only deleted after GRACE PERIOD (e.g., 30s) to let in-flight queries finish.

  - **Pitfalls** (named, deep):
    - *Segment merge during query*: **Symptom**: query reads sealed[3], merge thread removes sealed[3] mid-read,
      Arc dropped, dangling reference. **Fix**: queries clone Arc snapshot at start; merge atomically swaps the
      Vec<Arc> contents — old Arcs stay alive while queries hold them; GC waits for refcount to drop.
    - *Fragmentation*: **Symptom**: many small segments (each from a quick seal due to small writes), search
      cost grows linearly with segment count. **Fix**: merge policy aggressive on small segments; minimum
      ACTIVE segment lifetime so churn doesn't seal too eagerly.
    - *Mid-merge crash*: **Symptom**: merge writes new segment but crashes before atomic swap → on restart, old
      segments still exist + partial new segment exists. **Fix**: new segment persisted with a `.tmp` directory
      suffix; only renamed to final on successful Arc swap; restart sweeps `.tmp` dirs.
    - *Tombstone resurrection*: **Symptom**: segment A has tombstone for id 5, segment B has live id 5 (because
      same global id reused across segments??). **Fix**: GlobalId = (segment_id, local_id) — local_id never
      collides across segments by definition.
    - *Delete amplification*: **Symptom**: high-delete workload → tombstones dominate → search wastes time on
      tombstoned candidates. **Fix**: merge policy threshold on tombstone ratio (e.g., merge when ≥ 30%
      tombstoned).
    - *Memory blow-up during merge*: **Symptom**: merging 8 × 256 MB segments into one needs > 2 GB RAM peak.
      **Fix**: merge in batches (re-insert from disk-resident sealed using PersistedHnsw mmap reads); never
      materialize all vectors at once.
    - *Search topology coverage*: **Symptom**: federated top-k from each segment, but the global top-k may
      include a node that wasn't in any segment's top-k (because it was the 11th in its segment but globally
      4th). **Fix**: fetch top-(k * fanout) per segment (e.g., k*2); only matters when segments are size-skewed.
    - *Merge consumes CPU*: **Symptom**: merge thread saturates CPU, foreground search latency spikes. **Fix**:
      merge thread runs at lower priority via `nice` or `runtime-thread-per-core` low-priority slot; rate-limit
      via shared backpressure::Limiter.

  - **Test scenarios** (adversarial):

    - Merge during query stress test (100 concurrent queries during merge): no panic, recall unchanged.

    - Many small segments: 100 segments × 1k vectors each → measure search cost vs 1 segment × 100k → ≤ 1.5×.
