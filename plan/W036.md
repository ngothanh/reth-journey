**Friday — Crate: snapshot import + recovery integration**

- [ ] Snapshot import. Wire `recovery::Checkpointer` so a snapshot can be treated as a checkpoint barrier — recovery
  after snapshot import starts from the snapshot's LSN. (~30 min)
  - **Why**: A snapshot is a consistent state at some LSN. Importing it must be equivalent to "replay WAL from 0 up to that LSN" — i.e., it installs a new checkpoint barrier at LSN_snapshot. On crash post-import, recovery's RedoPass starts from LSN_snapshot+1, not from 0. Wire this through `recovery::Checkpointer::register_barrier(lsn)` so the recovery code path needs zero special-casing for snapshot imports.
  - **Read first**: ARIES checkpoint protocol; reth `crates/storage/provider/src/providers/snapshot/...`.
  - **Build steps**:
    1. (~10 min) Snapshot format header includes `lsn_high: Lsn`.
    2. (~10 min) Import: restore state files; call `Checkpointer::install_barrier(lsn_high)`; truncate WAL prior to lsn_high.
    3. (~10 min) Test: import snapshot → crash → recovery starts at lsn_high + 1; total state matches pre-crash.
  - **Pitfalls**:
    - *WAL not truncated*: recovery replays from 0 over the snapshot, double-applying. **Fix**: truncate as part of import atomicity.
    - *Snapshot from incompatible version*: format-version mismatch. **Fix**: header version check.
  - **Acceptance**: import + recovery round-trip matches; ≤2x snapshot file size in transient disk during import.
  - **Downstream**: storage-trie ships with snapshot support v1.0; mini-db (W95) reuses same checkpoint protocol.
