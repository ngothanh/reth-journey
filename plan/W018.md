**Wednesday — revm-interpreter dispatch**

- [ ] **Verify**: study revm-interpreter opcode dispatch; document strategy comparison. (~total 75 min across 3 phases)
  - 🔧 **Why this matters**: dispatcher is the throughput-critical loop (~20% of revm's headroom). Three
    strategies (match / function-pointer table / tail-call). Understanding revm's choice is prereq for any
    perf PR. Downstream: W19 precompile dispatch, W53 Handler dispatch.

  #### Phase 1 — Study plan (~15 min)

  - R1. Read revm `crates/interpreter/src/instruction_table.rs` and `interpreter.rs`. evmone
    `lib/evmone/baseline.cpp` for computed-goto.
  - R2. Enumerate every dispatcher strategy revm has tried (git log search "dispatch").
  - R3. Identify: const-eval table, fork-gating, function-ptr-vs-match per-opcode tradeoff.

  #### Phase 2 — Failing artifacts (~25 min)

  - [ ] `notes/dispatch_strategies.md` exists with: match vs table vs tail-call comparison, when each
    wins, revm's choice, evmone's choice, your bench numbers.
  - [ ] Measurement: `perf stat -e branch-misses` on a 1M-opcode trace, both your dispatcher and revm's.
  - [ ] Asm inspection: `cargo asm exec_vm::interpreter::run` shows ≤ 1 indirect call per opcode.
  - [ ] `EXEC_VM_PERF_BACKLOG.md` updated with tail-call experiment item.

  #### Phase 3 — One missing piece at a time (~35 min)

  - **When `notes/dispatch_strategies.md` says "they're equivalent":**
    - Symptom: doc concludes either works.
    - Why: didn't measure on AMD Zen 4 / Apple Silicon where indirect-call mispredict matters.
    - Fix: state the workload regime. Match wins for the 10 hottest opcodes (CMOV-friendly); table wins
      for cold tail (avoids 256-arm match miss). revm uses table; evmone uses tail-call.
    - Muscle: dispatcher choice is workload-dependent; measure on representative hardware.

  - **When asm shows ≥2 indirect calls per opcode:**
    - Why: handler is a vtable call OR table is `Box`-wrapped.
    - Fix: const fn table where possible; static table per spec; cache via OnceLock<HashMap<SpecId,
      &'static Table>>.
    - Muscle: hot table = static, lifetime = spec.

  - **5-year failure mode**: when LLVM stabilizes guaranteed tail-call, the table approach becomes
    obsolete. Migration: tail-call dispatch on nightly until stable.

**Thursday — revm hot path + ADD trace**

- [ ] **Verify**: trace ADD end-to-end through revm AND your exec-vm. Compare overhead. (~total 75 min across 3 phases)
  - 🔧 **Why this matters**: ADD is the cleanest microbench — no memory, no host. Cycles beyond
    `pop+pop+wrapping_add+push+gas-spend` ARE dispatcher overhead. Establishes the W31+ tail-call
    dispatch regression gate.

  #### Phase 1 — Plan (~15 min)

  - R1. ADD-only bytecode: `PUSH1 1 PUSH1 1 ADD JUMPDEST` 9-byte cycle.
  - R2. Bench at 3 loop sizes (1k, 10k, 100k) — detect dispatch overhead vs scaling.
  - R3. Run on revm + your exec-vm; capture cycles/opcode via `perf stat`.
  - R4. `perf record` both; identify top-5 functions in your impl.
  - R5. Stabilize harness: `taskset -c 2`, disable turbo.
  - R6. Throughput target: ≥ 50 ns/opcode (≥ 20 M opcodes/sec); revm baseline ≈ 3 ns.

  #### Phase 2 — Failing artifacts (~25 min)

  - [ ] `crates/exec-vm/benches/add_loop.rs` exists with the 3-size bench.
  - [ ] `notes/add_trace.md` table: revm vs exec-vm cycles/opcode at each size.
  - [ ] `perf record` profiles checked in; top-5 hot fns named.
  - [ ] `EXEC_VM_PERF_BACKLOG.md` updated with 5 biggest gaps + sample percentages.

  #### Phase 3 — One failure at a time (~35 min)

  - **When bench shows 20% run-to-run variance:**
    - Symptom: criterion outputs swing widely.
    - Why: hyperthreading, turbo, frequency scaling.
    - Fix: `taskset -c 2 cargo bench`; `sudo cpupower frequency-set -g performance`. Document in
      bench README.
    - Muscle: stable benches need pinned core + fixed frequency. Reapplies at: every microbench in
      W26 wal, W77 aeron, W92 ledger.

  - **When `black_box` dominates the bench:**
    - Symptom: bench's hottest fn is criterion's black_box.
    - Why: too aggressive pessimization.
    - Fix: pass bytecode in, return checksum out. Black_box once at boundary.
    - Muscle: black_box is at I/O boundary, not interior. Reapplies at: every microbench.

  - **5-year failure mode**: when LLVM ships tail-call dispatch, the ADD trace baseline shifts ~5×.
    Migration: re-baseline at first tail-call ship.
