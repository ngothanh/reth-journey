  - *Mental model*: `MarkEngine` is a pure reducer — `(index_tick, book_snapshot, last_trade, params) -> MarkPrice` — with **zero hidden state read from the environment**.   - *Contract* (signature-level interface, NEVER the body):
    ```rust
    pub trait OracleSource {
        /// 24/7 crypto-spot vs TradFi-with-market-hours; RWA features slot in behind this.
        fn index_price(&self, at: OpClock) -> Option<Px>;       // None == market closed (RWA seam)
        fn market_state(&self, at: OpClock) -> MarketState;      // Open | Closed | Halted (seam, default Open)
    }
    pub struct MarkParams { pub band_cap_bps: u32, pub funding_interval: Duration, pub carry_basis: CarryBasisParams }
    pub struct MarkEngine<O: OracleSource> { oracle: O, params: MarkParams /* per-instrument */ }
    impl<O: OracleSource> MarkEngine<O> {
        // deterministic: pure fn of inputs + OpClock; NO SystemTime::now() inside.
        pub fn compute_mark(&self, at: OpClock, book_mid: Px, last: Px) -> MarkPrice;
        pub fn mark(&self) -> MarkPrice;  // last computed (CachePadded snapshot for cross-thread read)
    }
    pub struct CarryBasisParams { /* crypto: premium-based; RWA: carry/basis — seam, not feature */ }
    ```
  - *Back-of-envelope*: target — at the §4A aggressive scale, mark ticks ~10/s × 2 instruments, but the W90 risk-engine recomputes margin **per mark tick across all 100k accounts**, so `compute_mark` itself must be sub-µs and its output must be a single `CachePadded<AtomicU64>` the risk shard reads without a lock. A band-clamped median of 3 inputs = ~3 compares + 1 clamp ≈ **~15 ns**; reading `SystemTime::now()` inside it = ~25 ns *and* a non-determinism bug (the **real cliff isn't latency — it's that a clock read makes the mark unreplayable**, so the W97 cluster StateChecker diverges). Two `MarkPrice` snapshots for 2 instruments on one 64 B line = false-sharing on the risk shard's read → must be `CachePadded` (reuse W4).

  #### Phase 3 — Make the tests pass, one failure at a time (~80 min)

  Ordered newbie→expert — the ladder you actually walk.

  - **(NEWBIE) When `mark_band_clamps_thin_book_trade` reports `mark 110_00 exceeded band cap 100_50`:**
    - Symptom: a 1-lot trade moved mark 10%.
    - Why: `mark = median(index, book_mid, last)` with no clamp — a thin book lets book_mid drift far from oracle, and median picks it.
    - Fix: `mark = clamp(median(...), index·(1 - cap), index·(1 + cap))` — the oracle index is the anchor; book/last only move mark *within* the band.
    - Cost avoided: a manipulable mark → 100k accounts marked to a fake price → mass spurious liquidation in the W90 risk-engine. A correctness/safety bug, not a latency one.
    - Muscle: a manipulation-resistant mark anchors on the oracle and clamps the book contribution. Reapplies at: W80 funding-rate clamp, W90 risk-engine mark input, W100 liquidation trigger price.

  - **(SENIOR) When `mark_is_deterministic_across_replays` reports `mark differs across replay at same op #42`:**
    - Symptom: identical inputs + identical op produce two different marks when wall time advances between calls.
    - Why: `compute_mark` read `SystemTime::now()` (e.g. to timestamp the tick or decay a TWAP) — a non-deterministic input the replicated core must never read.
    - Fix: pass the monotonic `OpClock` (W6) as the only time input; any decay/interval math is a pure function of `OpClock`, never wall clock. Push the *real* wall-clock stamping to the ingestion edge (the raw index feed), outside the replicated compute.
    - Cost avoided: the W97 VSR cluster diverges — replicas compute different marks → different margin → one liquidates an account the other keeps → StateChecker linearizability violation, the worst class of distributed bug, found months later in cluster-VOPR instead of here. **(determinism violation — gates the whole capstone)**
    - Muscle: the replicated core is a pure function of the replicated log + a monotonic clock; every environmental read (wall clock, RNG, OS state) is pushed to the edge. Reapplies at: W80 ledger deterministic apply, W90 risk-engine recompute, W92 ledger v1.0, W97+ perp-dex-core VSR core, W108 cluster-VOPR.

  - **(SENIOR) When `rwa_oracle_slots_in_without_engine_change` won't compile:**
    - Symptom: `MarkEngine::new(RwaOracle {}, ...)` errors — `MarkEngine` expects a `CryptoOracle`.
    - Why: first attempt typed the field as a concrete `CryptoOracle` (or `MarkEngine` with no type parameter), hard-coding the source.
    - Fix: `MarkEngine<O: OracleSource>` generic over the trait; the engine never names a concrete oracle. RWA = a new `impl OracleSource`, zero engine change.
    - Cost avoided: a v1.5 RWA rewrite of the engine — and, worse, failing the §4A v1.0 acceptance "RWA-aware seams demonstrated before any RWA feature ships," which is the *narrative edge* Bet #1 conversations depend on.
    - Muscle: abstract the variation point (oracle source) behind a trait the day the first concrete case ships, so the second case is an impl not a rewrite — this is the "RWA-aware seam, RWA feature deferred" §4A discipline in code. Reapplies at: W80 funding carry/basis params, W90 risk-engine instrument abstraction, W104 perp-dex-core RWA-aware seams.

  - **(SENIOR) When `mark_snapshot_cache_line_isolated` reports `TwoMarks.eth at offset 8 < cache line 64`:**
    - Symptom: two instruments' mark snapshots pack within one line.
    - Why: `CachePadded` on the atomic aligns the atom but the enclosing `MarkSnapshot` packed other fields after it; the second snapshot starts before the next line.
    - Fix: make the `CachePadded<AtomicU64>` the field whose padding is load-bearing and `#[repr(C)]` the registry, or `CachePadded` the whole snapshot.
    - Cost avoided: the W90 risk shard reading BTC + ETH marks per tick eats a ~7 ns MESI bounce per cross-thread mark update × 1M recomputes/s — a bar (c) regression invisible to `cargo test`, RED in the bench. **(bar (c) violation)**
    - Muscle: a `CachePadded` field pads itself, not its container; load-bearing containers opt in with `repr(C)`. Reapplies at: W79 aeron Image array (today), W90 risk per-shard margin slots, W92 ledger replica slots.

  - **(EXPERT) When `mark_no_alloc_on_compute_hot_path` reports allocs:**
    - Symptom: allocs proportional to call count; flame graph shows `__rust_alloc` in `compute_mark`.
    - Why: a `Vec`/`format!`/intermediate `String` in the compute (e.g. building a debug label, or collecting inputs into a `Vec` to median them).
    - Fix: median 3 values with branchless compares (no collection); no logging/formatting on the hot path; inputs by value.
    - Cost avoided: allocator on the per-mark-tick path the W90 risk-engine multiplies by 100k accounts. **(bar (c) violation)**
    - Muscle: the hot path medians fixed-arity inputs in registers, never via a heap collection. Reapplies at: W90 risk margin compute, W100 liquidation check.

  - **(EXPERT) When `mark_bench_physically_plausible_negative_control` reports out-of-band ops/s:**

  #### Phase 3 — Make the tests pass, one failure at a time (~85 min)

  - **(NEWBIE) When `subscription_position_monotonic` reports `position regressed: 4096 -> 4032`:**
    - Symptom: cursor moved backward by one frame.
    - Why: poll computed the new position from a stale local (`term_offset + consumed`) instead of advancing the atomic.
    - Fix: advance via a single `position.store(new, Release)` computed only from the *current* loaded position; `debug_assert!(new >= old)` before storing.
    - Cost avoided: silent re-delivery of consumed frames (duplicate downstream processing).
    - Muscle: a monotonic cursor advances only from its own current value, never a recomputed offset. Reapplies at: W79 oracle-mark OpClock monotonicity (today), W82 Image rotation, W92 ledger op_num.

  - **(SENIOR) When `subscription_image_positions_cache_line_isolated` reports offset 8 < line 64:**
    - Symptom: two adjacent `Image`s pack within one line despite `CachePadded` on the atomic.
    - Why: `CachePadded` aligns the atomic but `Image` holds other small fields after it; the second `Image` starts before the next line.
    - Fix: make the `CachePadded<AtomicI64>` the load-bearing field and `#[repr(C)]` the container, or `CachePadded` the whole `Image`.
    - Cost avoided: two subscribers' cursors false-share → ~7 ns MESI bounce per cross-thread advance (30-70% MPMC regression); green test, RED bench. **(bar (c) violation)**
    - Muscle: a `CachePadded` field pads itself, not its container. Reapplies at: W79 oracle-mark mark snapshots (today), W82 Image array, W92 ledger replica-slot array.

  - **(SENIOR) When `subscription_term_boundary_pad_handled` reports cursor stuck (`frames == 0`):**
    - Symptom: poll reads the PAD frame, never advances; `position & TERM_MASK != 0`.
    - Why: PAD detection missing — code treats the sentinel as a data frame (length 0) and loops.
    - Fix: on `frame_type == Pad`, roll the cursor explicitly to the next term start and continue (same as the W77 term-buffer reader).
    - Cost avoided: subscriber permanently wedged at a term boundary (a hang, the worst tail).
    - Muscle: terminal-frame sentinels need explicit roll handling, not a length-loop. Reapplies at: W77 reader, W83 archive cycle rotation.

  - **(SENIOR) When `subscription_handler_static_dispatch_negative_control` reports `monomorphization probe collapsed to 1 body`:**
    - Symptom: two distinct closure types share one `poll_via::<F>` body, or the `&mut dyn` ui fixture compiles when it must fail.
    - Why: first attempt typed `poll(&self, usize, &mut dyn FnMut(...))` (the ~10 ns indirect shortcut) — zero-alloc so the alloc test stays green, but every call goes through one vtable body; `F` never monomorphizes.
    - Fix: `pub fn poll<F: FnMut(&[u8], &FrameInfo)>(&self, limit: usize, mut handler: F) -> usize` — a named owned generic so Rust monomorphizes + inlines per call site.
    - Cost avoided: ~7 ns indirect + ~5 ns mispredict per poll, un-inlinable (~3 ns inlined vs ~12 ns dispatched, 4×) — invisible to the alloc test, caught only structurally. **(bar (c) violation)**
    - Muscle: zero-alloc is necessary but not sufficient — `&mut dyn` is allocation-free yet erases the type and blocks inlining; pin static dispatch with a monomorphization probe + trybuild. Reapplies at: W79 MBO publish handler (today), W83 runtime reactor dispatcher, W90 risk apply callback.

  - **(EXPERT) When `subscription_no_alloc_on_poll_hot_path` reports `~1,000,000 allocs`:**
    - Symptom: 1M allocs over 1M polls; bench drops from ~1M to ~200k msg/s; flame graph shows `__rust_alloc` + drop in the inner loop.
    - Why: poll signature is `poll(usize, Box<dyn FnMut(...)>)`; caller boxes per call.
    - Fix: make poll a monomorphized generic (above); if dynamic dispatch is genuinely needed, use a typed enum dispatcher.
    - Cost avoided: ~105 ns/poll × 1M/s = **~105 ms/sec allocator** + closure-state cache misses. **(bar (c) violation)**
    - Muscle: hot-path callbacks are monomorphized generics or typed enums — never `Box<dyn>`. Reapplies at: W79 MBO + oracle-mark publish (today), W83 reactor, W92 ledger apply.

  - **(EXPERT) When `subscription_bench_physically_plausible_negative_control` reports `ops/s = 8.00e9`:**
    - Symptom: throughput above the physical band — the poll loop was optimized away or the buffer was empty.
    - Why: `acc` not `black_box`'d, or the bench fed an empty buffer.
    - Fix: `black_box(acc)`; pre-fill the term buffer; assert ≥1 frame delivered per batch.
    - Cost avoided: a green bench measuring an empty loop backing a "1M msg/s" claim.
    - Muscle: every perf bench needs a plausibility band + a `black_box` sink. Reapplies at: every criterion bench.
