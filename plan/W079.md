  - *Mental model*: a `Subscription` is a read-side handle over a term buffer the publisher already wrote; each `Image` is an independent cursor (position) into that same shared log. No subscriber copies data — they read in place at their own position. The only shared mutable state is the publisher's tail; subscribers only advance their own positions.
  - *Contract*: the signature-level interface (NEVER the body) —
    ```rust
    pub struct Image { position: CachePadded<AtomicI64>, term_buffer: Arc<TermBuffer>, /* ... */ }
    pub struct Subscription { images: Vec<Image>, policy: LagPolicy }
    pub enum LagPolicy { BlockPublisher, EvictSlow { after: Duration } }
    impl Image {
        // static dispatch: F monomorphized per call site, no Box, no alloc on the hot path
        pub fn poll<F: FnMut(&[u8], &FrameInfo)>(&self, fragment_limit: usize, handler: F) -> usize;
        pub fn position(&self) -> i64;
    }
    ```
  - *Back-of-envelope*: target 1M msg/s × 4 subs = 4M polls/s; budget P99 < 5 µs/poll. A `Box::new(closure)` per poll = ~50 ns malloc + ~50 ns free + an indirect call (5 ns branch-mispredict on a cold target) ≈ **~105 ns/poll → 105 ms/sec of pure allocator at 1M polls/s** — that alone caps you near 200k msg/s (the **cliff: ~105 ns boxed vs ~3 ns monomorphized inline ≈ 35×**). One shared term buffer vs 4 private copies saves 3× the L2/memory bandwidth (a 4 KB frame copied 4× = 16 KB touched vs 4 KB read in place). Two adjacent `AtomicI64` positions on one 64 B line = ~7 ns L2 MESI bounce per cross-thread advance — must be `CachePadded`.
  - **Requirements** R1..R10 — write in `crates/messaging-aeron/notes/79_subscription_design.md`:
    - R1. Each `Image` has its own `position`; reads are read-only against the shared log (no mutation of term-buffer slots on poll).
    - R2. Subscriber poll does NOT free term-buffer slots — only term rotation does. (Slow subscriber must not corrupt a fast one's view.)
    - R3. `position` is monotonically non-decreasing; a regression is a debug-assert panic.
    - R4. Multiple subscribers on the same `Subscription` = multiple `Image`s, each independent.
    - R5. 1M msg/s with 4 subscribers, each P99 < 5 µs.
    - R6. Each `Image`'s `position: AtomicI64` lives on its own cache line (`CachePadded` — reuse W4 `CachePadded`).
    - R7. Zero allocations on the poll hot path.
    - R8. `LagPolicy`: `BlockPublisher` (publisher waits on the slowest, MinStrategy) or `EvictSlow` (drop the laggard, fast subs unaffected). Configurable.
    - R9. Static dispatch via generic `F: FnMut` — NO `Box<dyn FnMut>` in the poll signature.
    - R10. Term-boundary frame split: poll detects a PAD frame and rolls the cursor to the next term explicitly (no length-loop spin).

    fn subscription_handler_static_dispatch_negative_control() {

        // A &mut dyn FnMut / Box<dyn FnMut> signature collapses both calls into ONE

  #### Phase 3 — Make the tests pass, one failure at a time (~85 min)

  Ordered newbie→expert — the ladder you actually walk.

  - **(NEWBIE) When `subscription_position_monotonic` reports `position regressed: 4096 -> 4032`:**
    - Symptom: assertion fires; cursor moved backward by one frame's worth.
    - Why: poll computed the new position from a stale local (`self.term_offset + consumed`) instead of advancing the atomic; a re-entrant or retried poll wrote an older value.
    - Fix: advance position via a single `position.store(new, Release)` computed only from the *current* loaded position, and `debug_assert!(new >= old)` before storing.
    - Cost avoided: silent re-delivery of consumed frames (duplicate processing downstream) — a correctness bug invisible without this assert.
    - Muscle: a monotonic cursor advances only from its own current value, never from a recomputed offset. Reapplies at: W82 Image rotation position, W83 archive replay cursor, W92 ledger op_num.

  - **(SENIOR) When `subscription_image_positions_cache_line_isolated` reports `TwoImages.b at offset 8 < cache line 64`:**
    - Symptom: assertion fails — the `AtomicI64` position is `CachePadded` but two adjacent `Image`s still pack within one line because the enclosing `Image` struct didn't carry the padding to its boundary.
    - Why: `CachePadded<AtomicI64>` aligns the *atomic*, but `Image` holds other small fields after it under `repr(Rust)`, and a second `Image` starts before the next line; the W4 wrapper's discipline doesn't extend to its container.
    - Fix: put the `CachePadded<AtomicI64>` position as the field whose padding is load-bearing, and mark layout-sensitive enclosing structs `#[repr(C)]`; or `CachePadded` the whole `Image` if it's small.
    - Cost avoided: two subscribers' cursors false-share → ~7 ns L2 MESI bounce per cross-thread advance (30-70% MPMC-style regression); green `cargo test`, RED bench. **(bar (c) violation)**
    - Muscle: a `CachePadded` field pads itself, not its container — when the container's layout is load-bearing, it must opt in with `repr(C)`. Reapplies at: W4 CachePadded-in-struct, W82 Image array, W92 ledger replica-slot array.

  - **(SENIOR) When `subscription_term_boundary_pad_handled` reports cursor stuck (`frames == 0`):**
    - Symptom: poll reads the PAD frame at the boundary, never advances; `position & TERM_MASK != 0`.
    - Why: PAD detection missing — code treats the PAD sentinel as a data frame (length 0) and loops, or stalls waiting for "more data" that lives in the next term.
    - Fix: on `frame_type == Pad`, roll the cursor explicitly to the next term's start (`position = (term_id + 1) * term_len`) and continue. Same pattern as the W77 term-buffer reader.
    - Cost avoided: subscriber permanently wedged at a term boundary (a hang, not a slowdown — the worst tail).
    - Muscle: terminal-frame sentinels need explicit roll handling, not a length-loop. Reapplies at: W77 term-buffer reader, W82 Image rotation, W83 archive cycle rotation.

  - **(SENIOR) When `subscription_handler_static_dispatch_negative_control` reports `monomorphization probe collapsed to 1 body` (or trybuild case 2 unexpectedly compiles):**
    - Symptom: the two distinct closure types share one `poll_via::<F>` body, or `tests/ui/poll_sig_rejects_ref_mut_dyn.rs` compiles when it must fail — the signature erased `F` to `&mut dyn FnMut`.
    - Why: first attempt typed `poll` as `poll(&self, limit: usize, handler: &mut dyn FnMut(&[u8], &FrameInfo))` (the ~10 ns indirect-dispatch shortcut from D2) — it's zero-alloc so the alloc test stays green, but every call goes through one vtable-dispatched body; the generic `F` never monomorphizes.
    - Fix: declare `pub fn poll<F: FnMut(&[u8], &FrameInfo)>(&self, limit: usize, mut handler: F) -> usize` — a named owned generic so Rust monomorphizes + inlines per call site; the `&mut dyn` and `Box<dyn>` ui fixtures then fail to compile as intended.
    - Cost avoided: ~7 ns indirect call + ~5 ns branch-mispredict on a cold vtable target per poll, un-inlinable across the hot loop = the difference between ~3 ns inlined and ~12 ns dispatched (4×) — invisible to the alloc test, caught only structurally. **(bar (c) violation)**
    - Muscle: zero-alloc is necessary but not sufficient for the hot path — `&mut dyn` is allocation-free yet still erases the type and blocks inlining; pin static dispatch with a monomorphization probe + trybuild, not just an alloc counter. Reapplies at: W79 Tue MBO publish handler, W79 Sat fanout handler, W83 runtime reactor dispatcher, W92 ledger v1.0 apply callback.

  - **(EXPERT) When `subscription_no_alloc_on_poll_hot_path` reports `~1,000,000 allocs on poll hot path`:**
    - Symptom: 1M allocs over 1M polls; bench drops from ~1M to ~200k msg/s; flame graph shows `__rust_alloc` + drop in the inner loop.
    - Why: poll signature is `poll(usize, Box<dyn FnMut(&[u8], &FrameInfo)>)`; caller `Box::new(closure)` boxes per call (~50 ns malloc + ~50 ns free + indirect call into a cold target). Capturing `Arc<Mutex<HashMap>>` adds a fat pointer + cache-cold dispatch.
    - Fix: make poll generic — `pub fn poll<F: FnMut(&[u8], &FrameInfo)>(&self, limit: usize, mut handler: F)`. Rust monomorphizes per call site, inlines, zero alloc. Forbid `Box<dyn FnMut>` in the signature; if dynamic dispatch is genuinely needed, use a typed enum dispatcher (predictable branch, no alloc).
    - Cost avoided: ~105 ns/poll × 1M polls/s = **~105 ms/sec of allocator** + closure-state cache misses. **(bar (c) violation)**
    - Muscle: hot-path callbacks are monomorphized generics or typed enums — never `Box<dyn>`. Reapplies at: W79 Tue MBO publish handler, W79 Sat fanout handler, W83 runtime reactor dispatcher, W84 archive replay iterator, W92 ledger v1.0 apply callback.

  - **(EXPERT) When `subscription_bench_physically_plausible_negative_control` reports `ops/s = 8.00e9`:**
    - Symptom: throughput above the physical band — the poll loop was optimized away (handler had no observable effect) or the term buffer was empty so polls returned instantly.
    - Why: `acc` not `black_box`'d, or the bench fed an empty buffer; the compiler elided the work and the "throughput" measures an empty loop.
    - Fix: `std::hint::black_box(acc)` after the loop; pre-fill the term buffer with real frames; assert at least one frame delivered per poll batch.
    - Cost avoided: a green bench that measures nothing — you'd ship a "1M msg/s" claim backed by an empty loop.
    - Muscle: every perf bench needs a plausibility band + a `black_box` sink, or it silently lies. Reapplies at: W4 CachePadded bench, W79 Tue MBO bench, W79 Sat fanout bench, every criterion bench in the plan.

  #### 5-year failure mode

  - *Contract*:
    ```rust
    #[repr(C)] // fixed-shape for serialize-into; no per-event Vec
    pub enum MboEvent { Add { seq: u64, order_id: u64, px: i64, qty: u64 }, Cancel { .. }, Trade { .. }, Modify { .. }, Snapshot { .. } }
    pub struct MboFeed<P: Publication> { pub_: P, archive_tx: SpscProducer<MboEvent>, seq: u64 }
    impl<P: Publication> MboFeed<P> {
        pub fn publish(&mut self, evt: MboEvent) -> Result<(), PublishError>; // zero-alloc, serialize-into claim
    }
    ```
  - *Back-of-envelope*: target 1M events/s, P99 publish < 1 µs. `bincode::serialize(&evt)` = malloc (~50 ns) + encode (~150 ns) + free (~50 ns) ≈ **~260 ns/event → 260 ms/sec allocator at 1M evt/s** (the **cliff: ~260 ns serialize-then-offer vs ~30 ns repr(C) ptr::write-into-claim ≈ 8×**).   #### Phase 3 — Make the tests pass, one failure at a time (~110 min)

  - **(NEWBIE) When `mbo_100k_orders_correct_stream` reports a gap in `seq`:**
    - Symptom: seq jumps (e.g. 41 → 43); a Cancel produced no event.
    - Why: an order-book mutation path (e.g. cancel-on-empty, or a self-trade) returns early before emitting its MBO event.
    - Fix: emit the MBO event at the single chokepoint where the book mutates (one `apply_and_emit`), not at each call site — so no path can mutate without emitting.
    - Cost avoided: consumers reconstruct a divergent book (silent data loss); the bug surfaces only as a downstream MBP mismatch days later.
    - Muscle: pair every state mutation with its event emission at one chokepoint, never per-call-site. Reapplies at: W80 ledger transfer events, W92 ledger v1.0 apply-emit.

  - **(SENIOR) When `mbo_iceberg_visible_only` reports `hidden qty leaked to wire: 1000`:**
    - Symptom: a refresh event carries `qty == total_remaining`; the full iceberg size hit the wire.
    - Why: refresh emitted as `Modify(total_remaining)` — the EMIT layer read the storage struct's total field directly.
    - Fix: refresh = `Cancel(old_display_qty) + Add(new_display_qty)` (the W76 iceberg pattern); the emit layer must project only the visible field.
    - Cost avoided: leaking hidden liquidity to competitors — a regulatory/PnL bug, not a latency bug.
    - Muscle: hidden state never reaches the wire format — the EMIT layer owns visibility, not the storage layer. Reapplies at: W76 iceberg.rs (source), W80 FIX ExecutionReport (LeavesQty visible only), W82 v1.5 SHIP.

  - **(SENIOR) When `mbo_replica_determinism_3replica` reports diverging seq across replicas:**
    - Symptom: replicas 1/2/3 produce different `seq` (or payload) for the same logical event.
    - Why: `seq` derived from `SystemTime::now()` or a per-replica local counter that diverges; the publish path read non-deterministic state.
    - Fix: derive `seq` from the deterministic raft op_num (the same input → same seq on every replica); forbid wall-clock / local-counter reads in the publish path.
    - Cost avoided: consumers connected to different replicas see different streams → unreconcilable books across the cluster.
    - Muscle: any externally-observable value in a replicated apply must be a pure function of the replicated input. Reapplies at: W80 ledger transfer seq, W92 ledger v1.0 deterministic apply, W90 consensus-vsr.

  - **(EXPERT) When `mbo_zero_alloc_on_publish_hot_path` reports `~1,000,000 allocs`:**
    - Symptom: heaptrack/counter flags 1M allocs/sec; bench shows ~400k evt/s vs the 1M target.
    - Why: `let bytes = bincode::serialize(&evt)?; pub.offer(&bytes)?` allocates a fresh `Vec` per event (~260 ns).
    - Fix: `let claim = pub.try_claim(SIZE)?; bincode::serialize_into(claim.buffer(), &evt)?; claim.commit();` serializes directly into the term-buffer slot. For fixed-shape events, `#[repr(C)]` + `ptr::write(claim.ptr() as *mut MboEvent, evt)` ≈ 30 ns.
    - Cost avoided: ~260 ns × 1M = **~260 ms/sec allocator** + allocator contention across publisher threads. **(bar (c) violation)**
    - Muscle: ALWAYS serialize into a pre-claimed slot, never serialize-then-offer(&bytes) — the W77 transport_ipc pitfall re-stated at the MBO layer. Reapplies at: W77 transport_ipc, W79 Sat fanout publish, W80 ledger journal record, W83 archive frame write, W92 ledger v1.0 apply-result emit.

  - **(EXPERT) When `mbo_archive_async_no_publish_block` reports `1-3 µs P99.9 spikes`:**
    - Symptom: P99.9 publish latency spikes 1-3 µs correlated with archive page faults; cycle rotations show as ~50 µs blackouts.
    - Why: serial path `pub.offer(&b)?; archive.record_fragment(&b)?` puts the archive's mmap append (+ cold-page fault, + rotation) inline in the critical path.
    - Fix: (a) archive recording on a SEPARATE thread (the W77 pretoucher-paired worker); publish enqueues to a small SPSC ring; the archive thread drains async. (b) pretoucher keeps archive pages warm. (c) rotation signaled via a flag; publisher keeps writing while rotation completes async.
    - Cost avoided: 1-3 µs P99.9 spikes eliminated; pretoucher saves ~3 µs/15k-events of page-fault tail; rotation no longer pauses publish. **(bar (c) violation)**
    - Muscle: durability is ASYNCHRONOUS to publish — the publisher emits to an in-memory ring; durability workers consume on their own thread. Reapplies at: W83 archive recorder, W92 ledger v1.0 io_uring (the submission ring is the publisher's only synchronous obligation).

  - **(EXPERT) When `mbo_bench_physically_plausible_negative_control` reports `events/s = 9e9`:**
    - Symptom: above the physical band — the publish loop was elided (no claim committed, or events not consumed).
    - Why: no `black_box`, or `try_claim` returned a dummy that the optimizer saw as dead.
    - Fix: `black_box` the committed claim/seq; assert at least the expected event count landed in the term buffer.
    - Cost avoided: a "1M evt/s" claim backed by an empty loop.
    - Muscle: every bench needs a plausibility band + a real observable sink. Reapplies at: W79 subscription bench, W79 fanout bench, every criterion bench.
