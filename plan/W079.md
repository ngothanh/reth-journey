  subscriber has its own position cursor. Slow subscribers don't block fast ones (configurable: lag-tolerant or kicked). (~total 2.5 hrs across 3 phases)
  - 🔧 **Why this matters**: Multi-subscriber fan-out is the defining feature of pub-sub messaging. Aeron: single shared term buffer + N independent position cursors — no per-sub data copies. Downstream: W79 matching-engine wires market-data fan-out via subscription; W82 Image enriched with loss-detector + reorder buffer.

  #### Phase 1 — Problem, requirements, design (~40 min)

  - **The problem this primitive solves**: 4 subs each reading 1M msg/s — without shared underlying log, 4× the bandwidth/memory. Subscription's per-image position cursor lets N subs read same log independently.

  - **Requirements** — write in `crates/messaging-aeron/notes/79_subscription_design.md`:
    - R1. Each Image has its own position; reads read-only against shared log.
    - R2. Subscriber poll does NOT free term-buffer slots — only rotation does.
    - R3. Position monotonically non-decreasing.
    - R4. Multi-subscriber on same Subscription = multiple Images, each independent.
    - R5. 1M msg/s with 4 subscribers, each P99 <5 µs.
    - R6. Each Image's `position: AtomicI64` on its own cache line (CachePadded).
    - R7. Zero allocations on poll hot path.
    - R8. LagPolicy: BlockPublisher (MinStrategy) or EvictSlow (configurable).
    - R9. Static dispatch via generic `F: FnMut` — NO `Box<dyn FnMut>` in poll signature.
    - R10. Term-boundary frame split: poll detects PAD frame and rolls cursor to next term explicitly.

  - **Design walk-through**:
    - D1. Sketch Image + Subscription + LagPolicy enums.
    - D2. **Pre-mortem (handler boxed per poll):** `image.poll(64, Box::new(closure))` boxes per call. Walk through static dispatch via generic `F: FnMut`.
    - D3. **Pre-mortem (position cursor regression):** programming bug regresses position; subscriber re-reads frames. Assertion `new_pos > old_pos` panic-on-debug.
    - D4. **Pre-mortem (term-boundary frame split):** poll reads frame at term-boundary; second half in next term. Poll detects PAD; rolls cursor explicitly.
    - D5. **Pre-mortem (cross-sub HOL):** one slow sub blocks publisher (MinStrategy); other fast subs throttled. Configurable LagPolicy.

  - **Output**: `notes/79_subscription_design.md` with R1–R10 + D1–D5.

  #### Phase 3 — Make the tests pass, one failure at a time (~85 min)

  - **When `subscription_no_alloc_on_poll_hot_path` reports 100 ns/poll allocator overhead:**
    - Symptom: 1M msg/s bench drops to 200k msg/s when handler is non-trivial; flame graph shows `__libc_malloc` + `Box::drop` in inner loop.
    - Why: caller wrote `image.poll(64, Box::new(move |bytes, info| { ... }))` — boxes closure per call (~100 ns malloc + indirect call). If closure captures Arc<Mutex<HashMap>>, fat pointer + cache-cold dispatch.
    - Fix: pass closure by reference, use static dispatch via generic `F: FnMut`. Rust monomorphizes per call site, no allocation. Forbid `Box<dyn FnMut>` in poll signature; if dynamic needed, use typed enum dispatcher.
    - Cost avoided: ~100 ns/poll × 1M polls/s = ~100 ms/sec allocation overhead; eliminates closure-state cache misses.
    - Muscle: hot-path callbacks are static-dispatched generics or typed enums — never `Box<dyn>`. Reapplies at: W79 MBO feed publish handler, W83 runtime reactor task dispatcher, W84 archive replay iterator, W92 ledger v1.0 apply callback.

  - **When `subscription_term_boundary_pad_handled` reports cursor stuck:**
    - Symptom: poll reads PAD frame; doesn't advance to next term; subscriber stuck.
    - Why: PAD detection logic missing; treats PAD as data frame with length 0.
    - Fix: poll detects `frame_type == PAD`; explicitly rolls cursor to next term's start. Same pattern as W77 term_buffer reader.
    - Muscle: terminal-frame sentinels need explicit handling, not length-loop. Reapplies at: W77 term buffer reader, W82 Image rotation, W83 archive cycle rotation.

  - **5-year failure mode** (write in `notes/79_subscription_followup.md`): when subscribers run on different NUMA sockets, the shared term-buffer mmap creates cross-socket traffic on every poll. Migration: per-NUMA term-buffer replicas (kept in sync via publisher fan-out).

- [ ] [NEW v2] **Build**: `crates/matching-engine/src/mbo_feed.rs` — every order event (Add/Cancel/Trade) published to

  #### Phase 1 — Problem, requirements, design (~60 min, no code yet)

  - **The problem this primitive solves**: every order-book mutation must publish an event consumers use to reconstruct book. Hidden iceberg must NOT leak. Deterministic across raft replicas. 1M events/sec at <1 µs.

  - **Requirements** — write in `crates/matching-engine/notes/79_mbo_feed_design.md`:
    - R1. Every order-book mutation has corresponding MBO event published, in occurrence order.
    - R2. `seq` monotonic across all events.
    - R3. MBO consumers reconstruct order book bit-identical to engine's internal book.
    - R4. Iceberg events publish ONLY visible portions — Add(display_qty), Modify(refresh_display_qty), NEVER hidden total.
    - R5. Under raft replication, MBO publish is part of deterministic apply; every replica publishes identical event stream.
    - R6. 1M MBO events/s, P99 publish <1 µs.
    - R7. Zero allocations on publish hot path (serialize-into pre-claimed aeron slot).
    - R8. Archive recording asynchronous to publish (separate thread); pretoucher keeps archive pages warm.
    - R9. Consumer dedup by `seq` for at-least-once replay semantics.
    - R10. Periodic Snapshot events for late-joining consumer resync.

  - **Design walk-through**:
    - D1. Sketch MboEvent enum + MboFeed struct.
    - D2. **Pre-mortem (bincode allocates per event):** `let bytes = bincode::serialize(&envelope)?;` allocates Vec per event (~260 ns malloc+serialize+drop). At 1M evt/s = 260 ms/sec. Walk through serialize-into aeron try_claim slot.
    - D3. **Pre-mortem (archive blocks publish):** serial path `publisher.offer + archive.record_fragment` puts archive's mmap-queue append (~200 ns + page-fault) in critical path. P99.9 spikes correlated with archive page faults; rotation events visible as 50 µs blackouts. Walk through async archive thread + SPSC ring.
    - D4. **Pre-mortem (iceberg leak):** refresh emitted as `Modify(total_remaining)` instead of `Cancel(old_visible) + Add(new_visible)`. MBP aggregation shows phantom depth.
    - D5. **Pre-mortem (replica determinism):** replica publishes seq based on local op_num; if op_num differs across replicas, consumers see different seq for same event.
    - D6. **Pre-mortem (event ordering under recovery):** replica restarts mid-apply, replays from wal — emits MBO again. Consumer dedup via seq required.

  - **Output**: `notes/79_mbo_feed_design.md` with R1–R10 + D1–D6 + the event-ordering invariants.

  #### Phase 3 — Make the tests pass, one failure at a time (~120 min)

  - **When `mbo_zero_alloc_on_publish_hot_path` reports 1M allocs/sec:**
    - Symptom: heaptrack flags MBO publish at 1M allocs/sec; bench shows 400k evt/s instead of 1M target.
    - Why: `let bytes = bincode::serialize(&envelope)?;` allocates fresh Vec per event (~260 ns).
    - Fix: aeron `try_claim(size)` returns `&mut [u8]` slot in term buffer; `bincode::serialize_into(&mut slot, &envelope)?` serializes directly. For fixed-shape events (Add/Cancel/Trade), use `repr(C)` struct + `ptr::write` for ~30 ns.
    - Cost avoided: ~260 ns × 1M evt/s = ~260 ms/sec allocator; eliminates contention.
    - Muscle: ALWAYS serialize-into pre-claimed slot, never serialize then offer(&bytes). The W77 transport_ipc pitfall re-stated at MBO layer. Reapplies at: W80 ledger journal record, W83 archive frame write, W84 archive replay slot reads, W92 ledger v1.0 apply-result emit.

  - **When `mbo_archive_async_no_publish_block` reports 1-3 µs P99.9 spikes:**
    - Symptom: P99.9 publish latency shows 1-3 µs spikes correlated with archive page faults; rotation events visible as 50 µs blackouts.
    - Why: serial path `publisher.offer(&bytes)?; archive.record_fragment(&bytes, seq)?;` puts archive's mmap-queue append in critical path.
    - Fix: (a) archive recording on SEPARATE thread (pretoucher-paired worker from W77); publisher's offer writes to small SPSC ring; archive thread drains async. (b) pretoucher keeps archive pages warm. (c) Cycle rotation signaled via flag; publisher continues writing during rotation (rotation completes async).
    - Cost avoided: 1-3 µs P99.9 spikes eliminated; rotation no longer pauses publish; pretoucher saves ~3 µs/15k events of page-fault tail.
    - Muscle: durability is ASYNCHRONOUS to publish — publisher emits to in-memory ring; durability workers consume on own thread. Reapplies at: W83 archive recorder design, W92 ledger v1.0 io_uring (submission ring is publisher's only synchronous obligation).

  - **When `mbo_iceberg_visible_only` reports `qty > display` in events:**
    - Symptom: refresh event has `qty == total_remaining`; hidden leaked to wire.
    - Why: refresh emitted as `Modify(total_remaining)`.
    - Fix: refresh = `Cancel(old_display_qty) + Add(new_display_qty)` (W76 iceberg pattern).
    - Muscle: hidden state never reaches wire format — the responsibility is on the EMIT layer, not the storage. Reapplies at: W76 iceberg.rs (the source), W80 FIX ExecutionReport (LeavesQty visible only), W82 v1.5 SHIP.

  - **5-year failure mode** (write in `notes/79_mbo_feed_followup.md`): when consumer aggregation moves to GPU/FPGA, the per-event protobuf-style envelope is overhead. Migration: fixed-layout binary format with explicit `repr(C)` types; consumer reads via SIMD parallel.
