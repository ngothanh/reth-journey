**Tuesday — Revm interpreter core**

- [ ] Read revm-interpreter in full. Main execution loop. (~45 min)
  - **Why**: The interpreter loop is the single hottest path in any EVM — every gas-fee revenue dollar Ethereum earns flows through this `while` loop. To beat revm on a perf PR (W53/W59/W64) you must internalize exactly how its dispatch, gas tracking, and `InstructionResult` propagation work; otherwise your "optimization" will be slower because you'll miss a branch-hint or accidentally reintroduce a bounds check that LLVM had elided.
  - **Read first**:
    - `crates/interpreter/src/interpreter.rs` — `Interpreter::run`, `step`, the `loop { instruction_table[op](self, host) }` body
    - `crates/interpreter/src/instructions.rs` (~lines 1-200) — `InstructionTable<H>` definition: `type Instruction<H> = fn(&mut Interpreter, &mut H);` and the macro-generated `instruction_table::<H, SPEC>()` builder
    - `crates/interpreter/src/instructions/control.rs` — `JUMP`, `JUMPI`, `PC` (showcases program-counter mutation)
    - `crates/interpreter/src/gas.rs` — `Gas { limit, remaining, refunded, memoized_memory }` and `record_cost` (saturating sub returning bool)
  - **Design** (what to absorb, not write):
    ```rust
    pub type Instruction<H> = fn(&mut Interpreter, &mut H);

    // The hot loop, conceptually:
    loop {
      let opcode = bytecode[interpreter.instruction_pointer];
      interpreter.instruction_pointer += 1;
      (instruction_table[opcode as usize])(&mut interpreter, host);
      if interpreter.instruction_result != InstructionResult::Continue {
        break;
      }
    }
    ```
    **Invariants**:
    - `instruction_pointer` always points to next byte to fetch (post-increment semantics).
    - `Gas::remaining` is the SINGLE source of truth; every `record_cost` returns `bool` and the caller MUST set `InstructionResult::OutOfGas` on `false`.
    - `SharedMemory` lifetime is per-call-frame; bumping `memory.len()` is the only way memory grows, and growth gas is paid lazily on first access via `resize`.
  - **Build steps** (granular):
    1. (~10 min) Trace ADD opcode end-to-end: locate `arithmetic::add`, see `pop_top!`, `gas!(VERYLOW)`, write-back. Sketch the 6-line call chain in notes.
    2. (~10 min) Trace JUMPI: notice the `valid_jumpdest` check using a precomputed `JumpTable: BitVec`. Verify in `analysis.rs` that JUMPDEST analysis happens once at bytecode load — this is the single biggest perf insight in the EVM.
    3. (~10 min) Trace a memory-touching op (MLOAD): note `resize_memory!` calculates quadratic memory gas before any read. Misordering = consensus bug.
    4. (~10 min) Annotate the gas-out fast-path: `Gas::record_cost` uses `checked_sub` then `unlikely`-style branch (no `#[cold]` in revm currently — note as a perf-backlog candidate for W64).
    5. (~5 min) Diff against exec-vm's W17 dispatch; flag whether exec-vm's bounds-checked indexing differs (e.g., uses `get_unchecked` or not).
  - **Pitfalls** (named, for unsafe/concurrent):
    - *Stale instruction pointer on revert*: when a sub-call returns RETURN/REVERT, the parent frame's IP must be the byte AFTER the CALL opcode, not the CALL byte itself. **Symptom**: re-executes CALL forever, gas drains to 0. **Fix**: parent's `next_action` consumed via `take()`; IP advancement done by macro `gas!` family before sub-call dispatch.
    - *Memory-growth gas underflow*: `(new_size_words^2)/512 + 3*new_size_words` can overflow if `new_size_words` not capped at `MEMORY_LIMIT`. **Symptom**: free memory, consensus fork. **Fix**: `Gas::record_memory_expansion` returns `bool` post-saturation check; if true, return `MemoryOOG`.
    - *PUSH at end of bytecode*: PUSH32 with only 5 bytes left must zero-extend, not panic. **Symptom**: panic on adversarial contract. **Fix**: revm's `push::<N>` reads with `bytecode.get(ip..ip+N).unwrap_or(&[0; N])`-equivalent via slice padding.
  - **Test scenarios**:
    - Single-byte program `0x00` (STOP): expect `InstructionResult::Stop`, 0 gas used.
    - `PUSH1 0x05 PUSH1 0x06 ADD STOP`: expect stack top = 11, gas = 3+3+3+0.
    - `PUSH1 0x10 PUSH1 0x00 MSTORE`: expect memory.len() == 32, memory-expansion gas charged.
    - Adversarial: `JUMPDEST`-free `PUSH1 0x00 JUMP`: expect `InstructionResult::InvalidJump`.
  - **Acceptance**: Annotated trace file `notes/revm_interp_trace.md` covers ADD, JUMPI, MLOAD, CALL setup. You can answer "what does instruction_pointer point to mid-execution?" without hesitation.
  - **Downstream**: W50 (journaling — uses `InstructionResult::Revert` path), W58 (dispatch — replaces this loop), W59 (evmone perf comparison), W64 (revm perf PR — finds a real branch-hint or unchecked-arith opportunity here).

**Wednesday — Revm Host trait**

- [ ] Read Host trait and impls. (~45 min)
  - **Why**: The `Host` trait is revm's boundary between "pure EVM execution" and "I/O / world state". Anything that depends on chain state (SLOAD, BALANCE, EXTCODESIZE) goes through `Host`. exec-vm must replicate this seam exactly — if exec-vm's `Host` differs, downstream consumers (reth fork, tempo-evm-ext, fuzzer harness) cannot drop in revm-compatible mocks.
  - **Read first**:
    - `crates/interpreter/src/host.rs` — full `Host` trait (~30 methods: `env`, `load_account`, `block_hash`, `balance`, `code`, `code_hash`, `sload`, `sstore`, `tload`, `tstore`, `log`, `selfdestruct`)
    - `crates/revm/src/context/host.rs` — the production impl wired to `Context<DB>`
    - `crates/inspector/src/inspector.rs` — how `Inspector` wraps `Host` for tracing
  - **Design**:
    ```rust
    pub trait Host {
        fn env(&self) -> &Env;                // CfgEnv + BlockEnv + TxEnv
        fn load_account_delegated(&mut self, address: Address) -> Option<AccountLoad>;
        fn block_hash(&mut self, number: u64) -> Option<B256>;
        fn balance(&mut self, address: Address) -> Option<StateLoad<U256>>;
        fn code(&mut self, address: Address) -> Option<Eip7702CodeLoad<Bytes>>;
        fn sload(&mut self, address: Address, index: U256) -> Option<StateLoad<U256>>;
        fn sstore(&mut self, address: Address, index: U256, value: U256)
            -> Option<StateLoad<SStoreResult>>;
        fn tload(&mut self, address: Address, index: U256) -> U256; // no Option — transient is local
        fn tstore(&mut self, address: Address, index: U256, value: U256);
        fn log(&mut self, log: Log);
        fn selfdestruct(&mut self, address: Address, target: Address)
            -> Option<StateLoad<SelfDestructResult>>;
    }
    ```
    **Invariants**:
    - All `Option<...>`-returning methods return `None` ONLY on DB error (which terminates execution with `FatalError`); they never return `None` for "not found" — missing accounts return `Some(AccountLoad { is_cold, ..Default::default() })`.
    - `StateLoad<T>` always carries the `is_cold: bool` warm/cold marker used for EIP-2929 gas pricing — this is the load-bearing detail; exec-vm getting it wrong = gas miscalculation = consensus fork.
    - `sstore` returns `SStoreResult { original_value, present_value, new_value }` — needed for EIP-3529 refund accounting.
  - **Build steps** (granular):
    1. (~10 min) List all `Host` methods in `notes/host_trait_map.md`. For each, write what mutable state it touches.
    2. (~10 min) Identify which methods are pure-read (block_hash, balance, code, code_hash) vs read-with-warm-tracking (sload, load_account) vs mutating (sstore, log, selfdestruct, tstore).
    3. (~10 min) Map each method to the opcode(s) that call it (e.g., `sload` ← SLOAD; `selfdestruct` ← SELFDESTRUCT; `log` ← LOG0..4).
    4. (~10 min) Sketch how exec-vm's existing Host (W9) differs. Note divergences in `EXEC_VM_GAP_LIST.md`.
    5. (~5 min) Note: revm splits `Host` (used inside interpreter) from `DatabaseCommit` (used by frame finalization). exec-vm must preserve this split.
  - **Pitfalls** (named):
    - *Warm/cold leak across reverts*: a sub-call that reverts must NOT propagate `is_cold = false` for its accessed slots back to parent. **Symptom**: gas cheaper than spec; consensus fork. **Fix**: warm-set journaling (W50 topic); revert pops the warm-set delta.
    - *Code-hash for empty account*: `code_hash` of a never-touched account must be `KECCAK_EMPTY` (0xc5d2...), not zero. **Symptom**: EXTCODEHASH returns 0, contract logic relying on `iszero` mis-routes. **Fix**: `load_account_code_hash` returns `KECCAK_EMPTY` for nonexistent.
    - *Inspector double-charge*: wrapping Host in Inspector must not double-charge `is_cold` access. **Symptom**: tracer reports different gas than runner. **Fix**: Inspector intercepts AFTER state-mutation, not before.
  - **Test scenarios**:
    - SSTORE into existing-zero slot, then revert: balance unchanged, original_value preservation across revert correct.
    - EXTCODEHASH on never-touched address: expect `KECCAK_EMPTY`, gas = 2600 (cold) on first access.
    - SLOAD same slot twice in sub-call that reverts, then SLOAD in parent: parent's first SLOAD must be cold (2100 gas).
  - **Acceptance**: `host_trait_map.md` complete; exec-vm gap list updated; you can explain warm/cold semantics from memory.
  - **Downstream**: W50 (journaling — implements the warm-set + storage delta tracking); W54 (precompiles — they DON'T go through Host, instead intercept at frame setup); W55 (exec-vm journaling parity); W62 (storage-trie integration via Database trait).

**Thursday — Revm Database trait**

- [ ] Read Database trait. How it integrates with any storage. (~45 min)
  - **Why**: `Database` is the OTHER seam: between revm's in-memory `Context` and the durable backing store (reth's MDBX, foundry's `EmptyDB`, exec-vm's storage-trie). Mastering this lets you plug exec-vm into ANY KV — InMemoryDB for tests, storage-trie for production, a corrupting fuzz-DB for adversarial tests.
  - **Read first**:
    - `crates/database-interface/src/lib.rs` — `Database`, `DatabaseRef`, `DatabaseCommit` traits and `WrapDatabaseRef`
    - `crates/database/src/in_memory_db.rs` — `CacheDB<ExtDB>` reference impl
    - `crates/database/src/states/state.rs` — `State<DB>` wrapper that adds caching + bundle export
  - **Design**:
    ```rust
    pub trait Database {
        type Error: Debug;
        fn basic(&mut self, address: Address) -> Result<Option<AccountInfo>, Self::Error>;
        fn code_by_hash(&mut self, code_hash: B256) -> Result<Bytecode, Self::Error>;
        fn storage(&mut self, address: Address, index: U256) -> Result<U256, Self::Error>;
        fn block_hash(&mut self, number: u64) -> Result<B256, Self::Error>;
    }
    pub trait DatabaseRef { /* &self versions */ }
    pub trait DatabaseCommit { fn commit(&mut self, changes: HashMap<Address, Account>); }
    ```
    **Invariants**:
    - `basic(addr) -> None` means "account does not exist" (distinct from "exists but empty"); revm uses this for EIP-161 empty-account-removal semantics.
    - `code_by_hash` MUST be deterministic — same hash always returns same bytecode (or returns `Empty` for `KECCAK_EMPTY`). Violation = silent fork.
    - `DatabaseCommit` consumes a `HashMap<Address, Account>` where each `Account` carries `status: AccountStatus` (Touched, SelfDestructed, etc.). Status drives delete-vs-update at the storage layer.
  - **Build steps** (granular):
    1. (~10 min) Trace one full call: external caller → `Evm::transact()` → `Context::block_hash` → `JournaledState::sload` → `Database::storage`. Document the 4-layer cache hierarchy: JournaledState (per-tx) → State<DB> (per-block bundle) → CacheDB (in-process) → DB itself (MDBX).
    2. (~10 min) Identify where the `&mut self` requirement bites: `Database::basic(&mut self, ...)` enables lazy population of internal caches but blocks parallel block exec. Note this for block-stm (W89+).
    3. (~10 min) Read `bundle_state.rs`: `BundleState { state, contracts, reverts }`. This is the "diff" exported per block — sized for reverts (chain reorgs) and DB writes.
    4. (~10 min) Sketch how exec-vm's Database (W31+ storage-trie) maps. Note: storage-trie uses `&self` ref-only access via MDBX cursors, so exec-vm wraps it via `WrapDatabaseRef`.
    5. (~5 min) Note error semantics: `Err(...)` from any Database method → `EVMError::Database(_)` → entire transaction aborts (NOT just frame).
  - **Pitfalls** (named):
    - *Empty-account semantics drift*: EIP-161 says account with nonce=0, balance=0, code=KECCAK_EMPTY must be treated as nonexistent. **Symptom**: SELFDESTRUCT into a "fresh" address charges different gas; consensus fork. **Fix**: `AccountInfo::is_empty()` checks all three; Database `basic` returns `None` only for truly absent.
    - *Stale code cache after CREATE*: deploying a contract at addr A then SLOAD-ing A's code must see fresh bytecode, not cached `Bytecode::default()`. **Symptom**: contracts appear empty after deploy. **Fix**: `JournaledState::set_code` inserts into in-memory `contracts` map BEFORE finalize; commit propagates.
    - *Block-hash lookup off-by-one*: BLOCKHASH(N) inside block N is invalid (returns 0); valid range is N-256..N-1. **Symptom**: 1-block lookahead returns ghost data. **Fix**: clamp in `Host::block_hash` BEFORE delegating.
  - **Test scenarios**:
    - `Database::basic` returning `Err(IoError)` mid-transaction: entire `transact` returns `EVMError::Database(IoError)`, no partial commit.
    - SSTORE then SLOAD same slot in same tx: SLOAD must hit `JournaledState`'s in-memory map, never touch Database.
    - Database returns `code_by_hash(KECCAK_EMPTY) -> Bytecode::default()`: EXTCODESIZE of empty account returns 0, not error.
  - **Acceptance**: Trace document committed; exec-vm `Database` trait alignment task added to W50 Friday backlog.
  - **Downstream**: W50 Friday (exec-vm `Database`/`Host` alignment); W55 (journaling); W62 (storage-trie ↔ exec-vm integration); W94+ (block-stm needs `DatabaseRef` for parallel reads).

**Friday — Revm precompiles**

- [ ] Read revm-precompiles crate. Each precompile. (~60 min)
  - **Why**: Precompiles are the EVM's "syscall" surface — cryptographic and arithmetic primitives at fixed addresses 0x01..0x0a (post-Cancun). They're the trickiest part of exec-vm to get right because each has a unique gas formula, each pulls in heavyweight crypto (secp256k1, bn254, blst, kzg), and they're the most common consensus-fork source historically.
  - **Read first**:
    - `crates/precompile/src/lib.rs` — `Precompiles { inner: BTreeMap<Address, Precompile> }` and `Precompiles::cancun()`, `prague()` constructors
    - `crates/precompile/src/secp256k1.rs` — ECRECOVER
    - `crates/precompile/src/modexp.rs` — variable-gas precompile (the hardest gas formula)
    - `crates/precompile/src/bn128.rs` — pairing + add + mul
    - `crates/precompile/src/kzg_point_evaluation.rs` — EIP-4844 point eval
  - **Design**:
    ```rust
    pub type StandardPrecompileFn =
        fn(input: &Bytes, gas_limit: u64) -> PrecompileResult;

    pub enum Precompile {
        Standard(StandardPrecompileFn),
        Env(EnvPrecompileFn),
        // Stateful(...) for tempo-evm-ext extensibility
    }

    pub struct PrecompileOutput {
        pub gas_used: u64,
        pub bytes: Bytes,
    }
    ```
    **Invariants**:
    - Precompile MUST charge full gas up-front; partial gas charge then OOG mid-execution is illegal.
    - On any failure (invalid input, OOG), precompile returns `PrecompileError`; revm catches it and consumes ALL provided gas (mimics Ethereum spec).
    - `gas_used` returned ≤ `gas_limit`; revm sub-call frame keeps the difference.
  - **Build steps** (granular):
    1. (~10 min) For each precompile address 0x01..0x0a, list: name, gas formula, library used, max-input-size implicit cap (or lack thereof).
    2. (~10 min) Read ECRECOVER carefully — note `secp256k1::recover_ecdsa` returns `Result`; revm maps to `Bytes::default()` (NOT error) on invalid sig per spec. Verify exec-vm W19 does the same.
    3. (~10 min) Read MODEXP gas formula: `max(200, complexity * iteration_count / 3)` where complexity = ceil(max(b,m)/8)^2 and iteration_count derived from exp. Note this is YOUR most likely consensus-fork bug source.
    4. (~10 min) Read BN128 pairing: gas = `45000 + 34000 * k` where k = number of pairs. Crypto via `bn` crate (or `substrate-bn` in newer revm).
    5. (~10 min) Read KZG point evaluation: gas constant 50000. Uses `c-kzg` (libethereum's c-kzg-4844 binding). Trusted setup loaded once.
    6. (~5 min) Note: P256VERIFY (EIP-7212), Tempo's TIP-1020 precompile target, will plug in here.
  - **Pitfalls** (named):
    - *MODEXP gas off-by-one*: tiny rounding error in `complexity_size_computation` causes 200-gas refund vs charge differential. **Symptom**: testnet fork. **Fix**: replicate revm's `iteration_count_eip2565` byte-for-byte; do NOT rewrite the formula.
    - *BN128 invalid-point silently passes*: pairing precompile must reject points off-curve. **Symptom**: zkSNARK verifier accepts forged proofs. **Fix**: validate `is_on_curve()` BEFORE consuming pairs; reject with full gas burn.
    - *ECRECOVER v != 27,28*: ECRECOVER accepts only v=27|28; v=0,1 (compact form) is NOT valid here (it's valid only for transaction signatures). **Symptom**: contracts that pass raw v through fail; cross-chain bridges break. **Fix**: explicit `if v != 27 && v != 28 { return Bytes::default(); }` BEFORE recovery.
    - *KZG without trusted setup*: precompile silently returns zero if `KzgSettings` not loaded. **Symptom**: every blob verifies as zero. **Fix**: panic on init if KZG enabled but setup missing; load via `KzgSettings::load_trusted_setup_file()` at boot.
  - **Test scenarios**:
    - ECRECOVER with `v=29`: expect `Bytes::default()`, gas = 3000 (full charge).
    - MODEXP with empty input: expect `Bytes::default()`, gas = 200 (minimum).
    - BN128_PAIRING with 0 pairs: expect 32-byte `0x01` (identity), gas = 45000.
    - KZG_POINT_EVALUATION with malformed input: expect error, full gas burn 50000.
  - **Acceptance**: precompile audit table covers all 0x01..0x0a + EIP-7212; gas formulas annotated; tempo-evm-ext extension point in exec-vm registry confirmed via `Box<dyn Precompile>` registration test.
  - **Downstream**: W54 (precompile implementation week), W66 (tempo-tx-envelope precompile registration), W74+ (matching-engine uses none of these but tempo-evm-ext relies on registration extensibility).
