    impl PersistedHnsw {
        pub fn save(graph: &HnswGraph, vectors: &[f32], payload: &PayloadStore,
                    bloom: &Bloom, dir: &Path) -> Result<(), PersistError>;
        pub fn load(dir: &Path) -> Result<PersistedHnsw, PersistError>;
        pub fn load_with_verify(dir: &Path, verify_body: bool) -> Result<PersistedHnsw, PersistError>;
        pub fn vectors(&self) -> &[f32];           // view into the mmap
        pub fn neighbors(&self, node: NodeId, layer: u8) -> &[u32];  // O(1) index, not a probe

  - *Back-of-envelope* (bar-(b) host, but persist sits on the cold-start critical path so size it): a 1M×128-d f32 index = 512 MB vectors. mmap parse of a 256-byte header ≈ 1 syscall + ~300 ns. Page fault to bring in one 4 KB page ≈ ~3-4 µs (minor fault) to ~100 µs (major fault, disk). **Cliff: lazy paging touches only the working set (~MBs on first query) vs an eager `iter().sum()` smoke-check that faults all 512 MB = ~128k page faults ≈ 0.5-2 s.** That 200 ms-vs-2 s gap is the whole point of mmap; the bench in Phase 2 traps the eager version.

    - R2. `save()` is crash-atomic: a `kill -9` mid-save leaves either the prior snapshot intact or no snapshot — never a half-written one. Write to a sibling dir, fsync, rename the directory.
    - R3. `load()` mmaps `vectors.bin` and `adjacency.bin` read-only and returns within 200 ms on a 1M-vector index (cold OS cache acceptable for the first page; bench reports wall time).
    - R4. `load()` rejects a corrupted file with a structured error (CRC mismatch, length mismatch, version mismatch) — never SIGBUS, never silent garbage.
    - R5. Adjacency layout is fixed-size per node per layer (`m_max0` neighbors padded with `u32::MAX` sentinel) so a node's neighbors are reachable by `O(1)` index, not a hashmap probe.

    - R7. After mmap the loader calls `madvise(Random)` so the kernel does not waste I/O on sequential readahead.

  #### Phase 3 — Make the tests pass, one failure at a time (~55 min)

  Ordered newbie-first → expert-last — the ladder you actually walk.

  - **(NEWBIE) When `load_rejects_truncated_file` SIGBUS-es instead of returning `Err`:**
    - Symptom: process dies with SIGBUS (no Rust panic, no `Err`) when search touches a node past the truncation.
    - Why: you mmapped first and validated never; touching an address backed by no file page raises SIGBUS, which Rust cannot catch.
    - Fix: read the 256-byte header via `File::read` BEFORE mmap; compare `header.body_len` to `file.metadata().len()`; return `Err(LengthMismatch)` before any mmap.
    - Muscle: **mmap is a commitment — validate length and trust metadata BEFORE you touch the mapped region.** Reapplies at: W104 segment open, W108 replica file mapping.

  - **(SENIOR) When `save_load_roundtrip_recall_identical` fails to compile with E0515 / lifetime errors:**
    - Symptom: field `vectors_slice: &[f32]` cannot borrow from the sibling `_vectors_mmap` field — "cannot return value referencing local data".
    - Why: Rust has no language-level self-referential struct; the slice's lifetime must outlive the mmap it points into, but they share the struct's lifetime.
    - Fix: pick the escape hatch from D2. For a long-lived open-once index, `Box::leak` the `Mmap` and stash a `&'static [f32]`; reclaim the leak in `Drop` via `Box::from_raw`. (Or derive the slice on demand from the mmap in `vectors()`.)
    - Muscle: **self-referential structs are a design smell — erase the lifetime explicitly (`'static` + leak + manual Drop) or derive the view on demand.** Reapplies at: W104 segment manager (per-segment mmap), W108 read-only replica mmap sharing.

  - **(SENIOR) When `load_on_arm_matches_x86_bytes` produces garbage f32s:**
    - Symptom: a vector saved as `[1.0, 2.0]` on x86 decodes to `[3.85e-34, 1.10e-26]` when bytes are byte-swapped to simulate ARM.
    - Why: you used host-native endianness implicitly (`*ptr as f32` / raw transmute), not an explicit little-endian decoder.
    - Fix: every numeric on disk is explicit LE. `bytemuck::cast_slice` is fine on LE hosts; on BE hosts byte-swap. Simplest portable form: store `[u8;4]` and decode via `f32::from_le_bytes`.
    - Muscle: **on-disk formats are explicit-endian or they are wrong; "host native" is a portability bug waiting to fire on the first ARM CI run.** Reapplies at: W104 segment header, W107 manifest format.

  - **(SENIOR) When `crash_mid_save_leaves_prior_snapshot_intact` loads B's `vectors.bin` with A's `header.bin`:**
    - Symptom: `load()` succeeds but search returns wrong neighbors — header counts disagree with the actual vector data.
    - Why: you renamed individual files (`vectors.bin.tmp → vectors.bin` BEFORE `header.bin`). A crash between them leaves a coherent-looking but mismatched pair.
    - Fix: publish atomically — write the new snapshot into `snapshot.tmp/`, fsync each file, fsync the tmp dir, then `rename(snapshot.tmp, snapshot)`. The **directory rename is the single observable**; partial states are invisible.
    - Muscle: **atomic publish of multi-file state = write to a sibling directory, rename the directory.** Reapplies at: W104 segment swap, W107 manifest publication, W026 WAL group commit.

  - **(SENIOR) When `crash_mid_save_leaves_prior_snapshot_intact` still loses A after directory-rename:**
    - Symptom: even with directory rename, after a power-loss crash the new dir is missing a file and you've already deleted A.
    - Why: directory rename was correct, but you GC'd the OLD snapshot before fsyncing the parent directory (so the rename hadn't durably landed) — or deleted A before confirming B complete.
    - Fix: order = write, fsync each `.tmp`, fsync the tmp dir, rename, **fsync the parent dir**, only THEN GC the old. Better: keep N-1 snapshots; GC is a separate idempotent step.
    - Cost avoided: total loss of the prior snapshot on power loss — an unbounded RPO regression (turns a recoverable crash into data loss).
    - Muscle: **rename atomicity requires fsync of the parent directory; without it the rename may not survive power loss.** Reapplies at: W104 segment swap, W107 manifest publish, W026 WAL fsync boundary.

  - **(SENIOR) When `load_rejects_crc_mismatch` panics with SIGBUS instead of returning `Err`:**
    - Symptom: `load()` mmaps, the CRC check runs *after* a slice over the bad bytes is built, and a downstream read SIGBUS-es on an unmapped hole.
    - Why: CRC verification happened after mmap and after slice construction; the contract said "verify before mmap" but the code mapped first.
    - Fix: read the header via `File::read` first; verify file length == `header.expected_size`; only then mmap. Body CRC (if enabled) walks the mmap with bounds checks, or uses chunked `pread` to avoid mmapping the failing case at all.
    - Muscle: **verify length and trust metadata BEFORE touching the mapped region.** Reapplies at: W104 segment open, W108 replica file mapping.

  - **(EXPERT, perf — bar (c)-style hot path) When `cold_start_within_200ms_for_1m_vectors` reports ~2 s instead of ≤ 200 ms:**
    - Symptom: bench wall-time 10× the threshold; `perf stat` shows ~128k–2M page faults during `load()`.
    - Why: you eagerly walked the whole mmap (e.g. an `iter().sum()` smoke-check, or eager body-CRC) inside `load()`, paging in the entire file. mmap's win is *lazy* paging.
    - Fix: `load()` parses only the header + verifies the header's own CRC and length. Body CRC is gated behind `load_with_verify(true)` and off the hot path.
    - Cost avoided: ~1.8 s on a 512 MB index (≈128k major faults × ~14 µs avg) — turns a 2 s open into 200 ms.
    - Muscle: **mmap's value is lazy paging; any "verify the whole file on open" defeats the point.** Reapplies at: W104 segment open hot path, W108 replica startup.

  - **(EXPERT, negative-control) When `cold_start_bench_physically_plausible` fires (median < 1 ms or zero page faults):**
    - Symptom: the cold-start bench reports an implausible <1 ms median, or `minor_faults_during_load() == 0`.
    - Why: `load()` returned a cached/stale handle (OS cache not actually dropped, or a `static` memoized the mmap) — the bench measured nothing.
    - Fix: ensure `drop_os_cache` actually issues `posix_fadvise(DONTNEED)` + flush, and that each iter constructs a fresh `PersistedHnsw`; verify the fault counter is wired to `getrusage`.
    - Muscle: **every microbench gets a physically-plausible negative control — a number outside the laws of the machine means the bench is broken, not the code is fast.** Reapplies at: W104 segment bench, W108 chaos timing harness, W004 CachePadded bench.

        Insert { id: NodeId, level: u8, vector: Box<[f32]>, payload: Box<[u8]> },
        Delete { id: NodeId },
        SnapshotMark { snapshot_lsn: u64 },
    }
    impl VectorDb {
        pub fn insert(&self, vec: &[f32], payload: &[u8]) -> Result<NodeId, WalError>;  // logs+fsyncs then mutates
        pub fn open(dir: &Path) -> Result<VectorDb, WalError>;   // snapshot load + WAL replay
