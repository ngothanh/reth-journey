    pub enum VenueOp {
        NewOrder(NewOrder), Cancel(CancelOrder), Amend(AmendOrder),
        MarkTickObserved(MarkTick),                 // input from oracle-mark (W80), not computed here
        AdvanceClock(SeqTick),

        pub fn commit_num(&self) -> u64;                                     // the finality boundary (Wed)

  - *Back-of-envelope* (bar (c) — name the cost): target 1M orders/s ingest, ~100k accounts, mark ticks ~10/s (§4A capacity).
    - Dispatch cliff: a `HashMap<Discriminant, fn>` lookup ≈ ~25 ns probe + non-deterministic iteration if ever walked; a `match` on a `Copy` enum ≈ ~1–2 ns (jump table), 0 allocs, fully deterministic. At 1M ops/s: 25 ns × 1M = **25 ms/s of dispatch overhead vs ~2 ms/s** — and the HashMap path risks divergence, which is unbounded cost.
    - Apply-path alloc cliff: `String symbol` + `Vec<Fill>` ≈ ~3 allocs/op × 1M/s × ~50 ns = **150 ms of allocator wall-clock per second of trading** + cache pollution → p99 jitter. `Copy` op (`Symbol=[u8;8]`, fixed-cap inline fills) = 0 allocs, ~one cache line, memcpy ≈ 4 ns.
    - Apply-order cost: there is no perf cliff here — it is a *correctness* cliff. A non-fixed order is byte-divergence, the most expensive bug class (surfaces only in multi-replica long runs).
    - Second-log cost: a parallel hot-path Kafka write ≈ +1 network round-trip/op AND a divergence vector. The fix (projection read of the committed VSR log, W107) is *zero* hot-path cost.

  - **The problem this primitive solves**: composing four independently-deterministic SMs onto one VSR log introduces THREE new failure categories the individual crates never faced: (a) **composition non-determinism** (a `HashMap` in the dispatch, or a non-fixed inter-subsystem apply order, diverges replicas even though each subsystem is internally deterministic); (b) **op-union scope creep** (the temptation to put raw funding/liquidation *client commands* on the log, re-merging crates v3 split); (c) **the second-log betrayal** (a parallel hot-path log "for read scaling" that breaks the single-log lock). The fix: a `Copy` op union + a *fixed* apply order + a hard "no second hot-path log" rule (fan-out reads a projection, W107).
