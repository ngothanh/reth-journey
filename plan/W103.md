**Monday — vector-db: HNSW graph serialization**

- [ ] **Build**: `crates/vector-db/src/index/persist.rs` — graph + vectors + payload + bloom serialized to a directory.
  Use mmap for fast cold-start. (~75 min)
  - **Why**: Cold-start over a 10M-vector index by re-inserting takes minutes/hours; mmap'd graph + vectors makes
    open() near-instant (just remap files). This is how qdrant, faiss, hnswlib all do it.
  - **Read first**: faiss `read_index` / `write_index` in `index_io.cpp`; Qdrant
    `lib/segment/src/index/hnsw_index/graph_layers.rs` `save`/`load`; hnswlib `loadIndex`. Linux mmap(2) man
    page for `MAP_POPULATE` and `madvise(RANDOM)`.
  - **Design**: ```rust
    use memmap2::{Mmap, MmapMut};
    use std::path::Path;

    // Directory layout:
    //   <dir>/header.bin       — magic + version + dim + node_count + ep + level_offsets
    //   <dir>/vectors.bin      — N * D * 4 bytes (or N * D for SQ-encoded)
    //   <dir>/adjacency.bin    — flat adjacency: per-layer per-node fixed-size neighbor array
    //   <dir>/payload/         — mini-db data dir
    //   <dir>/quantizer.bin    — PQ codebook (if PQ enabled)
    //   <dir>/manifest.bin     — version, last applied wal LSN, checksums

    pub struct PersistedHnsw {
        header: Header,
        _vectors_mmap: Mmap,
        vectors_slice: &'static [f32],   // self-referential w/ lifetime erasure via ouroboros or unsafe
        _adj_mmap: Mmap,
        adjacency_slice: &'static [u32],
        payload: PayloadStore,
    }

    impl PersistedHnsw {
        pub fn save(graph: &HnswGraph<128>, dir: &Path) -> Result<()> {
            std::fs::create_dir_all(dir)?;
            // 1. Write vectors.bin
            let mut vfile = std::fs::File::create(dir.join("vectors.bin.tmp"))?;
            for v in graph.vectors.read().iter() {
                vfile.write_all(bytemuck::cast_slice(v.as_slice()))?;
            }
            vfile.sync_all()?;
            // 2. Write adjacency.bin (flat, fixed-size per node).
            let mut afile = std::fs::File::create(dir.join("adjacency.bin.tmp"))?;
            for layer in graph.layers.iter() {
                let l = layer.read();
                for n in 0..graph.node_count() {
                    let neighbors = l.adjacency.get(&(n as u32)).cloned().unwrap_or_default();
                    // Pad to fixed M_max.
                    let mut buf = vec![u32::MAX; graph.m_max0()];
                    for (i, &nb) in neighbors.iter().take(buf.len()).enumerate() { buf[i] = nb; }
                    afile.write_all(bytemuck::cast_slice(&buf))?;
                }
            }
            afile.sync_all()?;
            // 3. Write header + manifest.
            // ... CRC32 of each file
            // 4. ATOMIC rename .tmp → final.
            std::fs::rename(dir.join("vectors.bin.tmp"), dir.join("vectors.bin"))?;
            std::fs::rename(dir.join("adjacency.bin.tmp"), dir.join("adjacency.bin"))?;
            Ok(())
        }

        pub fn load(dir: &Path) -> Result<Self> {
            let vfile = std::fs::File::open(dir.join("vectors.bin"))?;
            let vmap = unsafe { Mmap::map(&vfile)? };
            vmap.advise(memmap2::Advice::Random)?; // ANN access pattern is random
            let afile = std::fs::File::open(dir.join("adjacency.bin"))?;
            let amap = unsafe { Mmap::map(&afile)? };
            let payload = PayloadStore::open(dir.join("payload"))?;
            // ... parse header, verify CRC, build self-referential PersistedHnsw
            Ok(Self { ... })
        }
    }
    ```
    **Invariants**: save() writes to .tmp + rename atomically (POSIX rename atomicity); adjacency is fixed-size
    per node per layer (pad with u32::MAX = sentinel for "no edge"); mmap is read-only after load; CRC32 over
    each file (header carries them); version field for forward/backward compat.
  - **Build steps**: 1. (~15 min) Directory layout + Header struct + serde; 2. (~20 min) save() with atomic
    rename + CRC; 3. (~25 min) load() with mmap + madvise(Random); 4. (~10 min) Test: build 100k vectors, save,
    load fresh process, search recall matches; 5. (~5 min) Cold-start timing: load 1M-vector index ≤ 200 ms.
  - **Pitfalls** (named):
    - *Self-referential lifetime hell*: **Symptom**: mmap lives in struct, slice borrows from mmap, Rust can't
      express. **Fix**: `ouroboros` crate OR `'static` lifetime erasure via `Box::leak` (acceptable for
      open-once long-lived index) OR explicit Pin + raw pointer (most flexible).
    - *Partial write on crash*: **Symptom**: vectors.bin half-written when crashed mid-save → next load reads
      garbage. **Fix**: ALL files written to .tmp, fsync, then rename. Verify CRC on load; mismatch → reject.
    - *mmap on non-existent file size growth*: **Symptom**: load() mmaps a file shorter than expected (truncated
      backup), reads past end SIGBUS. **Fix**: header carries expected size; verify before mmap.
    - *Endianness*: **Symptom**: index built on x86, opened on ARM — different byte order. **Fix**: all files
      explicitly little-endian; bytemuck::cast_slice with `Pod` types.
    - *Versioning*: **Symptom**: v0.5 index loaded by v0.6 with different adjacency padding → silently wrong.
      **Fix**: header version + reject on mismatch.
    - *No madvise*: **Symptom**: kernel uses sequential readahead for ANN's random access pattern → wasted I/O.
      **Fix**: `madvise(Random)` after mmap.
  - **Test scenarios**: build/save/load roundtrip; CRC corruption rejected; truncated file rejected;
    forward-version load fails with clear error; cold-start ≤ 200 ms on 1M-vector index.
  - **Acceptance**: 1M-vector save ≤ 5s; load ≤ 200 ms; recall after load identical to in-memory ground truth.
  - **Downstream**: W103 Tuesday WAL augments this for incremental updates between snapshots; W104 segment
    manager swaps in this persistence per segment.

**Tuesday — vector-db: wal for writes**

- [ ] **Build**: insertions write a WAL record (via `wal::Wal`) BEFORE updating graph. Crash recovery replays into
  in-memory graph. (~105 min)
  - **Why**: Snapshots (Monday's persist) are infrequent (minutes apart); the gap between snapshot and crash must
    be recoverable. WAL records each insert as an append-only log; recovery replays from last snapshot's LSN.
    Same pattern mini-db uses — direct reuse of `crates/wal/` (cross-crate inheritance again).
  - **Read first**: Qdrant `lib/segment/src/segment_constructor/segment_builder.rs` (WAL integration); your own
    `crates/wal/src/lib.rs` API; ARIES paper for recovery semantics; faiss has NO WAL (snapshot-only) — a
    differentiator we can point to.
  - **Design**: ```rust
    #[derive(Serialize, Deserialize)]
    pub enum VectorWalRecord {
        Insert { id: NodeId, vector: Vec<f32>, payload: Option<serde_json::Value> },
        Delete { id: NodeId },
        SnapshotMark { snapshot_lsn: u64, dir: PathBuf },
    }

    pub struct VectorDb<const D: usize> {
        graph: HnswGraph<D>,
        payload: PayloadStore,
        wal: wal::Wal,
        last_snapshot_lsn: AtomicU64,
    }

    impl<const D: usize> VectorDb<D> {
        pub fn insert(&self, vec: Vector<D>, payload: serde_json::Value) -> Result<NodeId> {
            // 1. WAL append + sync
            let rec = VectorWalRecord::Insert {
                id: self.graph.next_id(),
                vector: vec.as_slice().to_vec(),
                payload: Some(payload.clone()),
            };
            let lsn = self.wal.append(&rec)?;
            self.wal.sync_up_to(lsn)?;
            // 2. In-memory update (graph + payload).
            let id = self.graph.insert(vec);
            self.payload.put(id, &payload)?;
            Ok(id)
        }
        pub fn open(dir: &Path) -> Result<Self> {
            let snapshot_dir = dir.join("snapshot");
            let (graph, snap_lsn) = if snapshot_dir.exists() {
                let p = PersistedHnsw::load(&snapshot_dir)?;
                (p.into_hnsw_graph(), p.snapshot_lsn())
            } else {
                (HnswGraph::new(16, 200), 0)
            };
            let mut wal = wal::Wal::open(&dir.join("wal"))?;
            let payload = PayloadStore::open(&dir.join("payload"))?;
            let mut me = Self { graph, payload, wal, last_snapshot_lsn: AtomicU64::new(snap_lsn) };
            // Replay WAL from snap_lsn onwards.
            me.replay_wal(snap_lsn)?;
            Ok(me)
        }
        fn replay_wal(&mut self, from: u64) -> Result<()> {
            let mut count = 0;
            for rec in self.wal.iter_from(from)? {
                match rec? {
                    VectorWalRecord::Insert { id, vector, payload } => {
                        let v = Vector::<D>::from_slice(&vector)?;
                        self.graph.insert(v); // graph re-assigns id; but we want EXACT id replay → patch
                        if let Some(p) = payload { self.payload.put(id, &p)?; }
                        count += 1;
                    }
                    VectorWalRecord::Delete { id } => { /* tombstone */ }
                    VectorWalRecord::SnapshotMark { snapshot_lsn, .. } => {
                        self.last_snapshot_lsn.store(snapshot_lsn, Ordering::Release);
                    }
                }
            }
            tracing::info!(replayed_count = count, "vector-db wal recovery complete");
            Ok(())
        }
    }
    ```
    **Invariants**: WAL fsync MUST precede in-memory graph update (durability before visibility); SnapshotMark
    records embedded in WAL signal where replay can skip from; deletes are tombstones, not actual graph deletion
    (W103 Wed clarifies); WAL truncated only after snapshot durably saved AND SnapshotMark fsynced.
  - **Build steps**: 1. (~15 min) VectorWalRecord enum + bincode; 2. (~20 min) insert() with WAL-before-memory
    ordering; 3. (~25 min) open() + replay_wal(); 4. (~20 min) ID-stability problem (replay must assign same
    IDs as original) — solution: WAL record carries the ID; graph.insert_with_id() variant for replay;
    5. (~15 min) Test: insert 1k vectors, kill mid-batch, re-open, recall matches the surviving subset;
    6. (~10 min) Snapshot marker write + WAL truncation logic.
  - **Pitfalls** (named):
    - *ID drift on replay*: **Symptom**: original inserts assigned id=0,1,2,...; replay assigns 0,1,2,... but
      payload refers to id from original AND adjacency too — but if assign_level uses RNG, layer assignments
      differ → graph topology drift → recall regresses. **Fix**: WAL records carry id AND assigned level;
      graph.insert_with_id_and_level() reuses both. Test deterministic replay.
    - *Replay slow*: **Symptom**: between snapshots, 100k inserts; replay takes minutes. **Fix**: Snapshot more
      frequently (every 60s or 10k inserts, whichever first); SnapshotMark in WAL truncates.
    - *WAL fsync amplification*: **Symptom**: each insert calls Wal::sync → 100 ops/sec on consumer SSD.
      **Fix**: group commit via `Wal::sync_up_to` (same primitive mini-db uses); accept latency in exchange
      for throughput.
    - *Half-snapshot leak*: **Symptom**: snapshot partway written, SnapshotMark NOT in WAL, crash → recovery
      replays from old SnapshotMark → also tries to load incomplete snapshot. **Fix**: snapshot dir written
      atomically (rename); SnapshotMark written to WAL ONLY after snapshot rename success.
    - *Tombstone in WAL during compaction*: **Symptom**: delete records pile up, replay slow. **Fix**: snapshot
      bakes in tombstones (delete marks become absences in adjacency); replay only needs from latest snapshot.
  - **Test scenarios**: 10k inserts + kill -9 random byte position; re-open + replay; recall on surviving IDs
    matches; deterministic replay via seeded RNG; snapshot+restart elides WAL replay.
  - **Acceptance**: replay throughput ≥ 50k records/sec; deterministic recall after restart; WAL bounded by
    snapshot interval (auto-truncate).
  - **Downstream**: W103 Wed txn wrapper batches multiple inserts into one WAL record; W104 segment manager has
    per-segment WAL; ops runbook references recovery sequence.
