**Monday — vector-db: Scalar Quantization (SQ)**

- [ ] **Build**: `crates/vector-db/src/quantize/sq.rs` — `ScalarQuantizer { min, max, scale }`; f32 → u8 asymmetric codec; 4× memory reduction with < 2% recall loss. (~total 95 min across 3 phases)
  - 🔧 **Why this matters**: mirrors faiss `IndexScalarQuantizer` (uniform affine codec). The four traps the debug session teaches: (1) min/max trained on raw extremes collapses precision under a single outlier; (2) encoding the query as well as the db (symmetric) doubles quantization error; (3) returning the count as `N*D*4` (forgot the codec shrinks to u8) silently disables compression; (4) decoding the db code inside the distance inner loop with a float divide instead of a precomputed scale. First-attempt impls fail ≥1 test below and the debug session is the lesson. Downstream: W104 segment manager picks SQ as default for warm segments; W103 persistence stores SQ-encoded vectors + min/max on disk.

    - P2: predicted bytes for 100k × 128-d encoded (your first guess) and the f32 baseline.

  - *Mental model*: SQ maps each f32 component onto a u8 bucket via one affine transform `code = round((x-min)/scale)`, `scale = (max-min)/255`. It exists to cut memory 4× so 4× more vectors fit in cache/RAM; recall barely moves because embedding components are roughly uniformly distributed after normalization.
  - *Contract* (signatures only, NEVER the body):
    ```rust
    pub struct ScalarQuantizer { min: f32, max: f32, scale: f32 }
    impl ScalarQuantizer {
        pub fn train(vectors: &[Vec<f32>], pct: f32) -> Self;      // pct = 0.001 → use 0.1/99.9 percentiles
        pub fn encode(&self, v: &[f32], out: &mut [u8]);           // out.len() == v.len()
        pub fn decode_component(&self, code: u8) -> f32;           // min + code as f32 * scale
        pub fn distance_asymmetric(&self, query: &[f32], db_codes: &[u8]) -> f32; // L2², query stays f32
    }
    ```
  - *Back-of-envelope*: 128-d f32 vector = 512 B; u8-encoded = 128 B (4×). At 1M vectors that is 512 MB → 128 MB — the difference between spilling L3/RAM and fitting. Per-distance inner loop touches 128 bytes (2 cache lines) vs 512 (8 lines): ~4× fewer line fills (~100 ns each cold). Decode must be `min + code*scale` (1 mul + 1 add, ~1-2 cyc) NOT a float-divide per component (10-30 cyc) — at 128 comps × 1M candidates the divide is the difference between a 1.2× and a 4× slowdown.
  - **Requirements** R1..R7 — write in `notes/102mon_sq_design.md`:
    - R1: `train` runs BEFORE any `encode`; encoding without training is a type-level error (no `Default`).
    - R2: min/max/scale stored per-quantizer (each segment owns one — W104 mergeability).
    - R3: asymmetric distance only — query stays f32, db is u8; symmetric is forbidden (recall loss).
    - R4: encode clamps inputs to `[min, max]` so outliers saturate rather than wrap.
    - R5: recall@10 with SQ on 100k 128-d ≥ 0.93 vs unquantized ground truth.
    - R6: encoded storage is EXACTLY `N*D` bytes (4× compression), asserted at the byte level.
    - R7: SQ+HNSW search ≤ 1.2× the latency of unquantized HNSW (decode-in-loop is cheap).
  - **Design walk-through** D1..D4 — answer in the design doc; no peeking at faiss until Phase 3:
    - D1. Asymmetric vs symmetric: property table — symmetric (both u8) is one fewer decode but loses ~5% recall (query also quantized). Asymmetric decodes db on the fly. Pick asymmetric.
    - D2. Global vs per-dim min/max: global = 3 floats total, simple; per-dim = 2D floats, wastes nothing when dim ranges differ. v0.4 = global; document per-dim as the 5-year migration.
    - D3. **Pre-mortem (load-bearing):** write the exact bad trace — training set has one vector with norm 50× others; `min=-50, max=+50, scale≈0.39`; a normal value `+0.8` encodes to `round((0.8+50)/0.39)=130`; another normal value `-0.8` → `126`; the entire normal corpus collapses into codes 124-131 (8 of 256 buckets). Recall craters to ~0.78. If you can't write this trace you can't see why percentile training is required.
    - D4. **Anti-shortcut audit:** the "obvious" reaches — (a) true `min/max` (fails on outliers, see D3); (b) `f32::round` returns f32 then `as u8` *without clamp* (negative or >255 wraps in release — UB-ish silent corruption); (c) decode via `(code as f32) / 255.0 * (max-min) + min` recomputes the divide every call instead of caching `scale`.
  - **Output**: `notes/102mon_sq_design.md` with R1..R7, D1..D4 and the D3 outlier trace.

  #### Phase 3 — Make the tests pass, one failure at a time (~30 min)
  Ordered newbie → expert.
  - **(NEWBIE) When `sq_storage_is_exactly_n_times_d_bytes` reports `out.len() == 512`:**
    - Symptom: encoded buffer is 4× too large; `size_of_val(&out[0]) == 4`.
    - Why: `encode` wrote `f32`s (or returned `Vec<f32>`); the codec never narrowed to u8.
    - Fix: `out: &mut [u8]`, write `code as u8` per component.
    - Muscle: a quantizer that doesn't change the element type isn't quantizing — assert the byte width, not just the length. Reapplies at: W102 Tue PQ (`m` bytes/vec), W103 on-disk SQ format.
  - **(NEWBIE) When `sq_clamps_outliers_instead_of_wrapping` reports `out[0] == 12`:**
    - Symptom: a value far above max wraps to a tiny code; `(x-min)/scale = 1e6` then `as u8` truncates mod 256.
    - Why: `f32 as u8` saturates in Rust *only* for in-range floats; you computed an out-of-range index first. Without an explicit `.clamp(0.0, 255.0)` before the cast the rounding produced 1e6 then `as u8` gives garbage.
    - Fix: `let code = ((x - min) / scale).round().clamp(0.0, 255.0) as u8;` — clamp the *float* before the cast.
    - Muscle: clamp before narrowing; never trust an unbounded index into a fixed range. Reapplies at: W102 Tue PQ subspace code lookup, W104 segment id bucketing.
  - **(SENIOR) When `sq_recall_survives_one_percent_outliers` reports recall 0.78:**
    - Symptom: one 50× outlier stretches `min/max`; normal corpus collapses into ~8 of 256 codes (see D3 trace).
    - Why: `train` used true `min/max` (`fold(f32::MIN/MAX, ...)`), which the outliers dominate.
    - Fix: sort all training components, take `min = quantile(0.001)`, `max = quantile(0.999)`; clamp at encode (already added above). Recall recovers to ~0.93.
    - Muscle: any histogram/quantization training is outlier-fragile; percentile bounds are the standard guard. Reapplies at: W102 Tue PQ k-means init seeding, W103 stats-based compaction thresholds, every histogram encoder.
  - **(SENIOR) When `sq_asymmetric_distance_within_5pct_of_full_precision` shows 30% deviation:**
    - Symptom: SQ-decoded distances diverge wildly from f32 distances.
    - Why: you quantized the query too (symmetric) — both sides carry rounding error, which adds.
    - Fix: query stays f32; only db is decoded: `let d = q[i] - (min + db[i] as f32 * scale); sum += d*d;`.
    - Muscle: asymmetric distance is the default for ALL quantization (SQ, PQ, OPQ) — never quantize the query. Reapplies at: W102 Tue PQ ADC (the same principle, table-form).
  - **(SENIOR) When `sq_plus_hnsw_recall_at_10_ge_093` passes in isolation but fails at 0.88 inside HNSW:**
    - Symptom: codec correct alone; HNSW navigation on decoded distances loses recall.
    - Why: HNSW's `ef_search` was tuned for f32 distances; decode noise needs a slightly wider beam.
    - Fix: raise `ef_search` ~1.3× when searching quantized segments (document the knob for W104).
    - Muscle: a correct primitive can still degrade a *composed* system — tune the consumer's parameters for the lossy input. Reapplies at: W104 cross-segment search ef tuning, W102 Tue PQ+HNSW.
  - **(EXPERT) When `bench_sq_hnsw_vs_unquantized` reports 3.5× slower (anti-shortcut perf):**
    - Symptom: bench is far over the 1.2× budget although correctness tests are green.
    - Why: `decode_component` recomputes `(code as f32)/255.0*(max-min)+min` — a float divide (10-30 cyc) per component, 128× per candidate.
    - Fix: cache `scale = (max-min)/255.0` at train time; decode is `min + code as f32 * scale` (1 mul + 1 add). Re-bench → ~1.15×.
    - Cost avoided: ~10-30 cyc/component × 128 × candidate-count of float divides removed from the hot path (decode-in-loop must be mul+add, not divide).
    - Muscle: precompute the reciprocal/scale once; a divide in an inner loop is a design smell. Reapplies at: W102 Tue PQ LUT build, W104 distance kernels.

**Tuesday — vector-db: Product Quantization (PQ)**

- [ ] **Build**: `crates/vector-db/src/quantize/pq.rs` — `ProductQuantizer { m, ksub, dsub, codebook }`; train via k-means per subspace; ADC via per-query LUT. (~total 110 min across 3 phases)
  - 🔧 **Why this matters**: mirrors faiss `ProductQuantizer`. PQ is THE interview-load-bearing quantization: 16× compression at usable recall via the ADC trick (precompute a query×codebook LUT once, then each candidate distance is `m` table lookups + `m` adds instead of decoding 128 floats). The four traps: (1) random k-means init → poor centroids → recall 0.65; (2) rebuilding the LUT per candidate destroys the entire point of ADC; (3) `D % m != 0` silently truncates a subspace; (4) the LUT outgrows L1 when `ksub` is too big. First-attempt impls fail ≥1 test below; the debug session is the lesson. Downstream: W104 segment manager (PQ default for cold segments); W103 persistence (serializes codebook + codes).

  #### Phase 1 — Problem, prediction, design (~28 min, no code yet)
  - 🎯 **Pre-prediction prompt** — write sealed answers in `notes/102tue_pq_prediction.md`:
    - P1: the import/line you'd reach for k-means (write your own loop or `linfa-clustering`? state which and the init line).
    - P2: predicted codebook size in bytes and encoded-vector size in bytes for 128-d/m=8/ksub=256.
    - P3: predicted recall@10 of your first (random-init, 1-restart) attempt vs the 0.90 target.
    - P4: predict whether your first ADC loop hoists the LUT out of the candidate loop (yes/no — be honest).
    - P5: list every Phase-2 test you predict your first attempt will fail.
  - *Mental model*: PQ splits each vector into `m` sub-vectors of dim `dsub=D/m`, runs k-means (`ksub` centroids) per subspace, and stores each vector as `m` centroid-ids (1 byte each at ksub=256). Distance is approximated as the sum of per-subspace centroid distances, which ADC reads from a precomputed table.
  - *Contract*:
    ```rust
    pub struct ProductQuantizer { m: usize, ksub: usize, dsub: usize, codebook: Vec<f32> } // m*ksub*dsub
    pub struct PqLut(Vec<f32>); // m*ksub, query-specific
    impl ProductQuantizer {
        pub fn train(vecs: &[Vec<f32>], m: usize, ksub: usize, restarts: usize) -> Result<Self, PqError>;
        pub fn encode(&self, v: &[f32], out: &mut [u8]); // out.len() == m
        pub fn build_lut(&self, query: &[f32]) -> PqLut;  // ONCE per query
        pub fn distance_adc(&self, lut: &PqLut, codes: &[u8]) -> f32; // sum_{i<m} lut[i*ksub + codes[i]]
    }
    ```
  - *Back-of-envelope*: naive decode-then-distance is ~128 f32 ops/candidate. ADC is `m=8` lookups + 8 adds ≈ 16 ops — but only if the LUT is built once. LUT size = `m*ksub*4 = 8*256*4 = 8 KB`, fits in L1 (32 KB). codebook = `m*ksub*dsub*4 = 8*256*16*4 = 128 KB` (lives in L2/L3, read once at train). Rebuilding the LUT per candidate makes the "amortized" 8 KB build (~256 distance computes) run N times — turning 16 ops/candidate into 16 + (8 KB build) ≈ 2000 ops/candidate.
  - **Requirements** R1..R8 — write in `notes/102tue_pq_design.md`:
    - R1: `D % m == 0`; construction returns `Err(PqError::DimNotDivisible)` otherwise.
    - R2: codebook = `m*ksub*dsub*4` bytes (≈128 KB for the typical config).
    - R3: encoded vector = `m` bytes (16× for 128-d → 8 bytes).
    - R4: LUT built ONCE per query, reused across all candidate distance computes.
    - R5: recall@10 ≥ 0.90 at PQ(m=8, ksub=256) on 128-d.
    - R6: PQ+HNSW search ≤ 1.0× unquantized HNSW latency (LUT amortization beats decode).
    - R7: trained quantizer serializable (codebook round-trips byte-identical).
    - R8: k-means uses ++init + ≥5 restarts, pick best by within-cluster-sum-of-squares (WCSS).
  - **Design walk-through** D1..D4:
    - D1. Why ADC is fast: property table — naive (decode + L2 per candidate) ~128 ops; ADC (`m` lookups + adds) ~16 ops, one-time LUT build of `m*ksub` mults. Crossover at ~`ksub/dsub` candidates; HNSW visits thousands, so ADC wins by ~8×.
    - D2. LUT/codebook sizing: LUT 8 KB (L1), codebook 128 KB (L2). Why not ksub=4096? LUT becomes 128 KB and spills L1 → every lookup is an L2 hit (~7 ns) instead of L1 (~0.5 ns).
    - D3. **Pre-mortem (load-bearing):** random k-means init picks two seeds in the same dense blob; that subspace's 256 centroids cover a tiny region; encoding error explodes; recall = 0.65. Write the trace: seed_0 and seed_1 land 0.01 apart, 254 other centroids spread thin, a query 0.5 away rounds to the wrong cluster every time.
    - D4. **Anti-shortcut audit:** (a) random init (D3, fails recall); (b) single k-means run (no restart — luck-based, fails `++init_improves_recall`); (c) `for c in candidates { let lut = build_lut(q); ... }` (rebuilds LUT per candidate — fails the bench); (d) `assert!(D % m == 0)` as a debug-only assert (silently truncates in release — use a returned `Result`).
  - **Output**: `notes/102tue_pq_design.md` with R1..R8, D1..D4, the D3 bad-seed trace.

    - Cost avoided: a ~200 KB memcpy + extended lock hold removed from every filter call (turns ms-tail into µs-tail).
    - Muscle: share immutable hot data by `Arc`, don't deep-clone it under a lock. Reapplies at: W104 shared per-segment indices, any read-mostly shared structure.
