**Monday — vector-db: Scalar Quantization (SQ)**

- [ ] **Build**: `crates/vector-db/src/quantize/sq.rs` — `ScalarQuantizer { min: f32, max: f32, scale: f32 }`. Each
  f32 → u8. (~60 min)
  - **Why**: SQ is the simplest quantization — 4× memory reduction (f32 → u8) with typically < 2% recall loss on
    normalized embeddings. Standard production technique; every vector-db ships it. Foundational for the harder
    PQ work tomorrow.
  - **Read first**: faiss `IndexScalarQuantizer.cpp`; Qdrant `lib/segment/src/vector_storage/quantized/`;
    "Quantization for Nearest Neighbor and Maximum Inner Product Search" (Guo et al.).
  - **Design**: ```rust
    pub struct ScalarQuantizer<const D: usize> {
        // Per-dim min/max for asymmetric quantization (per-dim) OR global (simpler, used here).
        min: f32,
        max: f32,
        scale: f32, // = (max - min) / 255.0
    }
    pub struct QVectorSq<const D: usize>(Box<[u8; D]>);

    impl<const D: usize> ScalarQuantizer<D> {
        // Train: walk the corpus, compute min/max per dim or globally.
        pub fn train(samples: &[Vector<D>]) -> Self {
            let mut min = f32::INFINITY;
            let mut max = f32::NEG_INFINITY;
            for s in samples {
                for &x in s.as_slice() {
                    if x < min { min = x; }
                    if x > max { max = x; }
                }
            }
            let scale = (max - min) / 255.0;
            Self { min, max, scale }
        }
        pub fn encode(&self, v: &Vector<D>) -> QVectorSq<D> {
            let mut out = Box::new([0u8; D]);
            for (i, &x) in v.as_slice().iter().enumerate() {
                let clipped = x.clamp(self.min, self.max);
                out[i] = ((clipped - self.min) / self.scale).round() as u8;
            }
            QVectorSq(out)
        }
        // Asymmetric Distance Computation: query is f32, db is u8.
        // Decode db on-the-fly during inner loop; SIMD-friendly.
        pub fn distance_l2_asymmetric(&self, query: &Vector<D>, db: &QVectorSq<D>) -> f32 {
            let mut sum = 0f32;
            for i in 0..D {
                let db_f = self.min + db.0[i] as f32 * self.scale;
                let diff = query.as_slice()[i] - db_f;
                sum += diff * diff;
            }
            sum
        }
    }
    ```
    **Invariants**: train BEFORE encode; min/max stored per-quantizer (each segment may have its own quantizer);
    asymmetric distance (query unquantized, db quantized) gives ~ no recall loss vs symmetric; clamp inputs to
    [min, max] for outliers — otherwise overflow.
  - **Build steps**: 1. (~10 min) Struct + train() global min/max; 2. (~15 min) encode() + decode() with
    SIMD-friendly layout (AVX2 _mm256_set1 for min/scale); 3. (~15 min) Asymmetric distance L2 (and cosine
    optionally); 4. (~10 min) Test: recall@10 with SQ on 100k 128-d ≥ 0.93 vs unquantized ground truth;
    5. (~10 min) Memory test: storage is exactly N*D bytes (assert).
  - **Pitfalls** (named):
    - *Outlier domination*: **Symptom**: training set has one vector with norm 100× others, min/max range
      stretches, normal values map to a tiny region of [0,255], precision lost. **Fix**: use percentile-based
      min/max (e.g., 0.1 / 99.9 percentile); document.
    - *Asymmetric vs symmetric confusion*: **Symptom**: encode the query too (symmetric) — extra recall loss for
      no gain. **Fix**: asymmetric ONLY — query stays f32.
    - *Per-dim vs global trade*: **Symptom**: global min/max wastes precision when some dims have small range,
      others have large. **Fix**: v0.5 = global (simpler); v1.0 = per-dim (4× more state, marginally better
      recall). Document both options.
    - *No retraining on drift*: **Symptom**: workload changes, new vectors have larger range → clamped to old
      max, precision lost progressively. **Fix**: periodic retraining (W104 segment manager retrains per
      segment).
  - **Test scenarios**: 100k random + 1k outlier-heavy → recall ≥ 0.93; encode/decode roundtrip RMSE ≤ scale/2;
    memory exactly 4× compression.
  - **Acceptance**: recall@10 ≥ 0.93; memory 4× reduction; SQ-encoded HNSW search ≤ 1.2× slower than
    unquantized (decode overhead).
  - **Downstream**: W104 segment manager picks SQ as the default; W103 persistence stores quantized vectors
    on disk (further reduces I/O); cross-crate vector-db doesn't depend on mini-db for SQ but stores SQ-tables
    in mini-db as payload metadata (sidecar).
- [ ] Test: SQ + HNSW, recall@10 ≥ 0.93 at 4× memory reduction. (~30 min)

**Tuesday — vector-db: Product Quantization (PQ)**

- [ ] **Build**: `crates/vector-db/src/quantize/pq.rs` —
  `ProductQuantizer { num_subq: usize, codebook: Vec<Vec<Vector<8>>> }`. Train via k-means per subspace. (~75 min)
  - **Why**: PQ is the **interview-load-bearing** quantization technique. 16× compression with reasonable recall.
    Jégou et al. 2011 is the foundational paper; every modern vector-db (faiss, qdrant, milvus) ships it. The
    Asymmetric Distance Computation (ADC) trick — precompute LUT per query, sum from codes — is the magic that
    makes it fast.
  - **Read first**:
    - Jégou, Douze, Schmid 2011 "Product Quantization for Nearest Neighbor Search" — the foundational paper.
    - faiss `IndexPQ.cpp` + `ProductQuantizer.cpp` (the reference impl).
    - Ge et al. 2014 "Optimized Product Quantization" — OPQ, the rotation trick (skip for v0.5, mention).
    - Qdrant `lib/quantization/src/encoded_vectors_pq.rs`.
    - faiss tutorial wiki "Indexing 1M vectors".
  - **Design**: ```rust
    pub struct ProductQuantizer<const D: usize> {
        m: usize,                        // number of subquantizers (e.g., 8)
        ksub: usize,                     // codes per subquantizer (e.g., 256 → u8 codes)
        dsub: usize,                     // D / m, subspace dimension
        // codebook[i][c] = centroid c of subspace i.
        // Stored flat: [m * ksub * dsub] f32.
        codebook: Vec<f32>,
    }
    pub struct QVectorPq {
        m: usize,
        // m bytes (if ksub = 256). Each byte = index into that subspace's codebook.
        codes: Box<[u8]>,
    }

    impl<const D: usize> ProductQuantizer<D> {
        pub fn train(samples: &[Vector<D>], m: usize, ksub: usize, iters: usize) -> Self {
            assert!(D % m == 0, "D must be divisible by m");
            let dsub = D / m;
            let mut codebook = vec![0f32; m * ksub * dsub];
            // For each subspace, k-means cluster the projection of samples.
            for sub in 0..m {
                let projections: Vec<Vec<f32>> = samples.iter()
                    .map(|v| v.as_slice()[sub*dsub..(sub+1)*dsub].to_vec())
                    .collect();
                let centroids = kmeans(&projections, ksub, iters);
                for c in 0..ksub {
                    let off = (sub * ksub + c) * dsub;
                    codebook[off..off+dsub].copy_from_slice(&centroids[c]);
                }
            }
            Self { m, ksub, dsub, codebook }
        }
        pub fn encode(&self, v: &Vector<D>) -> QVectorPq {
            let mut codes = vec![0u8; self.m].into_boxed_slice();
            for sub in 0..self.m {
                let slice = &v.as_slice()[sub*self.dsub..(sub+1)*self.dsub];
                let mut best = (0u8, f32::INFINITY);
                for c in 0..self.ksub {
                    let off = (sub * self.ksub + c) * self.dsub;
                    let cw = &self.codebook[off..off+self.dsub];
                    let d = l2_squared(slice, cw);
                    if d < best.1 { best = (c as u8, d); }
                }
                codes[sub] = best.0;
            }
            QVectorPq { m: self.m, codes }
        }
        // Build LUT: query × codebook → m × ksub matrix of distances.
        // Then ADC distance = sum_i LUT[i][codes[i]].
        pub fn build_lut(&self, query: &Vector<D>) -> Vec<f32> {
            let mut lut = vec![0f32; self.m * self.ksub];
            for sub in 0..self.m {
                let q_slice = &query.as_slice()[sub*self.dsub..(sub+1)*self.dsub];
                for c in 0..self.ksub {
                    let off = (sub * self.ksub + c) * self.dsub;
                    let cw = &self.codebook[off..off+self.dsub];
                    lut[sub * self.ksub + c] = l2_squared(q_slice, cw);
                }
            }
            lut
        }
        pub fn distance_adc(&self, lut: &[f32], db: &QVectorPq) -> f32 {
            let mut sum = 0f32;
            for sub in 0..self.m {
                sum += lut[sub * self.ksub + db.codes[sub] as usize];
            }
            sum
        }
    }
    ```
    **Invariants**:
    - D % m == 0 (subspaces equal-sized; OPQ relaxes this via rotation).
    - codebook size = m * ksub * dsub * 4 bytes (for typical 128-d, m=8, ksub=256: 8*256*16*4 = 128 KB).
    - Encoded vector size = m bytes (16× compression for 128-d → 8 bytes).
    - ADC requires LUT built ONCE per query, reused across all candidate distance computes (this is the speed
      magic).
    - K-means uses Lloyd's algorithm; convergence not guaranteed but OK with bounded iters; multi-init helps.
  - **Build steps**:
    1. (~15 min) k-means impl for fixed-dim vectors (or pull `linfa-clustering` crate).
    2. (~20 min) train() per-subspace loop calling k-means.
    3. (~15 min) encode() linear-scan over codebook per subspace.
    4. (~15 min) build_lut() + distance_adc().
    5. (~10 min) Test: 100k 128-d → PQ(m=8, ksub=256), recall@10 ≥ 0.90 vs ground truth.
    6. (~5 min) Bench: PQ-encoded HNSW search throughput (target ≥ 2× unquantized due to LUT speedup).
    7. (~5 min) Document compression ratio + LUT cost in DESIGN.md.
  - **Pitfalls** (named, deep):
    - *Bad k-means init*: **Symptom**: random init → poor centroids → high quantization error → recall tanks.
      **Fix**: k-means++ init (probabilistic seeding); 3-10 restarts; pick best by within-cluster sum of squares.
    - *Subspace correlation*: **Symptom**: if dimensions are correlated, naive PQ wastes codes on redundancy.
      **Fix**: OPQ rotates the space first to decorrelate subspaces (Ge 2014). v0.5 = vanilla PQ; mention OPQ
      as v1.0 optimization.
    - *LUT cache miss*: **Symptom**: LUT is m * ksub * 4 = 8 KB at m=8, ksub=256; if you use larger ksub or m
      it spills out of L1. **Fix**: target LUT ≤ 16 KB; document the limit.
    - *Symmetric vs asymmetric*: **Symptom**: encoding the query (symmetric) loses recall vs LUT-based ADC.
      **Fix**: ADC (asymmetric) is the right default; symmetric SDC is for memory-constrained codebook
      pre-computation only.
    - *Recall measurement bias*: **Symptom**: if test set drawn from same distribution as train, recall
      inflated. **Fix**: hold out 10% for test; use SIFT-1M or GIST-1M public datasets for honest comparison.
    - *Variable subspace size*: **Symptom**: D=129 not divisible by m=8. **Fix**: assert at construction;
      caller pads vector or splits subspaces unevenly (out of scope v0.5).
    - *Catastrophic cancellation in LUT*: **Symptom**: query has very large norm, distances overflow f32 at
      accumulation. **Fix**: normalize before quantization; or use f64 LUT (memory cost; skip for now).
  - **Test scenarios** (adversarial):
    - 100k SIFT-1M subset → recall@10 ≥ 0.90 at PQ(m=8, ksub=256).
    - Bench: with HNSW + PQ, search throughput ≥ 8k qps single-thread (vs ~5k unquantized).
    - Compression: storage = 8 bytes/vec vs 512 bytes/vec → 64× reduction (better than 16× claim because
      original is f32, encoded is u8; the claim 16× is for what?? clarify: 128*4 = 512 → 8 bytes = 64×; 16× was
      a rough number — actual is 64× for 128-d).
    - Robustness: train on 100k, test recall on 10k held-out, recall@10 ≥ 0.88.
    - Quantizer determinism: same seed → same codebook (k-means with seeded RNG).
  - **Acceptance**:
    - recall@10 ≥ 0.90 at PQ(m=8, ksub=256) on 128-d random.
    - PQ-HNSW search latency ≤ unquantized HNSW latency (LUT speeds up inner loop).
    - Codebook + encoded vectors total ≤ 1/8 of raw storage.
    - Trained quantizer serializable to/from disk (W103 persistence consumes).
  - **Downstream**:
    - W104 segment manager: PQ is the default quantizer for cold segments.
    - W103: persist serializes codebook + encoded vectors.
    - Interview value: "implemented PQ from Jégou 2011 with ADC" is staff-level vector-db competence.

**Wednesday — vector-db: filtered search via bloom-bitmap**

- [ ] **Build**: `crates/vector-db/src/filter.rs` — `FilterMask` is a `bloom::ClassicBloomFilter` or precomputed bitmap.
  Search prunes candidates against filter before distance compute. (~75 min)
  - **Why**: Real vector workloads ALWAYS filter — "find similar products in price range $X-$Y", "find similar
    documents authored by user Z". Naive search-then-filter blows up tail latency (search returns 1000, filter
    keeps 5); naive filter-then-search defeats HNSW (need IDs upfront, then brute-force). The bitmap + HNSW
    integration is the **interview-load-bearing answer**.
  - **Read first**: Qdrant `lib/segment/src/index/struct_payload_index.rs` (the filtering integration);
    Pinecone's "Filtered Vector Search" engineering blog; Weaviate's inverted-index over payloads doc; faiss
    `IndexIVFPQ` filtering hooks (limited).
  - **Design**: ```rust
    pub trait Filter: Send + Sync {
        fn matches(&self, id: NodeId) -> bool;
        fn estimated_selectivity(&self) -> f32; // 0.0 = no match, 1.0 = all match
    }
    pub struct BitmapFilter {
        bits: roaring::RoaringBitmap,
        total: u32,
    }
    pub struct BloomFilter {
        inner: bloom::ClassicBloomFilter,
    }
    pub struct AndFilter(pub Box<dyn Filter>, pub Box<dyn Filter>);

    pub enum Strategy { Prefilter, Postfilter, Adaptive }

    impl Strategy {
        pub fn pick(filter: &dyn Filter, k: usize, graph_size: usize) -> Self {
            let sel = filter.estimated_selectivity();
            if sel < 0.01 { Strategy::Prefilter }       // very selective → prefilter is faster
            else if sel > 0.5 { Strategy::Postfilter }  // permissive → just search + drop
            else { Strategy::Adaptive }                 // medium → filter during search
        }
    }

    impl<const D: usize> HnswGraph<D> {
        pub fn search_filtered(&self, q: &Vector<D>, k: usize, ef: usize, f: &dyn Filter) -> Vec<(NodeId, f32)> {
            match Strategy::pick(f, k, self.node_count()) {
                Strategy::Prefilter => {
                    // Iterate the matched IDs (from a payload index), brute-force scan.
                    // Only sensible if matched count is small (< sqrt(N) rule of thumb).
                    let matched: Vec<_> = (0..self.node_count() as NodeId).filter(|&id| f.matches(id)).collect();
                    let mut scored: Vec<_> = matched.into_iter()
                        .map(|id| (id, q.distance(&self.vectors.read()[id as usize])))
                        .collect();
                    scored.sort_unstable_by(|a, b| a.1.partial_cmp(&b.1).unwrap());
                    scored.truncate(k);
                    scored
                }
                Strategy::Postfilter => {
                    // Run search with ef expanded by 1/selectivity, drop non-matching.
                    let expanded_ef = ((ef as f32) / f.estimated_selectivity()).ceil() as usize;
                    let results = self.search(q, expanded_ef, expanded_ef);
                    results.into_iter().filter(|(id, _)| f.matches(*id)).take(k).collect()
                }
                Strategy::Adaptive => {
                    // Inline-filter: search_layer skips non-matching nodes for "results" but follows their edges.
                    self.search_filtered_inline(q, k, ef, f)
                }
            }
        }
    }
    ```
    **Invariants**: filter never modifies graph; selectivity estimate may be wrong (Bloom over-estimates,
    bitmap is exact); strategy chosen per query based on estimate; inline strategy must still TRAVERSE the
    graph through non-matching nodes (else connectivity lost) but only ADMIT matching to result set.
  - **Build steps**: 1. (~10 min) Filter trait + BitmapFilter + BloomFilter; 2. (~15 min) Strategy enum +
    pick() heuristic; 3. (~20 min) Prefilter path with brute-force; 4. (~10 min) Postfilter with expanded
    ef; 5. (~15 min) Adaptive inline path — modify search_layer to accept &dyn Filter and filter results
    but still follow non-matching edges; 6. (~5 min) Tests: each strategy on 100k vectors with selectivities
    0.01, 0.1, 0.5, 0.9 — recall ≥ 0.90 across the board.
  - **Pitfalls** (named, deep):
    - *Low-selectivity blowup*: **Symptom**: filter selects 0.001 of corpus, postfilter strategy expands ef to
      200k, search becomes O(N). **Fix**: Strategy::pick switches to Prefilter for sel < 0.01.
    - *Inline filter disconnects graph*: **Symptom**: if inline filter both excludes non-matching from results
      AND prunes their edges from traversal, the graph fragments and connected matching nodes become
      unreachable. **Fix**: traverse THROUGH non-matching (use their edges) but never ADMIT them to results
      heap; the visited set still includes them.
    - *Bloom false-positive cascade*: **Symptom**: BloomFilter over-reports matches → admits non-matching IDs
      → caller's downstream check rejects them → recall measurement looks worse than reality. **Fix**:
      ALWAYS do a final exact check on returned IDs (callee semantics); document Bloom's role as a fast
      prefilter only.
    - *Selectivity estimate stale*: **Symptom**: bitmap's count is correct; bloom's selectivity is computed
      from set_bits/total_bits, can drift if filter mutates. **Fix**: recompute selectivity on each query
      (cheap for bitmap, cheaper for bloom).
    - *Filter index decoupling*: **Symptom**: payload index (mini-db) and HNSW node IDs go out of sync after
      delete → filter says ID exists, HNSW doesn't have it (or vice versa). **Fix**: both writes are atomic
      in the same txn (W103 covers atomic txn wrapper); on mismatch, search ignores phantoms.
    - *AND of multiple filters*: **Symptom**: AndFilter sequential — first filter dominates; selectivity is
      product but pick() doesn't know that. **Fix**: AndFilter.estimated_selectivity() = product of children;
      pick() uses combined estimate.
  - **Test scenarios** (adversarial):
    - Selectivity 0.001: Prefilter wins, 1ms; Postfilter loses, 100ms+.
    - Selectivity 0.5: Postfilter wins; Adaptive close second.
    - Selectivity 0.05: Adaptive should match best of Pre/Post within 20%.
    - AND of two filters at sel 0.1 each → combined 0.01 → Prefilter picks correctly.
    - Concurrent search with filter mutation (rare but possible): no panic, may return slightly stale.
  - **Acceptance**: recall@10 ≥ 0.90 across all three strategies at sel ∈ {0.01, 0.1, 0.5}; latency
    P99 ≤ 5 ms at any selectivity on 1M corpus; Strategy::pick chooses optimal within 20% in 90% of cases.
  - **Downstream**: W102 Thursday payload storage in mini-db feeds the filter (per-field bitmap indices);
    W104 segment manager merges filters across segments; the inline strategy is the production default.

**Thursday — vector-db: payload storage via mini-db**

- [ ] **Build**: `crates/vector-db/src/payload.rs` — payload (per-vector JSON metadata) stored in an embedded
  `mini_db::MiniDb`. Cross-crate inheritance: vector-db doesn't reimplement KV. (~75 min)
  - **Why**: **This is the inheritance principle in action across crates.** vector-db doesn't need a KV store —
    mini-db is one. Pulling mini-db as a dep is the simplest proof that the inheritance principle scales across
    product crates, not just within one. Resume-load-bearing.
  - **Read first**: Qdrant `lib/segment/src/payload_storage/` (their payload abstraction); your own `crates/mini-db/`
    public API (engine.rs); serde_json docs for the payload encoding.
  - **Design**: ```rust
    use mini_db::Db as MiniDb;
    use serde_json::Value as JsonValue;

    pub struct PayloadStore {
        db: Arc<MiniDb>,
        // Per-field bitmap indices for filter acceleration. Keyed by field name.
        indices: parking_lot::RwLock<hashbrown::HashMap<String, FieldIndex>>,
    }
    pub enum FieldIndex {
        Integer(BTreeMap<i64, roaring::RoaringBitmap>),
        Keyword(hashbrown::HashMap<String, roaring::RoaringBitmap>),
        Geo(/* geohash bucket index */),
    }

    impl PayloadStore {
        pub fn new(path: impl AsRef<Path>) -> Result<Self> {
            let cfg = mini_db::EngineConfig {
                data_dir: path.as_ref().to_path_buf(),
                memtable_bytes: 8 * 1024 * 1024,  // smaller; payload is sparse
                wal_sync_mode: mini_db::SyncMode::Periodic,
                ..Default::default()
            };
            Ok(Self { db: Arc::new(MiniDb::open(cfg)?), indices: Default::default() })
        }
        pub fn put(&self, id: NodeId, payload: &JsonValue) -> Result<()> {
            let key = id.to_le_bytes();
            let value = serde_json::to_vec(payload)?;
            self.db.put(&key, &value)?;
            // Maintain per-field indices.
            if let Some(obj) = payload.as_object() {
                let mut idx = self.indices.write();
                for (field, val) in obj {
                    Self::index_field(&mut idx, field, val, id);
                }
            }
            Ok(())
        }
        pub fn get(&self, id: NodeId) -> Result<Option<JsonValue>> {
            let key = id.to_le_bytes();
            Ok(self.db.get(&key)?.map(|b| serde_json::from_slice(&b)).transpose()?)
        }
        pub fn filter_by_keyword(&self, field: &str, value: &str) -> Option<BitmapFilter> {
            let idx = self.indices.read();
            if let Some(FieldIndex::Keyword(map)) = idx.get(field) {
                map.get(value).map(|bm| BitmapFilter { bits: bm.clone(), total: self.db.count().unwrap_or(0) as u32 })
            } else { None }
        }
        pub fn filter_by_range(&self, field: &str, lo: i64, hi: i64) -> Option<BitmapFilter> {
            let idx = self.indices.read();
            if let Some(FieldIndex::Integer(map)) = idx.get(field) {
                let mut bm = roaring::RoaringBitmap::new();
                for (_, v) in map.range(lo..=hi) { bm |= v; }
                Some(BitmapFilter { bits: bm, total: self.db.count().unwrap_or(0) as u32 })
            } else { None }
        }
    }
    ```
    **Invariants**: payload is per-NodeId; indices are rebuildable from payload (no separate WAL — indices are
    secondary); index updates are best-effort consistent (a brief window post-put before index reflects;
    document); mini-db inherits durability for the source-of-truth.
  - **Build steps**: 1. (~10 min) PayloadStore struct + open(); 2. (~20 min) put() with serde_json + mini-db
    put + index maintenance; 3. (~15 min) get(); 4. (~20 min) filter_by_keyword + filter_by_range returning
    BitmapFilter; 5. (~10 min) Test: insert 10k payloads with random schemas; filter by exact keyword, range,
    AND of two — assert correct ID set.
  - **Pitfalls** (named):
    - *Index reconstruction after restart*: **Symptom**: indices are in-memory; restart loses them. **Fix**:
      on open(), scan mini-db and rebuild indices (slow for large data); v1.0 would persist indices to mini-db
      under a separate key namespace.
    - *Index drift on delete*: **Symptom**: delete payload, but index still references node. **Fix**: delete
      path removes from each field's bitmap (mirror put logic in reverse).
    - *Schema flexibility*: **Symptom**: payload v1 has field "price" as integer, v2 has "price" as string —
      Integer index breaks. **Fix**: detect type per put; mismatched type → log warning + skip indexing for
      that field on that record.
    - *Cross-crate version skew*: **Symptom**: vector-db pinned to mini-db 1.0; new mini-db 1.1 breaks API.
      **Fix**: workspace pinning + integration tests; document the dep relationship in vector-db CHANGELOG.
  - **Test scenarios**: 10k mixed-schema payloads; filter combinations; restart + rebuild indices yields same
    filters.
  - **Acceptance**: filter_by_keyword P99 ≤ 100 µs on 1M payloads; index memory ≤ 5% of payload size;
    mini-db cross-crate dep documented in vector-db DESIGN.md.
  - **Downstream**: filter.rs consumes BitmapFilter from here; W104 segment manager has one PayloadStore per
    segment; HNSW search_filtered queries this. **Inheritance proof**: vector-db has zero KV code — it's all
    mini-db.
