  #### Phase 3 — Make the tests pass, one failure at a time (~50 min)

  - **(NEWBIE) When `decode_advances_cursor` reports cursor at position 0 after decode:**
    - Symptom: after `let v = u64::decode(&mut buf)?;` the slice `buf` still points at the same bytes; the
      next decode re-reads the value.
    - Why: your impl built the value but forgot `*buf = &buf[consumed..]`. The `&mut &[u8]` parameter is the
      whole point — it's how you tell the caller "I ate N bytes".
    - Fix: every `Decodable::decode` ends with `*buf = &buf[consumed..]` before `Ok(value)`. Compute `consumed`
      from the header + payload length you just read.
    - Muscle: a decoder's job is half "produce value", half "advance cursor". Reapplies at: W5 Wed list decode,
      W6 tx decode, W9 envelope decode.

  - **(NEWBIE) When `error_enum_is_flat_no_box` reports `Error` is 24+ bytes / won't impl `Copy`:**
    - Symptom: either `assert_eq!(size_of::<Error>(), 16)` fails (reports 24, the `String`-variant size) or the
      `_assert_copy::<Error>()` line refuses to compile (`the trait Copy is not implemented for Error`).
    - Why: a `Custom(String)` or `Box<dyn StdError>` variant smuggled a heap allocation into the hot decode
      error path — every malformed-input rejection (and at consensus time, every adversarial packet) would
      `malloc` a fresh string just to say "invalid". `String`/`Box` are not `Copy`, so the guard catches it.
    - Fix: flat enum, `Custom(&'static str)` only — borrow a `'static` message, never own one. The whole
      `Error` is then 16 bytes and `Copy`.
    - Cost avoided: 1 `malloc` (~50 ns) + 1 `free` per rejected input on the decode error path; at adversarial
      packet rates this is an allocator-pressure DoS vector, not merely "slow".
    - Muscle: a hot-path error type is flat, `Copy`, and `'static` — no heap in the failure path. Reapplies at:
      W6 tx decode error, W9 envelope error, every consensus decoder.

  - **(JUNIOR) When `signatures_match_alloy_rlp` fails with a trait-bound mismatch:**
    - Symptom: `the trait alloy_rlp::Encodable is implemented for u64, but the trait eth_rlp::Encodable
      requires fn encode(&self, out: &mut dyn BufMut)` — alloy uses a different signature than yours.
    - Why: you diverged from alloy's exact API surface (perhaps you took `&mut Vec<u8>` instead of `dyn
      BufMut`, or returned `Result` instead of unit from `encode`).
    - Fix: re-align signatures byte-for-byte with `alloy-rlp v0.4`. The compat test exists so the divergence
      is caught at compile time, not in production when someone tries to swap implementations.
    - Muscle: mirroring a mature crate means *exact* signature match, not "spiritually similar". Reapplies at:
      W6 Header struct field order, W9 envelope encoding.

  - **(SENIOR) When `length_does_not_call_encode` reports counter > 0:**
    - Symptom: your impl of `length()` for some composite type called `self.encode(&mut scratch); scratch.len()`.
      Counter increments; test fails.
    - Why: it's tempting to define `length` via the encode itself (DRY), but containers call `length()` *per
      child* to size their own header — that recurses to O(2^depth) encode work.
    - Fix: every `Encodable::length` is implemented as pure arithmetic — sum of children's `length()` plus
      header-bytes (`1 + length_of_length(payload_len)` for long form, `1` for short). No scratch buffer ever.
    - Muscle: encoded length is a *computed* property, never a *measured* one. Reapplies at: W6 Header encode,
      W9 TxEnvelope, every RLP type.

  - **(SENIOR) When `encodable_dyn_object_safe` reports "the trait `Encodable` cannot be made into an object":**
    - Symptom: `error[E0038]: the trait Encodable cannot be made into an object … because method encode has
      generic type parameters`.
    - Why: a generic method parameter (`<B: BufMut>`) cannot be dispatched dynamically — `vtable` slots are
      monomorphized per concrete `B`, which isn't known at the trait-object site.
    - Fix: take `out: &mut dyn BufMut` instead of `out: &mut B`. The single dynamic dispatch per `put_u8` is
      hidden behind `bytes`' own machinery and well-amortized.
    - Muscle: a serialization trait that will appear behind `dyn` keeps its writer parameter as `dyn`,
      not generic. Reapplies at: W9 envelope `dyn Encodable`, W10 trie child iteration.

  #### Phase 3 — Make the tests pass, one failure at a time (~55 min)

  - **When `boundary_b256_roundtrips` won't compile — E0117, "only traits defined in the current crate
    can be implemented for arbitrary types":**
    - Symptom: `impl From<alloy::primitives::B256> for eth_primitives::B256` in `boundary.rs` is rejected
      outright. The error points at the impl header, not the body.
    - Why: the orphan rule. A trait impl needs at least one item local to the crate writing it. Here
      `From` is `core`'s, `eth_primitives::B256` is `eth-primitives`', `alloy::primitives::B256` is
      `alloy-primitives`' — three crates, none of them this one. Two things make it feel wrong when it
      isn't: you *wrote* `eth-primitives` (irrelevant — locality is per-crate), and `B256` looks like your
      type (it is a type alias, and aliases are transparent to coherence).
    - Fix: stop reaching for `From`. Define `FromAlloy<T>` in `boundary.rs` and implement that instead —
      `impl FromAlloy<alloy::primitives::B256> for eth_primitives::B256` is legal because the trait is
      local. Add a blanket `IntoLocal` sugar trait if you want `.into_local()` at callsites. The newtype
      lever (wrap the alloy type locally, keep real `From`) also compiles, but taxes every callsite.
    - Muscle: **the orphan rule is satisfied by making the TRAIT local, not by owning the types.** When
      you cannot impl a std trait across two foreign types, define your own trait — that is the standard
      move, not a workaround. Reapplies at: W16 `eth-rpc-types` extraction, W22 provider→header ingestion,
      W49 revm type bridging, W63 Aeron→RPC types. Anywhere two type families meet.

  - **When `boundary_b256_roundtrips` fails with byte-order mismatch:**
    - Symptom: `a == a2` is false; the byte arrays are bit-reversed or word-reversed.
    - Why: you used `from_le_bytes` on one side and `from_be_bytes` on the other. `B256` is canonically
      big-endian (Ethereum's wire convention).
    - Fix: both directions go through the same big-endian byte array — construct from `[u8; 32]` on each
      side (or `to_be_bytes()` if routing through a U256 intermediate). Pin the canonical direction in
      `boundary.rs`'s module doc.
    - Muscle: any cross-type boundary involving multi-byte integers MUST commit to one byte order
      (big-endian for Ethereum) and document it. Reapplies at: W6 Header field conversions, W9 envelope
      hash conversions, W22 staged sync header ingestion.

    - Symptom: someone (you, last hour) added `use alloy_primitives::B256;` in main.rs for a quick test

      at: W16 `eth-rpc-types` extraction (same boundary discipline), W49 revm integration.

  - **When `etherscanlite_missing_env_var_fails_fast` panics deep in alloy-provider:**

    - Why: you read `std::env::var("ETH_RPC_URL").unwrap_or_default()` and passed the empty string to
      alloy-provider, which lazily fails when it tries to connect.
    - Fix: at startup (line 1 of `main`), `let rpc = std::env::var("ETH_RPC_URL").context("ETH_RPC_URL

  - **When `etherscanlite_handles_429_with_backoff` fails with no retry:**
    - Symptom: the binary errors on the first 429; never retries.
    - Why: alloy-provider's HTTP layer doesn't auto-retry; you have to wrap the call site.
    - Fix: wrap each provider call in `RetryFuture::new(|| provider.get_balance(addr).await,
      max_retries=3, backoff_ms=100)`. Reuse the W3 `RetryFuture` directly; if its signature doesn't
      fit, extract the abstraction at the boundary.
    - Muscle: external network calls need explicit retry-on-rate-limit at the call site; never trust
      a provider library to do it for you. Reapplies at: W22 staged sync HTTP downloads, W64 Aeron
      reconnect.

      successfully despite not being a valid EIP-55 checksum.
