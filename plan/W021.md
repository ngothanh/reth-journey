**Monday — `eth-rlp` extension: trie-friendly encoding**

- [ ] Re-read RLP spec sections relevant to trie nodes. (~45 min)
- [ ] **Build**: `crates/eth-rlp/src/trie.rs` — encode_branch_node, encode_extension_node, encode_leaf_node. (~total 140 min across 3 phases)
  - 🔧 **Why this matters**: MPT nodes have three shapes (branch, extension, leaf) each with its own RLP
    serialization including a 1-byte path-type prefix (the "compact path encoding" or "hex prefix").
    Centralizing these encoders in `eth-rlp` avoids duplication across eth-trie, storage-trie, and downstream
    provers — and avoids the classic "even/odd nibble parity" bug. Downstream: every trie node anywhere in
    the workspace (eth-trie, storage-trie, mini-db W95) routes through these.

  #### Phase 1 — Problem, requirements, design (~40 min, no code yet)

  - **The problem this primitive solves**: the MPT's wire format intermixes structural info (leaf vs
    extension; even-length vs odd-length nibble path) into the first byte of the path encoding — the
    "Hex-Prefix" (HP) scheme from yellow paper appendix C. Getting this byte wrong produces a
    well-formed RLP list whose hash disagrees with mainnet. Centralizing the encoders ensures every
    consumer uses the same HP table, the same embedded-vs-hashed threshold, and the same canonical
    list ordering.

  - **Requirements** — write in `crates/eth-rlp/notes/21_trie_rlp_design.md`:
    - R1. `encode_compact_path(nibbles, is_leaf, out)` writes the HP-prefix byte then packed nibble pairs.
    - R2. HP flag bit pattern (the table from yellow paper §C): `0x00` = extension/even, `0x10` =
      extension/odd, `0x20` = leaf/even, `0x30` = leaf/odd.
    - R3. `encode_leaf_node(path, value, out)` writes a 2-element RLP list `[compact_path, value]`.
    - R4. `encode_extension_node(path, child, out)` writes a 2-element RLP list `[compact_path, child_ref]`.
    - R5. `encode_branch_node(children: [Option<ChildRef>; 16], value, out)` writes a **17-element** RLP
      list: 16 child slots + 1 value slot. Absent children encode as `0x80` (RLP empty string).
    - R6. `ChildRef` is either inline RLP bytes (when child's full encoding `< 32` bytes — strictly less
      than) or a 32-byte keccak hash.
    - R7. Nibbles within a byte: MSB-first. `(byte >> 4, byte & 0x0F)` is the pair, in that order.
    - R8. Round-trip property: `encode(decode(bytes)) == bytes` for every node shape at every nibble
      length 0, 1, 2, 31, 32, 33, 64.
    - R9. Pass `ethereum/tests::TrieTests::trietest` and `trieanyorder` byte-identical.

  - **Design walk-through** — answer each:
    - D1. The HP-prefix byte is computed from `(is_leaf, odd)`. Write the formula. What does the byte
      look like for `is_leaf=true, nibbles=[3, 7, 5]` (3 nibbles, odd)?
    - D2. The "even" case appends a `0x00` padding byte BEFORE the nibble pairs (so the prefix is the
      whole first byte and the rest are pure nibble data); the "odd" case stuffs the first nibble into
      the lower 4 bits of the prefix byte. Why is this asymmetric? (Hint: nibbles are 4 bits each; an
      odd count leaves a stray nibble somewhere.)
    - D3. Embedded-vs-hashed threshold: why strictly `< 32` and not `<= 32`? (Hint: 32 is the keccak
      output size; ambiguous if both inline and hash can be the same length.)
    - D4. RLP list header: alloy's `Header::encode` handles short (0-55 bytes) vs long forms. Use it
      directly. What goes wrong if you hand-roll the header encoding for a near-55-byte boundary?
    - D5. Pre-mortem: write the off-by-one in even/odd nibble parity that produces intermittent
      state-root divergence (some blocks correct, some wrong) and explain why it's load-bearing — i.e.
      why mainnet has both even-length and odd-length paths in roughly equal proportions.

  - **Output**: `notes/21_trie_rlp_design.md` with R1–R9 + D1–D5 + the 4-case HP table.

  #### Phase 3 — Make the tests pass, one failure at a time (~70 min)

  - **When `compact_path_odd_extension` produces `[0x10, 0x37, 0x50]` (three bytes, wrong):**
    - Symptom: encoder treats the odd case as "prefix byte + nibble-pairs starting from nibble 0",
      yielding 3 bytes; expected 2 bytes `[0x13, 0x75]`.
    - Why: the first nibble (`3`) should be stuffed into the LOW 4 bits of the prefix byte, not
      treated as a normal data nibble. The prefix becomes `0x10 | 0x03 = 0x13`.
    - Fix: in the odd branch: `out.push((flag << 4) | nibbles[0]); out.extend(nibble_pairs(&nibbles[1..]));`
      — note the slice from index 1.
    - Muscle: HP encoding's odd case stuffs the leading nibble into the prefix byte; the even case
      pads with `0x00`. The asymmetry is THE bug to defend against. Reapplies at: W20 walker.rs path
      assembly, W31 persistent MPT key encoding, W20 state_root.rs.

  - **When `embedded_child_exactly_32_bytes_hashed` reports a 32-byte raw inline instead of a hash:**
    - Symptom: branch at the boundary (child encoded len = 32) contains the child's raw bytes; expected
      a 32-byte hash.
    - Why: encoder used `<=` instead of `<`. The two interpretations match for all sizes except exactly
      32.
    - Fix: `if child.encoded_len() < 32 { write_inline } else { write_hash }`. Test against both 31 and
      32 to nail the boundary.
    - Muscle: the inline-vs-hash threshold is strict-less-than-32; off-by-one breaks consensus at
      exactly the 32-byte case (rare but real). Reapplies at: W20 branch_compact.rs, W20 state_root.rs.

  - **When `branch_node_is_17_element_list` decodes to 16 elements:**
    - Symptom: branch RLP decodes as a 16-element list; expected 17.
    - Why: encoder omitted the 17th "value at this branch" slot (almost always empty in modern
      Ethereum, but spec-required).
    - Fix: always emit the 17th slot, defaulting to `0x80` (empty) when no value present. Yellow paper
      appendix C is explicit.
    - Muscle: every branch node has 17 RLP slots, even if the 17th is always empty in practice;
      omitting it produces a non-canonical encoding that other clients reject. Reapplies at: W20
      state_root.rs, W31 persistent MPT, W32 proof verification.

  - **When `round_trip_every_nibble_length` fails on length 1 (single nibble):**
    - Symptom: encode `[5]` → decode → re-encode produces `[0x35]` (correct prefix) but decoded value
      `[]` (nibbles empty) — round-trip is `[5] → [0x35] → []`.
    - Why: decoder reads the prefix byte, sees odd-leaf, extracts the lower nibble, then expects more
      bytes — finds none, returns empty. The "lower nibble of prefix is itself the only nibble" case
      isn't handled.
    - Fix: in decoder, after extracting prefix info, if `odd` AND no further bytes, the single nibble
      IS the only nibble — return `[low_nibble_of_prefix]`. Add tests for lengths 1, 3, 5, 63 (all
      odd-edge cases).
    - Muscle: HP decoder must handle the single-nibble case where the prefix byte is the entire
      payload. Reapplies at: W31 persistent MPT key decode, W32 proof verifier.

  - **5-year failure mode** (write in `notes/21_trie_rlp_followup.md` after green): when Verkle tries
    replace MPT, the HP encoding becomes obsolete — Verkle uses fixed-width 32-byte keys with no
    odd/even parity flags. State the migration: gate HP encoders behind `cfg(feature = "mpt")` and
    add `verkle::encode_node` parallel module. Trigger: Verkle activation.

**Tuesday — Reth RLP usage patterns + `eth-rlp` derive enhancements**

- [ ] Read reth's RLP usage patterns + alloy-rlp source freshly. (~60 min)
- [ ] **Extend**: eth-rlp-derive to support `#[rlp(trailing)]`. (~total 80 min across 3 phases)
  - 🔧 **Why this matters**: EIP types evolve via *trailing* fields — EIP-1559 added basefee to headers,
    EIP-4895 added withdrawals, EIP-4844 added blob fields. Old block headers must decode without these
    fields; new ones must include them. `#[rlp(trailing)]` annotates fields whose absence on decode is
    `None`/`Default`. Without this attribute, every Header schema change forks the codec. Downstream: every
    block-related codec in the workspace; W42+ block-import path; W64 RPC `eth_getBlockByNumber` responses.

  #### Phase 1 — Problem, requirements, design (~25 min, no code yet)

  - **The problem this primitive solves**: hard forks add fields to consensus structs (most commonly to
    `Header`). The wire format is RLP list; "missing field" in old headers means the list is shorter, not
    that the field is null-bytes. The decoder must accept both lengths and place the trailing items into
    `Option<T>` fields in declaration order. The encoder must skip `None`s from the end (but never emit a
    `None` BEFORE a `Some` — that's ambiguous on the wire).

  - **Requirements** — write in `crates/eth-rlp/notes/21_rlp_trailing_design.md`:
    - R1. New attribute `#[rlp(trailing)]` recognized on struct fields by `RlpEncodable` and
      `RlpDecodable` derives.
    - R2. Decoder: reads N items from RLP list where N = `mandatory_count + observed_trailing_count`.
      Missing trailings default to `None`/`Default::default()`.
    - R3. Encoder: encodes mandatory fields, then encodes trailing fields in declaration order, but emits
      NO bytes past the last `Some`/non-default trailing.
    - R4. Encoder rejects (panic at encode time) any `None` followed by a `Some` in the trailing
      sequence — that combination would be wire-ambiguous.
    - R5. All trailing fields must be `Option<T>` OR `T: Default + Eq + PartialEq`. Compile-time error
      on `#[rlp(trailing)]` field that's neither.
    - R6. Round-trip: pre-London header (no trailings) encodes back to identical bytes; Cancun header (all
      trailings present) encodes back to identical bytes.
    - R7. Decoding any mainnet header from genesis through current at 1k-block sample never panics.
    - R8. Pass alloy's `header_rlp_roundtrip` test fixtures (port them).

  - **Design walk-through** — answer each:
    - D1. Parse-time: detect `#[rlp(trailing)]` and partition fields into `(mandatory, trailing)` Vecs.
      What `syn` API do you use? (Hint: `Field::attrs` + `Attribute::parse_meta` or `Attribute::path`.)
    - D2. Decoder codegen: how do you handle the case where the RLP list has more items than total fields
      (mandatory + trailing)? (Hint: error — `TooManyItems` — never silently accept.)
    - D3. Encoder codegen for "skip from end": walk trailings in reverse, find index of last `Some`/non-
      default, encode items 0..=that_index. Write the codegen pseudocode.
    - D4. The "None before Some is forbidden" rule (R4) — encoder check before emit. What's the error
      message? Should this be a `panic!` or a `Result::Err`?
    - D5. Pre-mortem: a header with `base_fee = None, withdrawals_root = Some(...)` — what does
      encoder do, what does decoder do if such bytes were somehow constructed?

  - **Output**: `notes/21_rlp_trailing_design.md` with R1–R8 + D1–D5 + codegen sketch.

  #### Phase 3 — Make the tests pass, one failure at a time (~35 min)

  - **When `decoder_missing_trailing_yields_none` panics with "expected 18 items, got 14":**
    - Symptom: decoder treats trailing fields as mandatory; an RLP list with 14 elements (frontier
      header) fails to decode against a struct with 18 declared fields.
    - Why: codegen produces a decoder that asserts `list.len() == total_field_count` instead of
      `mandatory_count <= list.len() <= total_field_count`.
    - Fix: codegen partitions fields at compile time; decoder generates `let observed_trailings =
      list.len() - mandatory_count;` (with a bound check that `observed_trailings <= trailing_count`),
      then reads mandatory items normally and trailings up to `observed_trailings`, defaulting the rest.
    - Muscle: trailing-aware decoder accepts a length range, not an exact length; the upper bound is the
      total field count, not the mandatory count. Reapplies at: every EIP-evolution-aware codec (W42
      block-import, W67 raft AppendEntries with versioned fields).

  - **When `encoder_rejects_none_before_some` does NOT panic and produces ambiguous bytes:**
    - Symptom: encoder emits a list where `base_fee` slot is `0x80` (RLP empty) and
      `withdrawals_root` slot is a real B256. Decoder reads back `base_fee = None, withdrawals_root =
      None` (because the empty slot is treated as missing-from-end), silently corrupting the data.
    - Why: encoder walked fields linearly emitting each; no check for the "None-before-Some" anti-pattern.
    - Fix: before emitting, walk trailings in declaration order; if you ever see a `Some` after a
      `None`, panic with `"#[rlp(trailing)] field {} is Some but preceding {} is None — unrepresentable
      on wire"`. The panic is fine; this combination should be statically unreachable in correct code.
    - Muscle: wire formats with positional optional fields require a "no holes" invariant; encoder MUST
      panic on holes, not silently corrupt. Reapplies at: W42 block-import header encoding, W64 RPC
      response building (`eth_getBlockByNumber`).

  - **When `compile_fail_trailing_on_non_option_no_default` does NOT fail to compile:**
    - Symptom: `#[rlp(trailing)] foo: NonDefaultType` compiles successfully; the load-bearing
      compile-time guard is missing.
    - Why: derive macro doesn't emit a `where T: Option<_> | T: Default` bound or equivalent check.
    - Fix: in the derive's codegen, for each trailing field, emit:
      `const _: fn() = || { fn assert_impl<T: TrailingCompatible>() {} assert_impl::<#field_type>(); };`
      where `TrailingCompatible` has blanket impls for `Option<T>` and `T: Default`.
    - Muscle: derive macros enforce trait bounds at the call site via codegen'd `const _: fn() = ...`
      helpers; absence of the helper means the bound is aspirational. Reapplies at: every derive macro
      that requires field-level bounds (W4 SimpleEncode, W5 RlpEncodable).

  - **5-year failure mode** (write in `notes/21_rlp_trailing_followup.md` after green): when EIPs start
    using NON-trailing optional fields (e.g. EIP-7610-shape "remove a field in the middle"), the simple
    declaration-order trailing model breaks. Migration: add `#[rlp(version = "n")]` per-field for
    versioned-by-spec decoding. Trigger: any EIP that REMOVES a field from a consensus struct.
