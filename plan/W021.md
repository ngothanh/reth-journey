**Monday — `eth-rlp` extension: trie-friendly encoding**

- [ ] Re-read RLP spec sections relevant to trie nodes. (~45 min)
- [ ] **Build**: `crates/eth-rlp/src/trie.rs` — encode_branch_node, encode_extension_node, encode_leaf_node. (~105 min)
  - **Why**: MPT nodes have three shapes (branch, extension, leaf) each with its own RLP serialization including a 1-byte path-type prefix (the "compact path encoding" or "hex prefix"). Centralizing these encoders in eth-rlp avoids duplication across eth-trie, storage-trie, and downstream provers — and avoids the classic "even/odd nibble parity" bug.
  - **Read first**: alloy `crates/rlp/src/encode.rs` for `BufMut` helpers; alloy `crates/trie/src/nodes/leaf.rs` for compact path encoding; yellow paper appendix C (the four cases: leaf-even, leaf-odd, extension-even, extension-odd).
  - **Design**:
    ```rust
    pub fn encode_compact_path(nibbles: &[u8], is_leaf: bool, out: &mut Vec<u8>) {
        // Prefix byte: high nibble = 2*is_leaf + (len % 2). Low nibble = first nibble iff odd.
        let odd = nibbles.len() % 2 == 1;
        let flag = (if is_leaf { 2 } else { 0 }) | (if odd { 1 } else { 0 });
        if odd {
            out.push((flag << 4) | nibbles[0]);
            out.extend(nibble_pairs(&nibbles[1..]));
        } else {
            out.push(flag << 4);
            out.extend(nibble_pairs(nibbles));
        }
    }
    pub fn encode_leaf_node(path: &[u8], value: &[u8], out: &mut Vec<u8>);
    pub fn encode_extension_node(path: &[u8], child: ChildRef, out: &mut Vec<u8>);
    pub fn encode_branch_node(children: [Option<ChildRef>; 16], value: Option<&[u8]>, out: &mut Vec<u8>);
    ```
    **Invariants**:
    - Compact path prefix flag bit pattern: 0x00 = extension/even, 0x10 = extension/odd, 0x20 = leaf/even, 0x30 = leaf/odd.
    - Branch RLP is a 17-element list (16 children + value slot); absent children encoded as `0x80` (RLP empty string).
    - Extension is 2-element list: [compact_path, child_ref].
    - Leaf is 2-element list: [compact_path, value].
    - `ChildRef` is either inline RLP (encoded < 32 bytes) or 32-byte keccak hash.
  - **Build steps**:
    1. (~20 min) `encode_compact_path` with exhaustive 4-case test.
    2. (~25 min) `encode_leaf_node` — RLP list header + path + value.
    3. (~20 min) `encode_extension_node` — same with child_ref dispatch.
    4. (~25 min) `encode_branch_node` — 17-slot list, embedded child decision.
    5. (~10 min) Round-trip decoders symmetric to each encoder.
    6. (~5 min) Re-export from `eth-trie` so callers don't need both crates.
  - **Pitfalls**:
    - *Even/odd parity off-by-one*: classic. Encoding `[a, b, c]` (3 nibbles, odd) vs `[a, b]` (even) needs distinct prefix bytes. **Symptom**: state root diverges intermittently. **Fix**: property-test every nibble length 1..=64 round-trips.
    - *Embedded child threshold*: revm/reth use `< 32` (strictly less), not `<= 32`. **Symptom**: hashes mismatch on edge-size encodings. **Fix**: hash builder defines the threshold; encode_branch_node accepts pre-decided ChildRef.
    - *RLP list header length encoding*: lists 0-55 bytes use short header; >55 use long. **Symptom**: wrong byte for nodes near boundary. **Fix**: use alloy-rlp's `Header::encode` directly; don't roll your own.
    - *Big-endian nibbles*: nibbles are MSB-first per byte. **Symptom**: high-nibble swap. **Fix**: `(byte >> 4, byte & 0x0F)` ordering test with hex strings.
  - **Test scenarios**:
    - Round-trip each node shape with nibble lengths 0, 1, 2, 31, 32, 33, 64.
    - Property: encode → decode → encode produces byte-identical output.
    - Fixed mainnet vectors from `ethereum/tests` trie tests.
  - **Acceptance**:
    - Pass `TrieTests/trietest` and `TrieTests/trieanyorder`.
    - Inheritance ratio ≥ 0.95 vs alloy `nibbles.rs` + node encoders.
  - **Downstream**: every trie node anywhere in the workspace (eth-trie, storage-trie, mini-db W95) routes through these encoders.

**Tuesday — Reth RLP usage patterns + `eth-rlp` derive enhancements**

- [ ] Read reth's RLP usage patterns + alloy-rlp source freshly. (~60 min)
- [ ] **Extend**: eth-rlp-derive to support `#[rlp(trailing)]`. (~60 min)
  - **Why**: EIP types evolve via *trailing* fields — EIP-1559 added basefee to headers, EIP-4895 added withdrawals, EIP-4844 added blob fields. Old block headers must decode without these fields; new ones must include them. `#[rlp(trailing)]` annotates fields whose absence on decode = `None`/`Default`. Without this attribute, every Header schema change forks the codec.
  - **Read first**: alloy `crates/rlp-derive/src/de.rs` (proc-macro source) and `crates/eips/src/eip4895.rs` (withdrawals struct). Also the `#[rlp(trailing)]` PR in alloy if findable via git log.
  - **Design**:
    ```rust
    #[derive(RlpEncodable, RlpDecodable)]
    pub struct Header {
        pub parent_hash: B256,
        pub ommers_hash: B256,
        // ... 13 mandatory fields ...
        #[rlp(trailing)] pub base_fee_per_gas: Option<u64>,       // EIP-1559
        #[rlp(trailing)] pub withdrawals_root: Option<B256>,      // EIP-4895
        #[rlp(trailing)] pub blob_gas_used: Option<u64>,          // EIP-4844
        #[rlp(trailing)] pub excess_blob_gas: Option<u64>,        // EIP-4844
        #[rlp(trailing)] pub parent_beacon_block_root: Option<B256>, // EIP-4788
    }
    ```
    **Invariants**:
    - Decoder reads N items from RLP list, where N = mandatory_count + observed_trailing_count.
    - Trailing fields decoded *in declaration order*; missing = `None`/`Default::default()`.
    - Encoder skips trailing `None`s from the *end* (but a `Some` followed by `None` requires panicking — disallowed combination).
    - All trailing fields must be `Option<T>` or `T: Default + Eq + PartialEq` types.
  - **Build steps**:
    1. (~10 min) Parse-time: detect `#[rlp(trailing)]` attribute on field; partition fields into (mandatory, trailing) lists.
    2. (~20 min) Generate decoder: open RLP list, decode mandatory, then for each remaining list item match against next trailing field. Reject if mandatory count short.
    3. (~15 min) Generate encoder: encode mandatory; encode trailings in order, but emit nothing past the LAST `Some`. Reject mid-`None`-`Some` (with a panic at encode time).
    4. (~10 min) Tests: decode pre-London header (no basefee), decode Cancun header (all trailings present).
    5. (~5 min) Compile-time error on `#[rlp(trailing)]` for non-Option field with no `Default` impl.
  - **Pitfalls**:
    - *Skip-encoding rule*: encoder must not emit a `None` followed by a `Some` — that would make the RLP ambiguous. **Symptom**: decoder reads `Some` value into wrong field. **Fix**: encoder walks trailings in reverse, finds last `Some`, encodes all up to that index (turning intermediate `None`s into errors — they should be unrepresentable for chain compatibility).
    - *Field order on decoder*: trailing fields are positional. If you reorder Header struct, you break wire compat. **Symptom**: silent corruption. **Fix**: documented stable ordering; test against fixed hex fixtures per fork.
    - *Default vs None semantics*: some types use `T: Default` (e.g. `u64 = 0`), others `Option<T>`. Mixing is error-prone. **Symptom**: confused decoder. **Fix**: convention — always `Option<T>` for true "field may not exist"; `T: Default` only for cosmetic fields.
  - **Test scenarios**:
    - Frontier header (no trailings) → round-trip through Cancun-aware struct.
    - Cancun header (all trailings) → round-trip identically.
    - Adversarial: a header with `base_fee = None, withdrawals_root = Some(...)` — encoder rejects with compile-time-safe assert.
    - Mainnet block 12,965,000 (London activation): first block with basefee.
  - **Acceptance**:
    - Pass alloy's `header_rlp_roundtrip` test suite (steal/port fixtures).
    - Decode every block header from genesis through current at 1k-block sample without panic.
  - **Downstream**: every block-related codec in the workspace consumes this; W42+ block-import path; W64 RPC eth_getBlockByNumber response building.
