This is a career/interview week, not a Build week. There is no crate, no upstream mirror, and no engineered trap-test arc — manufacturing one would be padding. Every item below instead carries an explicit artifact file + an Output line that proves it done, and the per-screen post-mortems carry a hardened-acceptance pass criterion and a mental model of why the item exists now. The week's job: run four first-round phone screens without burning out the day-job, and turn each one into a structured post-mortem so W127-W129 prep is targeted at your *measured* weak spots, not a guess. The discipline this week is the post-mortem template, not the coding — a screen you don't extract a lesson from is a wasted screen.

The post-mortem artifact is one append-only file, `notes/interview_log_w126.md`, with one section per firm. Each section uses a fixed template so the Saturday cross-firm analysis can pattern-match across them:
```
## Firm N — <firm name> — <date> — <role/team>
- Format: <coding / system-design / behavioral / mixed>, <platform: CoderPad/HackerRank/phone>
- Questions asked: <verbatim or close paraphrase, one per line>
- Where I stalled: <the exact moment — "blanked on heap-vs-BST tradeoff", "couldn't articulate MESI">
- What went well: <concrete, not "felt good">
- Outcome signal: <advanced / pending / rejected / unclear> + interviewer's stated next step
- Targeted fix → feeds W127-W129: <the ONE drill this screen tells me to do>
```
