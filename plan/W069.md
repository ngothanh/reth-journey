(~total 250 min across 3 phases; Phase 1 ~150 min today, Phase 2/3 Tuesday)
  - 🔧 **Why this matters**: liquidation is where a perpetuals exchange either survives or dies. When a leveraged position's mark-to-market loss eats its margin, the exchange must close it *before* the position goes net-negative (bankrupt) — otherwise the loss is socialized and the venue is insolvent. This mirrors dYdX V4's `liquidations.go` and Binance/Bybit's maintenance-margin liquidation, built on W66's integer-deterministic `LinearContract`/`Position`. Four traps land below: (1) any `f64` in the bankruptcy-price or margin-ratio math makes two raft replicas diverge → `matching-engine` v1.0 (W74) fails its determinism gate; (2) triggering on **last-trade price** instead of **mark price** lets an attacker self-trade a thin book to liquidate victims (the exact LUNA/lower-tier-venue collapse vector); (3) computing the bankruptcy price with the wrong sign for a SHORT position liquidates it at a profit-to-the-trader price, draining the exchange; (4) a per-liquidation heap allocation (e.g. `Vec<CloseOrder>` per call) blows the ≤500 ns liquidation-check budget during a cascade of thousands/sec. **State plainly: your first attempt WILL fail ≥1 test below — the debug session is the lesson.** Downstream: W71 ADL queue consumes the `BankruptPosition` event this Build emits when the close-out can't fill above bankruptcy; W74 raft-replicates this exact state machine; W83+ ledger reuses the bankruptcy-loss double-entry; W88 VOPR replays cascades.

  - *Mental model*: the `LiquidationEngine` is the per-symbol risk guard that runs on every mark-price update
    and every fill: for each open position it asks "does equity still cover maintenance margin at the current
    *mark* price?" If not, it computes the **bankruptcy price** (equity = 0) and the **liquidation price**
    (maintenance margin = 0, slightly better for the trader), then emits a forced close-out order. The gap
    between fill price and bankruptcy price is the loss the **insurance fund** (Thursday's Build) absorbs; if
    the fund is depleted, the loss escalates to ADL (W71). Because two raft replicas must apply the same
    mark-update sequence to byte-identical state, **every arithmetic op is integer with an explicit
    denominator** — float is presentation-layer-only.

  - *Contract* (signatures only — never the body):
    ```rust
    // inherits SignedFrac { num: i128, denom: i128 }, LinearContract, Position from W66 contract.rs
    pub struct LiquidationEngine<'c> { contract: &'c LinearContract }
    pub enum LiquidationOutcome {
        Healthy,                                   // equity ≥ maintenance at mark
        Liquidate(CloseOrder),                     // forced close-out routed back through the book
        Bankrupt(BankruptPosition),                // close-out cannot fill ≥ bankruptcy price → escalate
    }
    pub struct CloseOrder { account: AccountId, symbol: Symbol, size: i64, limit_price: i64 } // size = -position.size
    pub struct BankruptPosition { account: AccountId, symbol: Symbol, size: i64, bankruptcy_price: i64, loss: i128 }
    impl<'c> LiquidationEngine<'c> {
        fn equity(&self, pos: &Position, mark: i64) -> i128;          // margin + unrealized_pnl(mark)
        fn maintenance_margin(&self, pos: &Position, mark: i64) -> i128; // notional × mmr (W66 margin.rs)
        fn bankruptcy_price(&self, pos: &Position) -> i64;            // price where equity == 0; sign-correct per side
        fn liquidation_price(&self, pos: &Position) -> i64;           // price where equity == maintenance margin
        fn check(&self, pos: &Position, mark: i64) -> LiquidationOutcome;  // the hot path, ≤500 ns, 0 allocs
        // book-aware variant: simulates the close-out fill against the book to compute the residual/loss on
        // escalation. `check` is the allocation-free trigger; `check_against` is called only on the rare
        // already-underwater branch where a `Bankrupt` deficit must be quantified against resting liquidity.
        fn check_against(&self, pos: &Position, mark: i64, book: &OrderBook) -> LiquidationOutcome;
    }
    ```

  - *Back-of-envelope* (bar (c) — HFT critical path): the liquidation check runs on **every mark-price tick
    for every open position in the symbol**. At 1000 open positions/symbol and a mark update every ~1 ms
    under volatility, that is ~1 M checks/sec/symbol; during a cascade (sharp move) the mark re-ticks and
    every position is re-checked — call it a **5 M checks/sec** burst. Budget per check ≤ **500 ns** so the
    whole-book sweep stays under ~500 µs/tick. One `check()` = unrealized-PnL (one `i64` mul + one sub on a
    warm `Position` line, ~2 ns) + maintenance compare (~1 ns) + a branch — target **~5-10 ns** warm, all
    integer. The cliffs: (1) `f64::div`/`f64::mul` in the PnL or ratio math = 10-30 cycles ≈ 3-10 ns *each*
    PLUS the cross-arch determinism violation (the real cost — a divergent replica is not "slow", it is
    **wrong**); (2) a `Vec`/`Box` allocation per check during a cascade = ~50 ns malloc × 5 M/sec = **250
    ms/sec of pure allocator**, i.e. a 25% CPU tax that arrives exactly when the system is already stressed
    (back-pressure as correctness); (3) reading `last_trade_price` from a `HashMap<Symbol,_>` instead of the
    warm `LinearContract.mark_price` field = a random L2/L3 fetch ≈ 7-70 ns vs ~0.5 ns L1 = **~10-100× cliff**
    on the hottest path in the system. The naive "just close it at last trade" reach is both slow AND a
    manipulation hole.

  - **Requirements** R1..R9 — write in `crates/matching-engine/notes/69_liquidation_design.md`:
    - R1. `check(&self, pos, mark) -> LiquidationOutcome` is the only public entry; **0 heap allocations**,
      `#[inline]`, no `f32`/`f64` reachable.
    - R2. **Mark-price trigger, not last-trade**: liquidation triggers on `equity(pos, mark) <
      maintenance_margin(pos, mark)` where `mark` is the clamped `LinearContract.mark_price` (W66 R4), NEVER
      the last-trade price. A self-traded thin book must NOT trigger liquidation.
    - R3. **Bankruptcy price, sign-correct per side**: the price `bp` where `equity == 0`. For a LONG
      (`size > 0`): `bp = entry - margin/size` (price falls until margin is gone). For a SHORT (`size < 0`):
      `bp = entry + margin/|size|` (price rises until margin is gone). A single unsigned formula gets ONE
      side wrong — derive both and prove the sign.
    - R4. **Liquidation price ≠ bankruptcy price**: the position is force-closed at the *liquidation* price
      (equity == maintenance margin, slightly inside bankruptcy) so the close-out has a maintenance-margin
      buffer. `liquidation_price` is strictly between the current mark and `bankruptcy_price`.
    - R5. **Close-out direction**: `CloseOrder.size = -pos.size` (a long closes by selling, a short by
      buying), `limit_price = bankruptcy_price` (the worst price the engine accepts before escalating).
    - R6. **Bankruptcy escalation**: if the close-out cannot fill at ≥ `bankruptcy_price` (LONG) / ≤
      `bankruptcy_price` (SHORT), emit `Bankrupt(BankruptPosition { loss })` where `loss > 0` is the deficit
      the insurance fund (Thursday) must cover. `loss` is `i128` integer.
    - R7. **All-integer math**: every price/margin/PnL value is `i64`/`i128`; every ratio is `SignedFrac`
      (W66 R3 float ban extends to this module). A `clippy`/lint check forbids float in `perps/`.
    - R8. **Per-check budget**: `check()` ≤ 500 ns p99 warm (target ~5-10 ns); 0 allocations measured by a
      counting allocator in the bench.
    - R9. **Determinism gate**: 10_000 random (mark-tick, position) pairs replayed on two builds (`x86_64`
      vs `aarch64`, different `-C target-cpu`) produce byte-identical `LiquidationOutcome` streams.

        let c = LinearContract::test_with(100_000);
        let eng = LiquidationEngine::new(&c);
        // Case A — fully empty book below bankruptcy: residual == full position, best fill == 98_000.
        // bankruptcy_price for this long works out to 99_500 (R3); only resting liquidity is at 98_000.
        let long = Position::long(100).entry(100_000).margin(50_000);
        let book = OrderBook::test_with_resting_bid(/*price=*/98_000, /*qty=*/0); // nothing fills ≥ bankruptcy
        let mark = 99_400; // already past liquidation
