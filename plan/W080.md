  TestRequest (35=1), ResendRequest (35=2), SequenceReset (35=4), Logout (35=5). (~total 4 hrs across 3 phases)
  - 🔧 **Why this matters**: FIX 4.4 is institutional lingua franca; every Tier-A exchange speaks it. Sequence-number-based reliability + paired session ordering are subtle. Knight Capital 2012 root-caused to FIX sequence-state inconsistency. Downstream: W82 v1.5 SHIP; W84+ FIX 5.0 SP2 enrichment.

  #### Phase 1 — Problem, requirements, design (~70 min, no code yet)

  - **The problem this primitive solves**: lossless ordered delivery over TCP with sequence-based gap recovery. Persist seq across restarts. Heartbeat liveness. Pair-session ordering on simultaneous resends.

  - **Requirements** — write in `crates/matching-engine/notes/80_fix_session_design.md`:
    - R1. `MsgSeqNum` strictly monotonic per direction.
    - R2. Lost gap → ResendRequest, NOT silent drop.
    - R3. Re-sent messages carry `PossDupFlag=Y`.
    - R4. Admin messages (Heartbeat, TestRequest) NOT re-sent — replaced by `SequenceReset(GapFillFlag=Y)`.
    - R5. Session state persists across restarts — sequence numbers durable.
    - R6. 100k msg/s session throughput, P99 parse+dispatch <2 µs.
    - R7. Group commit on seq durability: amortize fsync over batches of 64 messages.
    - R8. Pre-allocated buffer encode (NO `format!`/`String::push_str`) — hand-written encoder + `itoa`.
    - R9. Logout flush: stop new sends, drain outbound, send Logout, await ack, close TCP.

  - **Design walk-through**:
    - D1. Sketch FixSession + state enum.
    - D2. **Pre-mortem (wal::append + fsync per send):** fsync ~100 µs NVMe → throughput caps at 10k msg/s; iostat shows fsync dominating. Walk through group commit (10 ms window OR 64 messages).
    - D3. **Pre-mortem (format! in encoder):** `format!("8=FIX.4.4\u{01}9={}\u{01}35={}\u{01}..", ...)` allocates String per call (~330 ns) + uses full Display machinery (~50 ns/int). At 100k msg/s = 33 ms/sec. Walk through hand-written encoder + itoa.
    - D4. **Pre-mortem (sequence-number gap recovery):** unbounded ResendRequest can flood. Cap recipient gap-fills admins, replays app messages; cap retransmits.
    - D5. **Pre-mortem (Knight Capital pattern):** Logon(reset_seq=true) silently resets seq_out=1 — only if both sides agree (Tag 141 in both directions). Asymmetric reset = catastrophe. Server validates Tag 141; rejects asymmetric.
    - D6. **Pre-mortem (durability of seq_out):** app crash between sending msg and persisting seq_out → restart sends with same seq → peer rejects. Persist seq_out BEFORE sending via wal::Sequencer.

  - **Output**: `notes/80_fix_session_design.md` with R1–R9 + D1–D6.

  #### Phase 3 — Make the tests pass, one failure at a time (~130 min)

  - **When `fix_throughput_100k_msg_per_sec` reports 8k msg/s with fsync per send:**
    - Symptom: throughput caps at 10k msg/s; iostat shows fsync dominating; multiple parallel sessions DON'T help (fsync serializes at disk).
    - Why: `wal.append(seq).then(wal.fsync())` per message — fsync ~100 µs on NVMe with write-back-cache disabled. 100k × 100 µs = 100% CPU on fsync.
    - Fix: group commit — collect outbound into batch (10 ms window OR 64 messages); single wal append + single fsync covers batch. Each message's ack waits for group commit. Latency P99 ~10 ms acceptable for FIX (institutional traders expect ms-grade). Alternative: io_uring `IORING_FSYNC` with `IOSQE_IO_LINK` chains fsyncs.
    - Cost avoided: ~100 µs/msg → ~1 µs/msg amortized = ~100× throughput improvement.
    - Muscle: durability syscalls amortize over BATCHES, never per-element — W26 WAL group-commit principle. Reapplies at: W80 ledger journal commit, W83 archive recorder fsync policy, W89 ledger v1.0 io_uring fsync batching, W92 ledger v1.0 SHIP.

  - **When `fix_encoder_no_alloc` reports 330 ns/msg allocator overhead:**
    - Symptom: perf flame graph shows `core::fmt::write` and `__libc_malloc` dominating outbound; throughput caps at 30k msg/s.
    - Why: `let msg = format!("8=FIX.4.4\u{01}9={}\u{01}35={}\u{01}..", body_len, msg_type, ...)` allocates String per call (~330 ns); `format!` for integer-to-ASCII uses full Display machinery (~50 ns vs `itoa` ~5 ns).
    - Fix: encode directly into `bufpool::PooledBuf` via hand-written encoder: `buf.write_tag(8); buf.write_value(b"FIX.4.4"); buf.write_soh();`. Use `itoa::Buffer` (~5 ns/integer) for numeric. Buffer recycled after sending.
    - Cost avoided: ~330 ns/msg × 100k msg/s = ~33 ms/sec; 6× throughput improvement.
    - Muscle: FIX/text-wire encoders are bar-(c) hot paths — `format!` is forbidden; pre-allocated buffer + hand-coded field writers are mandatory. Reapplies at: W80 ledger JSON-rpc encoder, W82 v1.5 SHIP audit (no format! in matching), W84 archive metadata encoder.

  - **When `fix_asymmetric_logon_reset_rejected` reports silent acceptance:**
    - Symptom: server received Logon with reset_seq=true; server didn't check Tag 141 in its own outgoing Logon; accepted silently → seq state inconsistency.
    - Why: server validates only inbound Tag 141; doesn't enforce its own outgoing must match.
    - Fix: server validates Tag 141 in BOTH directions during Logon handshake; rejects + logs alert if asymmetric. Knight Capital 2012 pattern.
    - Muscle: every "destructive operation" needs explicit bi-directional handshake confirmation. Reapplies at: W75 view-change quorum confirmation, W76 state-transfer correlation id, W83 archive cycle rotation.

  - **5-year failure mode** (write in `notes/80_fix_session_followup.md`): when binary FIX (Simple Binary Encoding, SBE) replaces tag=value, the encoder's hand-written tag dispatch becomes wrong abstraction. Migration: SBE schema-driven encoder with same buffer-pool discipline.

- [ ] [NEW v2 aeron v0.7] **Build**: `crates/messaging-aeron/src/multicast.rs` — UDP multicast publisher: IGMP join,
  TTL, source filter. (~total 3 hrs across 3 phases)
  - 🔧 **Why this matters**: Multicast is throughput multiplier — publisher 1 packet, network duplicates to N subs. CME, NYSE, Nasdaq all use multicast. Downstream: W81 SSM filter enrichment; W82 Image multi-source loss detector.

  #### Phase 1 — Problem, requirements, design (~50 min, no code yet)

  - **The problem**: 1000 subs × 1M pps unicast = 1B pps (saturates 10 GbE). Multicast: 1M pps emitted; switch duplicates to each subscriber on egress.

  - **Requirements** — write in `crates/messaging-aeron/notes/80_multicast_design.md`:
    - R1. Multicast addresses in 224.0.0.0/4; avoid 224.0.0.0/24 (link-local); use 239.0.0.0/8 (admin-scoped).
    - R2. TTL bounds geographic reach: 1=LAN, 32=site, 64=region.
    - R3. `set_multicast_loop_v4(false)` on publisher — don't receive own packets.
    - R4. Subscriber must `IP_ADD_MEMBERSHIP` on correct interface; multi-NIC chooses explicitly.
    - R5. 1 pub + 10 subs → throughput identical to 1 pub + 1 sub (publisher cost N-independent).
    - R6. P99 latency LAN <50 µs.
    - R7. Cloud env compatibility documented (AWS/GCP/Azure IGMP varies).

  - **Design walk-through**:
    - D1. Sketch MulticastPublication + MulticastSubscription structs.
    - D2. **Pre-mortem (default `set_multicast_loop_v4(true)`):** publisher receives own packets via loopback; at 1M pps that's 1M extra packets/sec into recv queue = 100% CPU on useless self-copy. Walk through `set_multicast_loop_v4(false)` audit.
    - D3. **Pre-mortem (IGMP cloud-env):** deploy to AWS → IGMP not supported by default; multicast doesn't work silently. Document fallback to unicast.
    - D4. **Pre-mortem (multi-NIC interface ambiguity):** host has eth0 (frontend) + eth1 (mcast backbone); IGMP joins on eth0 by default → no traffic. Explicit `setsockopt(IP_MULTICAST_IF, eth1.addr)`.
    - D5. **Pre-mortem (TTL too low):** TTL=1, packet doesn't cross router → 0 subs on other VLAN.
    - D6. **Pre-mortem (route-table interaction):** multicast packet drops because routing table has no route for group. Explicit `ip route add` or rely on `IP_MULTICAST_IF` (bypasses routing).

  - **Output**: `notes/80_multicast_design.md` with R1–R7 + D1–D6.

  #### Phase 3 — Make the tests pass, one failure at a time (~100 min)

  - **When `multicast_set_multicast_loop_false_audit` reports publisher CPU saturated:**
    - Symptom: publisher CPU saturates at 1M pps despite emitting only 1M packets; netstat -su InDgrams matches OutDgrams; bench publisher unable to scale past 800k pps.

## Saturday — Reth PR + ledger: state machine framework

- [ ] Reth PR. (~150 min)
- [ ] **Build**: `crates/ledger-deterministic/src/state_machine.rs` —
  `StateMachine { accounts: BTreeMap<u128, Account>, ... }`. `apply(op: Op) -> Result<OpResult>` is deterministic: no
  `time::wall()`, no `rand`, no f64. Only `time::Monotonic` is allowed and only for instrumentation, never for logic. (~total 3.5 hrs across 3 phases)
  - 🔧 **Why this matters**: bar-(c) ledger's load-bearing axiom. Every later layer (VOPR W87-88, static-mem W89, io_uring W89, VSR W91-92) ASSUMES `apply(op_stream)` yields bit-reproducible state across runs, machines, and architectures. One float, one syscall, one allocator-dependent iteration order = determinism collapse = entire v1.0 deliverable lost.

  #### Phase 1 — Problem, requirements, design (~60 min, no code yet)

  - **The problem**: deterministic apply is non-negotiable for VOPR/replication. Three subtle leaks: floats, HashMap iteration, wall-clock tracing. Each breaks determinism silently.

  - **Requirements** — write in `crates/ledger-deterministic/notes/80_state_machine_design.md`:
    - R1. `apply(op)` is **total** (no panics, no allocs in hot path), deterministic.
    - R2. NO `time::wall()`, NO `rand`, NO f64. Only `time::Monotonic` and only for instrumentation.
    - R3. State hash canonical (order-independent for accounts, journal_seq included).
    - R4. P99 apply <10 µs (v0.5), <3 µs (v0.7), <1 µs (v1.0).
    - R5. Ops use only `repr(C)` types with no heap inner storage; if collections needed, `ArrayVec`.
    - R6. Tracing spans `cfg(not(determinism))`-gated; only `SeqClock` (op-counter-driven) reaches state.
    - R7. CI lint: `disallowed-types` for `HashMap`, `std::time::SystemTime`, `rand`, `f32`/`f64`.
    - R8. Op dispatch via match sorted by frequency (Transfer 90% first); discriminant at offset 0.

  - **Design walk-through**:
    - D1. Sketch StateMachine + LedgerSM with FixedMap.
    - D2. **Pre-mortem (HashMap iteration leak):** `state_hash()` iterates `accounts.values()` via HashMap (insertion-order-randomized) → two machines produce different hashes. Use BTreeMap or FixedMap with stable iter.
    - D3. **Pre-mortem (allocator-dependent op order):** Op carries `Vec<Item>` whose construction allocator order affects internal layout → cross-machine divergence even if state_hash sorted. Use ArrayVec.
    - D4. **Pre-mortem (wall-clock leak via tracing):** `tracing::info!("apply at {}", Instant::now())` works in dev but generates different timestamp each run; if timestamp enters state (Account's last_update), determinism breaks.
    - D5. **Pre-mortem (f64 in fee):** `let fee = balance as f64 * 0.0025;` introduces IEEE-754 non-determinism. Use bps integer math.
    - D6. **Pre-mortem (enum dispatch mispredict):** workload 90% Transfer, 9% Lookup, 1% CreateAccount; if match arms are random-ordered, branch predictor wastes ~5 ns/mispredict. Sort match arms by frequency.

  - **Output**: `notes/80_state_machine_design.md` with R1–R8 + D1–D6.

  #### Phase 3 — Make the tests pass, one failure at a time (~90 min)

  - **When `state_machine_no_floats_lint` reports f64 in fee calc:**
    - Symptom: cargo-deny fires; 3-machine VOPR test (W87) discovers 1-tick discrepancy in <0.01% of scenarios; debugger struggles because divergence is in LSB of f64.
    - Why: `let fee = balance as f64 * 0.0025;` — IEEE-754 division/multiplication non-deterministic across arches; x86 default rounding vs aarch64; aarch64 fma vs x86 separate mul+add.
    - Fix: integer math throughout — represent percentages as `fee_bps: u32`, compute `fee = (balance * fee_bps as u64) / 10_000`. For ratios, `q64.64` fixed-point. Compile-time lint: `clippy::float_arithmetic` denied.
    - Cost avoided: ~30 ms/sec float compute (separately) + cross-machine determinism preserved (the catastrophic case).
    - Muscle: deterministic state machine = integer math only. Reapplies at: W81 circuit breaker bps math, W82 v1.5 SHIP audit, W87 VOPR cross-machine reproducibility, W92 ledger v1.0 SHIP.

  - **When `state_machine_op_dispatch_branch_predictor_friendly` reports BR_MISP elevated:**
    - Symptom: bench shows wildly varying throughput depending on op-type mix; `perf stat` shows BR_MISP elevated on apply hot path; under adversarial mix (alternating types), 50% mispredict = ~2.5 ms/sec.
    - Why: naive `match` compiles to jump table, but CPU's branch predictor learns discriminant pattern poorly if streams interleave; each mispredict ~5 ns.
    - Fix: (a) sort match arms by frequency (Transfer first); CPU's static predictor assumes "first arm taken". (b) `Op` struct `repr(u8)` with discriminant at offset 0 (one cache line for tag). (c) For extreme cases, separate `apply_transfer/apply_lookup/apply_create_account` and dispatch via function-pointer table.
    - Cost avoided: ~5 ns × 100k mispredicts/s = ~500 µs/sec; under adversarial mix, ~2.5 ms/sec.
    - Muscle: enum dispatch in hot loop must order arms by observed frequency; type-pun structs put discriminant at offset 0. Reapplies at: W74 MatchCommand dispatch, W77 NAK message-type dispatch, W82 Image frame-type dispatch, W87 VOPR scenario action dispatch.

  - **When `state_machine_state_hash_canonical_iteration` reports HashMap usage:**
    - Symptom: state_hash uses HashMap iteration; two machines produce different hashes.
    - Why: HashMap iteration order depends on insertion order + hash seed; non-deterministic per-run.
    - Fix: BTreeMap (sorted iteration) or FixedMap with stable iter. Cargo-deny `disallowed-types = ["HashMap", "AHashMap", "FxHashMap"]` for module.
    - Muscle: deterministic state machine never iterates hash-based collections; lookups are by-key. Reapplies at: W75 STP determinism, W82 v1.5 SHIP, W87 VOPR cross-machine.

  - **5-year failure mode** (write in `notes/80_state_machine_followup.md`): when WASM-compiled SM becomes the deployment target, determinism gets enforced by WASM spec (no floats, no syscalls). Migration: SM trait abstraction; native Rust + WASM impl share same trait.
