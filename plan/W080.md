- [ ] [NEW v2 aeron v0.7] **Build**: `crates/messaging-aeron/src/multicast.rs` — UDP multicast publisher:
  IGMP join, TTL, source filter. (~total 3 hrs across 3 phases)
  - 🔧 **Why this matters**: mirror Aeron `UdpChannel` multicast mode. Multicast is the throughput multiplier —
    publisher emits 1 packet, the switch duplicates to N subscribers at egress, so publisher cost is
    **independent of N**. CME, NYSE, Nasdaq market-data feeds are all multicast. The 2-4 traps:
    (1) default `IP_MULTICAST_LOOP=true` floods the publisher's own recv queue at line rate; (2) per-sub
    iteration in the offer path silently recreates unicast (loses the whole point); (3) multi-NIC hosts join
    IGMP on the wrong interface and receive nothing; (4) cloud IGMP support varies and fails silently.
    First-attempt impls fail ≥1 test below; that debug session is the lesson. Downstream: W81 SSM source-filter

  - *Contract*: `MulticastPublication::new(group: Ipv4Addr, port: u16, iface: Ipv4Addr, ttl: u8) -> io::Result<Self>`;

  #### Phase 3 — Make the tests pass, one failure at a time (~100 min)
  Newbie failures first, expert last.
  - **(SENIOR) When `multicast_set_multicast_loop_false_audit` reports publisher CPU saturated / `IP_MULTICAST_LOOP=1`:**
    - Symptom: assertion fires (loop=1); under load, publisher CPU pegs at 1 core at ~800k pps despite emitting
      1M; `netstat -su` shows `InDgrams ≈ OutDgrams` on the publisher socket.
    - Why: default `IP_MULTICAST_LOOP=true` delivers a copy of every sent datagram back to the publisher's own
      recv queue; the recv softirq allocates an sk_buff (~1 KB kernel alloc) per looped packet.
    - Fix: `socket.set_multicast_loop_v4(false)` at construction; verify via `getsockopt`. For self-receive tests,
      use a separate subscription socket.
    - Cost avoided: ~1M packet copies/s + ~1 GB/s allocator churn + ~1 full core — restores N-independent emit
      rate **(bar (c) violation)**.
    - Muscle: every default socket option is a potential bar-(c) violation — audit `getsockopt` for
      `IP_MULTICAST_LOOP`, `SO_REUSEADDR`, `TCP_NODELAY`, `IP_TOS` at startup. Reapplies at: W81 SSM option audit,
      W82 Image socket-option audit, W85+ AF_XDP socket options.
  - **(EXPERT) When `multicast_1_pub_10_subs_throughput_unchanged` reports ~1/10th rate at 10 subs:**
    - Symptom: 1-sub offer-rate ~1M pps, 10-sub ~100k pps; assertion fires on the >5% delta.
    - Why: the offer path iterates `for sub in subs { send_to(sub.addr, frame) }` — publisher cost is O(N); the
      multicast benefit is gone.
    - Fix: single `send_to(group_addr, frame)` per event; the switch/NIC fans out at egress. The offer path never
      sees the subscriber set.
    - Cost avoided: O(N)→O(1) publisher cost; at N=1000 that is the difference between line rate and a 1000×
      throughput collapse **(bar (c) violation)**.
    - Muscle: multicast's value is publisher cost INDEPENDENT of N; if the publisher enumerates subscribers you've
      recreated unicast. Reapplies at: W82 Image multi-sub publishing, W90 marketdata fan-out.
  - **(SENIOR) When `multicast_multi_nic_explicit_interface_select` reports 0 frames:**
    - Symptom: subscriber joins, publisher sends, recv times out with 0 datagrams on a multi-NIC host.
    - Why: `IP_ADD_MEMBERSHIP` with `imr_interface = INADDR_ANY` lets the kernel pick the default-route iface
      (eth0/frontend); the mcast traffic is on eth1/backbone.
    - Fix: set `imr_interface` to eth1's address explicitly (and `IP_MULTICAST_IF` on the publisher side).
    - Cost avoided: silent total signal loss in production (worse than slow) — a config-correctness failure, not
      a perf one.
    - Muscle: on multi-homed hosts, the interface for join/send is never "default" — bind it explicitly.
      Reapplies at: W81 SSM join interface, W82 Image endpoint binding, W90 marketdata NIC pinning.
  - **(perf, bar (c)) When `multicast_p99_loopback_in_band` reports P99 > 20 µs under publisher load:**
    - Symptom: loopback round-trip P99 inflates past 20 µs once the bench drives the publisher at load; with the
      `IP_MULTICAST_LOOP` regression present, `netstat -su` again shows `InDgrams ≈ OutDgrams`.
    - Why: the self-flood recv-path (sk_buff alloc + softirq per looped packet) contends with the measured
      round-trip, OR an extra per-packet heap alloc in the offer path adds ~50 ns × queue depth of latency.
    - Fix: confirm `set_multicast_loop_v4(false)` (the D2 fix) AND that `offer` does exactly one `send_to` into a
      pre-pinned buffer with zero per-call alloc.
    - Cost avoided: ~5-15 µs of added tail latency per round-trip under load — the difference between an in-band
      feed and a missed market-data SLA **(bar (c) violation)**.
    - Muscle: a latency gate needs a LOWER bound too — a no-op that "passes" a ceiling is the most dangerous
      green. Bound both ends. Reapplies at: W82 Image latency band, W90 marketdata round-trip gate.
  - **5-year failure mode** — write in `notes/80_multicast_followup.md`: when cloud-native multicast
    (AWS Transit Gateway multicast, EVPN-MX) becomes universal, the IGMPv2 fallback complexity vanishes.
    Trigger: > 50% of subscribers are cloud-hosted and IGMP-capable. Migration: deprecate ASM; SSM-only path.
