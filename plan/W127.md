This is a light-by-design week: three live technical rounds with recovery days between. There is no Build exercise — do NOT manufacture one. The deliverable is a disciplined per-firm debrief loop so that by W130 you can compare offers on evidence, not vibes, and so each round's stumble feeds the next round's prep. Every item below names its artifact file and a pass criterion.

**Monday — Technical round: firm 1 (coding + systems design)**

- [ ] Pre-round warm-up: re-read your own `notes/interview_prep/firm1_brief.md` (role, stack, interviewer names, the one question you will ask them). (~30 min)
  - 🎯 Hardened acceptance: brief names the firm's primary language, the team's domain (matching/marketdata/consensus/exec), and ≥1 question that proves you read their eng blog or open-source — not a generic "what's the culture like."
  - *Mental model*: HFT/infra interviewers screen for signal density; walking in with their domain vocabulary loaded (e.g. "you do thread-per-core for the gateway, right?") converts the first 5 minutes from a cold start into a peer conversation. The 119 prior weeks gave you the vocabulary — this 30 min loads it into working memory.
  - Output: `notes/interview_prep/firm1_brief.md` updated with a top-of-file `READY:` line listing the role, domain, and your one question.
- [ ] 90-120 min live technical round: coding + systems design. (~120 min)
  - 🎯 Hardened acceptance: during the round, narrate your back-of-envelope (Jeff-Dean numbers) on at least one design question and name at least one trap you'd write a test for — the same muscle from every Build week. Treat "I don't know" + a correct first-principles derivation as a pass, a confident wrong number as a fail.
  - *Mental model*: the system-design loop rewards the exact habit the plan drilled — state the latency budget, enumerate primitives with a property table, name the failure interleaving. You are not performing; you are doing W004 Phase-1 out loud.
  - Output: round happened; raw scratch in `notes/interview_prep/firm1_round.md` (questions asked, your answers, where you stalled) written within 60 min of finishing while memory is fresh.
- [ ] Same-day debrief: convert raw scratch into a scorecard. (~30 min)
  - 🎯 Hardened acceptance: `notes/interview_prep/firm1_debrief.md` has three sections — {what I nailed, what I stumbled on (each tagged `[reprep]` if it recurs at firm 2/3), one thing I learned about the firm} — and a 1-10 mutual-fit score with a one-line reason. No section may be empty.
  - *Mental model*: memory of an interview decays within hours; an unwritten debrief is a lost data point you cannot recover at W130 offer-comparison time. The `[reprep]` tags are the feed-forward: they become Tuesday's targeted study list so firm 2 doesn't re-trip the same wire.
  - Output: `notes/interview_prep/firm1_debrief.md` with all three sections + fit score; `grep -c '\[reprep\]' notes/interview_prep/firm1_debrief.md` ≥ 0 (count is the Tuesday backlog).
- [ ] Commit notes. (~10 min)
  - Output: `git log -1 --oneline` shows the firm-1 debrief commit.

**Tuesday — Recover + targeted re-prep**

- [ ] Recover deliberately: light 4-hour day-job day, no interview prep before noon — protect cognition for Wednesday. (~30 min logged)
  - 🎯 Hardened acceptance: a one-line `recovery_log` entry confirming the morning was off-prep; back-to-back hard rounds with no recovery is the documented way candidates degrade by firm 3.
  - *Mental model*: interview performance is a depletable resource like the hot path's cache — running three rounds with zero recovery is the human equivalent of thrashing L1. The recovery day is back-pressure as correctness applied to yourself.
  - Output: `notes/interview_prep/recovery_log.md` has a dated Tuesday entry.
- [ ] Targeted re-prep from firm-1 `[reprep]` tags only (no broad re-study). (~60 min)
  - 🎯 Hardened acceptance: for every `[reprep]` item from Monday, write a 3-5 line "if asked again, here's the crisp answer" card; if a `[reprep]` was a knowledge gap (not a nerves gap), the card cites the exact spec section or a Build week where you already solved it.
  - *Mental model*: the highest-ROI study before firm 2 is the delta you just measured, not a generic re-read. This is the debug loop — Monday produced the failing tests (stumbles); Tuesday makes exactly those pass.
  - Output: `notes/interview_prep/reprep_cards.md` has one card per Monday `[reprep]` tag.
- [ ] Commit notes. (~10 min)
  - Output: `git log -1 --oneline` shows the Tuesday re-prep commit.

**Wednesday — Technical round: firm 2**

- [ ] Pre-round warm-up: re-read `notes/interview_prep/firm2_brief.md` + the `reprep_cards.md` from Tuesday. (~30 min)
  - 🎯 Hardened acceptance: brief carries firm 2's domain + your one informed question; you can recite the reprep cards from memory before opening them.

  - Output: `notes/interview_prep/firm2_debrief.md` with three sections + fit score; carries new `[reprep]` tags for firm 3.

  - Output: `git log -1 --oneline` shows the firm-2 debrief commit.
