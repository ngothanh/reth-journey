**Monday — Missing arithmetic: SDIV, SMOD, ADDMOD, MULMOD, EXP, SIGNEXTEND**

- [ ] Implement. Unit tests against revm for edge cases. (~120 min)
  - **Why**: Signed-division and modular-exponentiation opcodes are where ~60% of historical EVM consensus bugs live. SDIV by zero, SMOD edge cases at INT_MIN, MULMOD with mod=0, EXP gas formula (EIP-160), SIGNEXTEND with byte index ≥ 31 — each has a published CVE somewhere in EVM history. Master the edge cases or fork mainnet.
  - **Read first**:
    - `revm/crates/interpreter/src/instructions/arithmetic.rs` — see `sdiv`, `smod`, `addmod`, `mulmod`, `exp`, `signextend`
    - `revm/crates/interpreter/src/gas/calc.rs::exp_cost` — gas = 10 + 50 * bytes(exp); EIP-160 changed coefficient
    - Yellow Paper §9.4 (signed arithmetic), §9.1 (EXP gas formula)
  - **Design**:
    ```rust
    fn sdiv<H>(interp: &mut Interpreter, _host: &mut H) {
        gas!(interp, gas::LOW);                            // 5 gas
        pop_top!(interp, op1, op2);
        // U256 → I256 sign reinterpret
        let result = i256_div(I256::from(op1), I256::from(*op2));
        *op2 = result.into();
    }

    fn i256_div(a: I256, b: I256) -> I256 {
        if b == I256::ZERO { return I256::ZERO; }                  // EVM: div by 0 → 0
        if a == I256::MIN && b == I256::MINUS_ONE { return I256::MIN; } // overflow: INT_MIN/-1 → INT_MIN
        a / b
    }
    ```
    **Invariants**:
    - Division by zero in EVM returns ZERO (NOT a fault). Same for modulo.
    - `INT_MIN / -1` does NOT trap — returns `INT_MIN` per Yellow Paper (preserves "no-trap" contract).
    - `ADDMOD(a, b, 0)` returns 0; `MULMOD(a, b, 0)` returns 0. Spec is explicit: mod=0 → result=0, not error.
    - EXP gas: `gas = 10 + EXP_BYTE_COST * ceil(log_256(exp))`. EIP-160 raised `EXP_BYTE_COST` from 10 to 50.
    - SIGNEXTEND: byte index `b ≥ 31` returns input unchanged; `b < 31` sign-extends from bit `(b+1)*8 - 1`.
  - **Build steps** (granular):
    1. (~15 min) Implement `i256_div`, `i256_mod` helpers using ruint's I256 OR manual U256 sign-flip. Test on the two pitfall vectors before integration.
    2. (~15 min) Implement SDIV, SMOD wired through `pop_top!`. Note `pop_top!` pops 2 but exposes second as `&mut` for in-place write — a perf detail.
    3. (~15 min) Implement ADDMOD, MULMOD: use `U256::add_mod` (or `(a as U512 + b as U512) % m`). Pitfall: a+b overflows U256 in general, MUST use U512 intermediate OR Barrett reduction.
    4. (~20 min) Implement EXP. Gas formula: count leading-zero bytes of `exp`, `gas = 10 + EXP_BYTE_COST * (32 - lz_bytes)`. Spec_id determines `EXP_BYTE_COST = if spec >= TANGERINE { 50 } else { 10 }`.
    5. (~20 min) Implement SIGNEXTEND. Branchless preferred: `mask = (1<<((b+1)*8)) - 1`, `sign_bit = 1 << ((b+1)*8 - 1)`, `if x & sign_bit { x | !mask } else { x & mask }`.
    6. (~25 min) Build differential test harness: for each opcode, run 10k random U256 inputs through exec-vm AND revm, assert outputs identical AND gas identical.
    7. (~10 min) Hand-write the edge vectors: `[(SDIV, INT_MIN, -1)`, `(SDIV, 5, 0)`, `(EXP, 1, 0)`, `(SIGNEXTEND, 31, X)`, `(MULMOD, MAX, MAX, MAX)`]`.
  - **Pitfalls** (named):
    - *I256::MIN / I256::-1 panic*: native Rust i128 division panics on this combo. **Symptom**: panic mid-execution; replays reproducibly diverge from revm's "return INT_MIN". **Fix**: explicit early-return check.
    - *ADDMOD overflow in u256*: `(a + b) % m` overflows in U256 when `a + b >= 2^256`. **Symptom**: subtly wrong large-input results. **Fix**: use U512 intermediate or `U256::add_mod` (ruint provides this).
    - *EXP gas pre/post Tangerine*: different `EXP_BYTE_COST` across forks; if you hard-code 50, replaying pre-Tangerine blocks under-charges. **Symptom**: re-execution of mainnet block 1M diverges. **Fix**: `spec.is_enabled_in(TANGERINE)` gate.
    - *SIGNEXTEND with b ≥ 32*: spec says "if b ≥ 31, return input unchanged" but adversarial b=u256::MAX must NOT shift-overflow. **Symptom**: panic on `1 << huge`. **Fix**: branch on `b >= 31` BEFORE any shift.
  - **Test scenarios**:
    - Differential: 10k random inputs against revm. Zero divergences.
    - SDIV(0x80..00, 0xFF..FF) → 0x80..00 (no panic).
    - ADDMOD(MAX, MAX, MAX) → 1 (NOT panic).
    - EXP(2, 256) on Frontier vs Tangerine: different gas, same result (2^256 mod 2^256 = 0).
    - SIGNEXTEND(255, anything) → input unchanged.
  - **Acceptance**: 0/10000 divergence vs revm on differential fuzz; all 5 edge vectors pass; gas matches across fork boundaries.
  - **Downstream**: W53 (test-vector run depends on these passing); W63 (cargo-fuzz target reuses differential harness); W64 (revm perf PR area).

**Tuesday — Missing bitwise: BYTE, SHL, SHR, SAR**

- [ ] Implement against revm fixtures. (~120 min)
  - **Why**: SHL/SHR/SAR (EIP-145) and BYTE have non-obvious edge cases around shift-by-256+, sign-preserving SAR, and BYTE's "byte 0 is the most-significant byte" big-endian indexing. Differential testing against revm is the only sane validation.
  - **Read first**: `revm/crates/interpreter/src/instructions/bitwise.rs` — `byte`, `shl`, `shr`, `sar`.
  - **Design**:
    ```rust
    fn shl<H>(interp: &mut Interpreter, _: &mut H) {
        gas!(interp, gas::VERYLOW);
        pop_top!(interp, shift, value);
        if shift >= U256::from(256) { *value = U256::ZERO; }
        else { *value = *value << shift.as_limbs()[0]; }
    }

    fn sar<H>(interp: &mut Interpreter, _: &mut H) {
        gas!(interp, gas::VERYLOW);
        pop_top!(interp, shift, value);
        let signed = I256::from(*value);
        if shift >= U256::from(256) {
            *value = if signed.is_negative() { U256::MAX } else { U256::ZERO };
        } else {
            *value = (signed >> shift.as_limbs()[0] as usize).into();
        }
    }

    fn byte<H>(interp: &mut Interpreter, _: &mut H) {
        gas!(interp, gas::VERYLOW);
        pop_top!(interp, idx, value);
        if idx >= U256::from(32) { *value = U256::ZERO; }
        else {
            // big-endian: byte 0 is most-significant
            let i = 31 - idx.as_limbs()[0] as usize;
            *value = U256::from(value.byte(i));
        }
    }
    ```
    **Invariants**:
    - Shift by ≥256 saturates: SHL → 0, SHR → 0, SAR → 0 (positive) or -1 (negative).
    - SAR preserves sign bit (arithmetic shift). SHR is logical (fills with zero).
    - BYTE big-endian: BYTE(0, x) extracts most-significant byte of x.
  - **Build steps** (granular):
    1. (~15 min) Implement SHL, SHR with shift cap. Use `value.as_limbs()[0] as usize` for shift amount AFTER cap check.
    2. (~20 min) Implement SAR. Pitfall: Rust's `>>` on signed integer is arithmetic (good) but on unsigned is logical. Convert to I256 first.
    3. (~15 min) Implement BYTE with big-endian indexing. The exec-vm bug-magnet: forgetting `31 - idx`.
    4. (~30 min) Differential test against revm: 10k random (shift, value) tuples; assert outputs identical.
    5. (~20 min) Edge vectors: `(SHL, 256, MAX)→0`, `(SAR, 256, -1)→-1`, `(SAR, 256, +1)→0`, `(BYTE, 0, 0xff00..)→0xff`, `(BYTE, 31, 0x..01)→0x01`, `(BYTE, 32, ANY)→0`.
    6. (~20 min) Pre-EIP-145 (pre-Constantinople) handling: SHL/SHR/SAR were invalid opcodes returning InvalidOpcode. Fork-gate via `spec.is_enabled_in(CONSTANTINOPLE)`.
  - **Pitfalls** (named):
    - *Shift amount overflow into limb*: passing `shift.as_limbs()[0]` (u64) to `<<` without cap underflows when shift > 256. **Symptom**: panic in debug, UB in release. **Fix**: cap-check BEFORE limb extraction.
    - *SAR on positive number behaves like SHR*: confirm sign-preservation only matters for negative. **Symptom**: tests miss the bug. **Fix**: edge vector specifically `SAR(0x80..00, 4) = 0xF8..00` (sign bit propagates).
    - *BYTE little-endian confusion*: revm uses `value.byte(31 - idx)` (their `byte` method indexes LSB-first). Direct copy works; reinventing fails. **Symptom**: silently swap MSB/LSB. **Fix**: rely on ruint's `byte()` and replicate the `31 - idx` mirror.
  - **Test scenarios**:
    - SHL(256, MAX) = 0; SHL(255, 1) = 0x80..00; SHL(0, X) = X.
    - SAR(255, 0x80..00) = -1 (= 0xFF..FF); SAR(1, 0xFF..FE) = 0xFF..FF.
    - BYTE(0, 0xAB_00..00) = 0xAB; BYTE(31, 0x..00_CD) = 0xCD.
    - Pre-Constantinople SHL: InvalidOpcode, 0 gas refund.
  - **Acceptance**: differential green; pre/post-Constantinople fork-gate works; edge vectors all pass.
  - **Downstream**: W53 (test vectors), W63 (fuzz), W64 (perf — BYTE is cheap, SAR has a branch-predictor sensitivity).

**Friday — TLOAD/TSTORE (EIP-1153, Cancun)**

- [ ] Transient storage scoped to call frame. Adds `transient: HashMap` to call-frame state. (~30 min)
  - **Why**: EIP-1153 transient storage is the most common modern source of reentrancy-mitigation gas-griefing bugs. TLOAD/TSTORE have storage-like opcodes (3 args max stack manipulation) but persistence semantics that match revert-rollback. Mis-scoping causes either consensus bug (transient leaks across txs) OR DoS (transient persists, balloons memory).
  - **Read first**: EIP-1153 spec; `revm/crates/interpreter/src/instructions/host.rs::tload, tstore`; `revm/crates/context/src/journaled_state.rs::tload, tstore`.
  - **Design**:
    ```rust
    // exec-vm/src/state.rs additions:
    pub struct JournaledState {
        // ...existing fields...
        pub transient_storage: HashMap<(Address, U256), U256>,
    }

    impl Host for ExecVmHost {
        fn tload(&mut self, addr: Address, key: U256) -> U256 {
            self.journal.transient_storage.get(&(addr, key)).copied().unwrap_or(U256::ZERO)
        }
        fn tstore(&mut self, addr: Address, key: U256, value: U256) {
            let had = self.journal.transient_storage.get(&(addr, key)).copied().unwrap_or(U256::ZERO);
            self.journal.push_entry(JournalEntry::TransientStorageChange { address: addr, key, had_value: had });
            self.journal.transient_storage.insert((addr, key), value);
        }
    }
    ```
    **Invariants**:
    - Transient storage is per-TRANSACTION, not per-call-frame. Sub-call's TSTORE survives that sub-call's commit; only TX BOUNDARY clears.
    - REVERT must roll back transient writes (via JournalEntry::TransientStorageChange).
    - Gas: TLOAD = 100 (warm-like), TSTORE = 100. NO refund (unlike SSTORE).
  - **Build steps** (granular):
    1. (~5 min) Add `transient_storage: HashMap<(Address, U256), U256>` to JournaledState.
    2. (~10 min) Implement TLOAD/TSTORE opcodes. Both gate on `spec.is_enabled_in(CANCUN)`.
    3. (~5 min) Add `TransientStorageChange { address, key, had_value }` to JournalEntry; wire into revert path.
    4. (~5 min) Add tx-boundary clear: `JournaledState::clear()` resets `transient_storage`.
    5. (~5 min) Test: tstore in sub-call that REVERTS; assert tload in parent returns 0.
  - **Pitfalls** (named):
    - *Scoping confusion (per-call vs per-tx)*: EIP-1153 is explicit: per-tx. A novice (and the bullet's "scoped to call frame" wording — IGNORE that wording) implementation that wipes on call return creates a consensus bug. **Symptom**: revm differs on multi-call patterns. **Fix**: clear ONLY on tx finalize.
    - *Forgetting REVERT rollback*: if you skip journaling tstore, REVERT-then-TLOAD reads stale value. **Symptom**: reentrancy mitigation patterns break. **Fix**: every TSTORE pushes a journal entry.
    - *Pre-Cancun execution*: TLOAD/TSTORE on pre-Cancun fork must return InvalidOpcode. **Symptom**: replay of mainnet history wrong. **Fix**: spec-gate.
  - **Test scenarios**: TSTORE 1=42 in sub-call → REVERT → TLOAD 1 in parent = 0. TSTORE 1=42 in tx1 → tx2 TLOAD 1 = 0 (cleared between txs).
  - **Acceptance**: revm differential green for all TLOAD/TSTORE sequences; per-tx clearing verified.
  - **Downstream**: W53 (test vectors integrate Cancun); W55 (exec-vm journaling already supports the new entry variant).

**Saturday — MCOPY (EIP-5656, Cancun) + opcode-coverage matrix audit**

- [ ] MCOPY copies memory regions. (~30 min)
  - **Why**: MCOPY (EIP-5656, Cancun) replaces the idiomatic `memcpy via STATICCALL to identity precompile (0x04)` pattern with a 3-gas-base opcode. The pitfalls are overlap semantics (src/dest regions can overlap — must behave like memmove, NOT memcpy), memory-growth gas (resize to `max(src+len, dest+len)`), and SIMD-eligibility (this is a hot candidate for the W60 SIMD pass).
  - **Read first**: EIP-5656; `revm/crates/interpreter/src/instructions/memory.rs::mcopy`.
  - **Design**:
    ```rust
    fn mcopy<H>(interp: &mut Interpreter, _: &mut H) {
        pop!(interp, dest, src, len);
        if len == U256::ZERO {
            gas!(interp, gas::VERYLOW);
            return;
        }
        let len_usize = as_usize_or_fail!(interp, len, OutOfGas);
        // Quadratic memory gas based on max(dest+len, src+len):
        let new_size = max(dest, src).saturating_add(len_usize);
        resize_memory!(interp, new_size);
        gas_or_fail!(interp, gas::verylowcopy_cost(len_usize));
        // memmove semantics — overlap-safe
        interp.shared_memory.copy(dest_usize, src_usize, len_usize);
    }
    ```
    **Invariants**:
    - Gas: 3 + 3 * ceil(len/32) (linear copy cost) + memory-expansion delta.
    - Overlap-safe: `memmove` semantics. If `src < dest` and they overlap, naive forward loop corrupts.
    - `len = 0` is a no-op (still charges base gas 3, no memory growth).
  - **Build steps** (granular):
    1. (~5 min) Implement opcode 0x5E. Pop 3 args (dest, src, len).
    2. (~5 min) Special-case len=0: 3 gas, return.
    3. (~5 min) Compute memory growth: `new_size = max(dest_end, src_end)`; resize charges Δ-gas.
    4. (~5 min) Use `SharedMemory::copy(dest, src, len)` which delegates to `slice::copy_within` (memmove semantics, overlap-safe in std).
    5. (~5 min) Test: dest=0, src=0, len=32 (self-copy → no change). dest=16, src=0, len=32 (overlap: bytes 0..32 read into 16..48).
    6. (~5 min) [SIMD candidate seed for W60] Note in `EXEC_VM_PERF_BACKLOG.md`: MCOPY with 32-byte-aligned dest+src is a candidate for AVX2 `_mm256_loadu`/`_mm256_storeu` loop.
  - **Pitfalls** (named):
    - *Forward-loop overlap corruption*: writing `for i in 0..len { mem[dest+i] = mem[src+i]; }` with `src < dest < src+len` reads already-overwritten bytes. **Symptom**: differential vs revm fails on overlap test. **Fix**: use `slice::copy_within` which detects direction.
    - *Memory-growth charged once or twice*: charging expansion for each of src and dest separately overcharges. **Symptom**: differential gas wrong. **Fix**: ONE resize call to `max(dest_end, src_end)`.
    - *Pre-Cancun execution of 0x5E*: opcode 0x5E was undefined pre-Cancun (InvalidOpcode). **Symptom**: replay of pre-Cancun blocks diverges if 0x5E appears (unlikely but possible). **Fix**: spec-gate.
  - **Test scenarios**: overlap-forward (src=0, dest=16, len=32); overlap-backward (src=16, dest=0, len=32); zero-len; len > memory (triggers expansion).
  - **Acceptance**: revm differential green; SIMD candidate noted.
  - **Downstream**: W53 (test vectors); W60 (SIMD applied here); W64 (perf PR candidate area).
