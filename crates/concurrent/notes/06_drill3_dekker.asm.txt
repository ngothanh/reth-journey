Drill #3 — Dekker two-flag mutual exclusion: aarch64 disassembly of `enter`
==========================================================================

Target : aarch64-apple-darwin (Apple M-series, ARMv8.4+ — has FEAT_LRCPC)
Build  : cargo build --release -p concurrent
Source : crates/concurrent/src/dekker.rs

The three variants differ by ONE instruction and ONE letter:

  variant        store      between      load       correct?
  ------------------------------------------------------------
  DekkerAcqRel   stlrb      --           ldaprb     NO
  DekkerFence    stlrb      dmb ish      ldaprb     yes
  DekkerSeqCst   stlrb      --           ldarb      yes

  LDAR   = load-acquire, RCsc. ARM orders an earlier STLR before it. StoreLoad covered.
  LDAPR  = load-acquire, RCpc. Cheaper; explicitly NOT ordered against an earlier STLR.

`Ordering::Acquire` only requires RCpc, so LLVM emits the cheaper LDAPR — and that is
precisely the reordering Dekker's forbids. `Ordering::SeqCst` requires RCsc, forcing LDAR.

The `isb` in every loop is `core::hint::spin_loop()` (the backoff), not the protocol.
